# TwoRoom 速度上下文学习 Benchmark 报告

**版本**：v6.4
**日期**：2026-07-20  
**证据级别**：Validation 机制验证；单训练种子；正式 Test 尚未启用

## 摘要

本报告研究 History-3 LeWM 能否从两段历史交互中识别隐藏速度，并在不更新权重
的情况下，把识别结果用于多步预测和 CEM 闭环规划。

四模型双向上下文实验已经证明：只有原始数据加多速度合成数据训练的
`H3-SpeedFull` 稳定出现“快速历史高于慢速历史”的规划效应，50 步成功率差为
`14.00` 个百分点，六个评测种子方向一致。三个原始或单速控制模型均未出现
同等效应。

机制验证把“预测是否准确”和“有限 CEM 是否成功”拆开。主要结果如下：

1. 固定评测器的 query 未来轨迹时，多速度混训模型的同速历史具有最低的整段
   rollout MSE；单速混训控制没有这一模式。
2. 精确动力学 oracle 在 query 动力学匹配条件下实现 100% 的 horizon 末端成功。
   固定 300 条候选时，同速历史与快速历史的真实末端结果基本相当。
3. 把真实执行预算从 50 步增加到 100 步后，快速−同速从 `+6.33` 降至
   `+1.00` 个百分点，说明真实执行截止是快速历史高分的重要来源。
4. 100 步时残留的“快速−慢速 `+8.67`”主要来自 25 步 model horizon。只把
   horizon 延长到 50 步后，差值变为 `−1.67` 个百分点；相对基线缩小
   `10.33` 个百分点，95% 区间为 `[-16.00,-4.67]`，Holm 校正
   `p=0.00186`。
5. 候选数从 300 增到 600 会大幅提高三种上下文的绝对成功率，但只把
   快速−慢速缩小 `2.67` 个百分点，未通过预注册归因门。迭代数从 30 增到
   60 没有缩小差距。
6. 在 50 步固定 probe 上，后 25 步平均 MSE 为慢速历史 `0.21659`、同速历史
   `0.08340`、快速历史 `0.09854`。长 horizon 没有改变“同速历史预测误差最低”。
7. 在共同成功任务上，快速历史的高成功率不等于真实到达更快；规划 horizon
   变长也会把到达时间整体推后。

阶段结论是：SpeedFull 已形成速度条件化的预测和规划能力，但单个 endpoint
成功率的方向和大小同时受两个时间上限控制：真实环境允许执行多久，以及模型每次
规划能向前看多久。25 步 model horizon 会特别压低慢速历史，因为模型根据慢速历史
判断同一动作走得更短，目标更容易落在内部可达范围之外。把视野延长到 50 步后，
慢速历史的成功率从 `63.00%` 提高到 `73.33%`，原来的快速历史单向优势消失。

上述查询和历史速度值都在 SpeedFull 训练集合中，因此当前结论是“见过速度值上的
历史条件化”，不是训练未见速度的插值结论。

因此，Speed Benchmark 不采用单一 Eval score。正式结果必须联合报告速度
可辨识性、预测校准、候选动作、model-horizon 敏感性、执行预算曲线、连续轨迹、
真实效率、计算量和能力保持。

本文是 TwoRoom 速度轨道的唯一当前结果报告。数据生成与历史实验协议保留在
`protocols/`，旧版阶段总结保留在 `archive/`，但不再作为当前结论入口。

## 1. 研究问题

### 1.1 模型看到了什么

History-3 输入由两段历史转移和一个当前查询组成：

```text
历史 1：observation → action → next observation
历史 2：observation → action → next observation
查询：当前 observation + 待评估 action sequence
```

模型不接收速度标签。它只能根据历史动作和画面位移推断隐藏速度。CEM 使用模型
预测候选动作的结果，执行选中的动作后再根据新画面重新规划。

LeWM 的时间 predictor 使用 causal attention：第 `t` 个模型帧只能读取第
`1…t` 个模型帧及对应动作，不能读取后续帧。单张图像内部的 ViT 仍使用正常空间
attention。这里一个模型帧跨 5 个原始环境步；中间 5 个动作会输入模型，但中间
图像不会作为 5 个独立时间 token 输入。

### 1.2 术语与任务假设

当前 query 只有一帧 RGB 图像，不包含速度状态或速度标签。评测器仍会固定一个
模型不可见、但决定 query 后续转移的隐藏动力学速度 `v_query`。两段历史转移由
速度 `v_history` 生成，是模型识别速度的唯一直接证据。

本文采用以下术语：

| 正式术语 | 定义 | 冻结产物中的旧字段 |
|---|---|---|
| 慢速历史 | `v_history < v_query` | `slow`、`wrong_slow` |
| 同速历史 | `v_history = v_query` | `correct` |
| 快速历史 | `v_history > v_query` | `fast`、`wrong_fast` |

速度值本身没有对错，三种历史也都是合法、可回放的数据。“同速”只描述历史速度
与评测器固定的查询环境速度相同。若任务不假设历史和 query 来自同一稳定动力学
阶段，就只能讨论低速、中速和高速历史是否改变模型，不能把其中一种视为标准答案。

旧字段为保证配置、脚本和结果哈希可复现而保留，不再把 `correct/wrong` 解释成
速度本身正确或错误。

### 1.3 物理速度与 frameskip

当前实验中有两个数值都为 5、但作用不同的参数：

| 参数 | 当前设置 | 实际含义 |
|---|---:|---|
| `agent.speed` | 查询环境约 5；历史为 3.1、约 5、7.0 | 每个原始环境步的动作—位移增益 |
| `frameskip/action_block` | 始终为 5 | 一个模型步跨 5 个原始环境步，并输入这 5 个稠密动作 |

无碰撞时，一个模型步的位移近似为：

```text
Δx_block ≈ agent.speed × Σ(action_1, …, action_5)
```

训练和现有 Eval 始终固定 `action_block=5`；多速度数据改变的是 `agent.speed`，
不是 frameskip。因此现有结果应解释为“模型在固定 frameskip 下，根据历史推断
单位动作位移”。快速历史会让模型内部 rollout 预计同一动作组走得更远、目标更早
进入规划视野，但真实查询环境仍按自己的速度执行，并没有被历史加速。

### 1.4 Speed Benchmark 的判断层级

| 层级 | 要回答的问题 | 主要证据 |
|---|---|---|
| 速度可辨识性 | 两段历史是否提供足够速度信息 | RGB+action 速度恢复 |
| 速度条件化 | 模型是否随上下文速度稳定变化 | 双向上下文效应、控制模型 |
| 预测校准 | 同速历史是否更接近评测器固定的 query 未来 | 固定动作 rollout MSE |
| 候选动作 | 上下文如何改变规划选择 | cost rank、top-k、argmin |
| 预算曲线 | 高成功率是否依赖执行截止 | 慢速/同速/快速历史的 `S(B)` |
| 规划资源 | 成功率排序是否依赖 planner 配置 | horizon、samples、iterations 单因素对照 |
| 连续轨迹 | 未成功时是否仍接近目标 | final/best distance、AUC |
| 真实效率 | 同一成功任务是否更快、更省 | 配对 steps、path efficiency |
| 能力保持 | 新训练是否损伤原能力 | 原始 ID/OOD Eval |

“快速历史分数更高”只能直接说明它在当前规划协议下更容易过成功线，不能单独
证明预测更准或真实到达更快。

## 2. 数据与模型

### 2.1 数据

| 数据 | 规模与内容 | 用途 |
|---|---|---|
| 原始 TwoRoom | 9,000 train / 1,000 episode-heldout，`agent.speed=5` | 原始能力基线 |
| 速度 5 同分布合成 v2 | 10,000 episodes，904,228 transitions | 合成能力重建与单速控制 |
| SpeedFull 多速度数据 | 16,384 episodes，多速度和多几何分层 | 学习隐藏速度变化 |

速度 5 合成数据的状态、目标、像素和终止状态均通过模拟器回放，mismatch 为 0。
所有模型共享从原始训练 split 计算的冻结 normalizer。

### 2.2 模型矩阵

| 本文简称 | 实验标识 | 训练数据 | 优化步数 | 实验作用 |
|---|---|---|---:|---|
| 原始单训 | `H3-OrigHeldout` | 原始数据 | 6,420 | 原始 LeWM 基线 |
| 单速合成单训 | `H3-Synth5Matched` | 仅速度 5 合成数据 | 6,420 | 合成数据来源控制 |
| 单速混训 | `H3-OrigPlusSynth5` | 原始 + 速度 5 合成 | 12,840 | 单速混训控制 |
| 多速度混训 | `H3-SpeedFull` | 原始 + 多速度合成 | 12,840 | 多速度训练目标 |

`H3-Synth5Matched` 不是一个新任务，而是“只用我们合成的速度 5 数据训练”；
`H3-SpeedFull` 也不是纯合成单训，它使用原始数据和多速度合成数据混合训练。
正文优先使用中文简称，实验标识只用于对应配置、checkpoint 和产物路径。

四模型共享 History-3、action-block-5、模型种子 3072、normalizer 和 checkpoint
选择规则。

`H3-OrigPlusSynth5` 是 SpeedFull 的主要控制，但两套合成数据的 geometry、
分层和 loader 并非完全相同。因此，训练层结论归属于当前完整多速度配方，不能
写成只改变速度字段的单变量因果效应。

### 2.3 训练速度与现有 Eval 的重合

SpeedFull 的 32 个训练速度包含旧 E4 的全部 8 个速度：

```text
3.1 / 3.3 / 3.5 / 4.1 / 5.0 / 5.1 / 5.9 / 7.0
```

Directional v2 的查询速度 5.0/5.1、慢速历史 3.1 和快速历史 7.0 也全部在训练
集合中。现有主结果因此属于“速度值见过、query/geometry 留出”。它证明模型会
根据历史识别并调用训练过的速度规律，但不能证明对训练未见速度的插值或外推。

SpeedFull 数据另有与训练速度不重合的 synthesis validation 速度，但当前
directional、预测校准和 CEM 配置影响主结果没有使用这些速度。早期 SpeedClean
把 E4 的 8 个速度全部排除在 synthetic train 外，但混训中的原始数据仍包含速度
5.0；它没有建立稳定的规划效应，且训练配方与 SpeedFull 不同，不能作为单变量的
未见速度结论。SpeedFull 的 synthesis validation 速度也不属于封存 Test，最多
用于下一版 runner 和 Calibration 预检。

## 3. 评测协议

### 3.1 慢速、同速和快速历史对照

评测器固定的 query 隐藏动力学速度为 5.0 或 5.1：

```text
慢速历史：历史速度 3.1
同速历史：历史速度与查询环境速度一致
快速历史：历史速度 7.0
```

两个方向 Eval 共享 query 单帧、goal、geometry、同速历史、模拟器种子和 CEM
随机计划，只把另一项历史替换为慢速或快速版本。

每个 Eval、每个条件均独立执行：

```text
50 次 × 6 个评测种子 = 300 次
```

相同的同速历史条件在两个 Eval 中也分别完整运行，不能把多个任务合计成 300。

### 3.2 冻结的 Planner Profile 与执行预算

CEM 搜索配置在三个执行预算间保持不变：

| 参数 | 数值 |
|---|---:|
| Action block | 5 个原始步 |
| Model rollout horizon | 5 个 action blocks，即 25 个原始步 |
| Receding horizon | 5 个 action blocks |
| CEM samples / iterations / top-k | 300 / 30 / 30 |
| 成功半径 | 16 px |

TwoRoom 当前 Validation 的执行预算阶梯为：

| 预算档 | 原始步数 | 作用 |
|---|---:|---|
| Tight | 50 | 检查紧截止下的上下文响应 |
| Standard | 75 | 观察中等资源下的成功变化 |
| Relaxed | 100 | 检查放宽截止后差异是否保留 |

每个预算、每个 Eval、每个条件均有完整 `50×6=300` 个配对观测。短预算轨迹必须
是长预算轨迹的严格前缀。50/75/100 是当前 Validation 的冻结实现，不自动成为
其他任务或正式 Test 的通用预算。

四模型归因使用 Tight 预算，每个模型执行 1,200 条闭环记录，合计 4,800 条。
机制验证同时报告 SpeedFull 的 Tight/Standard/Relaxed 曲线。

### 3.3 固定候选与预测校准

机制协议在出分前冻结于
`configs/benchmark/tworoom_planner_mechanism_attribution_v1.yaml`。

#### 固定候选动作

每个 query 生成 300 条、每条 25 个原始步的动作序列：

- 239 条冻结随机候选；
- 60 条朝向目标、角度和幅度分层的候选；
- 1 条全零候选。

同一候选 bank 在慢速、同速、快速历史和两个模型间完全共享。记录每条候选的
模型代价、排序、top-30、选中候选和真实动力学结果。

候选有效性预检要求 query 真实动力学的精确模拟能够稳定到达目标。纯随机候选未
通过该门，因此在任何正式模型结果生成前替换为上述混合候选；预注册配置保留了
修订原因。

#### 真实 rollout 预测误差

query 真实动力学的精确 oracle 在候选 bank 中选择一条与任务相关的 probe
action。真实模拟器以评测器固定的隐藏速度执行该动作，保存第
5、10、15、20、25 个原始步的真实帧。两个模型分别在三种历史条件下预测同一
动作，并在各自原生 latent 空间中计算 MSE。

不同 checkpoint 的 latent 尺度不可直接比较，因此只做同一模型内的配对比较。

### 3.4 CEM 规划配置影响实验

该实验在正式出分前冻结于
`configs/benchmark/tworoom_cem_config_impact_v1.yaml`。真实执行预算固定为
100 步，每次只改变一个 CEM 参数：

| 配置 | Model horizon | Candidates | Iterations | Top-k |
|---|---:|---:|---:|---:|
| 基线 | 5 blocks / 25 步 | 300 | 30 | 30 |
| 长前视 | 10 blocks / 50 步 | 300 | 30 | 30 |
| 宽搜索 | 5 blocks / 25 步 | 600 | 30 | 30 |
| 深搜索 | 5 blocks / 25 步 | 300 | 60 | 30 |

Receding horizon 始终为 5 个 blocks，因此长前视只增加“模型向前看多久”，不会
改变每次规划后实际执行 25 步再重规划的规则。每个配置、每个方向 Eval、每个
条件仍完整执行 `50×6=300`。三个新配置产生 3,600 条记录；加上 1,200 条已审计
基线，配置矩阵共有 4,800 条原始记录。

主指标是每个配置的“快速−慢速”相对基线改变多少。统计使用 50,000 次按
评测种子分层的配对 bootstrap、200,000 次配对符号翻转和三个配置的 Holm 校正。
同时用 300 条固定 probe 检查 5 至 50 步预测误差，避免把长视野下的模型漂移误写
成搜索结论。

### 3.6 Horizon 记录说明

预注册的宽泛 horizon 列表曾写入原始步 1/2/3，但该模型每 5 个原始动作输出一个
预测帧，实际可观测点为 5/10/15/20/25。预注册主分析要求的
5/10/15/25 全部存在，第 20 步作为描述指标。该记录差异不影响主分析，但在正式
Test 配置中应直接按 action block 表达，避免再次混淆。

## 4. 既有四模型结果

### 4.1 基础能力

| 模型 | 原始 episode-heldout | 速度 5 同分布 Eval |
|---|---:|---:|
| 原始单训 | 91.00% | 93.67% |
| 速度 5 合成单训 | 91.67% | 94.00% |
| 单速混训 | 87.67% | 91.33% |
| 多速度混训 | 96.33% | 95.00% |

速度 5 合成单训在两个评测域均通过非劣效判定，说明合成数据能够独立重建基础
规划能力。

### 4.2 50 步双向规划

| 模型 | 慢速历史 | 同速历史 | 快速历史 | 快速−慢速 | 配对 p |
|---|---:|---:|---:|---:|---:|
| 原始单训 | 51.67% | 52.00% | 52.00% | +0.33 pp | 1.0 |
| 速度 5 合成单训 | 43.33% | 43.67% | 44.67% | +1.33 pp | 0.125 |
| 单速混训 | 32.67% | 32.67% | 31.67% | −1.00 pp | 0.375 |
| 多速度混训 | 50.67% | 58.33% | **64.67%** | **+14.00 pp** | **5.12e-12** |

多速度混训模型的快速-only/慢速-only 为 43/1，六个种子的快速−慢速为
`+10/+14/+20/+12/+14/+14 pp`。三个控制模型没有通过冻结的 5 个百分点效应门。

这建立了规划层速度条件化，但尚未解释快速历史为什么高于同速历史。

## 5. 机制结果

### 5.1 多步预测校准

多速度混训模型的各 horizon 平均 MSE 如下，数值越低越好：

| 原始步 | 慢速历史 | 同速历史 | 快速历史 |
|---:|---:|---:|---:|
| 5 | 0.02691 | **0.01027** | 0.01395 |
| 10 | 0.08058 | **0.02640** | 0.04038 |
| 15 | 0.13180 | **0.03907** | 0.06061 |
| 20 | 0.16768 | **0.04898** | 0.06881 |
| 25 | 0.19957 | **0.06538** | 0.07369 |

按预注册主 horizon 5/10/15/25 先在每个 query 内平均：

| 模型 | 慢速历史 | 同速历史 | 快速历史 | 同速−快速 95% 区间 |
|---|---:|---:|---:|---:|
| SpeedFull | 0.10972 | **0.03528** | 0.04716 | `[-0.01760,-0.00630]` |
| 单速混训控制 | 0.05420 | 0.05247 | **0.05078** | `[+0.00151,+0.00189]` |

多速度混训模型的同速历史在整段 horizon 上具有更低的平均预测误差；单速控制
没有“同速历史误差最低”的模式。这是预测层速度 ICL 的直接证据。

末端第 25 步需要单独限定：同速历史的 pooled mean 较低，但同速−快速历史的
bootstrap 区间为 `[-0.02292,+0.00543]`，且同速/快速历史更低误差的 query 数为
125/175。不能声称同速历史在每个 query 的末端都更准确。

### 5.2 精确动力学正对照

| Oracle 使用的历史速度假设 | query 真实动力学第 25 步平均距离 | 曾进入成功半径 | 第 25 步仍成功 |
|---|---:|---:|---:|
| 慢速历史假设 | 23.90 px | 100.00% | 34.33% |
| query 动力学匹配假设 | **2.85 px** | **100.00%** | **100.00%** |
| 快速历史假设 | 24.17 px | 6.00% | 6.00% |

同速假设对 300/300 个配对的真实末端距离都不劣于快速假设；相对慢速假设为
291 个更优、9 个并列。候选 bank 在 query 真实动力学下的末端可达率为 100%，
正对照通过。

慢速假设的“曾成功”与“末端成功”分离是因为固定动力学 rollout 不在首次进入成功
半径时停止。较慢假设会选择较大的动作；在真实较快速度执行时，轨迹可能穿过
目标后继续前进。

### 5.6 真实到达步数

50 步时，173 个快速历史与同速历史都成功的配对任务中：

```text
快速历史 steps-to-success − 同速历史 steps-to-success = +1.40 步
bootstrap 95% CI = [0.49, 2.30]
```

快速历史没有让共同成功的任务更快完成。它的成功率更高来自成功集合变化：一些
更难的任务在快速历史下赶在截止前成功。直接比较各条件“成功样本的平均步数”
也会受到成功集合不同的选择偏差，因此主报告采用共同成功配对。

### 5.7 CEM 规划配置影响

每个配置的三种条件均为 300 个配对观测。`Δ gap` 表示该配置的
“快速−慢速”减去基线的同一差值；负值表示差距缩小。

| 配置 | 慢速历史 | 同速历史 | 快速历史 | 快速−慢速 | Δ gap（95% 区间） | Holm p | 预注册判定 |
|---|---:|---:|---:|---:|---:|---:|---|
| 基线：H5/N300/I30 | 63.00% | 70.67% | 71.67% | +8.67 pp | — | — | 参考 |
| 长前视：H10 | **73.33%** | 72.33% | 71.67% | −1.67 pp | **−10.33** `[-16.00,-4.67]` | **0.00186** | 主要来源 |
| 宽搜索：N600 | 80.67% | 82.67% | **86.67%** | +6.00 pp | −2.67 `[-7.33,+2.00]` | 0.643 | 未通过 |
| 深搜索：I60 | 64.00% | 68.67% | 73.00% | +9.00 pp | +0.33 `[-2.00,+3.00]` | 1.000 | 未通过 |

长前视的差距变化在六个评测种子上分别为
`−14/−2/−14/−2/−14/−16 pp`，方向全部一致。它通过“至少缩小 3 个百分点、
区间完全低于 0、Holm p 小于 0.05”三项预注册门，并且缩小量超过基线差距的
一半，因此判为主要来源。

三条件分解表明，差距缩小来自慢速历史的针对性改善：

- 慢速历史：`+10.33 pp`，95% 区间 `[+5.00,+15.67]`，配对
  `p=0.000194`；
- 同速历史：`+1.67 pp`，区间 `[-3.00,+6.33]`；
- 快速历史：`0.00 pp`，区间 `[-5.00,+5.00]`。

H10 下快速与慢速历史的配对差异不再显著（`p=0.583`），但差值区间为
`[-6.33,+3.00]`，没有完全落入预注册的 `[-3,+3]` 等价带。因此可以说“原来的
快速历史单向优势消失”，不能进一步声称三种历史已经通过严格等价检验。

宽搜索带来很大的绝对收益：慢速、同速、快速历史相对基线分别提高
`17.67/12.00/15.00 pp`。这说明 300 candidates 对整体规划性能仍不充分，但
三种条件一起提高，快速−慢速的相对缩小未通过归因门。搜索宽度影响绝对
分数，却不是残留速度方向差异的主要来源。增加迭代数则没有带来同等收益。

### 5.9 50 步预测诊断

固定 probe 的前 25 步使用 query 真实动力学从冻结候选 bank 选出的动作，后
25 步为真实零动作。300/300 个 probe 在第 25 步均进入成功半径。

| 聚合区间 | 慢速历史 MSE | 同速历史 MSE | 快速历史 MSE | 同速−慢速 95% 区间 | 同速−快速 95% 区间 |
|---|---:|---:|---:|---:|---:|
| 5–25 步 | 0.12161 | **0.03811** | 0.05141 | `[-0.09639,-0.07192]` | `[-0.01970,-0.00715]` |
| 30–50 步 | 0.21659 | **0.08340** | 0.09854 | `[-0.15493,-0.11315]` | `[-0.02942,-0.00144]` |
| 5–50 步 | 0.16910 | **0.06075** | 0.07498 | `[-0.12552,-0.09281]` | `[-0.02456,-0.00437]` |

第 50 步单点 MSE 为慢速历史 `0.22841`、同速历史 `0.09944`、快速历史
`0.12411`；同速−慢速区间为 `[-0.14982,-0.10960]`，同速−快速为
`[-0.03910,-0.01053]`。因此，H10 消除快速历史 endpoint 优势不是因为其他历史
在长 rollout 上变得更准确。同速历史在 50 步范围内仍最符合 query 真实
动力学。

## 6. 机制解释

速度任务同时受两个不同的时间上限约束：

```text
model horizon：每次 CEM 让世界模型向前预测多久
execution budget：真实环境最多允许执行多久
```

增加 execution budget 不能改变 model horizon 内部的可达性。此前把真实预算从
50 放宽到 100 后，快速−同速基本消失，但快速−慢速仍为 `+8.67 pp`，
正是因为每次 CEM 仍只向前看 25 步。

多速度混训模型从历史推断出不同单位动作位移。慢速历史让模型认为同一动作走得
更短，在 25 步内部视野中，更多目标看起来不可达；快速历史让模型认为走得更远，
更多候选能在 horizon 末端接近目标。当前 LeWM cost 只使用 horizon 最后一个
latent 与 goal 的距离，因此内部可达时间会直接改变候选代价和动作幅度。

把 model horizon 延长到 50 步后，慢速历史的成功率提高 `10.33 pp`，快速历史
没有提高，原来的快速−慢速优势消失。这是对“规划视野不足”的直接单因素
证据。
H10 的共同成功任务约在第 50 步到达，也与“末端代价把计划对齐到新的 horizon”
一致；但 terminal-only cost 本身尚未做独立消融。

候选数翻倍把三种条件一起提高，说明搜索宽度限制了绝对性能；它没有稳定消除
方向差异，因此不是原残留快速−慢速的主要来源。迭代数翻倍没有相应收益，
说明当前瓶颈不是简单的“30 轮尚未优化完”。

50 步预测诊断仍由同速历史误差最低，精确动力学 oracle 也明确偏好同速假设。
因此完整链路是：

```text
速度上下文
  → 模型内部位移与 rollout 变化
  → 与 model horizon 共同决定“内部是否可达”
  → terminal goal cost 和候选排序变化
  → CEM 搜索、滚动重规划与真实执行截止共同决定 endpoint success
```

这个结果不会削弱速度 ICL 的证据；它限定了证据的含义。上下文确实改变了模型
预测和规划，但某个条件在单一 CEM profile 下的 endpoint 排名不是模型正确性的
稳定排序。

## 7. 结论边界

### 7.1 已经建立

1. 速度 5 合成数据可以重建基础规划能力。
2. SpeedFull 在训练见过的速度值上形成了预测层和规划层的稳定历史速度响应。
3. 四模型控制支持当前完整多速度训练配方的区分作用。
4. 同速历史在 5–50 步固定 query 真实轨迹上的平均预测误差低于慢速和快速历史。
5. 快速历史的 50 步 endpoint 优势包含显著的有限执行截止成分。
6. 100 步时残留的快速−慢速主要由 25 步 model horizon 造成；H10 通过
   冻结的主要来源判定。
7. 搜索宽度显著影响绝对成功率，但 N600 没有通过方向差异归因门；I60 也没有。
8. Endpoint success、prediction error、steps-to-success 和 compute 必须分开
   评价。
9. Speed Benchmark 必须同时报告执行预算曲线和 model-horizon 敏感性。

### 7.2 尚未建立

1. H10 下三种历史条件通过严格的 `±3 pp` 实用等价检验；当前区间仍过宽。
2. Terminal-only cost、horizon 长度和 receding replanning 三者各自的独立贡献。
3. 同速历史在每个 query 和每个 horizon 都优于慢速和快速历史。
4. 当前训练配方归因可以跨训练种子复现。
5. 速度支持是两个训练配方间唯一变化的单变量因果结论。
6. 正式 Test 或跨任务外推。
7. SpeedFull 能对训练未见的连续速度进行插值或范围外外推。

### 7.3 对应下一版结论等级

按下一版协议的等级解释，现有数据已经建立“历史速度会改变模型输出和规划”的
A级证据，并在查询环境速度约为 5 的一行得到“同速历史预测误差最低”的 B 级
先导证据。这些速度值都在 SpeedFull 训练中出现过，因此只属于见过速度轨道。

现有固定候选中，同速历史相对快速历史的真实末端差异区间仍跨 0，因此尚未达到
“同速历史稳定选择出更合适候选”的 C 级规划校准门。训练数据也未做到只改变速度
支持和多个训练种子，所以尚未达到 D 级训练方法结论。

## 8. 下一阶段

CEM 资源根因已经定位。下一阶段不再继续补丁式扩大旧 Validation，而是按
[History-3 速度 Benchmark v2 方案](protocols/TwoRoom_History3_Speed_Benchmark_v2_Protocol.md)
重建一套可形成正式结论的评测。

### 8.1 模型

首页直接比较原始 LeWM 和多速度模型；训练归因同时加入单速训练控制：

| 模型 | 作用 |
|---|---|
| 原始 LeWM | 判断原始单速训练是否产生同类历史速度响应 |
| 单速训练控制 | 排除额外数据量、训练步数和合成流程 |
| 多速度模型 | 检验多速度训练是否形成速度 ICL |

单速控制与多速度模型必须匹配 geometry、采集策略、有效训练曝光量、loader 和
优化设置，只允许速度支持不同，并至少完成三个成对训练种子。当前单 checkpoint
四模型结果可作为先导证据，不能代替这组正式复现。

### 8.2 Eval

基础能力使用原始 episode-heldout 和合成速度 5 同分布 Eval。速度 ICL 主任务
分为两条轨道：

1. 训练见过的速度值 + 新 geometry：验证基本的历史速度识别与调用；
2. 训练未见、但位于训练速度范围内的新速度值 + 新 geometry：验证连续插值。

每条轨道都使用严格配对的 `3×3` 速度矩阵：

```text
3 档查询环境速度 × 3 档历史速度
```

同一个 query 在三档查询速度下保持当前像素、geometry、起点和目标完全相同；真实
未来分别按各自查询环境速度生成。每个矩阵单元、每个模型、每个训练种子都独立
使用 `50×6=300`，不能把九个单元、两条轨道或多个训练种子均分同一批 300。

每条轨道每个 checkpoint 为 2,700 条，两条轨道为 5,400 条。按一个原始 LeWM
checkpoint、三个单速控制种子和三个多速度种子计算，一个主 planner profile
最低为 37,800 条。

### 8.3 先判能力，再看闭环分数

结果按以下顺序出表：

1. 两段历史能否恢复速度；
2. 相同 query 和 action 下，模型预测速度是否随三档历史变化；
3. 预测下一状态位置、位移大小和方向是否接近真实模拟器未来；
4. 同速历史是否在三个 query 速度行都具有最低物理状态误差；
5. 固定候选下，同速历史是否降低真实动力学 regret；
6. 冻结 CEM 下的执行预算曲线、连续轨迹、到达步数和计算量；
7. 原始能力是否保持。

只有前五层成立，才能把结果称为“History-3 速度 ICL 已进入规划层”。某个固定
CEM 配置下快速历史成功率最高，只说明该配置的有限视野和截止偏好，不能代替
预测与候选正确性。

LeWM 没有像素解码器。v2 不训练额外坐标头，而是在冻结速度网格上用精确模拟器
生成相同 action 的 oracle future，经同一冻结 encoder 后与模型预测 latent
匹配。最近 oracle 速度对应的真实状态作为模型的物理位置估计，逐
`1/2/3/5/10` 个模型步报告速度误差、位置误差（px）、位移大小误差、方向误差和
latent MSE。这个评测不使用最终 target，是判断 speed 自适应的主证据。

### 8.4 执行顺序

1. 新建并回放 Calibration/Validation 速度矩阵，并做训练/Eval 数值交集审计；
2. 在 Calibration 上冻结三档速度、难度、goal cost 和 planner profile；
3. 完成至少三个成对的单速/多速度训练种子；
4. 冻结指标、统计和结论门；
5. 先运行物理转移预测与固定候选，再运行完整闭环；
6. 达到进入门后封存并一次性运行 Test。

`agent.speed` 是本阶段唯一改变的速度变量，`frameskip/action_block=5` 全程固定。
History-3 速度结论稳定后，先在 History-3 下增加一个真正需要历史推断的隐藏因子；
再在速度和第二个因子上比较 History-1/3/5；最后研究独立
frameskip/action-repeat、更多单因子和因子组合。静态门位置若已在 query 单帧中
可见，不能直接作为 ICL 因子。
