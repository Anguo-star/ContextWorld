# TwoRoom History-3 速度 ICL Benchmark 报告

**版本**：v12.0
**日期**：2026-07-21
**状态**：Validation 已完成；正式 Test 仍封存

## 1. 当前结论

本报告比较三种训练数据配方，检验 History-3 LeWM 能否在不更新权重的情况下，
从前两段动作—画面转移判断当前环境的速度规律，并把它用于当前 query 的未来预测
和规划。

结论可以概括为四句话：

1. **有效配方是原始数据与多速度合成数据按 1:1 混训。** 只加入速度固定为 5 的
   合成数据，只产生弱速度响应；加入 32 个速度后，相对 loss 降低由约 `4%–12%`
   提高到 `65%–91%`。
2. **速度适应不是单帧假象。** 在训练速度范围内，多速度模型对训练见过和未见过
   的速度都通过了 1/2/3/5-block 完全自回归真实未来 latent 门；第 5 个 block
   相当于 query 后 25 个原始环境步。
3. **已证实所测区间内插值，尚不能声明范围外外推。** 多速度训练范围为
   `2.6–7.9`。本次低于 2.6 和高于 7.9 的两条轨道连一步正式门都未通过。
4. **规划成功率支持“速度历史有用”，但不替代预测准确性。** CEM 的成功率同时受
   前视长度、候选数和执行预算影响；真实未来 latent 才是当前速度校准的直接证据。

允许写出的阶段性结论是：

> 原始速度 5 数据与多速度合成数据按 1:1 混训，使 History-3 LeWM 能根据两段
> 历史转移，大幅提高训练范围内相应速度的多步未来预测准确性。该效应跨三个训练
> 种子复现，能插值到训练没出现过的区间内速度，并且没有损伤原任务能力；但当前
> 两条范围外轨道未通过，尚不能声明范围外速度校准能力。

本报告不声称模型能直接输出精确数值速度，也不把高速历史在有限 CEM 预算下更容易
到达目标解释成“高速历史总是更准确”。

## 2. 训练数据配方与公平对照

### 2.1 三类模型

| 报告名称 | 训练数据 | 原始:合成抽样比 | 训练种子 | 作用 |
|---|---|---:|---:|---|
| 原始数据模型 | 原始 TwoRoom，速度 5 | 仅原始 | 3072 | 公共参考 |
| 单速合成混训模型 | 原始数据 + 速度 5 合成数据 | 1:1 | 3072/4096/5120 | 控制额外数据与训练流程 |
| 多速度合成混训模型 | 原始数据 + 32 个速度的合成数据 | 1:1 | 3072/4096/5120 | 目标方法 |

单速和多速度模型使用相同的 608 个场景请求、geometry、reset、goal、采集策略、
History-3 架构、normalizer、optimizer、batch mixture、训练步数和 checkpoint
选择。两组之间唯一有意改变的是合成数据中的速度支持。

每个混训模型实际抽样：

```text
原始数据：6,574,080 次
合成数据：6,574,080 次
总训练步数：12,840 optimizer steps
```

多速度合成训练包含 32 个离散速度，范围为 `2.6–7.9`。所有训练和评测均固定：

```text
history = 3
frameskip/action block = 5 个原始环境步
```

这里改变的是环境中的 `agent.speed`，不是 frameskip。

### 2.2 当前推荐配方

若目标是让模型从 History-3 判断隐藏动力学速度，应采用：

```text
50% 原始 TwoRoom 速度 5 数据
+ 50% 场景匹配的多速度合成数据
+ 覆盖目标使用范围的多个离散 agent.speed
+ 固定 action block 和观测频率
```

最后一条很重要：当前结果在三个训练范围内未见速度上复现，但本次所测两端范围外
没有通过。训练数据无需精确包含每一个 Eval 速度，却应覆盖准备声明能力的速度区间。

## 3. Eval 数据和计算方式

### 3.1 History-3 测的是什么

模型输入为：

```text
x0 --u0--> x1 --u1--> x2(query)
```

`x2` 只有一张静态图像，不包含速度标签。模型只看到像素和动作，不接收
`agent.speed`、二维状态或真实未来。

评测器为 query 固定一个“参考未来速度”，并用模拟器生成相同动作下的真实未来。
历史速度与参考未来速度相同时称为“同速历史”；其他条件只称为较慢或较快历史，
不使用“正确/错误历史”。只有假设历史和 query 来自同一个、短期速度稳定的环境时，
同速历史才是预测准确性的参照。

### 3.2 四条速度轨道

| 轨道 | 速度 | 与多速度训练的关系 | 完整矩阵 | 每格样本 |
|---|---|---|---:|---:|
| 训练范围内已见 | 3.1 / 5.1 / 7.0 | 训练出现过 | 3×3 | 50×6=300 |
| 训练范围内未见 | 3.4 / 4.8 / 6.9 | 未训练，但位于 2.6–7.9 | 3×3 | 50×6=300 |
| 低端范围外 | 1.75 / 1.95 / 2.15 / 2.35 | 全部低于 2.6 | 4×4 | 50×6=300 |
| 高端范围外 | 8.25 / 8.75 / 9.50 / 10.25 | 全部高于 7.9 | 4×4 | 50×6=300 |

每个参考速度和每个历史条件都有完整的 300 个 query，不能把 300 次平摊给多个
速度。确定性离线评分使用六组互不重复的 50 个 query。

当前 v5 catalog 先从每档距离的 100 个候选中固定选择 50 个，再要求：

- 每条轨道有 300 个不同起点；
- 300 张 query 图像的内容哈希全部不同；
- 六个评测种子的 query 集合互不重叠；
- 四条轨道使用相同的静态 query 银行；
- 每条轨迹无碰撞、无边界截断、无提前终止；
- 三种动作族各占 100 个 query；
- 1/2/3/5-step 真实目标像素在不同速度间可区分。

当前 catalog 已通过 `300/300` 个不同 query 图像和完整 payload 唯一性门。该门的
完整性修订在任何模型分数产生前完成，没有改变速度、样本数、指标或判断门；审计
细节保存在执行协议和提交历史中。

### 3.3 离线真实未来 Latent

每个 query 在评分前已经保存五个未来 action block 和真实未来帧。模型只看到三张
真实输入帧 `x0/x1/x2`；`x3…x7` 全部由模型自己的预测递推，不使用真实中间帧
teacher forcing。

未来动作采用三种等量安全回路，第四个 block 后回到 query 状态；其中两个动作族的
h5 真实状态与 h1 相同。h5 仍经过五次模型自回归，所以能测回路上的误差传播和返回
校准，但不代表任意持续远离起点的开放轨迹也能保持五步。

第 `h` 个 horizon 的 loss 为：

```text
L_h(v_history → v_reference)
= MSE(自回归预测 latent_h,
      当前 checkpoint 的冻结 encoder(真实未来帧_h))
```

同一个 checkpoint、参考速度和 horizon 内计算：

```text
同速历史优势
= 其他历史的平均 loss − 同速历史 loss

相对 loss 降低
= 同速历史优势 / 其他历史的平均 loss
```

相对 loss 降低大于 0，表示同速历史让预测更接近该速度真正产生的未来。不同
checkpoint 的 encoder 空间不同，所以跨模型比较相对 loss 降低和成对训练种子
效应，不直接比较原始 MSE。

本指标不把 latent 反推成速度、像素坐标或轨迹。模型评分期间环境调用数为 0，
模型权重前后哈希一致，完整 rollout 与截短 rollout 的共同预测前缀最大差异为 0。

计数如下：

```text
每个 checkpoint：15,000 条条件轨迹，60,000 个 horizon loss
7 个 checkpoint：105,000 条条件轨迹，420,000 个 horizon loss
```

机器汇总中的 `status=passed` 只表示执行和完整性审计通过；范围外能力是否通过由
第 3.4 节的科学判断门决定。

### 3.4 正式判断门

每条轨道和每个 horizon 独立通过，必须同时满足：

1. 三个多速度 checkpoint 在每个参考速度上的同速历史优势均为正；
2. 每个参考速度的六个评测种子方向全部为正；
3. 多速度相对成对单速模型的提升，在三个训练种子上全部为正。

“同速历史分别低于每一种其他历史”是更严格的诊断，不替代平均 loss 正式门。
多步能力按从 h1 开始连续通过的最远 horizon 报告；四条轨道和四个 horizon 不合并
成一个总分。

### 3.5 Benchmark 证据层

| 层级 | 指标 | 主要回答的问题 |
|---|---|---|
| 数据有效 | 因子 readback、回放、哈希、唯一 query、速度 split | Eval 是否可信 |
| 预测校准 | 1/2/3/5-step 真实未来 latent | 历史是否让未来预测更准确 |
| 决策校准 | 冻结候选动作的选择误差 | 速度信息是否改善动作排序 |
| 闭环效用 | 50/75/100 步成功率、距离与到达时间 | 固定资源下是否真正完成任务 |
| 资源敏感性 | horizon、candidates、iterations | CEM 配置怎样影响结果 |
| 训练归因 | 单速/多速度成对种子 | 提升是否来自速度多样性 |
| 能力保持 | 原始与速度 5 合成 Eval | 新能力是否损伤基础任务 |

| 范围外轨道 | 参考速度 | h1 | h5 | h1 逐 checkpoint/seed 方向 |
|---|---:|---:|---:|---|
| 低端 | 1.75 | +9.43% | +0.07% | 通过 |

| 低端 | 2.35 | −10.68% | +1.41% | 未通过 |

| 高端 | 8.75 | −10.00% | −1.22% | 未通过 |
| 高端 | 9.50 | +10.62% | +2.97% | 通过 |

部分端点为正，不能抵消同一轨道其他速度的失败。轨道平均在 h3 或 h5 略为正，也

一个事后描述性检查给出了清楚的失败形态：在 h1–h3，三个多速度 checkpoint 对
低端四个参考速度都偏好最慢历史 1.75，对高端四个参考速度都偏好最快历史 10.25。
这个现象与“超出训练支持后被吸向测试端点或发生边界饱和”一致，但当前数据不能区分具体
机制。可以确定的是：模型会对范围外历史作出响应，却没有把四个范围外速度逐一校准
到各自真实未来。

### 4.6 旧一步评测的角色

较早的 v4 一步 Eval 使用另一套冻结动作探针，得到多速度模型约 `49%` 的相对 loss
降低，同样远高于原始和单速对照。v5 的历史探针在一个 block 内连续执行动作，速度
证据更强，同时使用新的唯一 query 银行、三种等量未来动作族和多步真实目标，因此
绝对百分比不能与 v4 直接比较。两套数据是独立证据，不合并样本量，也不把两个
百分比平均成一个分数；当前直接预测结论以 v5 为主。

## 5. 规划层结果

### 5.1 固定候选动作

正值表示同速历史平均选择了更接近真实最优的候选。

| Eval | 只用原始数据 | 原始+单速合成 | 原始+多速度合成 |
|---|---:|---:|---:|
| 训练范围内已见速度 | 0.017 px | −0.080 px | **3.675 px** |
| 训练范围内未见速度 | 0.013 px | 0.008 px | **3.135 px** |

速度历史已经影响动作排序，但严格逐速度候选门没有全部通过。因此只能说平均选择
有所改善，不能说每个速度都稳定选得更准。

### 5.2 CEM 的三个执行预算

冻结主配置为：

```text
model horizon = 10 action blocks = 50 个原始环境步
receding horizon = 5 action blocks
candidates / iterations / top-k = 300 / 30 / 30
真实执行预算 = 50 / 75 / 100 步
```

同一条 100 步轨迹读取三个截止点，因此短预算是长轨迹的严格前缀。每个模型、速度
和历史条件仍独立使用 `50×6=300`。

| 只用原始数据 | 75 | 47.11% | 47.44% | 48.89% |
| 只用原始数据 | 100 | 55.56% | 56.56% | 58.00% |
| 原始+单速合成 | 50 | 36.89% | 37.26% | 36.37% |
| 原始+单速合成 | 75 | 52.52% | 51.30% | 51.81% |
| 原始+单速合成 | 100 | 60.93% | 59.96% | 60.48% |
| 原始+多速度合成 | 50 | **41.52%** | **42.41%** | **43.67%** |
| 原始+多速度合成 | 75 | **55.00%** | **56.89%** | **60.04%** |

| 只用原始数据 | 75 | 49.11% | 47.44% | 48.11% |
| 只用原始数据 | 100 | 58.56% | 57.89% | 56.89% |
| 原始+单速合成 | 50 | 36.11% | 36.33% | 36.26% |
| 原始+单速合成 | 75 | 51.96% | 51.56% | 52.63% |
| 原始+单速合成 | 100 | 61.26% | 62.44% | 62.11% |
| 原始+多速度合成 | 50 | **41.33%** | **42.70%** | **43.44%** |
| 原始+多速度合成 | 75 | **57.93%** | **59.07%** | **60.78%** |
| 原始+多速度合成 | 100 | **68.15%** | **69.85%** | **72.19%** |

多速度模型的成功率随历史速度提高，但这不表示高速历史对每个参考未来都最准确。
高速历史让单位预测位移更大，在有限规划视野和执行预算内更容易触及目标。

### 5.3 CEM 资源消融

以下机制实验使用一个多速度 checkpoint，真实执行预算固定为 100 步，每种历史各
`50×6=300`。它只解释规划器机制，不代替三个训练种子的模型结论。

| CEM 配置 | 前视长度 | 候选数 | 迭代数 | 低速历史 | 同速历史 | 高速历史 |
|---|---:|---:|---:|---:|---:|---:|
| 资源消融基线 | 25 步 | 300 | 30 | 63.00% | 70.67% | 71.67% |
| 延长前视 | 50 步 | 300 | 30 | 73.33% | 72.33% | 71.67% |
| 增加候选 | 25 步 | 600 | 30 | **80.67%** | **82.67%** | **86.67%** |
| 增加迭代 | 25 步 | 300 | 60 | 64.00% | 68.67% | 73.00% |

前视从 25 步延长到 50 步后，高速−低速成功率差从 `+8.67 pp` 变为
`−1.67 pp`，说明短规划视野是高速历史占优的主要原因。候选数提高了绝对成功率；
迭代数翻倍没有明显帮助。

## 6. 基础能力与数据质量对照

### 6.1 基础能力保持

下表是相对原始数据模型的规划成功率差。每个模型和 Eval 独立使用
`50×6=300`。

| 训练数据配方 | 三个种子的原始留出 Eval 差值 | 速度 5 合成 Eval 差值 | 两域能力保持 |
|---|---|---|---|
| 原始+单速合成 | −0.67 / −1.33 / −0.67 pp | −3.33 / −4.33 / −4.00 pp | 0/3 通过 |
| 原始+多速度合成 | +5.33 / +3.67 / +5.67 pp | +1.33 / +1.33 / +2.33 pp | **3/3 通过** |

单速模型没有明显破坏原始留出能力，但速度 5 合成 Eval 的置信区间未通过冻结非劣
效门。多速度模型在两域全部通过。

### 6.2 合成数据能否重建基础能力

| 训练方式 | 原始 future-25 Eval | 合成速度 5 future-25 Eval |
|---|---:|---:|
| 只用原始数据 | 91.00% | 93.67% |
| 只用速度 5 合成数据 | 91.67% | 94.00% |

因此合成数据本身可以重建基础规划能力。速度 ICL 需要的是合成数据包含多种速度，
不是仅仅“使用合成数据”。

### 6.3 为什么早期 E4 分数很低

| Eval | 平均起点到目标距离 | 跨房间比例 |
|---|---:|---:|
| 原始 future-25 | 42.87 px | 23.67% |
| 合成速度 5 future-25 | 41.43 px | 26.33% |
| E4 固定远目标 | 121.97 px | 50.00% |

原始和合成 future-25 的模型内成功率最大只差 `3.67 pp`；切换到 E4 后最小下降
仍为 `62.67 pp`。早期分数地板主要来自远目标和有限 planner，不是合成 Eval
整体无效。

## 7. 阶段判断与下一步

### 7.1 Speed Benchmark 是否已经完备

History-3 速度主轨目前已经具备：

- 原始、单速合成和多速度合成三类公平训练对照；
- 训练范围内已见、范围内未见、低端范围外和高端范围外四条速度轨道；
- 每格真实独立的 `50×6=300` query；
- 1/2/3/5-step 完全自回归真实未来 latent；
- 固定候选、多个执行预算和 CEM 资源消融；
- 三个成对训练种子和基础能力保持。

因此，**用 History-3 验证训练范围内速度 ICL 的 Benchmark 基础已经完整，可以进入
新的因子类别。** 本次范围外未通过是已测模型的能力边界，不是 Benchmark 缺项。

若产品目标要求范围外速度，需另开训练版本扩大速度支持，再复用本协议；不能根据
当前失败结果偷偷移动 Eval 速度并仍称为同一次预注册实验。

### 7.2 更长 History 是否优先

当前两段历史已经让范围内速度效应稳定保持到五个未来 block。范围外上下文也通过
真实状态确认可辨识，因此范围外失败更像训练支持外的校准问题，不是“历史太短”已
有直接证据。

更长 History 可以以后用于研究噪声上下文、识别样本效率和更复杂规则，但不是进入
下一类别前的阻塞项，也不应被当作修复范围外失败的默认手段。

### 7.3 下一类任务

建议按以下顺序推进：

| 顺序 | 工作 | 要回答的问题 | 能力名称 |
|---:|---|---|---|
| 1 | 门位置 query-only 基线 | 当前单帧是否已经足够识别门位置 | 可见几何泛化，不先称为 ICL |
| 2 | 速度×门位置组合 | 隐藏速度能否与当前可见几何组合，并推广到未见组合 | 隐藏动力学×可见几何组合泛化 |
| 3 | 第二个隐藏动力学 | 当前帧相同，但动作方向映射规则不同，模型能否从历史转移识别 | 新的纯 ICL 类别 |
| 4 | History-1/3/5 | 不同规则和噪声下需要多少历史 | 上下文长度与样本效率 |

“第二个隐藏动力学”不是门位置。一个合适的例子是动作方向映射：相同动作在不同
环境中分别按正常坐标、交换 x/y 轴或旋转后的方向执行。静态 query 看不出规则，
只有动作—画面历史能识别，而且它改变方向而不是像 speed 一样只改变位移幅度。
