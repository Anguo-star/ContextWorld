## 0. 最终结论与数据总览

### 0.1 一句话结论

> 匹配多速度模型已经学会从 History-3 读取速度线索，并据此改变相同 action 下的
> 下一状态位移；但响应幅度只有真实速度跨度的约 30%，且随自回归快速衰减，所以
> 当前证明的是“可复现的速度响应”，不是“准确、持久的完整速度自适应”。

这一结论由真实模拟器下一状态直接验证，不依赖最终目标距离或 CEM 成功率。M2 在
原始 heldout 和速度 5 合成 Eval 的两域能力保持门均为 3/3 训练种子通过，因此
速度响应不是以基础能力退化换来的。

## 1. 到底在测什么

### 1.1 模型输入

History-3 包含两个历史转移和一张当前 query 图像：

```text
历史 1：observation → action block → next observation
历史 2：observation → action block → next observation
query：当前 observation + 待预测 action sequence
```

模型只接收像素和动作，不接收速度标签、状态坐标或 query 的真实未来。评测期间
不更新权重。

Query 只有一张静态图像，单凭它无法知道速度。因此速度没有天然的“正确/错误
上下文”。本文只使用：

- 低速历史；
- 中速历史；
- 高速历史。

评测器另外固定一个模型不可见的 `v_query`，用精确模拟器生成真实未来。在
“历史和 query 来自同一个短期稳定环境”的任务假设下，历史速度等于 `v_query`
的条件称为“同速历史”，只用于检查物理校准。若不采用这个稳定环境假设，只能
讨论模型是否随历史响应，不能判断哪种历史应该最准确。

### 1.2 速度与 frameskip

本实验改变的是每个原始环境步的位移增益 `agent.speed`。训练和评测始终固定：

```text
frameskip/action block = 5
```

一个模型步跨 5 个原始环境步，并接收块内全部 5 个有序动作。快速历史让模型预测
同一组动作走得更远，但不会改变 query 模拟器的真实速度。改变 frameskip 或动作
重复次数属于另一个问题。

### 1.3 为什么不能只看旧 Eval score

前一阶段已经把训练速度和 query 速度都固定为 5，交叉比较三套 Eval：

| Eval | 平均起点—目标距离 | 跨房间比例 |
|---|---:|---:|
| 原始 future-25 | 42.87 px | 23.67% |
| 合成速度 5 future-25 | 41.43 px | 26.33% |
| E4 固定几何 speed-5 | 121.97 px | 50.00% |

原始与合成 future-25 的模型内成功率最大只差 `3.67 pp`；从任一 future-25
切换到 E4 后，最小下降仍为 `62.67 pp`。E4 的 s0/s1/s2 三个模板在四个模型和
三种历史下全部失败，只有 s3 全部成功。

原始和合成 future-25 的平均距离在数值上接近 s3 的 `45.18 px`，但不能把它们
等同为 s3：前两者来自许多真实 episode，仍包含约四分之一跨房间任务；s3 是单个
固定同房间几何。

阶段根因是 E4 的固定远目标与有限 planner 共同形成地板，而不是合成 Eval 整体
有问题，也不是混合了多种速度。v2 因此：

- 配对固定 geometry、query 像素和 action，只改变速度；
- 使用 `72/80/88/96/104/112 px` 的中等距离带；
- 先测真实下一状态，再看固定候选和 CEM；
- 不跨不同距离分布直接解释模型能力。

## 4. 真实下一状态：主要结果

### 4.1 评测方法

对相同 query 和相同原始 action 序列，精确模拟器按 `v_query` 生成真实未来。
主结果不使用最终 target。

LeWM 没有坐标解码头。评测器在速度 `2.5–8.0`、步长 `0.05` 的冻结网格上生成
精确 future，再通过同一个冻结 encoder 编码。与模型预测 latent 最近的 oracle
future 提供推断速度和物理位置；同时直接报告模型预测到真实 query future 的
latent MSE。

Action probe 包含恒定方向、变幅和转向，并限制在无碰撞区域。报告
1/2/3/5/10 个 action block；第一个 block 就是用户关心的“同一 action 下，模型
预测下一状态走了多远”。

### 4.2 一步速度与位移响应

下表先回答模型是否真的随历史速度改变下一状态。响应增益定义为：

```text
(高速历史推断速度 − 低速历史推断速度)
÷ (真实历史速度跨度)
```

| 轨道 | 模型 | 一步响应增益 | 高速−低速预测位移 |
|---|---|---:|---:|
| 训练见过速度 | M0 原始单速基线 | 0.047 | 0.077 px |
| 训练见过速度 | M1 匹配单速控制 | 0.069 | 0.101 px |
| 训练见过速度 | M2 匹配多速度模型 | **0.299** | **0.531 px** |
| 训练未见速度 | M0 原始单速基线 | 0.048 | 0.070 px |
| 训练未见速度 | M1 匹配单速控制 | 0.058 | 0.076 px |
| 训练未见速度 | M2 匹配多速度模型 | **0.305** | **0.498 px** |

M2 的响应在三个训练种子和六个评测种子上方向一致，并稳定大于相同训练种子的
M1。原始模型和单速控制不是完全不响应，但幅度很小；多速度训练稳定放大了真实
下一状态的速度条件化。

### 4.3 一步预测是否准确

M2 三个训练种子的组均值如下。每行加粗值是该 query 速度的同速历史。

| 见过速度 `v_query` | 低速历史误差 | 中速历史误差 | 高速历史误差 |
|---:|---:|---:|---:|
| 3.1 | **0.735 px** | 1.001 px | 1.257 px |
| 5.1 | 0.562 px | **0.384 px** | 0.432 px |
| 7.0 | 1.139 px | 0.870 px | **0.634 px** |

| 未见速度 `v_query` | 低速历史误差 | 中速历史误差 | 高速历史误差 |
|---:|---:|---:|---:|
| 3.4 | **0.631 px** | 0.829 px | 1.102 px |
| 4.8 | 0.503 px | **0.388 px** | 0.515 px |
| 6.9 | 1.088 px | 0.873 px | **0.615 px** |

组均值看起来三行都校准正确，但正式方法结论不能只看跨训练种子平均：

- 见过速度的中间行 `v_query=5.1`，M2 种子 3072 和 4096 的高速历史一步误差
  略低于同速历史；
- 种子 5120 的一步关系正确，但中间行的多步轨迹误差门仍失败；
- 未见速度的中间行 `v_query=4.8` 虽然一步门通过，多步轨迹门在三个训练种子上
  都失败。

预测位置误差与位移长度误差在无碰撞 probe 中给出相同判定；直接 latent MSE 的
多步门也纳入正式统计。因此平均有效不等于每个训练复现都已准确校准。

### 4.4 响应随自回归变弱

| 轨道 | 模型步数 | M2 响应增益 | 高速−低速累计预测位移 |
|---|---:|---:|---:|
| 训练见过速度 | 1 | 0.299 | 0.531 px |
| 训练见过速度 | 2 | 0.262 | 0.975 px |
| 训练见过速度 | 3 | 0.160 | 0.978 px |
| 训练见过速度 | 5 | 0.092 | 1.018 px |
| 训练见过速度 | 10 | 0.048 | 1.026 px |
| 训练未见速度 | 1 | 0.305 | 0.498 px |
| 训练未见速度 | 2 | 0.261 | 0.869 px |
| 训练未见速度 | 3 | 0.162 | 0.883 px |
| 训练未见速度 | 5 | 0.093 | 0.926 px |
| 训练未见速度 | 10 | 0.049 | 0.946 px |

绝对累计位移差没有消失，但相对于真实速度跨度的校准增益随 rollout 明显衰减。
这说明模型学到的是“朝正确方向调节”，尚不是能够长期保持真实速度比例的动力学
估计。

## 5. 固定候选动作

每个 query 冻结相同的 300 条、10-block 候选序列。模型只负责排序和选择，候选
由真实 `v_query` 模拟器执行。真实代价差是“被选候选与 bank 中真实最优候选的
末端代价差”。正的“同速收益”表示其他历史选择的候选具有更高真实代价差。

| 轨道 | M0 原始单速 | M1 匹配单速 | M2 匹配多速度 |
|---|---:|---:|---:|
| 训练见过速度 | 0.017 px | −0.080 px | **3.675 px** |
| 训练未见速度 | 0.013 px | 0.008 px | **3.135 px** |

M2 的平均固定候选收益明显高于 M1，并在三个成对训练种子上保持正向差异。这说明
历史速度响应已经影响候选选择，而不只是改变一个不参与决策的内部表征。

但严格的“每个 query 速度行、每个训练种子都由同速历史取得最低代价差”仍未
全部通过。固定候选平均改善是支持证据，不能覆盖物理多步校准失败。

## 6. CEM 闭环与规划资源

### 6.1 100 步结果

下表是 100 步成功率。每个单元格依次为低/中/高速历史；M1/M2 是三个训练种子的
组均值。

| 轨道 | `v_query` | M0 原始单速 | M1 匹配单速 | M2 匹配多速度 |
|---|---:|---:|---:|---:|
| 训练见过 | 3.1 | 36.33 / 38.00 / 39.00 | 41.67 / 39.89 / 40.00 | **46.11 / 49.67 / 50.00** |
| 训练见过 | 5.1 | 61.00 / 61.33 / 64.33 | 68.44 / 67.67 / 69.00 | **72.33 / 75.00 / 77.56** |
| 训练见过 | 7.0 | 69.33 / 70.33 / 70.67 | 72.67 / 72.33 / 72.44 | **76.11 / 79.11 / 83.22** |
| 训练未见 | 3.4 | 44.67 / 45.67 / 42.67 | 46.33 / 47.56 / 47.33 | **54.44 / 56.00 / 56.78** |
| 训练未见 | 4.8 | 61.33 / 60.00 / 60.00 | 65.78 / 67.00 / 67.33 | **73.11 / 75.33 / 76.33** |
| 训练未见 | 6.9 | 69.67 / 68.00 / 68.00 | 71.67 / 72.78 / 71.67 | **76.89 / 78.22 / 83.44** |

M1 三种历史基本相同。M2 则在六个 query 行中都表现为高速历史成功率最高，包括
低速和中速 query 行；这不是“同速历史预测最准确”的模式。

### 6.2 执行预算曲线

把三个 query 行分别等权平均，M2 的曲线为：

| 轨道 | 执行预算 | 低速历史 | 中速历史 | 高速历史 |
|---|---:|---:|---:|---:|
| 训练见过 | 50 | 41.52% | 42.41% | 43.67% |
| 训练见过 | 75 | 55.00% | 56.89% | 60.04% |
| 训练见过 | 100 | 64.85% | 67.93% | **70.26%** |
| 训练未见 | 50 | 41.33% | 42.70% | 43.44% |
| 训练未见 | 75 | 57.93% | 59.07% | 60.78% |
| 训练未见 | 100 | 68.15% | 69.85% | **72.19%** |

100 步平均 final distance 也同向变化：见过速度为低/中/高速历史
`36.55/34.44/30.88 px`，未见速度为 `35.71/34.04/30.98 px`。

这些结果确认了一个合理的下游效应：高速历史让模型预计同一动作走得更远，CEM
会据此选择更容易在有限视野和执行预算内到达目标的动作。真实 query 环境没有被
历史加速；变化来自模型 rollout 和候选选择。

因此，高速历史的闭环分数更高可以证明历史速度影响了规划，却不能证明它比同速
历史更接近真实下一状态。低速 query 行中，真实下一状态表明确是低速历史最准确，
但 CEM 仍偏向高速历史；两类指标必须分开解释。

### 6.3 冻结资源与既有消融

本轮闭环固定：

```text
model horizon = 10 action blocks = 50 个原始步
receding horizon = 5 action blocks
CEM candidates / iterations / top-k = 300 / 30 / 30
最大真实执行预算 = 100 步
```

一次 100 步轨迹同时读取 50/75/100 步成功率，因此三个预算使用相同 query、
历史和 CEM 随机计划，短预算是长轨迹的严格前缀。

此前单训练种子机制实验已经说明为什么闭环必须与预测误差分开：旧 25-step model
horizon 下，100 步执行预算仍出现高速−低速 `+8.67` 个百分点；只把 model
horizon 延长到 50 步后，差值变为 `−1.67` 个百分点。候选从 300 增至 600 会
提高绝对成功率，但只缩小 `2.67` 个百分点；迭代从 30 增至 60 没有帮助。

这说明快速历史会让目标更早进入有限规划视野，有限 CEM 高分可以是合理的资源
效应，不等同于预测更准确。本轮采用 50-step model horizon，并把真实下一状态放在
闭环分数之前。

## 7. 基础能力保持：原始与合成两域

M1 和 M2 分别在原始 episode-heldout、速度 5 合成同分布 Eval 上与 M0 配对比较。
每个模型、每个 Eval 都是独立 `50×6=300`，并补充 1/2/3/5-step rollout error。

非劣效门在出分前冻结：成功率差区间下界不低于 `−5 pp`，final distance 差区间
上界不高于 `+5 px`，且 M0 可解的任务分层不得在新模型中完全坍塌。

规划成功率相对 M0 的配对差如下：

| 模型 | 种子 | 原始 heldout | 速度 5 合成 Eval | 两域非劣效 |
|---|---:|---:|---:|---|
| M1 匹配单速控制 | 3072 | −0.67 pp | −3.33 pp | 未通过 |
| M1 匹配单速控制 | 4096 | −1.33 pp | −4.33 pp | 未通过 |
| M1 匹配单速控制 | 5120 | −0.67 pp | −4.00 pp | 未通过 |
| M2 匹配多速度模型 | 3072 | +5.33 pp | +1.33 pp | 通过 |
| M2 匹配多速度模型 | 4096 | +3.67 pp | +1.33 pp | 通过 |
| M2 匹配多速度模型 | 5120 | +5.67 pp | +2.33 pp | 通过 |

M1 的原始 heldout 门均通过；失败来自速度 5 合成 Eval 的成功率差区间下界低于
`−5 pp`。M2 三个训练种子在两域全部通过，说明目标模型没有用原始能力退化换取
速度响应。

Rollout latent MSE 的组均值如下，只展示第 1 和第 5 个 action block：

| 模型 | 原始 H1 / H5 | 速度 5 合成 H1 / H5 |
|---|---:|---:|
| M0 原始单速基线 | 0.01572 / 0.07285 | 0.01542 / 0.07432 |
| M1 匹配单速控制 | 0.01168 / 0.05945 | 0.01021 / 0.05298 |
| M2 匹配多速度模型 | 0.01337 / 0.06600 | 0.01288 / 0.05902 |

不同 checkpoint 的 latent 空间不完全相同，因此这些数值不作为跨模型非劣效门。
它们仍揭示一个重要现象：M1 的 rollout MSE 较低，但速度 5 规划成功率非劣效门
失败。预测 loss 改善不保证冻结 CEM 的成功率同步改善，这与速度主实验的结论
一致。

## 8. 下一步

当前问题出现在 CEM 之前，所以不应继续通过调整 endpoint 距离分布或增加 CEM
预算来掩盖。下一阶段优先级为：

1. 保持 Test 封存，在独立 Calibration 上定位速度 5 收缩来自训练目标、历史
   表征还是多步 loss；
2. 设计只针对响应幅度和 rollout 持久性的训练改动，并继续使用匹配 M1/M2 和三个
   成对训练种子；
3. 重新冻结新版本后复跑同一 Validation，至少先通过 B 级物理校准；
4. B/C 稳定后再比较 History-1/3/5，判断更长历史是否改善速度估计；
5. 速度轨道闭合后，再扩展动作延迟、摩擦等当前单帧不可见的隐藏因子；
6. 静态门位置若能从 query 图像直接看到，不作为优先 ICL 因子。
