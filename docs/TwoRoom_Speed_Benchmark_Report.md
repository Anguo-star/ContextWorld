# TwoRoom History-3 速度学习报告

**更新日期**：2026-07-21
**当前阶段**：Validation 已完成；正式 Test 保持封存

## 1. 先看结论

本实验要回答一个简单问题：世界模型只看到两段过去的“动作—画面变化”，能否在
不更新参数的情况下，判断当前环境移动得快还是慢，并据此预测后续画面？

答案是：**在训练覆盖的速度范围内可以；超出训练范围后，当前模型不可以。**

有效的训练配方是：

```text
50% 原始 TwoRoom 数据（agent.speed = 5）
+ 50% 多速度合成数据（32 个速度，范围 2.6–7.9）
```

主要结果如下：

- 多速度模型在训练见过的速度和训练未见但位于训练范围内的速度上，都通过了
  1/2/3/5 步自回归预测测试；
- 同速历史的预测 loss，在第一步只有其他速度历史的约 `10%–11%`，第五步约为
  `33%–35%`；
- 第一步逐 query 严格胜率为 `95%–97%`，第五步仍为 `80%–81%`；
- 三个独立训练种子结果一致，且原始任务能力没有下降；
- 低于 2.6 和高于 7.9 的范围外速度没有通过任何正式 horizon，因此不能声称模型
  已学会任意速度外推。

这里的 `10%` 是 **loss 比值**，不是“10% 准确率”。它表示在同一 checkpoint、
同一 query 和同一未来动作下，使用同速历史得到的 latent 误差只有其他速度历史
平均误差的十分之一左右。

据此，当前可以公开表述为：

> 原始数据与多速度合成数据按 1:1 混训后，History-3 LeWM 能从两段历史转移中
> 读取速度信息，并用它校准训练范围内的多步未来预测。该能力可插值到训练没有
> 精确出现过的区间内速度，但尚不能外推到训练范围之外。

本报告不声称模型能输出精确的数值速度，也不把 CEM 在有限预算下更容易到达目标
等同于预测更准确。

## 2. 模型究竟看到了什么

History-3 的输入形式是：

```text
x0 --u0--> x1 --u1--> x2（query）
```

`x2` 是一张静态图像，不带速度标签。速度无法从这一帧直接读出，模型只能根据
`u0/u1` 引起的画面变化推断当前移动规律。

评测假设历史和 query 来自同一个短期稳定的环境。于是：

- **同速历史**：历史和 query 后续使用相同的 `agent.speed`；
- **较慢历史**：历史速度比 query 后续速度慢；
- **较快历史**：历史速度比 query 后续速度快。

这些名称只描述数据关系，不表示某段历史本身“正确”或“错误”。如果任务不再假设
历史与 query 共用同一速度，同速历史也就不再是标准参照。

所有实验固定 `action block = 5`，即每次模型预测跨越 5 个原始环境步。它是时间
聚合设置，不是 `agent.speed`。因此：

| 报告名称 | 自回归次数 | 对应原始环境步 |
|---|---:|---:|
| h1 | 1 | 5 |
| h2 | 2 | 10 |
| h3 | 3 | 15 |
| h5 | 5 | 25 |

真实未来动作使用三类安全回路。第四个 action block 后会回到 query 附近，其中
两类回路的 h5 真实状态与 h1 相同。因此 h5 能验证五次连续自回归后的误差传播和
返回校准，但不能代表任意开放轨迹都能稳定预测 25 步。

## 3. 公平对照怎样设置

### 3.1 三种训练配方

| 模型 | 训练数据 | 训练种子 | 用途 |
|---|---|---:|---|
| 原始数据模型 | 只用原始速度 5 数据 | 3072 | 公共参考 |
| 单速合成混训模型 | 原始数据 + 速度 5 合成数据，1:1 | 3072/4096/5120 | 控制额外数据和训练流程 |
| 多速度合成混训模型 | 原始数据 + 32 个速度的合成数据，1:1 | 3072/4096/5120 | 检验速度多样性 |

单速和多速度实验使用相同的 608 个场景请求、几何布局、起点、目标、采集策略、
网络结构、normalizer、优化器、训练步数和 checkpoint 选择规则。两组之间唯一有意
改变的是合成数据是否包含多个速度。

每个混训模型都抽样 6,574,080 次原始样本和 6,574,080 次合成样本，共训练
12,840 个 optimizer step。这样的对照可以区分“增加了数据”与“增加了速度变化”。

### 3.2 四条评测轨道

| 轨道 | 参考速度 | 与多速度训练集的关系 | 历史×参考矩阵 |
|---|---|---|---:|
| 范围内已见 | 3.1 / 5.1 / 7.0 | 训练中出现过 | 3×3 |
| 范围内未见 | 3.4 / 4.8 / 6.9 | 未出现，但位于 2.6–7.9 | 3×3 |
| 低端范围外 | 1.75 / 1.95 / 2.15 / 2.35 | 低于 2.6 | 4×4 |
| 高端范围外 | 8.25 / 8.75 / 9.50 / 10.25 | 高于 7.9 | 4×4 |

每一个“参考速度 × 历史速度”单元都包含完整的 `50 query × 6 seeds = 300` 个样本，
不是把 300 次分摊给整条轨道。不同速度和历史条件复用同一组 300 个静态 query
进行配对比较；组内每张 query 图像内容唯一，六个评测种子的 query 集合互不重叠。

数据生成阶段还检查了碰撞、边界截断、提前终止、速度 readback、真实未来的速度
可区分性以及完整 payload 哈希。模型评分时不再调用环境。

### 3.3 评测规模

```text
每个 checkpoint：15,000 条条件轨迹，60,000 个 horizon loss
7 个 checkpoint：105,000 条条件轨迹，420,000 个 horizon loss
```

模型权重在评分前后哈希一致。完整五步 rollout 与单独截短 rollout 的共同预测前缀
完全一致，说明没有使用未来信息或真实中间帧。

## 4. 指标怎样理解

每个 checkpoint 都用自己的冻结 encoder，把模拟器预先生成的真实未来帧编码成
latent。第 h 步误差为：

```text
L_h = MSE(模型连续自回归得到的 latent_h,
          冻结 encoder 编码的真实未来帧_h)
```

中间预测不会被真实帧替换。由于不同 checkpoint 的 latent 空间不同，原始 MSE
只能在同一 checkpoint 内解释，不能直接拿来给不同模型排高低。

为让结果更直观，报告三个互补指标：

| 指标 | 计算 | 怎样读 |
|---|---|---|
| loss 比值 | 同速历史 loss ÷ 其他历史平均 loss | 越低越好；`0.10×` 表示误差约为十分之一 |
| query 胜率 | 同速 loss 小于其他历史平均 loss 的 query 比例 | 越高越稳定 |
| 严格胜率 | 同速 loss 小于每一种其他历史 loss 的 query 比例 | 更严格，越高越好 |

旧实验协议中的“相对 loss 降低”正好等于 `1 − loss 比值`。它仍用于不改变预注册
判定门，但不再作为面向读者的主百分数，更不能称为准确率。

正式通过还要求三个多速度训练种子、每个参考速度和六个评测种子的方向一致，并且
多速度模型相对同种子的单速模型提升为正。四条轨道和四个 horizon 分开判断，不
合并成一个总分。

## 5. 核心预测结果

### 5.1 多速度模型的完整结果

每格为“loss 比值 / 严格胜率”。

| 评测轨道 | h1 | h2 | h3 | h5 |
|---|---:|---:|---:|---:|
| 范围内已见 | **0.104× / 97.0%** | **0.086× / 96.3%** | **0.157× / 91.4%** | **0.328× / 81.3%** |
| 范围内未见 | **0.114× / 95.3%** | **0.091× / 94.7%** | **0.171× / 90.5%** | **0.348× / 79.7%** |
| 低端范围外 | 0.998× / 26.2% | 1.007× / 25.2% | 0.994× / 28.0% | 0.995× / 25.9% |
| 高端范围外 | 1.062× / 25.2% | 1.096× / 25.3% | 0.989× / 28.6% | 0.989× / 32.6% |

范围内同速历史的误差明显更低，而且优势在绝大多数独立 query 上成立。范围外的
loss 比值约为 1、严格胜率约为四种历史对称比较时的 25%，没有可靠校准证据。

### 5.2 正式判定

| 评测轨道 | h1 | h2 | h3 | h5 | 连续通过到 |
|---|---:|---:|---:|---:|---:|
| 范围内已见 | 通过 | 通过 | 通过 | 通过 | **h5** |
| 范围内未见 | 通过 | 通过 | 通过 | 通过 | **h5** |
| 低端范围外 | 未通过 | 未通过 | 未通过 | 未通过 | h0 |
| 高端范围外 | 未通过 | 未通过 | 未通过 | 未通过 | h0 |

因此已经证实的是区间内速度插值，而不是任意速度外推。`h5` 是本次最长 horizon，
结论应写成“至少保持到冻结回路的第五次预测”，而不是“能力只能保持五步”。

### 5.3 为什么提升来自多速度训练

下表列出三个训练配方。每格仍为“loss 比值 / 严格胜率”。

| 轨道 | 训练配方 | h1 | h5 |
|---|---|---:|---:|
| 范围内已见 | 原始数据 | 0.908× / 59.3% | 0.963× / 41.7% |
| 范围内已见 | 单速合成混训 | 0.883× / 65.8% | 0.929× / 49.9% |
| 范围内已见 | 多速度合成混训 | **0.104× / 97.0%** | **0.328× / 81.3%** |
| 范围内未见 | 原始数据 | 0.905× / 59.4% | 0.964× / 41.1% |
| 范围内未见 | 单速合成混训 | 0.877× / 64.3% | 0.931× / 49.2% |
| 范围内未见 | 多速度合成混训 | **0.114× / 95.3%** | **0.348× / 79.7%** |

原始模型和单速模型并非完全不受历史影响，但它们的偏好较弱。多速度训练使严格
胜率相对成对单速模型提高：范围内已见 h1/h5 分别为 `+31.19/+31.44` 个百分点，
范围内未见为 `+30.93/+30.56` 个百分点。三个训练种子的全部正式成对方向均为正。

这支持“能力来自训练中的速度多样性”，而不是仅仅来自额外样本、不同训练流程或
某一个幸运 checkpoint。

### 5.4 范围外失败是什么样的

低端范围外 h1 的逐速度 loss 比值为 `0.906×、0.957×、1.024×、1.107×`；高端
为 `1.430×、1.100×、0.894×、0.823×`。模型在低端倾向训练范围的最低方向，在
高端倾向最高方向；h1–h3 选择也集中在各自最靠近训练区间的端点。

这更像训练端点吸引或饱和，而不是模型已经学会连续规律并向区间外延伸。范围外
轨道因此是有价值的能力边界测试，不是一个尚未补齐的 Benchmark 缺口。

## 6. 从预测到规划

预测 loss 回答“模型是否更接近真实未来”；规划成功率回答“在给定 CEM 资源和
执行预算下能否到达目标”。两者有关，但不是同一个指标。

### 6.1 固定候选动作

冻结候选动作后，多速度模型所选动作与真实最优动作的平均终点差距，在范围内已见
和未见轨道分别为 `3.675 px` 与 `3.135 px`。结果显示速度历史会改善动作排序，但
最严格的逐单元门没有全部通过，因此该层只作为支持证据，不替代 latent 主结果。

### 6.2 多个执行步数预算

下表为多速度模型在较慢、同速和较快历史下的成功率。每个条件独立运行
`50×6=300` 次。

| 轨道 | 执行预算 | 较慢历史 | 同速历史 | 较快历史 |
|---|---:|---:|---:|---:|
| 范围内已见 | 50 | 41.52% | 42.41% | 43.67% |
| 范围内已见 | 75 | 55.00% | 56.89% | 60.04% |
| 范围内已见 | 100 | 64.85% | 67.93% | 70.26% |
| 范围内未见 | 50 | 41.33% | 42.70% | 43.44% |
| 范围内未见 | 75 | 57.93% | 59.07% | 60.78% |
| 范围内未见 | 100 | 68.15% | 69.85% | 72.19% |

较快历史在有限执行预算下成功率更高是合理现象：模型预期每个动作块走得更远，
可能更快覆盖到目标。它不能单独证明该历史符合 query 的真实动力学；预测准确性
仍应由真实未来 latent 判断。

### 6.3 CEM 资源为什么重要

保持模型、query、历史和 100 步执行预算不变，每次只增加一种规划资源：

| 配置 | 较慢历史 | 同速历史 | 较快历史 |
|---|---:|---:|---:|
| 基线：horizon 25 / 300 candidates / 30 iterations | 63.00% | 70.67% | 71.67% |
| horizon 50 | 73.33% | 72.33% | 71.67% |
| candidates 600 | 80.67% | 82.67% | 86.67% |
| iterations 60 | 64.00% | 68.67% | 73.00% |

延长规划视野明显改变了历史条件之间的排序，增加候选数则整体提高成功率。这说明
单一 CEM score 会把模型误差、规划视野、搜索充分程度和执行预算混在一起。Speed
Benchmark 因而必须同时报告真实未来预测、固定候选排序和资源阶梯下的闭环表现。

## 7. 原任务能力是否保留

多速度混训的三个训练种子均通过原始 heldout、速度 5 匹配合成集和 E4 保持门，
即 `3/3` 通过；单速混训为 `0/3`。这说明当前多速度配方在获得速度校准能力的同时，
没有观察到原始规划能力下降。

独立的原始能力重建实验还表明：只用速度 5 合成数据训练，可以接近但不能完全
取代原始训练数据；混训是当前更稳妥的配方。E4 的主要限制仍是起点到目标的距离
分布与 CEM 预算不匹配，因此它不应单独承担速度 ICL 判定。

## 8. 当前能力边界与下一阶段

History-3 速度部分现在具备一套完整 Benchmark 基础：隔离的训练对照、训练已见
与未见速度、双向范围外压力测试、1/2/3/5 步真实未来、固定候选规划、CEM 预算
阶梯以及基础能力保持。

当前仍有三条明确边界：

- 已完成的是 History-3，尚未测试更长历史是否继续改善速度估计；
- 区间内插值已通过，范围外速度未通过；
- 五步结果来自冻结安全回路，尚未覆盖更长的开放轨迹。

下一阶段不再继续堆叠速度实验记录，而按以下顺序扩展能力类别：

1. 先用 query-only 基线检查门位置等可见几何是否真的需要历史；
2. 再测试“隐藏速度 × 可见门位置”的训练未见组合，验证因素解耦；
3. 最后加入第二种真正隐藏的动力学，例如隐藏动作增益或动作响应延迟；
4. 更长 History 作为跨因素的统一扩展，而不是先为单一速度单独改架构。

门位置本身通常可以从 query 图像看见，因此更适合作为视觉泛化或组合测试，不能
不加区分地称为速度同类的 ICL。
