# TwoRoom History-3 速度 ICL：训练配方与评测结果

**版本**：v11.0
**日期**：2026-07-21
**状态**：Validation 已完成；正式 Test 仍封存

## 1. 先说结论

当前比较了三种训练数据配方：只用原始数据、原始数据加单一速度合成数据、原始
数据加多速度合成数据。

这里的速度 ICL 指：评测时不更新模型权重，模型只根据 History-3 中的两段历史
转移，改变对当前 query 后续状态的预测。

结果很明确：

1. **在已测配方中，只有原始数据与多速度合成数据按 1:1 混训产生了明显的速度
   ICL。** 同样加入合成数据、但合成速度始终为 5 的模型只有很弱的速度响应。
2. **离线真实下一帧 latent loss 已直接确认速度 ICL。** 在训练中出现过的速度上，
   同速历史相对另外两种历史平均降低 loss：原始模型 `3.10%`、单速混训 `4.13%`、
   多速度混训 **`49.68%`**；在训练没出现过的速度上分别为 `3.10% / 4.16% /
   48.93%`。
3. **训练归因在三个成对种子上全部复现。** 多速度相对单速的额外 loss 降低在训练
   内速度为 `+35.94 / +42.97 / +57.75` 个百分点，在未训练速度为
   `+35.36 / +42.46 / +56.50` 个百分点。
4. **速度历史已经影响 CEM 规划，但 CEM 成功率不能代替预测精度。** 高速历史通常
   提高有限预算下的成功率；这部分收益受规划视野和搜索预算影响，不表示高速历史
   在所有任务上都更准确。
5. **多速度混训没有损伤基础能力。** 三个训练种子在原始 Eval 和速度 5 合成 Eval
   上全部通过能力保持门。

因此，当前最准确的结论是：

> 原始数据与多速度合成数据按 1:1 混训，已经让 History-3 LeWM 根据历史速度大幅
> 提高相应真实下一帧的预测准确性；该能力在训练内和未训练速度上均跨三个训练种子
> 复现，并且没有损伤基础能力。速度 History-3 主阶段可以冻结，进入下一类 ICL。

## 2. 训练数据应该怎样配

### 2.1 已比较的三种配方

| 报告名称 | 原始数据 | 合成数据 | 原始:合成抽样比 | 训练种子 | 目的 |
|---|---|---|---:|---:|---|
| 原始数据模型 | 原始 TwoRoom，速度 5 | 无 | 仅原始 | 3072 | 原始模型参考 |
| 单速合成混训模型 | 原始 TwoRoom，速度 5 | 608 个匹配场景，速度固定为 5 | 1:1 | 3072/4096/5120 | 判断“增加合成数据”本身是否有效 |
| 多速度合成混训模型 | 原始 TwoRoom，速度 5 | 同一批 608 个匹配场景，32 个速度 | 1:1 | 3072/4096/5120 | 判断“合成数据包含多种速度”是否带来速度 ICL |

单速和多速度混训严格保持相同的场景请求、房间布局、reset、goal、采集策略、模型
结构、normalizer、optimizer 和 batch mixture。唯一有意改变的是合成数据中的
`agent.speed`。

每个混训模型实际抽样：

```text
原始数据：6,574,080 次
合成数据：6,574,080 次
总训练步数：12,840 optimizer steps
```

多速度合成训练覆盖 32 个离散速度，范围为 `2.6–7.9`。所有训练和评测都固定：

```text
history = 3
frameskip/action block = 5
```

这里改变的是 `agent.speed`，不是 frameskip。

### 2.2 当前应采用的配方

在已经测试的三种配方中，如果目标是让模型从 History-3 判断速度，应采用：

```text
50% 原始 TwoRoom 速度 5 数据
+ 50% 场景匹配的多速度合成数据
+ 多个离散 agent.speed
+ 固定 frameskip/action block = 5
```

这份配方已经同时通过下一帧 latent、训练归因和基础能力保持检查，可作为后续 ICL
类别的训练配方模板。它证明的是上下文能提高相应速度下一帧的预测准确性，不声明
模型直接恢复了一个精确的数值速度。

## 3. 怎样评测速度 ICL

### 3.1 Eval 速度

模型只看到两段历史转移和一张静态 query 图像，不接收速度标签或状态坐标。评测器
需要指定一个速度，用精确模拟器生成这张 query 在执行 action 后的参考未来；本文称
它为“参考未来速度”。结果文件为了兼容旧代码仍使用字段名 `query_speed`，但这个值
不会输入模型，静态 query 图像本身也不包含速度。

历史本身没有“正确、错误”之分；本文只称为低速、中速和高速历史。只有假设历史与
query 来自同一个短期速度稳定的环境时，才检查“历史速度与参考未来速度相同”是否
产生更准确的预测。

| Eval | 低速/中速/高速 | 与多速度合成训练的关系 |
|---|---|---|
| 训练中出现过的速度 | 3.1 / 5.1 / 7.0 | 三个速度都训练过 |
| 训练中没出现过的速度 | 3.4 / 4.8 / 6.9 | 没训练过，但位于训练速度范围内 |

每类 Eval 都构造完整 `3×3` 矩阵：三个参考未来速度分别搭配低速、中速和高速历史。
每个模型、参考未来速度和历史条件都保留完整样本量：

```text
50 个 query × 6 个评测种子 = 300 次
```

### 3.2 主指标：直接比较上下文所指向的未来 latent

构建 Eval 时，数据生成器从完全相同的 query 初始状态出发，用完全相同的 action，
按历史速度 `v` 执行并冻结真实下一帧。正式评分只用当前 checkpoint 自己的冻结
encoder 编码该图片：

```text
参考 latent(v) = encoder(Eval 中冻结的 target_pixels(v))
匹配 loss(v)   = MSE(模型在速度 v 历史下预测的下一帧 latent, 参考 latent(v))
```

Eval payload 已经离线保存 `query_pixels`、`query_action` 和真实 `target_pixels`。
评分时不启动模拟器，只用当前 checkpoint 的冻结 encoder 编码 `target_pixels`。
目标图片必须跨模型固定，target latent 不能跨模型固定，因为每个 checkpoint 的
encoder 空间不同。

这里的目标是“当前 query 执行 action 后的真实下一帧”，不是已经作为输入给模型的
历史 next frame；拿历史输入本身做目标会造成信息泄漏，也测不到模型对当前 query 的
预测能力。

这个指标不把 latent 解码成速度或坐标。它直接回答：模型看到某种速度历史后，预测
的下一帧表示是否接近这种动力学真正产生的画面表示。因此它是速度 ICL 准确性的
唯一直接指标。

但只报一个匹配 loss 仍然不够。普通画面预测误差可能掩盖上下文作用，所以同一个
checkpoint 内还要比较：生成同一个参考未来时，使用同速历史是否比使用另外两种
速度历史更准确。

```text
同速历史优势(v)
= 另外两种速度历史的平均 latent loss
  − 同速历史的 latent loss

相对 loss 降低
= 同速历史优势 / 另外两种速度历史的平均 latent loss
```

相对 loss 降低大于 0，表示与参考未来同速的历史确实把预测拉向了正确的未来；数值
越大，历史提供的速度信息作用越强。它仍不等于“恢复了多少数值速度”，所以不能单独
判断速度幅度是否一比一准确。

七个 checkpoint 已在冻结数据上完成只读离线评分，共 `37,800` 条结果；环境调用数
为 0。每个速度/历史/评测种子格包含 50 个不同 query，确定性推理没有靠重复同一
query 凑数。此前在线物理 probe 的结果没有转用为本指标分数。

所有比较都在同一个 checkpoint 的 latent 空间内完成；不同 checkpoint 的原始 MSE
不直接比较，只比较各自的相对 loss 降低和训练种子一致性。

### 3.3 当前完整指标清单

| 评测层 | 具体指标 | 回答的问题 | 当前结果 |
|---|---|---|---|

| 统计复现 | 每格 50×6 个不同 query、三个成对训练种子、cluster bootstrap 区间、种子方向 | 结果是否由单个 seed 或重复样本造成 | 已纳入正式汇总 |

## 4. 下一帧 Latent 评测

### 4.1 Eval 已包含什么

| Eval | 速度 | 冻结 bundle | 每个矩阵格评分数 |
|---|---|---:|---:|
| 训练中出现过的速度 | 3.1 / 5.1 / 7.0 | 900 | 50×6=300 个不同 query |
| 训练中没出现过的速度 | 3.4 / 4.8 / 6.9 | 900 | 50×6=300 个不同 query |

每条轨道有 300 个静态 query，并在三个参考未来速度下各生成一个 bundle，共 900 个。
每个 bundle 都保存当前 query、一个 5-step action block、真实下一帧，以及低速、
中速、高速三种 History-3 上下文。三个参考未来速度共享相同的静态 query 图像。
300 个静态 query 被不重叠地分给六个评测种子，每个种子 50 个。因此评分只读取冻结
文件，不在线生成 Eval，也不重复确定性样本。

### 4.2 三种训练配方的直接对比

表中数值是：同速历史的下一帧 latent loss，相对另外两种速度历史的平均 loss 降低
多少。每个参考速度先独立计算百分比，再对三个速度等权平均。数值越高，说明历史中
的速度对当前 query 预测越有帮助。

| Eval | 只用原始数据 | 原始+单速合成混训 | 原始+多速度合成混训 |
|---|---:|---:|---:|
| 训练中出现过的速度 | 3.10% | 4.13% | **49.68%** |
| 训练中没出现过的速度 | 3.10% | 4.16% | **48.93%** |

原始模型和单速混训存在约 `3%–4%` 的弱历史偏好；只有多速度混训把效应提高到约
`48%–49%`。因此不能写成“原始模型完全不会随上下文变化”，准确说法是：多速度
训练带来了数量级更大的、可稳定复现的速度 ICL。

### 4.3 各参考速度的结果

| Eval | 参考速度 | 只用原始数据 | 单速混训 | 多速度混训 |
|---|---:|---:|---:|---:|
| 训练中出现过 | 3.1 | 4.14% | 5.21% | **53.73%** |
| 训练中出现过 | 5.1 | 0.75% | 1.70% | **41.24%** |
| 训练中出现过 | 7.0 | 4.40% | 5.47% | **54.08%** |
| 训练中没出现过 | 3.4 | 3.94% | 5.01% | **52.94%** |
| 训练中没出现过 | 4.8 | 0.94% | 1.93% | **39.64%** |
| 训练中没出现过 | 6.9 | 4.44% | 5.54% | **54.21%** |

中间速度的区分难度更高，但多速度模型仍保留约 `38%–41%` 的相对 loss 降低，远高
于两个对照。

### 4.4 三个训练种子的归因复现

| Eval | 训练种子 | 单速混训 | 多速度混训 | 多速度额外提升 |
|---|---:|---:|---:|---:|
| 训练中出现过 | 3072 | 3.28% | 39.22% | +35.94 pp |
| 训练中出现过 | 4096 | 4.26% | 47.23% | +42.97 pp |
| 训练中出现过 | 5120 | 4.85% | 62.60% | +57.75 pp |
| 训练中没出现过 | 3072 | 3.13% | 38.49% | +35.36 pp |
| 训练中没出现过 | 4096 | 4.35% | 46.80% | +42.46 pp |
| 训练中没出现过 | 5120 | 5.00% | 61.50% | +56.50 pp |

六组成对比较全部为正，说明提升来自合成训练中的速度多样性，而不是增加数据量、
训练步数或某一个幸运初始化。

三个多速度模型在两条轨道、三个参考速度上共有 18 个 cluster-bootstrap 区间，
相对 loss 降低的 95% 区间下界全部大于 0；最小下界为 `22.57%`。这与六个评测
种子的逐种子正方向互相印证。

正式主门以“同速历史优于另外两种历史的平均 loss”为准，三个多速度模型在两条
轨道、三个参考速度和六个评测种子上全部通过。另保留一个更苛刻的诊断：要求同速
历史分别优于两种历史。该诊断在训练内速度为 `2/3` 模型通过，在未训练速度为
`3/3` 通过；唯一例外是训练种子 3072 的速度 5.1，同速 loss 为 `0.008345`，高速
历史为 `0.008258`，差 `0.000087`。同一单元中，同速历史仍比另外两种历史的平均
loss 低 `25.78%`，而且六个评测种子方向全部为正，因此不推翻主结论。

过去通过速度网格反推的速度、位置和多步轨迹数值不再进入正式报告。

### 4.5 已完成的固定候选动作结果

正值表示同速历史平均选择了更接近真实最优的候选。

| Eval | 只用原始数据 | 原始+单速合成混训 | 原始+多速度合成混训 |
|---|---:|---:|---:|
| 训练中出现过的速度 | 0.017 px | −0.080 px | **3.675 px** |
| 训练中没出现过的速度 | 0.013 px | 0.008 px | **3.135 px** |

这说明速度历史已经影响动作排序。但逐速度、逐训练种子的严格候选校准仍未全部
通过，因此只能说“开始影响决策”，不能说“每种速度都稳定选择得更准”。

## 5. CEM 成功率

### 5.1 当前主实验的固定 CEM 配置

```text
model horizon = 10 action blocks = 50 个原始环境步
receding horizon = 5 action blocks
candidates / iterations / top-k = 300 / 30 / 30
真实执行预算 = 50 / 75 / 100 步
```

同一条 100 步轨迹读取 50/75/100 步三个截止点，因此短预算是长轨迹的严格前缀。

### 5.2 训练出现过速度的成功率

下表把三个 query 速度等权平均；单速和多速度混训再对三个训练种子取平均。底层
每个“模型种子 × query 速度 × 历史条件”始终独立运行 `50×6=300` 次，没有把
这 300 次拆给多个速度。

| 训练数据配方 | 执行预算 | 低速历史 | 中速历史 | 高速历史 |
|---|---:|---:|---:|---:|
| 只用原始数据 | 50 | 37.00% | 35.78% | 36.22% |
| 只用原始数据 | 75 | 47.11% | 47.44% | 48.89% |
| 只用原始数据 | 100 | 55.56% | 56.56% | 58.00% |
| 原始+单速合成混训 | 50 | 36.89% | 37.26% | 36.37% |
| 原始+单速合成混训 | 75 | 52.52% | 51.30% | 51.81% |
| 原始+单速合成混训 | 100 | 60.93% | 59.96% | 60.48% |
| 原始+多速度合成混训 | 50 | **41.52%** | **42.41%** | **43.67%** |
| 原始+多速度合成混训 | 75 | **55.00%** | **56.89%** | **60.04%** |
| 原始+多速度合成混训 | 100 | **64.85%** | **67.93%** | **70.26%** |

单速混训模型的三种历史基本持平；多速度混训模型随历史速度增加而提高成功率。

### 5.4 改变 CEM 参数会怎样

以下是较早使用一个原始+多速度合成混训 checkpoint 完成的单训练种子机制实验。
真实执行预算固定为 100 步，每种历史各 `50×6=300`。它用于解释 CEM 机制，不
作为三个训练种子的正式模型结论。

| CEM 配置 | 前视长度 | 候选数 | 迭代数 | 低速历史 | 同速历史 | 高速历史 |
|---|---:|---:|---:|---:|---:|---:|
| 基线 | 25 步 | 300 | 30 | 63.00% | 70.67% | 71.67% |
| 延长前视 | 50 步 | 300 | 30 | 73.33% | 72.33% | 71.67% |
| 增加候选 | 25 步 | 600 | 30 | **80.67%** | **82.67%** | **86.67%** |
| 增加迭代 | 25 步 | 300 | 60 | 64.00% | 68.67% | 73.00% |

这组结果的含义很直接：

- 前视从 25 步延长到 50 步后，高速−低速成功率差从 `+8.67 pp` 变为 `−1.67 pp`，
  说明短规划视野是高速历史占优的主要原因；
- 候选从 300 增加到 600 明显提高三种历史的绝对成功率，但没有专门消除速度方向
  差异；
- 迭代从 30 增加到 60 没有明显帮助。

因此，CEM 表应该同时报告预测误差、多个执行预算和规划资源，不能只看一个最终
成功率。

## 6. 基础能力有没有损失

下面是相对原始数据模型的规划成功率差。每个模型、每个 Eval 都独立使用
`50×6=300`。

| 训练数据配方 | 三个训练种子的原始留出 Eval 差值 | 速度 5 合成 Eval 差值 | 两域能力保持 |
|---|---|---|---|
| 原始+单速合成混训 | −0.67 / −1.33 / −0.67 pp | −3.33 / −4.33 / −4.00 pp | 0/3 通过 |
| 原始+多速度合成混训 | +5.33 / +3.67 / +5.67 pp | +1.33 / +1.33 / +2.33 pp | **3/3 通过** |

单速混训模型在原始留出 Eval 上没有明显退化，但速度 5 合成 Eval 的置信区间未通过
冻结的非劣效门。多速度混训模型在两域全部通过。

## 7. 其他已经完成的对照

### 7.1 只用速度 5 合成数据能否训练基础能力

| 训练方式 | 原始 future-25 Eval | 合成速度 5 future-25 Eval |
|---|---:|---:|
| 只用原始数据 | 91.00% | 93.67% |
| 只用速度 5 合成数据 | 91.67% | 94.00% |

因此，合成数据本身可以重建基础规划能力。速度 ICL 需要的是合成数据中包含多种
速度，而不是仅仅“使用合成数据”。

### 7.2 为什么早期 E4 分数很低

| Eval | 平均起点到目标距离 | 跨房间比例 |
|---|---:|---:|
| 原始 future-25 | 42.87 px | 23.67% |
| 合成速度 5 future-25 | 41.43 px | 26.33% |
| E4 固定远目标 | 121.97 px | 50.00% |

原始和合成 future-25 的模型内成功率最大只差 `3.67 pp`；切换到 E4 后最小下降
仍为 `62.67 pp`。早期分数地板主要来自远目标和有限 planner，不是合成 Eval
整体无效。

## 8. 当前最终判断与下一步

### 8.1 速度阶段怎样收口

已经确认：

- 多速度混训在冻结真实下一帧上产生了大幅、可复现的 History-3 速度 ICL；
- 三个成对训练种子都远高于单速对照，训练归因成立；
- 训练没出现过的区间内速度复现了同样的下一帧准确性提升；
- 速度历史差异也体现在固定候选和多个执行预算下的 CEM 成功率；
- 基础能力没有退化。

保留边界：

- 结论是“上下文提高相应速度下一帧的预测准确性”，不是直接输出精确数值速度；
- 一个训练种子的中间速度在“分别优于两种历史”诊断上近似并列；
- 多步离线 latent 目标和更长 History 尚未构建，它们属于后续增强，不再阻塞当前
  History-3 速度主阶段。

速度的 History-3 主问题已经回答，可以进入下一阶段。多步离线目标和更长 History
保留为速度能力增强项，不再阻塞新类别。

### 8.2 下一阶段做什么

TwoRoom 原生可变项中，门位置会直接画在当前 query 图像上，不能未经检查就称为
ICL。下一阶段按以下顺序推进：

| 顺序 | 工作 | 要回答的问题 | 结论边界 |
|---:|---|---|---|
| 1 | 门位置 query-only 基线 | 不看历史，仅看当前图像是否已足够识别门和规划路径 | 若已足够，门位置属于可见条件泛化，不称为 ICL |
| 2 | 速度×门位置组合 | 已学会的隐藏速度能否与当前图像可见的门位置组合，并推广到训练未见的参数组合 | 这是隐藏动力学与可见几何的组合泛化 |
| 3 | 第二个隐藏动力学因子 | 扩展一个静态单帧不可见、必须从转移历史判断的规则 | 通过同样的下一帧 latent 和规划分层后，才称为新的 ICL 类别 |
| 4 | History 长度 | 在类别和指标稳定后统一比较 History-1/3/5 | 避免同时改变因子与上下文长度 |

因此，**可以马上进入“门位置可见性基线 + 速度×门位置组合”阶段**。不建议直接训练
一个“门位置 ICL 模型”并把提升归因于历史；先通过 query-only 基线决定它在
Benchmark 中是负对照还是需要上下文的因素。新的纯隐藏 ICL 类别则需要给 TwoRoom
增加例如动作响应延迟或动作映射这类当前帧不可见的动力学规则，并单独冻结协议。
