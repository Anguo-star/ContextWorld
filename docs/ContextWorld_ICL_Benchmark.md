# ContextWorld：世界模型的上下文动力学预测基准

ContextWorld 检验世界模型能否在**权重不更新**时，通过上下文学习（in-context learning，ICL）利用近期图像和动作辨认当前隐藏动力学，并预测给定动作的后果。九项任务覆盖速度、动作幅度、机械臂质量、动作延迟、摩擦、阻尼、夹爪携带、门通行和传送门出口。评测输入只有图像与动作；模型输出未来表示（latent），用该模型自己的冻结目标编码器编码真实未来后评分。不同模型的表示空间可以不同。

**任务主指标测预测层面的上下文适应，不是规划成功率。** 首页表格展示逐任务的 Development 分数；冻结的 `contextworld_joint_scratch_v1_reference_results_freeze_v3` 是独立保存的固定参考，不随新实验改写。扩量训练、多步预测和原环境规划保持结果是后续 Development 研究，不能称为 v3 Test 排行榜。

NRE 是归一化响应误差；E/B 是完整预测误差与条件均值参照误差之比；CEM 是交叉熵法（cross-entropy method）规划器。下文分别给出定义，三者不能互换。

| 读数 | 回答的问题 | 本页位置 |
|---|---|---|
| 任务主指标（%） | 原协议查询中，模型是否选对或更准确地预测了对应隐藏条件的未来？ | [训练对照表](#training-comparison)、[评分定义](#4-评分方法) |
| 匹配历史胜率、响应 NRE、多步 E/B | 历史是否有用、条件响应是否准确、完整未来预测误差有多大？ | [诊断定义](#42-条件响应与历史作用)、[结果附录](reference/ContextWorld_Expanded_Training_Results.md) |
| 原环境 CEM 成功率（%） | ICL 训练后，原有环境的规划能力是否保持？ | [单独结果表](reference/ContextWorld_Expanded_Training_Results.md#原环境-cem) |
| 决策 ICL 研究 | 历史能否改善动作选择与真实执行？ | [指标研究](ICL_Metric_Study.md#rollout-error-diagnostic)；尚非九任务正式分数 |

这些读数的单位、参照和查询分布不同，不合成总分；一个任务的高判别分数不等于准确的完整轨迹或可用的规划。任务定义、数据、协议、结果、使用方法和局限依次见下文；逐任务完整数值与训练规模实验见[结果附录](reference/ContextWorld_Expanded_Training_Results.md)，冻结 v3 结果与评分身份见[参考附录](reference/Benchmark_Result_Provenance.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织。
九项任务分别报告任务主指标、条件响应和多步预测诊断；原环境 CEM 单独报告。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不作为评分汇总单位。

表中历史长度是**包含当前帧的观测帧数**。通常相邻观测间隔 5 个物理步；例如长度 3 表示两个过去观测和一个当前观测，以及它们之间已执行的两个动作块。

## 2. 数据与划分

数据由物理模拟器生成。每项任务改变一个隐藏动力学因素，保存连续交互轨迹、查询动作及真实未来。Training 用于训练，Development 用于实现检查与方法选择，Test 用于方法固定后的最终报告。表中的训练方式比较统一使用 Development；其分数不作为 Test 成绩报告。

**六项二值配对任务以训练配对数表示规模：2k=2,048，8k=8,192，32k=32,768；Cube 的 10k=10,000。** 一对包含两种隐藏条件下的轨迹，不等于两个独立来源 episode。速度、动作延迟和门通行规则另列各自的覆盖单位。

| 任务 | 训练方案比较使用的 Training | 覆盖单位与含义 | Development / Test |
|---|---|---|---|
| 推手移动幅度 | **32,768 对** | 状态与动作窗口；可从同一来源 episode 取得多个窗口 | 各 256 对 |
| 接触摩擦 | **32,768 对** | 重置状态与接触几何 | 各 256 对 |
| 运动阻尼 | **32,768 对** | 初始状态；包含成对的前向／镜像样本 | 各 256 对 |
| 机械臂质量 | **32,768 对** | 初始关节状态与探测动作 | 各 256 对 |
| Cube 夹爪携带 | **10,000 对** | 来自 10,000 个不同来源 episode | 各 256 对 |
| 传送门出口 | **32,768 对** | 不同初始距离与动作幅值的场景 | 各 256 对 |
| 速度 | 覆盖 **32 档速度** | 档数表示参数种类，不是样本数 | 每个参考速度 300 个查询 |
| 动作延迟 | 覆盖 **延迟 0–10** | 11 种隐藏延迟，一步评分合并为 6 个物理响应组 | 各 300 个查询 × 11 种延迟 |
| 门通行规则 | 覆盖 **96 个门位** | 每个门位包含可通过／被阻挡两种规则 | Development：16 个门位、共 300 个查询；Test：42 个门位、共 300 个查询 |

配对数、动作窗口数与独立来源 episode 数不能互换。各档规模及覆盖变化见[结果附录](reference/ContextWorld_Expanded_Training_Results.md#训练数据规模对照)；速度、延迟和门通行规则没有扩量对照。扩量只改变 Training，Development 和 Test 保持固定。每条结果的数据包版本、文件清单（manifest）和评测身份记录在[结果 JSON](research/data/icl_training_study_v2.json)；生成与划分检查见[数据生成方法](Data_Generation.md)。

公开 Test 采用离线评测，没有托管提交服务。方法、训练预算和检查点选择应在 Development 上完成；读取 Test 后不得再用它调整方法。稳定公共数据下载版本尚未公布，包格式和本地加载方式见[HF 数据集指南](HF_Dataset_Export.md)。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 连续真实历史图像，包括最后的当前图像；
2. 历史图像之间已经执行的动作序列；
3. 接下来要执行的查询动作序列；
4. 每种候选隐藏规律对应的模拟器真实未来，仅供评分。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像（含当前帧）+ 历史动作 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

原协议用预测与候选真实未来的距离计算任务主指标；补充多步诊断比较完整预测与真实轨迹的误差。两者均使用同一检查点的目标编码器，定义见 §4。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器从 `x0` 连续执行到真实未来，中途不重置或改写状态。独立重放仅用于检查模拟器状态的一致性，不替换保存的数据。

多步评测沿此轨迹继续执行完整候选动作，保留速度、接触状态和待生效的动作队列；每个候选从同一源轨迹独立重放。

### 3.3 配对构造与起点交换

原生判别查询的一对样本分别使用两种隐藏规律。两者在查询时刻共享约定的当前可见状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

动作延迟使用七帧历史（H7），并保留真实延迟队列。当前 Development 面板在查询前已将所有待执行命令清零；队列长度随延迟变化，但不提供给模型。因此，该面板中的条件差异不能归因为尚未执行的非零历史动作。其他连续轨迹仍需分别检查速度、接触与队列状态，不能仅凭画面相同推定完整状态相同。

扩展后的多步候选允许部分动作或时刻产生相同未来，例如零动作或尚未生效的延迟动作；这些情况照常计分，不为增大条件差异而删去。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 按任务检查来源场景、生成模板与查询图像哈希的隔离；
检查范围与 clean export 流程见[数据生成方法](Data_Generation.md#审计冻结与-clean-export)。
这些属于数据构造与导出的校验约束；汇总成绩 JSON 不单独记录各项重叠计数。
生成阶段还约束静态起点不能泄漏隐藏模式：仅凭 `x0` 的静态判别准确率上限为 50%，
由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限为 55%；历史必须产生可测的物理响应。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只用于数据校验与评分，不进入模型输入。

## 4. 评分方法

先看模型是否辨别了正确规律，再看响应及完整预测是否准确。匹配与错配历史的对照用于判断历史的作用；原环境 CEM 单独检查规划能力保持。**不同读数不能互相替代，也不加权合成总分。**

### 4.1 任务主指标：按原协议判断正确率

总表保留原协议的任务主指标，单位为百分数。不同任务的判断问题如下：

| 任务 | 一次判断何时正确 | 随机选择参照 |
|---|---|---:|
| 推手移动幅度、质量、摩擦、阻尼、携带、传送门 | 匹配历史下的预测，更接近本条件的真实未来，而非另一条件的真实未来 | 50% |
| 门通行规则 | 在相同历史下，选对可通过／被阻挡对应的真实未来 | 50% |
| 动作延迟 | 选对一步未来的物理响应组；对六组宏平均 | 16.67% |
| 速度 | 匹配历史的预测误差，严格小于该组每一种竞争历史的误差 | 插值／已见为 33.33%；外推为 25% |

Delay 的六组为 0、1、2、3、4、5–10；最后一组在一步预测时域内具有相同静止响应。Speed 的四种分布分别报告，总表采用未见速度插值。

严格比较将平局记为失败。因此随机选择参照**不是无历史模型的预期成绩**，各列也不是同一种准确率的不同样本集合。高主指标说明模型完成了该判别问题，不能据此认定响应幅值、完整轨迹或规划已准确。

<a id="44-历史指标与机制诊断"></a>

### 4.2 条件响应与历史作用

结果附录的任务表保留两个诊断：

- **匹配历史胜率（History，%）**：对同一真实目标，匹配历史的预测误差是否小于错配历史的误差。它计胜负，不计改善幅度；Speed 中与主指标相同。
- **响应 NRE**：预测的条件差异与真实条件差异之间的归一化平方误差。0 为准确恢复响应；1 为零条件响应的误差水平；超过 1 表示比零响应误差更大。

二值配对中，令真实条件差为 $\Delta z=z_B-z_A$，预测条件差为 $\Delta\hat z=\hat z_B-\hat z_A$：

$$
\mathrm{NRE}=\frac{\sum\|\Delta\hat z-\Delta z\|^2}{\sum\|\Delta z\|^2},
\qquad
\mathrm{Gain}=\frac{\sum\langle\Delta\hat z,\Delta z\rangle}{\sum\|\Delta z\|^2}.
$$

先累计响应能量再相除，不平均每对的比值；多条件任务按其原协议分组。响应 Gain 的理想值为 1，近零表示幅值偏弱。NRE 已是平方误差比，无须再次平方。原结果中的响应分 `100×(1−NRE)` 只是等价显示，完整指标表和扩量表保留该显示形式。

条件差分会消去各条件共有的预测偏差。例如，预测同时向无关方向偏移，仍可能获得 NRE=0。因此还需查看完整预测误差。

| 指标 | 含义 |
|---|---|
| 最弱条件 | 隐藏条件、响应组或参考速度中最低的主指标 |
| Switch | 任务特定的历史切换读数；例如 Strength 检查预测条件差与真实条件差的内积是否为正，不验证正确幅值 |
| Joint | 六项二值配对任务中，两侧都选对未来、都用对历史且该对 NRE<1 的比例；Speed、Delay、Door 不定义此项 |
| Alignment | 预测与真实条件响应的余弦相似度，理想值 1 |
| 优于零响应比例 | NRE<1 的样本对比例，不表示幅值已充分校准 |

这些指标用于细看失败类型，完整能力门槛见[参考附录](reference/Benchmark_Result_Provenance.md)。门槛不决定是否存在进步，也不将未达标成绩置零。

</details>

<a id="41-多步完整预测分"></a>

### 4.3 多步完整误差比 E/B

补充诊断固定历史和后续动作，比较预测与模拟器真实后果，**不以移动距离、到达目标速度或规划成功替代预测准确度**。模型从初始真实历史自由推演，不补入未来真实观测；第 5、10、15、20、25 个物理步等权评分。

对场景 $q$、隐藏条件 $k$、共用动作候选 $c$、时刻 $t$，真实和预测表示为 $z_{qkct}$、$\hat z_{qkct}$。条件均值 $\bar z_{qct}$ 只由评分器计算，不提供给模型。先在场景内等权平均条件、候选和时刻：

$$
L_q=\frac{1}{K_qC_qT}\sum_{k,c,t}\|\hat z_{qkct}-z_{qkct}\|^2,
\qquad
B_q=\frac{1}{K_qC_qT}\sum_{k,c,t}\|z_{qkct}-\bar z_{qct}\|^2.
$$

表中报告 **$E/B=\sum_q L_q/\sum_q B_q$，越低越好**：

| 误差比 | 含义 |
|---:|---|
| 0 | 在该评分表示中，完整预测准确 |
| 1 | 误差与所有条件共用平均真实未来的理想参照相同 |
| 大于 1 | 完整误差大于条件均值参照 |

参照使用真实未来，是一种理想误差基准，不是实际部署的无历史预测器。在所有条件完整等权、共享当前观测与动作时，不区分历史、始终输出同一未来的确定性模型不能取得低于 1 的误差。

**为什么不再显示负几千、负几万的分数？** 归档结果使用 `S_pred=100×(1−E/B)`。例如 −10,000 分对应 E/B=101，并非“负准确率”。当条件未来差异很小、而共同预测偏差较大时，误差比会很大。本文改用 E/B 直接展示，不截断数值、不改计算或结果；归档 JSON / CSV 的 `score` 字段仍保留原换算分。

完整误差包含**条件响应误差与共同预测偏差**。二值等权且动作、时刻和权重一致时，响应部分等于 NRE；不同面板或分组下不能直接代入不同协议的 NRE。表示归一化消除了整体缩放，却不能消除编码器的几何差异：E/B 和 NRE 描述各自表示中的误差，**不能据此给不同模型排统一物理精度名次**。

### 4.4 汇总、不确定性与覆盖

各检查点先累计误差与参照能量再相除，相同配置的全部可用训练重复等权汇总。任务主指标、History、NRE 和 CEM 的 `±` 为训练重复的样本标准差；多步 E/B 的 `[95% 区间]` 是来源组 bootstrap 区间，表示给定这些检查点时的场景抽样不确定性。训练重复数另列，不把 CEM 评测种子当作独立训练。

Bootstrap 将同一 episode 的窗口、同源前向／镜像样本一起抽取，每组保留全部条件、候选和时刻，并在各训练重复间使用相同抽样。没有有限分母时报告无定义，不填满分、不静默删除；小分母需结合表示解释。

补充多步公式版本为 `multistep_complete_prediction_v1`，覆盖版本为 `multistep_development_coverage_v2`。Speed 插值、Delay、Door 各有 300 个 Development 源场景，其余六项各 256 个，共 2,436 个。保留全部注册条件、候选和五个时刻，不按模型成绩筛选；不覆盖 Speed 其他分布或 Test。数据、来源分组与动作构造见[数据生成方法](Data_Generation.md#九任务的动作选择与多步预测诊断)。

<a id="45-主分解释历史对照与辅助物理读出"></a>

### 4.5 历史对照与规划

在固定场景、动作和评分表示下，完整误差的**匹配历史误差下降**定义为 $G_H=(E_--E_+)/B$，其中 $E_-$ 是错配历史的平均误差，$E_+$ 是匹配历史的误差。正值表示匹配历史有帮助，但不表示最终预测已准确。二值等权配对下，它等于 4×响应 Gain，不应计为独立证据。任务表中的 History 是胜率，与这个下降量不是同一指标；详细对照见[指标研究](ICL_Metric_Study.md#root-cause-entry)。

**原环境 CEM** 检查能力保持，当前训练后评测通常使用 42–47 六个种子，每个 50 次，共 300 次；原始模型保留其历史预算，见结果文件。T0 按四个原环境训练，相关任务复用该环境参考；T1–T3 的任务模型分别评测。复用值不代表额外独立证据。

隐藏动力学规划需要另外固定当前状态、目标、候选与预算，并验证不同规律确实影响动作选择。已有候选与闭环诊断见[预测与规划研究](ICL_Metric_Study.md#rollout-error-diagnostic)，尚不构成九任务统一规划成绩。

### 4.6 协议有效性与版本

输入合法、划分隔离、权重不变等协议条件决定评测有效性；能力不足不使成绩无效，也不阻止报告 Test 低分。方法与检查点在 Development 上确定后，Test 应报告预先确定的同一任务集合。

冻结 v3 保留原身份与数值。当前扩量成绩及补充多步诊断单独记录，不重新标为 v3。改变任务、数据分布或评分规则时采用新版本；显示 E/B 只是归档分数的等价换算。

## 5. 模型与训练方案比较

### 5.1 训练方案与实验设置

<a id="training-schemes"></a>

结果表统一使用 **T0–T3** 四个训练方案代号。先区分两类数据：**原环境数据**是默认环境中的交互轨迹；**ICL 数据**是 ContextWorld 按任务合成、包含隐藏动力学变化的 Training 轨迹。它们都用于预测训练；ICL 评测时不更新参数。

| 代号 | 训练方案 | 初始化 | 训练数据与采样比例 | 训练轮数 | 更新哪些模块 |
|---|---|---|---|---|---|
| **T0** | 仅原环境数据训练 | 模型默认初始化 | 原环境 100% | 10 epochs | 各模型原生可训练模块 |
| **T1** | 直接混合数据训练 | 模型默认初始化，不加载 T0 权重 | 原环境 50% + 对应任务 ICL 50% | 10 epochs | 各模型原生可训练模块 |
| **T2** | 原环境预训练后，混合数据联合训练 | 加载对应环境的完整 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | Encoder、预测器及其余原生可训练模块 |
| **T3** | 原环境预训练后，冻结 Encoder 混合训练 | 加载与 T2 相同的 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | 固定 Encoder 参数与训练态缓冲区；训练预测器、projector、动作编码器等其余模块 |

下载结果的 `regime` 字段中，`original`、`scratch`、`joint`、`frozen` 分别对应 T0、T1、T2、T3。

T2 / T3 加载模型权重后重新建立优化器，不接续 T0 的优化器状态。T0 按原环境训练一份模型；T1–T3 分别针对每项任务训练。因此，结果表的一行汇集同一模型家族与方案的九项实验，不表示同一份权重同时获得九项能力。

**模型与优化配置。**

| 模型 | T0 / T1 的默认初始化 | 原生可训练模块 | 优化器 | 学习率 | Weight decay |
|---|---|---|---|---:|---:|
| LeWM | Encoder 与预测器随机初始化 | Encoder、预测器及其余原生训练模块 | AdamW | 5×10⁻⁵ | 0.001 |
| PLDM | Encoder 与预测器随机初始化 | Encoder、预测器及其余原生训练模块 | AdamW | 5×10⁻⁵ | 0.001 |
| DINO-WM | 加载预训练 DINOv2-small Encoder 并冻结，预测器随机初始化 | 预测器、动作编码器等；Encoder 始终固定 | AdamW | 5×10⁻⁴ | 0 |

DINO-WM 的 T1 也使用预训练视觉 Encoder，不能解释为整个模型都从随机权重开始。它的 T3 加载在原环境训练过的预测器等模块，视觉 Encoder 仍保持冻结；本报告没有更新其 Encoder 的 T2 方案。历史上转换额外状态输入得到的初始化另列于附录，不作为 T3。

本报告的对比配方各阶段使用 **8 张 GPU、每卡 batch size 128、梯度累积 1（全局 batch size 1024）**。输入为图像与动作；通常使用 3 帧历史、帧间隔 5、预测下一帧，动作延迟的 ICL 训练使用 7 帧历史。训练目标沿用各模型的原生目标，未添加 COJA 辅助损失。T3 改变 Encoder 的更新方式，其余原生损失保留。入口与参数映射见[训练配置](../configs/training/stablewm_family_profiles_v1.yaml)及[模型训练指南](StableWM_Training.md)。

**数据来源与混合方式。**

| 原环境 | 原环境训练数据（相对于数据根目录） | 对应 ICL 任务 |
|---|---|---|
| TwoRoom | `quentinll/tworoom.h5` | 速度、动作延迟、门通行规则、传送门出口 |
| PushT | `quentinll/pusht_expert_train.h5` | 推手移动幅度、接触摩擦、运动阻尼 |
| Reacher | `quentinll/reacher.h5` | 机械臂质量 |
| Cube | `quentinll/ogbench/cube_single_expert.h5` | Cube 夹爪携带 |

ICL 成分只读取对应任务数据包的 **Training** 划分，不使用 Development / Test 训练。主表的任务数据版本与样本规模见 §2，较小规模在[结果附录](reference/ContextWorld_Expanded_Training_Results.md#训练数据规模对照)单列；同一任务的 T1、T2、T3 使用相同版本。每条结果的数据身份与初始化权重身份见[结果 JSON](research/data/icl_training_study_v2.json)。

**50/50 指训练轨迹窗口的采样比例，不是来源 episode 数或数据文件大小各占一半。** 默认混合数据集按两个成分的可用窗口数构建 epoch：设其长度分别为 N原、NICL，则名义 epoch 长度为 `2 × max(N原, NICL)`，在划分与分批前的 epoch 排程中，两成分窗口数相等；较小成分会重复采样。因此，加入 ICL 不会简单地把原环境曝光减半，扩量也可能增加每轮更新次数。实际训练还受训练/验证划分、分布式采样与末尾不完整 batch 的处理影响；具体实现见[混合数据加载器](../contextworld/training/stablewm_bundle.py)。

**比较预算时需区分轮数与曝光量。** T2 / T3 比 T1 多出原环境预训练经历；各数据版本的 epoch 长度也可能不同。相同的 10 epochs 不能直接视为相同计算量、相同独立样本数或相同数据曝光次数。

**重复实验的汇总方式：** 相同任务、数据版本、训练方案和输入协议的全部可用训练重复参与均值；已有三个训练种子的配置使用三者，不选取其中一个。多步诊断表显示完整误差比均值，任务详情报告场景 bootstrap 区间和训练重复数；训练标准差保存在结果 JSON。原协议指标沿用“均值 ± 样本标准差”和各指标的有效重复数。只有一次训练时，标准差不写作零。具体种子、初始化检查点及逐次结果见对应结果文件。

每个检查点的 CEM 先按评测次数汇总，再跨训练重复等权平均。六个 CEM 评测种子是同一检查点的评测重复，不能当成六次独立训练。不同规模、训练方式和初始化协议始终分别汇总。

LeWM / PLDM 在八项任务上的 T2 / T3 使用相同任务数据、混合比例、历史长度、帧间隔及原始初始化权重。跨模型保留各自骨干、训练目标和优化器；这些结果可以比较能力获得程度，但不能单独分离某个架构部件的贡献。

### 5.3 主要发现与解释边界

| 关键观察 | 代表性对照（Development） | 支持的判断 |
|---|---|---|
| 同一任务，不同模型获得的能力不同 | Delay T1：LeWM 97.64%，PLDM 99.98%，DINO-WM 16.63%；Door T1 三者均为 100% | 差异具有任务特异性，不能概括为某个模型全面更强 |

| 多步失准不只有一种形式 | Strength T3 的真实观测替换明显降低末步误差；DINO-WM Delay T1 的首步误差已经较大 | 递推后失准与首步残差应分别研究，不能给所有失败同一个解释 |

**九任务没有统一最优的训练方案。** 质量任务中 LeWM / PLDM 的 T1 已达到 87.11% / 91.21%，无需先加载原环境权重。Strength、Friction 则更受训练方案影响，具体幅值和历史对照见任务表。部分 ICL 改善伴随原环境 CEM 下降，两类结果必须同时报告。

**多步诊断补充了判别表看不到的信息。** Speed 插值中，LeWM 的 T0 / T1 / T3 完整误差比分别为 1.498 / 0.363 / 0.144，PLDM 为 3.377 / 0.520 / 0.302。对 DINO-WM，同一冻结视觉表示下，Strength 的 T0→T1 为 3.300→1.996，Door 为 4.233→1.329：自身表示中的误差减小，但仍高于条件均值参照。LeWM / PLDM 的跨方案比较还包含表示变化，不能直接换算为物理误差改善。

这些是固定检查点上的能力差异与误差现象。[同初始化的 LeWM 四任务对照](ICL_Metric_Study.md#matched-encoder-contrast)显示：在这组 Development 对照中，T3 相比 T2 的 Friction、Cube、Strength 原生 latent 响应 NRE 降低，Mass 则升高；Friction 的多步完整误差并未随原协议主分一起改善。该对照固定了训练数据，但目标 projector 仍可训练，表示几何与预测器优化轨迹同时变化，不能归因于单一模块；详见[跨表示空间的核对](ICL_Metric_Study.md#conditional-map-boundary)。

## 6. 任务说明

九项任务分别训练、分别评分。下文给出每项任务的物理问题、正式主指标与适用范围；各模型的完整数值、标准差、区间和其他速度分布见[九任务结果明细](reference/ContextWorld_Expanded_Training_Results.md#九任务明细)。

### 6.1 即时连续响应

<a id="task-speed"></a>

#### 6.1.1 速度

用三帧历史辨认 TwoRoom 速度；正式分数要求匹配历史的预测误差严格小于该组每一种竞争历史。分别测已见速度、未见插值和两侧外推；首页仅列未见插值。严格平局记失败，插值随机选择参照为 33.33%。[速度完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-speed)。

<a id="task-action-strength"></a>

#### 6.1.2 推手移动幅度

在共享当前画面和动作时，根据历史区分 PushT 推手的 60／140 两档动作响应，选择正确的真实下一状态。随机选择参照为 50%；它不检验连续幅值外推。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-action-strength)。

<a id="task-robot-arm-mass"></a>

#### 6.1.3 机械臂质量

根据相同力矩下的历史运动辨认 Reacher 的两档质量，选择正确下一状态；不检验连续质量估计或闭环控制。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-robot-arm-mass)。

### 6.2 时间延迟动力学

<a id="task-action-delay"></a>

#### 6.2.1 动作延迟

用七帧历史识别延迟 0–10 对一步未来的影响。正式分数对六个**物理响应组** 0、1、2、3、4、5–10 作宏平均；最后一组在该时域内响应相同，故不要求区分组内精确延迟。随机参照 16.67%。三帧 T0† 仅是投影参考。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-action-delay)。

### 6.3 接触或附着条件动力学

<a id="task-contact-friction"></a>

#### 6.3.1 接触摩擦

历史中的接触响应区分两档摩擦系数 0.05／0.80，预测相同当前状态和查询动作下的下一状态；不检验任意摩擦系数插值或长期接触规划。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-contact-friction)。

<a id="task-motion-damping"></a>

#### 6.3.2 运动阻尼

接触结束后的历史运动区分物体减速快慢（阻尼 0.2／1.0）。配对数据交换起点，避免只看起点就猜中条件；正式分数仍是下一状态选择率。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-motion-damping)。

<a id="task-cube-gripper-carry"></a>

#### 6.3.3 Cube 夹爪携带规则

根据历史判断闭合夹爪能否携带方块，并选择对应真实下一状态。Training 的 10,000 对来自不同来源 episode；分数不代表多步夹持规划。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-cube-gripper-carry)。

### 6.4 隐藏结构转移规则

<a id="task-door"></a>

#### 6.4.1 门通行规则

外观相同的门可能可通过或被阻挡；模型必须根据历史选择对应未来。Development 有 16 个门位，Public Test 有训练中未见的 42 个门位；主指标不测多步穿门控制。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-door)。

<a id="task-portal-exit"></a>

#### 6.4.2 传送门出口位置

同一入口可通往两种出口；两种条件在查询前汇合到相同当前状态，只有历史揭示规则。主指标是正确出口下一状态的选择率，不检验连续出口坐标。[完整结果](reference/ContextWorld_Expanded_Training_Results.md#task-portal-exit)。

## 7. 接入与复现

参评模型实现 `LatentWorldModelAdapter`：接收历史图像、历史动作和查询动作，返回未来 latent；真实未来由该模型的冻结目标编码器编码。接口、历史对齐和最小示例见[Adapter 规范](External_Model_Adapter_Contract.md)，本地数据根目录与 HF 包格式见[数据集指南](HF_Dataset_Export.md)。先在 Development 验证接口和选择方法，再在锁定方法后报告 Test。

```bash
python -m contextworld.benchmarks.external_model_cli \
  --benchmark-root /path/to/ContextWorld-bundle \
  --evaluation-split development \
  --task action_strength \
  --adapter lewm \
  --checkpoint /path/to/weights.pt \
  --model-name my-model \
  --output /path/to/development-result.json
```

这是 Development 原协议入口，不会运行补充多步诊断或 CEM。[高级评测说明](Data_Generation.md#冻结权重评测与误差定位)提供逐检查点多步推演和误差定位命令；外部 Adapter 的多步反馈还需验证动作对齐。

## 8. 可复现性与结果报告

报告至少注明数据版本与划分、训练数据和比例、初始化、更新模块、训练预算、检查点及评测版本。表格与 CSV 从同一份 JSON 生成，检查点和数据哈希用于追溯来源；九任务结果按 §5.1 汇总全部可比训练重复。当前补充多步表含 136 个检查点×任务单元，汇总为 86 个模型／训练方案／任务组合；冻结权重与数据身份检查全部通过。缺少同协议检查点的组合保留为空，不补零。

正式成绩的有效性取决于输入合法、数据隔离及评测时权重不变。方法在 Development 上确定后，Test 应报告预先确定的同一任务集合，包含低分结果；Development 能力门是否通过不作为 Test 报告前提。冻结 v3 的结果保持原样，见[参考附录](reference/Benchmark_Result_Provenance.md)。

完整权重、数据包和逐查询输出尚无稳定公共下载，因此公开汇总还不能支持外部完整复现。包格式、数据身份与发布准备见[HF 数据集指南](HF_Dataset_Export.md)和[发布说明](Expanded_Training_Release.md)。

## 9. 适用范围与限制

- **数据范围：** 多步表覆盖九任务主分布的 2,436 个 Development 源场景，Speed 只含未见速度插值。任务主指标使用原查询动作；两者的动作分布与预测时域不同，不可直接相减，也都不是 Test 成绩。
- **模型范围：** 每项 ICL 任务分别训练；总表的一行不是一个统一九任务模型。不同模型保留各自的架构、目标和优化器，跨模型差异不能唯一归因到架构。
- **测量范围：** 完整误差包含共同预测偏差，但仍在各检查点自身表示中归一化。历史对照检验上下文收益，物理读出检验选定坐标，并单独检查其可见性；两者不能消除编码器几何差异及读出器对分布外预测的误差。历史收益为正也不表示完整预测已准确，详见 §4.3–4.5。
- **决策范围：** 此前独立的决策与观测替换诊断覆盖 134 个场景与 70 个检查点×任务单元，使用固定候选和物理代价；部分目标、候选和时域尚不具备足够的决策区分度。Speed 闭环实验仅覆盖六个场景，其他任务和完整场景集的闭环收益尚未确定。原环境 CEM 仅衡量能力保持。
- **归因范围：** 冻结 Encoder 固定该模块的参数与训练态缓冲区，但未必固定所有可训练的表示变换；扩量可能改变覆盖和优化步数。要分离这些作用，需进一步控制实验。

## 10. 比较与版本管理

新结果应引用明确的数据版本、训练方案和评测划分。相同任务定义与评分协议下可以比较新模型或训练方法；改变查询分布、任务定义或评分规则时，应记录新的 benchmark 版本。冻结 v3 的数值保存在[冻结参考附录](reference/Benchmark_Result_Provenance.md)，不以新实验覆盖历史结果。
