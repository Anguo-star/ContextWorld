# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 通过控制隐藏动力学和可见历史，衡量世界模型是否学会利用交互经验预测未来。本文介绍任务、数据、评分方法，以及三个模型在不同训练方式下的完整结果和主要发现。

快速阅读：[任务与数据](#1-benchmark-概览) · [指标解释](#4-评测指标) · [完整统计表](#training-comparison) · [主要发现](#53-主要发现与解释边界) · [复现与报告](#8-可复现性与结果报告)。

ContextWorld 评测 latent 世界模型能否从最近几步交互中识别隐藏的环境动力学，并据此
预测下一状态。模型只通过上下文适应：评分过程不更新任何模型参数，也不向模型提供速度、
动作延迟、物体质量、接触属性或空间转移规则等模拟器隐藏变量。

评测直接在参评模型自己的 latent 空间中进行，不要求图像解码器或像素重建。因此，
JEPA、LeWM、PLDM、PreJEPA 以及其他 latent 世界模型可以使用同一套数据与评分协议。

数据如何生成——连续仿真、配对构造、划分隔离以及九项任务的生成入口——见
[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
而不是按环境数量组织；九项任务分别计分，不计算跨任务平均分或统一总分。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不构成分数权重。

## 2. 数据与划分

数据由物理模拟器生成。每项任务改变一个隐藏动力学因素，保存连续交互轨迹、查询动作及真实未来。Training 用于训练，Development 用于实现检查与方法选择，Test 用于方法固定后的最终报告。表中的训练方式比较统一使用 Development；其分数不作为 Test 成绩报告。

**规模统一以训练配对数表示：2k=2,048，8k=8,192，32k=32,768。** 一对包含两种隐藏条件下的轨迹，不等于两个独立来源 episode。

| 任务 | 实际训练档位 | 如何比较 | Development / Test |
|---|---|---|---|
| 推手移动幅度 | **2k → 8k → 32k** | LeWM 二阶段联合有三档；三个模型的从头训练对比 2k / 32k | 各 256 对 |
| 接触摩擦 | **8k → 32k** | 增加重置状态与接触几何，起点不是 2k | 各 256 对 |
| 运动阻尼 | **8k → 32k** | 增加初始状态，包含成对镜像样本，起点不是 2k | 各 256 对 |
| 机械臂质量 | **2k → 32k** | 增加初始关节状态与探测动作 | 各 256 对 |
| Cube 夹爪携带 | **2k → 10k 独立来源** | 旧 32k 仍复用 2,048 个来源，属于变体扩增，不计为独立规模档 | 各 256 对 |
| 传送门出口 | **2k → 32k 覆盖扩展** | 同时改变初始距离与动作幅值；旧、新 32k 的区别是覆盖，不是数量 | 各 256 对 |
| 速度 | 没有扩量对照；32 档速度 | 32 档是参数种类，不是 32k 样本 | 每个参考速度 300 个查询 |
| 动作延迟 | 没有扩量对照；延迟 0–10 | 沿用基础版训练载荷 | 各 300 个查询 × 11 种延迟 |
| 门通行规则 | 没有扩量对照；96 个训练门位 | 沿用基础版训练载荷 | 16 / 42 个门位置，各 300 个场景 |

不同任务的独立覆盖单位不同。Strength 的 32k 包新增 30,720 个状态与动作窗口，来自 12,069 个来源 episode；Friction、Damping 各新增 24,576 个初始状态，其中 Damping 包含 12,288 组前向／镜像样本；Mass 新增 30,720 个初始关节状态与探测动作。Cube 的 10k 来自 10,000 个不同来源 episode。这些数量不能统称为“32k 独立 episode”。

这些数据版本只改变 Training；Development 和 Test 沿用各自固定载荷。其余三任务使用基础版训练数据。每条结果的具体数据包版本、manifest 和评测身份记录在[结果 JSON](research/data/icl_training_study_v2.json)。数据生成与划分检查见[数据生成方法](Data_Generation.md)。

公开 Test 采用离线评测，没有托管提交服务。方法、训练预算和检查点选择应在 Development 上完成；读取 Test 后不得再用它调整方法。稳定公共数据下载版本尚未公布，包格式和本地加载方式见[HF 数据集指南](HF_Dataset_Export.md)。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 最近若干帧真实图像；
2. 已经执行的动作序列；
3. 当前图像；
4. 接下来要执行的查询动作；
5. 每种候选隐藏规律对应的模拟器真实未来。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器连续向前执行。`x0` 之后不写入状态、不重建模拟器，也没有仲裁
过程改写中间状态；历史与未来之间没有任何 reset。干净模拟器重放只用于审计，确认不可见
的求解器缓存不改变 `x3`，从不用于生成保存进数据集的画面或目标。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只保留在审计通道，不进入模型输入。

## 4. 评测指标

### 4.1 主分与历史利用

六个二值配对任务的主分是选择正确真实未来的比例，随机基线为 50%。Door 使用同历史下的两种目标选择正确率；Delay 使用六个物理响应组宏平均，随机基线为 16.67%；Speed 要求匹配历史的预测优于每一个竞争历史条件，随机基线为 33.33%。Speed 分别报告已见速度、未见插值、低端外推和高端外推。

由于任务主分的定义与随机基线不同，不计算跨任务平均总分。能力比较保留以下互补维度，也不以通过门槛与否替代实际分数：

| 指标 | 含义与解读 |
|---|---|
| 主分↑ | 按对应任务定义，选择正确未来或匹配历史的比例 |
| 最弱条件↑ | 隐藏条件、响应组或参考速度中表现最弱的一项 |
| History↑ | 匹配历史是否比错误历史产生更准确的目标预测 |
| Switch↑ | 交换历史后预测选择是否按任务定义切换；不能单独证明方向和幅值正确 |
| Joint↑ | 六个配对任务中，两种条件都选对未来、都正确利用历史，且该样本对 NRE<1 的比例；其他三任务不定义此项 |
| Gain≈1 | 预测条件响应在真实条件响应方向上的相对幅值；理想值 1，接近 0 表示响应过弱 |
| Alignment↑ | 预测与真实条件响应的余弦相似度；理想值 1 |
| NRE↓ | 条件响应误差的平方范数除以真实响应的平方范数；理想值 0，完全不随历史变化的预测为 1 |
| CalResp↑ | NRE<1 的样本对比例；表示优于零响应，不等于幅值已充分校准 |
| CEM↑ | 对应原环境的规划成功率，独立于 ICL 评分 |

### 4.2 响应指标与评分有效性

设切换隐藏条件后的真实目标 latent 差为 Δz，匹配历史下的预测差为 Δẑ，则每对样本的 Gain 为 `〈Δẑ, Δz〉 / ‖Δz‖²`，NRE 为 `‖Δẑ − Δz‖² / ‖Δz‖²`，Alignment 为两者的余弦相似度。报告按任务协议汇总这些量，并检查真实未来在模型表示中是否可分。

距离只在同一检查点的 latent 空间中计算。不同检查点的原始 latent MSE 不具有共同单位；归一化响应指标描述各自表示中的相对响应质量，不能当成同一物理单位的绝对预测误差。高主分也不能自动证明正确响应幅值或范围外泛化。

评分协议还规定最弱条件、历史利用和适用的 bootstrap 条件。完整能力判定按检查点分别计算，要求响应门的任务还检查 Gain≥0.50、NRE<1。具体阈值和固定参考来源见[评分与复现附录](reference/Benchmark_Result_Provenance.md)。通过种子数表示稳定满足全部条件的次数，不会把未通过检查点的实际分数改成零。

### 4.3 原环境规划

CEM 在 TwoRoom、PushT、Reacher 和 Cube 原环境上评测，衡量引入 ICL 训练后的原有规划能力。CEM 预算为六个评测种子（42–47），每个种子 50 次，共 300 次；历史原始模型的预算差异在总表前注明。

原环境 CEM 不能替代隐藏规律下的规划评测。要验证 ICL 对决策的帮助，需要在相同候选动作和真实后果上比较正确历史、无历史与错误历史下的排序、选择 regret 或闭环成功率。

### 4.4 比较原则

同任务的模型使用相同查询。正式优劣或非劣性声明应使用逐查询配对分析并报告置信区间；描述性分数变化本身不提供显著性结论。训练样本量、独立覆盖、初始化和表示更新方式应分别控制，才能讨论原因。

## 5. 模型与训练方案比较

### 5.1 实验设置

本文比较九项任务、LeWM、PLDM 和 DINO-WM，以及以下训练方案：

- **原始模型**：只用对应原环境数据训练，直接评测其权重。
- **ICL 从头**：原环境数据与对应任务的 ICL 数据按 50/50 混合，使用模型家族的默认初始化训练。
- **二阶段联合**：加载完整原始模型权重，重新建立优化器，在相同混合数据上联合训练 Encoder、预测器及其他原生训练模块。
- **二阶段冻结**：使用相同原始初始化和混合数据，固定 Encoder 参数和训练态缓冲区，继续训练预测器、projector、动作编码器等其余模块。

DINO-WM 的视觉 Encoder 始终使用冻结的预训练权重，“从头”与“二阶段”描述预测器的初始化。它没有更新视觉 Encoder 的二阶段联合方案，因此不列该组合。标有 ‡ 的转换初始化来自包含额外状态输入的旧 DINO-WM 原始模型：转换保留视觉和动作相关参数，其结果作为独立训练方案列出，不能替代新 `pixels+action` 原始权重的完整初始化。

训练 seed 在每行标注。ICL 训练为 10 epochs、8 张 GPU、每卡 batch 128、梯度累积 1；原始模型和二阶段初始化使用对应原环境权重。DINO-WM 新二阶段结果使用 seed 3073，从头训练使用 seed 3072，二者不是同训练种子的对照。每项任务分别训练一个检查点；不同任务行不代表同一权重同时获得九项能力。二阶段训练包含额外的原环境预训练预算，因此它与从头训练的差异同时涉及初始化和总训练经历。

LeWM / PLDM 的八任务联合与冻结方案使用相同任务数据、混合比例、历史长度、帧间隔及原始初始化权重。跨模型保留各自骨干、训练目标和优化器；这些结果可以比较能力获得程度，但不能单独分离某个架构部件的贡献。配对数和 epoch 数也不等于独立样本数或各数据成分的曝光量。

### 5.3 主要发现与解释边界

**数据扩量：存在任务与训练方式相关的收益，尚无统一 scaling 规律。**

- **Strength 是最清楚的三档正例。** 固定 LeWM 二阶段联合配方与初始化，2k→8k→32k 的 ICL 主分为 **55.66%→82.42%→90.82%**，Gain 为 **0.144→0.576→0.757**，NRE 为 **0.810→0.390→0.222**；ICL 单调改善，后一个四倍扩量的增益更小。CEM 为 **86.00%→85.33%→86.00%**，没有同样的提升趋势。LeWM 从头训练的 2k→32k 仅为 **50.00%→50.78%**，说明规模收益依赖训练方式。
- **Mass 与 DINO-WM Friction 有明显的两档收益。** Mass 2k→32k 时，LeWM 为 **84.77%→87.11%**，PLDM 为 **52.54%→91.21%**，DINO-WM 为 **50.59%→80.47%**；Friction 8k→32k 时，DINO-WM 为 **49.61%→81.84%**，LeWM / PLDM 仍约 50%。同样扩量，不同模型收益不同。
- **其他任务不支持“扩量即可解决”。** Damping 三模型扩量后约 **50% / 58% / 57%**；Cube 增至 10k 独立来源后 LeWM / PLDM 仍为 50%，DINO-WM 为 61.33%；Portal 还改变了物理覆盖，不能当成纯数量曲线。

以上规模对比均使用相同任务的 Development，三个模型的两档从头训练对比均取 seed 3072、epoch 10。相同 epoch 不自动等于相同更新次数；扩量也会改变样本重复曝光与覆盖。当前支持的是具体配方下的扩量收益，尚不足以拟合普适 scaling law，也没有模型规模曲线。

**训练方式可以决定已有数据是否转化为条件响应。** 固定数据与原始初始化，PLDM Strength 的主分由联合训练的 60.55% 提高至冻结 Encoder 后的 98.05%，Joint 由 17.97% 提高至 94.92%，NRE 由 0.798 降至 0.115。LeWM Friction 由 50.20% 提高至 87.50%；PLDM Portal 由 53.91% 提高至 92.58%。这些结果说明，数据量不足不能单独解释这些失败，原始表示中已有可用于学习相应任务的信息。

**完整初始化的作用随任务而异。** DINO-WM Speed 的未见插值主分从 55.22% 提高到 86.00%，Gain 从 0.028 提高到 0.505，NRE 从 0.962 降到 0.411，原环境 CEM 均为 100%。完整初始化在 Damping 上的主分仅从 57.42% 变为 57.62%，NRE 则从 1.021 升至 1.083；Cube 主分从 61.33% 变为 62.30%，仍只有较弱的条件响应。这些结果支持任务依赖的初始化收益，不能因 Speed 改善而推断其他任务也会随之学会。

**继续调整表示也可能有益，冻结并非统一解法。** PLDM Damping 冻结后的主分从 77.54% 降至 56.05%，Gain 从 0.830 降至 0.135，NRE 从 0.221 升至 0.882；LeWM Mass 也在选择和响应指标上退步。已有证据支持“表示更新方式与模型、任务存在交互”，尚不能证明 JEPA 普遍阻碍 ICL，或某任务在所有训练方案下都必须更新 Encoder。

**选择、响应幅值、泛化和规划需要分别测量。** DINO-WM Cube 从头训练的主分为 61.33%，但 Gain 仅 0.095；LeWM / PLDM Speed 从头训练的未见插值约 98%，两侧外推约 29–36%；其他训练方案的外推同样需要单独读取。PLDM Strength 冻结后 ICL 大幅改善，原环境 CEM 却由 72.00% 降至 59.33%；PLDM Damping 则出现 ICL 下降、CEM 上升。因此，较高主分不能替代充分校准、外推或规划能力的证据。

**混合训练并非总会损害原环境规划。** PLDM Friction 冻结方案的 CEM 为 79.67%，原始模型参考为 73.00%；PLDM Mass 分别为 89.00% 和 80.00%。这些是描述性对照，不是经过配对显著性检验的普遍改进结论。不同任务的保持与损失应按实际指标分别报告，不能统一解释为合成数据质量差。

ContextWorld 的作用是让上述差异可以被识别和检验：同一当前画面和查询动作下，模型是否利用历史选择正确未来，是否产生足够准确的条件响应，以及这种能力能否泛化。成功任务提供正对照，弱响应或失败任务提供机制研究对象；任务失败不自动证明数据不可学。

具体根因仍待验证。冻结 Encoder 同时改变了表示参数、训练态缓冲区和目标表示随训练变化的过程，当前对照尚未分离各项作用。区分这些机制需要分别控制表示更新、目标变化与优化过程。更大数据或模型是否遵循稳定 scaling 规律，也需要多个规模点和受控训练预算才能判断。

历史 ICL 是否提升隐藏条件下的动作决策仍是独立问题：需要固定候选动作与真实后果，比较正确历史、无历史和错误历史下的动作排序、选择 regret 或闭环成功率。当前原环境 CEM 不提供这项结论。


## 6. 任务说明

以下说明各任务的物理含义、数据构造与适用范围。全部模型分数统一见 §5.2。

### 6.1 即时连续响应

#### 6.1.1 速度

##### 任务目标

模型根据近期移动判断当前速度，并预测同一动作对应的下一状态。

##### 数据构成

Training 覆盖 32 档速度。评测分别包含训练中出现的速度、训练范围内未见速度，以及低于
和高于训练范围的速度；每个参考速度使用六个评测种子 × 50 个查询。

##### 评测方法

主指标是训练范围内未见速度的一步严格正确率：与真实速度一致的历史必须同时优于另外
两档历史。训练内插值与两侧外推分别计分。

##### 适用范围

任务分别检验 History=3 下的已见速度、未见插值与范围外外推，三者不能互相替代。原任务 CEM 衡量原环境规划保持。隔离多速度数据的影响需要同种子的单速度对照，不能仅凭两种训练配方的差值归因。

#### 6.1.2 推手移动幅度

##### 任务目标

模型判断相同二维动作会让 PushT 推手移动较短还是较远。两档参数为 60 和 140。

##### 数据构成

扩量 Training 包含 32,768 对场景，Development 和 Public Test 各包含 256 对。配对查询共享当前
状态、画面和动作。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查模型是否使用正确历史、是否随历史切换预测，
以及最弱幅度条件是否达标。通过门槛为每个检查点至少 95%。

##### 适用范围

任务验证二值动作响应，不验证连续幅度估计或范围外外推。

#### 6.1.3 机械臂质量

##### 任务目标

模型根据相同力矩下的近期运动判断 Reacher 机械臂较轻还是较重。两档密度为 500 和
1500。

##### 数据构成

扩量 Training 包含 32,768 对场景，Development 和 Public Test 各包含 256 对。任务改变主体连杆
和末端球的质量，保持第二连杆不变。

##### 评测方法

主指标是真实下一状态选择正确率，并检查历史切换、最弱质量条件、bootstrap 置信下界和
latent 响应。完整能力判定要求每个检查点分别达到 75%。

##### 适用范围

任务验证两档质量的一步适应，不验证连续质量估计、范围外外推或多步闭环控制。

### 6.2 时间延迟动力学

#### 6.2.1 动作延迟

##### 任务目标

模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

##### 数据构成

延迟范围为 0–10。Training 覆盖完整范围；Public Test 包含
300 个查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

动作延迟有两个不同强度的评测问题，回答的研究问题不同，不能互相替代：

- **六组物理响应识别（正式指标）**：延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，
  各组在每个查询内等权宏平均。总体正确率须至少 75%，最弱组至少 60%，bootstrap 95%
  下界至少 70%。该指标判断模型是否区分六组一步响应，不区分 5–10 组内的延迟值。
- **二元历史响应诊断**：只判断预测在 delay=0 与 delay≠0（合并为一类）之间是否随历史
  正确切换，不要求区分不同的非零延迟。这是判断“历史是否引起了正确方向的条件差异”
  的更弱标准，主要用于快速诊断。

##### 适用范围

正式结果验证 History=7 下六个一步物理响应组（0、1、2、3、4、5–10）分别达标。
一步未来无法区分 5–10，因此不表示精确识别全部 11 档延迟；h2/h3 是辅助诊断，
不属于当前通过条件。也不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。二元诊断数值只说明
“有无延迟”的区分，不能单独支撑延迟识别结论。

### 6.3 接触或附着条件动力学

#### 6.3.1 接触摩擦

##### 任务目标

模型根据推手与物体接触时的响应判断摩擦较小还是较大。两档摩擦系数为 0.05 和 0.80。

##### 数据构成

扩量 Training 包含 32,768 对样本，Development 和 Public Test 各包含 256 对。配对查询的当前
完整物理状态误差不超过 `1e-5`，历史接触结束后至少连续三步无接触，不同划分不共享查询
或生成模板。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱摩擦条件，四项门限
分别为 95%、95%、95% 和 90%。本报告使用 Development 对比训练方式；Test 仅用于方法固定后的最终报告。

##### 适用范围

任务检验接触经验对下一步条件预测的作用，不验证任意摩擦系数插值或长期接触规划。

#### 6.3.2 运动阻尼

##### 任务目标

模型根据接触结束后的运动判断物体减速较快还是较慢。两档阻尼为 0.2 和 1.0。

##### 数据构成

扩量 Training 包含 32,768 对样本，Development 和 Public Test 各包含 256 对。配对样本交换起点，
使仅凭起点预测标签的准确率为 50%。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱阻尼条件，四项门限
分别为 95%、95%、95% 和 90%。本报告使用 Development 对比训练方式；Test 仅用于方法固定后的最终报告。

##### 适用范围

任务检验历史中的衰减信息是否影响下一步预测，不验证任意阻尼参数或长期轨迹。

#### 6.3.3 Cube 夹爪携带规则

##### 任务目标

模型根据夹爪与方块的近期响应判断闭合夹爪能否携带方块，并预测共享查询动作对应的真实
下一状态。

##### 数据构成

扩量 Training 包含来自 10,000 个独立来源 episode 的 10,000 对，Development 和 Public Test 各包含 256 对。四类动作模板在每个划分中严格均衡；源轨迹、动作模板、场景、配对内容和 query 画面互不重叠。

##### 评测方法

每个检查点的真实未来正确率至少为 75%，正确历史至少 75%，上下文切换至少 90%，最弱
规则至少 70%。通过 Development 的模型还需报告原 Cube CEM；CEM 的当前预算与解释规则见
§4.3。外部模型使用独立结果身份，不会覆盖仓库提供的参考结果。

##### 适用范围

任务检验二值携带规则的一步 ICL，不验证连续夹持强度或多步闭环适应；原 Cube 规划单独由 CEM 衡量。

### 6.4 隐藏结构转移规则

#### 6.4.1 门通行规则

##### 任务目标

模型根据历史中的穿门或碰壁结果判断外观相同的门能否通过。

##### 数据构成

Training 覆盖 96 个门位置，Development 覆盖 16 个门位置，Public Test 使用 42 个训练中
未见的门位置并包含 300 个场景。

##### 评测方法

每个查询保存“可通过”和“被阻挡”两种模拟器真实未来。评分分别检查两个穿门方向、历史
是否改变判断，以及两种未来在 latent 中是否可分；每个评测种子与方向的组合都必须达标，
配对 bootstrap 的 95% 下界必须大于 0。

##### 适用范围

任务验证一步门规则判断，不验证多步闭环穿门规划。

#### 6.4.2 传送门出口位置

##### 任务目标

模型根据历史中的传送结果判断进入同一入口后会从靠近边界还是远离边界的位置出现。

##### 数据构成

扩量 Training 包含 32,768 对场景，Development 和 Public Test 各包含 256 对。两种规律在查询前
汇合到相同当前状态，因此当前画面和动作本身不能泄露答案。

##### 评测方法

主指标是真实出口下一状态选择正确率，并检查正确历史、预测切换、最弱出口条件、
bootstrap 置信下界和 latent 响应。完整能力判定按每个检查点分别计算。

##### 适用范围

任务验证二值出口规则的一步适应，不验证连续出口坐标、范围外出口或多步传送规划。

## 7. 接入与复现

外部模型通过统一的 `LatentWorldModelAdapter` 提供图像编码与条件预测接口。输入只有图像和动作，输出为预测未来的 latent；评分器不要求图像解码器。接口形状、历史对齐和最小适配示例见[Adapter 规范](External_Model_Adapter_Contract.md)。数据加载见[HF 数据集指南](HF_Dataset_Export.md)，内置模型的训练与初始化参数见[训练指南](StableWM_Training.md)。

从可用数据包运行 Development 评测：

```bash
python -m contextworld.benchmarks.external_model_cli \
  --benchmark-root /path/to/ContextWorld-bundle \
  --evaluation-split development \
  --task action_strength \
  --adapter lewm \
  --checkpoint /path/to/weights.pt \
  --model-name my-model \
  --output /path/to/development-result.json
```

新模型沿用相同任务查询和评分方法。报告中注明数据版本与划分、训练数据比例、样本覆盖、初始化权重、更新模块、训练预算、种子、检查点和评测版本。若要声称某因素造成能力变化，应使用只改变该因素的对照；跨模型比较本身不能完成这种归因。

## 8. 可复现性与结果报告

原始结果的检查点与数据哈希用于追溯分数来源。主文档和 CSV 由同一份 JSON 自动生成，避免不同页面维护不同数值。冻结 v3 的数据、评分规则和三种子结果继续保留；新的训练数据与方法使用独立结果记录。

本表的完整权重和逐查询输出尚无稳定公共下载，当前公开汇总不足以支持外部完整复现。HF 数据集的准备状态及加载约束见[发布说明](Expanded_Training_Release.md)。数据包可获取性与模型能力结果是两个独立问题。

## 9. 适用范围与限制

ContextWorld 衡量固定权重下的条件预测：模型是否识别历史中的规律，是否产生方向与幅值正确的响应，以及是否泛化到新的场景或参数范围。它不直接证明长期 rollout、隐藏规律下的动作优化或闭环控制能力。

这些训练方式对比是单训练种子的 Development 研究。分数用于描述能力变化并定位机制问题；正式显著性或稳定性结论还需要相同查询的配对分析与独立训练重复。响应指标在各检查点自己的 latent 空间中归一化，不是共享物理单位的预测误差。

## 10. 比较与版本管理

新结果应引用明确的数据版本、训练方案和评测划分。相同任务定义与评分协议下可以比较新模型或训练方法；改变查询分布、任务定义或评分规则时，应记录新的 benchmark 版本。冻结 v3 的数值保存在[参考附录](reference/Benchmark_Result_Provenance.md)，不以新实验覆盖历史结果。
