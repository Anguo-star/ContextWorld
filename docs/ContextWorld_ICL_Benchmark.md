# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 评测世界模型能否从最近几步真实交互中识别隐藏动力学，并据此预测未来。模型只接收图像与动作，评测时不更新权重；预测和真实未来在参评模型自己的表示（latent）空间中比较，不要求图像解码器。

**主评价只有一个问题：模型能否根据历史，准确预测隐藏动力学下的整段未来？** 本文以多步完整预测分为主，按九项任务比较模型和训练方案。动作选择与 CEM 是下游验证；旧选择率和响应指标保留在折叠的历史结果中。

| 内容 | 用途 | 公开范围 |
|---|---|---|
| 多步完整预测分 | 主评价：历史条件下的完整未来预测质量 | 九任务主评测分布的 Development 查询，共 2,436 个场景 |
| 原环境 CEM | 原有规划能力保持 | 四个原环境，单独报告 |
| 动作选择与机制诊断 | 解释预测改善是否转化为决策收益 | 九任务 134 场景诊断；Speed 另有小规模闭环实验 |
| 旧协议结果 | 复核选择率、条件响应和数据扩量实验 | 原固定 Development 查询，数值保留 |

当前多步结果覆盖九项任务的主评测分布；Speed 限于未见速度插值，尚未扩展至其余三类分布，也未评测 Test。该评分方案尚未冻结为新版基准。CEM（交叉熵方法）在模型预测上搜索动作序列，其成功率与预测分回答不同问题。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织。
九项任务分别报告多步完整预测分；原环境 CEM 作为下游结果单列。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不作为评分汇总单位。

表中历史长度是**包含当前帧的观测帧数**。通常相邻观测间隔 5 个物理步；例如长度 3 表示两个过去观测和一个当前观测，以及它们之间已执行的两个动作块。

## 2. 数据与划分

数据由物理模拟器生成。每项任务改变一个隐藏动力学因素，保存连续交互轨迹、查询动作及真实未来。Training 用于训练，Development 用于实现检查与方法选择，Test 用于方法固定后的最终报告。表中的训练方式比较统一使用 Development；其分数不作为 Test 成绩报告。

**六项二值配对任务以训练配对数表示规模：2k=2,048，8k=8,192，32k=32,768；Cube 的 10k=10,000。** 一对包含两种隐藏条件下的轨迹，不等于两个独立来源 episode。速度、动作延迟和门通行规则另列各自的覆盖单位。

| 任务 | 训练方案比较使用的 Training | 覆盖单位与含义 | Development / Test |
|---|---|---|---|
| 推手移动幅度 | **32,768 对** | 状态与动作窗口；可从同一来源 episode 取得多个窗口 | 各 256 对 |
| 接触摩擦 | **32,768 对** | 重置状态与接触几何 | 各 256 对 |
| 运动阻尼 | **32,768 对** | 初始状态；包含成对的前向／镜像样本 | 各 256 对 |
| 机械臂质量 | **32,768 对** | 初始关节状态与探测动作 | 各 256 对 |
| Cube 夹爪携带 | **10,000 对** | 来自 10,000 个不同来源 episode | 各 256 对 |
| 传送门出口 | **32,768 对** | 不同初始距离与动作幅值的场景 | 各 256 对 |
| 速度 | 覆盖 **32 档速度** | 档数表示参数种类，不是样本数 | 每个参考速度 300 个查询 |
| 动作延迟 | 覆盖 **延迟 0–10** | 11 种隐藏延迟，一步评分合并为 6 个物理响应组 | 各 300 个查询 × 11 种延迟 |
| 门通行规则 | 覆盖 **96 个门位** | 每个门位包含可通过／被阻挡两种规则 | 16 / 42 个门位置，各 300 个场景 |

配对数、动作窗口数与独立来源 episode 数不能互换。各档规模及覆盖变化集中见 §5.4；速度、延迟和门通行规则没有扩量对照。扩量只改变 Training，Development 和 Test 保持固定。每条结果的数据包版本、manifest 和评测身份记录在[结果 JSON](research/data/icl_training_study_v2.json)；生成与划分检查见[数据生成方法](Data_Generation.md)。

公开 Test 采用离线评测，没有托管提交服务。方法、训练预算和检查点选择应在 Development 上完成；读取 Test 后不得再用它调整方法。稳定公共数据下载版本尚未公布，包格式和本地加载方式见[HF 数据集指南](HF_Dataset_Export.md)。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 连续真实历史图像，包括最后的当前图像；
2. 历史图像之间已经执行的动作序列；
3. 接下来要执行的查询动作序列；
4. 每种候选隐藏规律对应的模拟器真实未来，仅供评分。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像（含当前帧）+ 历史动作 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

主评测比较整段预测 latent 与匹配隐藏条件下的真实未来；旧协议另以候选距离判断是否选对未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器从 `x0` 连续执行到真实未来，中途不重置或改写状态。独立重放仅用于检查模拟器状态的一致性，不替换保存的数据。

多步评测沿此轨迹继续执行完整候选动作，保留速度、接触状态和待生效的动作队列；每个候选从同一源轨迹独立重放。

### 3.3 配对构造与起点交换

原生判别查询的一对样本分别使用两种隐藏规律。两者在查询时刻共享约定的当前可见状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

Delay 额外保留各条件真实的待生效动作队列；它们可以不同，因此同一当前画面不等于同一完整 Markov 状态。

扩展后的多步候选允许部分动作或时刻产生相同未来，例如零动作或尚未生效的延迟动作；这些情况照常计分，不为增大条件差异而删去。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只用于数据校验与评分，不进入模型输入。

## 4. 评分方法

### 4.1 多步完整预测分

**主指标只衡量一件事：给定真实历史与后续动作，模型能否准确预测整段未来。** 模型从初始历史自由推演，评分时不向预测器补充未来真实观测。五个评分时刻固定为第 5、10、15、20、25 个物理步，等权计入，不能根据模型成绩选择最好的一步。轨迹误差按这五个观测时刻定义；“完整”指比较完整预测表示，包含各隐藏条件共有的预测偏差。

评分固定动作序列，直接比较预测与对应真实后果，不使用目标距离或到达时间。较大的步幅本身不会加分，也不能靠提前经过终点掩盖预测错误。

对源场景 $q$，隐藏条件为 $k$，共用动作候选为 $c$，未来时刻为 $t$。真实未来表示记为 $z_{qkct}$，预测为 $\hat z_{qkct}$；$\bar z_{qct}$ 是同一场景、动作和时刻下，各隐藏条件真实未来的均值。先在场景内等权平均条件、候选和时刻：

$$
L_q=\frac{1}{K_qC_qT}\sum_{k,c,t}\|\hat z_{qkct}-z_{qkct}\|^2,
\qquad
B_q=\frac{1}{K_qC_qT}\sum_{k,c,t}\|z_{qkct}-\bar z_{qct}\|^2.
$$

**多步完整预测分**为：

$$
\boxed{S_{\mathrm{ICL}}=100\left(1-\frac{\sum_q L_q}{\sum_q B_q}\right).}
$$

| 分数 | 含义 |
|---|---|
| 100 | 整段未来在评分表示中预测准确 |
| 0 | 误差与“所有隐藏条件共用平均未来”的理想参照相同 |
| 负数 | 完整预测误差大于该参照；负值保留，不截断 |

这是相对理想参照的连续分数，**不是百分比准确率，没有有限的下界**。零分不代表没有预测能力；它要求达到知道所有真实未来后才可计算的条件均值，强于一个普通无历史模型。例如 −100 分表示完整误差为参照的两倍。分数同时惩罚条件响应错误和各条件共同的预测偏差，不会因为只选对未来类别就接近满分。负分也不表示模型完全没有利用历史：模型可以改善条件响应，却仍存在更大的共同误差。

参照 $\bar z$ 只由评分器计算，不提供给模型，也不是一个实际部署的预测器。在当前图像与动作相同、隐藏条件完整等权的配对上，始终输出相同未来的确定性模型不能取得正分。原始数据训练的模型若能通过历史泛化，同样可以得高分；不预设它必须失败。

模型与真实未来在同一检查点的冻结表示中比较，因此本分数描述 latent 完整预测质量，不宣称具有统一物理单位。定义和评分程序对所有模型相同，不按模型分数调整参照或阈值。

### 4.2 汇总、范围与版本

统计先累计完整误差和参照误差，再相除；不平均逐场景或逐时刻的比值。先独立计算每个检查点的分数，再等权平均相同训练配置的重复。95% 区间按来源组重采样：同一 episode 的多个窗口、同源前向／镜像样本一起抽取；每组保留全部条件、候选和时刻，各训练重复使用同一抽样。它表示给定这些检查点时的来源抽样不确定性，训练重复的标准差另存于结果文件。九项任务分别报告，不合并跨任务总分。

参照总能量为零时，分数无定义，必须报告，不能填为满分或静默删样本。参照能量很小时，共同误差可能产生很大的负分；应结合固定的数据范围解释，不能把数值幅度直接当作跨模型的物理误差倍数。

评分公式版本为 `multistep_complete_prediction_v1`，数据覆盖版本为 `multistep_development_coverage_v2`。Speed 插值、Delay、Door 各使用 300 个注册 Development 源场景，其余六项各 256 个，共 2,436 个。每个场景沿用固定隐藏参数，扩展相同规则的未来动作，保留全部条件、候选和五个时刻，不按模型成绩筛选。它们覆盖对应的主评测源查询；**不包括 Speed 其他分布或 Test**。

最初 134 场景子集的[结果文件](research/data/multistep_prediction_v1.json)保持原样。扩展数据沿用评分公式和动作构造规则，并逐项验证子集中的输入与真实未来一致。详细覆盖与来源分组见[数据生成方法](Data_Generation.md#九任务的动作选择与多步预测诊断)。

旧的正确未来选择率、条件响应指标及 v3 冻结结果保持原样，仅作历史比较和机制诊断；它们不与新分数混合排名。新分数不以旧能力门是否通过为报告前提。

### 4.3 规划验证

CEM 衡量下游动作规划，单独报告，不组成 ICL 主分。原环境 CEM 检查原有规划能力保持；隐藏动力学下的候选选择和闭环实验检查条件预测是否有决策价值，两者也不能混用。

原环境 CEM 通常使用六个评测种子（42–47），每个种子 50 次，共 300 次。部分原始参考沿用历史预算，具体身份与配置见结果文件。原有结果无需因 ICL 评分公式变化而重新运行。

### 4.4 历史指标与机制诊断

<details>
<summary>旧选择分、条件响应及历史利用的定义</summary>

**旧选择分与历史利用。**

六个二值配对任务的旧选择分是选择正确真实未来的比例，随机选择参照为 50%。Door 使用同历史下的两种目标选择正确率；Delay 使用六个物理响应组宏平均，随机参照为 16.67%。Speed 要求匹配历史的预测优于该组每一个竞争历史条件：已见速度、未见插值各含三档速度，随机参照为 33.33%；低端、高端外推各含四档，为 25%。四种速度分布分别报告。

历史表保留原始百分数；以下读数用于解释旧结果，不组成新的主分：

| 指标 | 含义与解读 |
|---|---|
| 旧选择分↑ | 按对应任务定义，选择正确未来或匹配历史的比例 |
| 响应分↑ | `100 × (1 − NRE)`，100 为完全恢复条件响应，0 与零响应同等误差，负值表示误差更大；单位为分，不是成功率 |
| 最弱条件↑ | 隐藏条件、响应组或参考速度中表现最弱的一项 |
| History↑ | 匹配历史是否比错误历史产生更准确的目标预测 |
| Switch↑ | 历史切换响应的任务特定读数；例如 Strength 检查预测差与真实差的内积是否为正，不能据此认定幅值正确 |
| Joint↑ | 六个配对任务中，两种条件都选对未来、都正确利用历史，且该样本对 NRE<1 的比例；其他三任务不定义此项 |
| Gain≈1 | 预测条件响应在真实条件响应方向上的相对幅值；理想值 1，接近 0 表示响应过弱 |
| Alignment↑ | 预测与真实条件响应的余弦相似度；理想值 1 |
| NRE↓ | 条件响应误差的平方范数除以真实响应的平方范数；理想值 0，完全不随历史变化的预测为 1 |
| 优于零响应↑ | NRE<1 的样本对比例，不解释为幅值已充分校准 |
| CEM↑ | 对应原环境的规划成功率，独立于 ICL 评分 |

各任务的旧选择分定义和随机参照不同，且每项任务分别训练检查点，因此不合并为跨任务总分。严格比较将平局记为失败：例如 Speed 完全不随历史变化时，竞争历史的损失相等，严格胜率为 0；随机选择参照不能解释为无历史模型的得分。

**条件响应与完整预测诊断。**

设切换隐藏条件后的真实目标 latent 差为 Δz，匹配历史下的预测差为 Δẑ，则每对样本的 Gain 为 `〈Δẑ, Δz〉 / ‖Δz‖²`，NRE 为 `‖Δẑ − Δz‖² / ‖Δz‖²`，Alignment 为两者的余弦相似度。共享配对实现先累加响应能量，再计算总体 Gain、Alignment 与 NRE，并非直接平均每对的比值；任务分组沿用各自协议。评分同时检查真实未来在模型表示中是否可分。

**连续响应分为 `100 × (1 − NRE)`，不截断负值，也不再次平方 NRE。** 它与 NRE 携带相同信息，用于直观展示改善程度，不是一条独立证据。先按原协议计算每个检查点的 NRE，再跨可比训练重复汇总；响应分的标准差为 NRE 标准差的 100 倍，缺失值保持缺失。任务详情和扩量表使用响应分展示该维度，原始 NRE 保留在 CSV / JSON 中。

例如真实目标为 −1、1，预测为 −ε、ε 时，ε=0.001、0.5、1 都可在严格选择及 NRE<1 的联合判断中成功，但响应分分别只有 0.1999、75、100。这说明正确率与响应幅值应分别阅读。条件差分也会消去两侧共同预测偏差，因此响应分满分仍不能证明绝对未来预测准确。

距离只在同一检查点的 latent 空间中计算。不同检查点的原始 latent MSE 不具有共同单位；归一化响应指标描述各自表示中的相对响应质量，不能当成同一物理单位的绝对预测误差。高旧选择分也不能自动证明正确响应幅值或范围外泛化。

**完整预测误差补足共同偏差。** 对共享当前状态与查询动作的 K 种隐藏条件，记正确历史下的预测为 pᵢ、真实目标为 zᵢ，目标均值为 z̄。定义：

$$
E_{\mathrm{pred}}=\frac{\sum_i\|p_i-z_i\|^2}{\sum_i\|z_i-\bar z\|^2}.
$$

0 表示在该表示中预测准确；1 表示与每种条件都预测 z̄ 的误差相当。z̄ 是只用于评分的理想参照：在完整、等权配对且各条件共享当前观测与查询动作时，任何不区分历史、输出同一预测的确定性模型都不能取得小于 1 的误差。这是误差参照，不是新增通过门槛；模型不会收到 z̄ 或隐藏参数。

该误差可分解为**条件响应误差＋共同预测偏差**：前者比较去均值后的预测与真实未来，后者衡量两个均值的偏离。在二值等权配对上，响应项等于上述 NRE；多条件任务不能直接代入采用不同分组权重的旧 NRE。两项都小，才支持完整未来预测准确。另报告**历史误差下降**：错配历史的完整误差减去正确历史的完整误差，使用相同分母。它说明匹配历史减少了多少误差，但仍需同时看正确历史误差的绝对读数；在二值等权配对上，该下降量恰为 4×Gain，不是独立证据。

这些定义用于解释已有机制实验，见 §5.5；九任务多步主分按 §4.1 统一计算。各模型使用自己的目标编码器，因此误差比也不能解释为共同物理单位的状态误差。跨模型的实际动作后果仍由模拟器评分。完整预测误差也不能替代规划成绩：候选共享的某些偏差可能不影响动作排序，而较小的预测误差也可能颠倒接近最优的动作。统计先累计误差与参照能量再求比，置信区间按完整场景重采样。

完整能力判定是评分协议的补充，不决定模型是否取得进步，也不将低于阈值的分数置零。各任务的历史阈值统一见[评分与复现附录](reference/Benchmark_Result_Provenance.md)。

### 4.5 评分有效性：历史对照与物理校准

主分描述完整预测误差。验证它是否反映 ICL，还需要区分两个问题：**正确历史是否减少误差，以及减少之后的预测是否足够准确。** 这两项验证复用 §4.2 的全部场景、检查点和五个时刻，不重新训练世界模型，不改变主分。

**历史对照。** 对相同当前图像和后续动作，分别输入每种隐藏条件下的真实历史。匹配历史的预测与其真实未来比较；错误历史则取其余所有条件历史的平均误差。历史动作保持一致，后续始终自由推演，不补入未来真实观测。令两种完整误差比分别为 $E_+$、$E_-$，分母均为 §4.1 的同一个 $\sum_q B_q$，历史收益定义为 $G_H=E_--E_+$。正值表示正确历史减少误差，但仍需结合 $E_+$ 判断预测质量；例如从 10 降到 9 有历史收益，却仍远高于均值参照。

该对照比删除历史更少改变输入结构。Delay 的历史同时提供延迟规律和待生效动作队列的证据，因此其收益应解释为对隐藏动力学与隐藏状态的联合推断，不能全部归为静态参数识别。各条件历史图像有差异，也不等于其信息已被证明足够或可泛化。

**物理校准。** 从真实未来的 latent 拟合固定的线性读出器，再把预测 latent 转成选定物体坐标。校准按来源组划分三折，每折只用另外两折的真实未来拟合；同来源窗口及镜像样本不得跨折。每个来源最多取 32 帧，使用固定正则和特征压缩，不根据结果调参。读出器不参与世界模型训练或主分计算。

物理表同时给出两类 RMSE：真实未来 latent 的**校准误差**，以及模型预测 latent 的**预测读出误差**。前者检查读出器本身能否从未参与拟合的真实表示恢复位置；后者在同一读出器下比较正确与错误历史。TwoRoom 使用像素坐标，PushT 使用位置及角度的像素等效量，Mass 与 Cube 使用毫米坐标，不跨单位平均。具体坐标、折分和复现命令见[数据生成方法](Data_Generation.md#历史对照与物理校准)。

这是一项使用 Development 标注的辅助验证，**不是新的公共物理主分**。真实 latent 解码准确，并不能保证读出器对偏离真实表示分布的预测仍然准确；它也只检查选定坐标；其中部分离屏坐标不能从单帧图像恢复，具体反例见 §5.7。校准误差大时，该读出不足以支持物理判断，也不能据此断言编码器已丢失物理信息。物理读出可支持或质疑 latent 结论，但不能消除所有跨编码器比较的歧义。验证结果见 §5.7。

### 5.1 训练方案与实验设置

| 代号 | 训练方案 | 初始化 | 训练数据与采样比例 | 训练轮数 | 更新哪些模块 |
|---|---|---|---|---|---|
| **T0** | 仅原环境数据训练 | 模型默认初始化 | 原环境 100% | 10 epochs | 各模型原生可训练模块 |
| **T1** | 直接混合数据训练 | 模型默认初始化，不加载 T0 权重 | 原环境 50% + 对应任务 ICL 50% | 10 epochs | 各模型原生可训练模块 |
| **T2** | 原环境预训练后，混合数据联合训练 | 加载对应环境的完整 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | Encoder、预测器及其余原生可训练模块 |
| **T3** | 原环境预训练后，冻结 Encoder 混合训练 | 加载与 T2 相同的 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | 固定 Encoder 参数与训练态缓冲区；训练预测器、projector、动作编码器等其余模块 |

T2 / T3 加载模型权重后重新建立优化器，不接续 T0 的优化器状态。T0 按原环境训练一份模型；T1–T3 分别针对每项任务训练。因此，结果表的一行汇集同一模型家族与方案的九项实验，不表示同一份权重同时获得九项能力。

**50/50 指训练轨迹窗口的采样比例，不是来源 episode 数或数据文件大小各占一半。** 默认混合数据集按两个成分的可用窗口数构建 epoch：设其长度分别为 N原、NICL，则名义 epoch 长度为 `2 × max(N原, NICL)`，在划分与分批前的 epoch 排程中，两成分窗口数相等；较小成分会重复采样。因此，加入 ICL 不会简单地把原环境曝光减半，扩量也可能增加每轮更新次数。实际训练还受训练/验证划分、分布式采样与末尾不完整 batch 的处理影响；具体实现见[混合数据加载器](../contextworld/training/stablewm_bundle.py)。

**比较预算时需区分轮数与曝光量。** T2 / T3 比 T1 多出原环境预训练经历；各数据版本的 epoch 长度也可能不同。相同的 10 epochs 不能直接视为相同计算量、相同独立样本数或相同数据曝光次数。

**重复实验的汇总方式：** 相同任务、数据版本、训练方案和输入协议的全部可用训练重复参与均值；已有三个训练种子的配置使用三者，不选取其中一个。新主表显示多步分数均值，任务详情报告场景 bootstrap 区间和训练重复数；训练标准差保存在结果 JSON。历史表沿用“均值 ± 样本标准差”和各指标的有效重复数。只有一次训练时，标准差不写作零。具体种子、初始化检查点及逐次结果见对应结果文件。

每个检查点的 CEM 先按评测次数汇总，再跨训练重复等权平均。六个 CEM 评测种子是同一检查点的评测重复，不能当成六次独立训练。不同规模、训练方式和初始化协议始终分别汇总。

LeWM / PLDM 在八项任务上的 T2 / T3 使用相同任务数据、混合比例、历史长度、帧间隔及原始初始化权重。跨模型保留各自骨干、训练目标和优化器；这些结果可以比较能力获得程度，但不能单独分离某个架构部件的贡献。

### 5.3 主要发现与解释边界

**ICL 训练能改善完整预测，但收益依赖任务与训练方式。** 速度插值中，LeWM 的 T0 / T1 / T3 分别为 −49.77 / 63.73 / 85.63，PLDM 为 −237.69 / 47.99 / 69.84。DINO-WM 使用同一冻结视觉表示，Strength 的 T0→T1 从 −229.98 提高至 −99.62，Door 从 −323.32 提高至 −32.88；这些改善尚不等于完整未来已预测准确。九任务没有一致最优的训练方案。

**扩大场景覆盖会改变小样本判断。** DINO-WM Door 的 T1 在原 16 场景子集为 4.14，全部 300 场景为 −32.88。新表使用全部注册主分布查询，旧子集另存，不把小样本中的正分概括成完整分布能力。Speed 的多步结果仍限于未见速度插值，不能外推到训练范围之外。

**部分误差主要在递推后显现，另一些首步就存在。** 同一检查点、同一组场景和动作下，Strength 的 LeWM T3 第 5 步误差为 0.30，第 25 步自由误差为 2.34；每步输入真实历史后，末步误差为 0.24。PLDM T3 对应为 0.26 / 2.28 / 0.33。相反，LeWM Damping T1 的首步误差已为 254.09，真实输入后的末步仍为 71.73。这些误差共用各检查点的整段未来参照分母，说明需要分别研究单步残差和预测反馈，不能给所有失败同一个解释。

**同一任务也可能在不同阶段失准。** Delay 中，LeWM / PLDM T1 的末步误差由自由推演的 2.19 / 2.71 降至真实输入下的 0.73 / 0.74；DINO-WM T1 的首步已经是 66.15，末步两种输入为 65.59 / 66.13。这排除了“所有 Delay 差异都由多步反馈造成”的解释。Cube 中，LeWM / PLDM T1 的首步与后续误差都较大；预训练初始化减轻了退化，但未一致优于各自 T0。DINO-WM 的 Cube T1 / T3 明显优于 T0，二者分数接近。Friction 和 Mass 也没有共同最优方案，不能把冻结 Encoder 或扩量概括为通用解决办法。

**真实输入并非必然改善预测。** PLDM Portal T2 的末步自由误差为 23.70，真实输入误差为 24.84。诊断保留差值的正负，不将其称为可相加的“误差来源占比”：真实输入同时纠正状态并刷新动力学证据，也可能改变预测器所处的输入分布。全部方案的分步对照见各任务折叠表。

**旧选择率、完整预测和规划收益不能互相替代。** Strength 的 LeWM / PLDM T3 旧选择率为 97.27% / 98.05%，新多步分为 −46.36 / −44.52。两种评测的动作分布与时域不同，不能把差值全部归因于自回归；它说明原查询选对未来，不保证对更长、更多候选动作预测准确。原环境 CEM 保持原口径，单独报告。

模型容量、历史长度和训练覆盖仍是待检验因素。当前结果对下一步的约束是：

- **先定位递推问题。** Strength T3 等模型在真实输入下误差较小，自由推演后明显增大，值得优先检验多步训练和递推时的信息保持。
- **再定位单步残差。** DINO-WM Delay、LeWM Damping T1 等在真实输入下仍有较大误差，应先区分训练覆盖、目标与预测器拟合；尚不能直接归因为参数量不足。
- **历史长度需要独立对照。** 真实输入同时纠正状态并提供新的动力学证据，不等于只增加历史长度。现有结果既不能证明长历史无用，也不能证明延长历史就能解决问题。

此外，物理读出存在校准和离屏可见性限制，见 §5.7；不能将其误差直接归因为模型学习失败。因此，当前没有依据要求所有任务统一扩大模型。应先在误差类型明确的少数任务上选择干预，保持数据与训练预算可比；上述结论均来自冻结检查点评测。

### 5.5 预测误差与动作选择

主分只评价自由推演。定位误差时，另对同一场景、动作、检查点与目标表示进行两种输入对照：

| 分支 | 每一步预测使用的历史 | 可以回答什么 |
|---|---|---|
| 自由推演 | 初始真实历史，随后使用模型自己的预测 | 实际开放环推演能达到怎样的准确性 |
| 真实观测输入 | 用模拟器的真实历史窗口替换预测窗口，不提供待预测目标帧 | 不输入之前的错误预测后，误差是否减小 |

两分支的第一个预测必须一致。随后在五个固定时刻分别累计完整预测误差，全部除以该检查点整段未来的同一个平均条件差异能量。这样可以比较误差随深度的变化，避免每个时刻更换分母；该诊断误差比不是某一步的准确率。

分任务折叠表报告第 5 步、第 25 步以及第 25 步的配对差值与区间；五个时刻完整记录见结果文件。自由误差减真实输入误差为正，表示预测反馈与信息更新影响了表现。这个差值不是可相加的根因占比：真实输入既纠正状态，也更新了动力学证据，不能单独证明更长历史或更大模型必需。

真实输入使用开放环预测时尚不可见的信息，**只作诊断，不作为 ICL 主分或可实现的规划成绩**。动作选择与 CEM 的既有结果集中保留如下。

#### 九任务诊断：先确认决策需要动力学，再定位预测问题

**动力学影响未来，不一定影响当前目标下的最佳动作。** 该诊断覆盖九项任务、134 个 Development 场景及 70 个“检查点×任务”单元，使用冻结的 T0、T1、T3 权重。Speed 使用六个固定场景；其余任务各使用 16 个源查询，全部保留。Delay 使用三个原生 H7 的 T1 检查点；其他任务比较可用的 T0、T1、T3，不包含 T2。这些小规模机制实验与 §5.2 的扩展 Development 预测结果分别报告。

每个场景的各隐藏条件共用目标和候选动作。模拟器从真实历史连续执行候选，在 **5、10、15、20、25 步的固定时刻**评分；提前经过目标不等于终点准确。候选包含幅值、持续时间、停止或反向动作，以及任务所需的路径、横向修正或夹爪控制；隐藏参数保持原值。

令真实代价为 $J(k,c)$，其中 $k$ 是隐藏条件、$c$ 是候选。**决策差距**

$$
G=\min_c\operatorname{mean}_k J(k,c)-\operatorname{mean}_k\min_c J(k,c)
$$

比较“所有条件共用一条最优动作”与“按条件分别选最优动作”。$G>0$ 表示该候选集有利用动力学信息的空间；$G=0$ 表示该目标、候选和时域不能要求模型靠区分条件来胜过最佳共用动作。它不证明原任务没有 ICL，也不证明完整动作空间中无法获益。候选最优误差非零时，还说明当前候选集不能精确到达目标。

#### 固定候选：历史是否改善实际动作选择

**速度。** 四类分布分别使用全部 300 个场景；31 个候选将原 5 步动作乘以 0–1.5 的系数，步长 0.05。目标为该类最慢速度执行原动作后的终点，全部场景保留。三项代价均为**像素距离**；错配历史对其余速度等权平均，不跨分布合并。

#### 多步误差来源：真实观测对照

沿用上面的六个场景、三种速度和两个检查点，对每个匹配历史条件保留**同一条 CEM 动作与同一条可达动作**，不重新搜索。在第 5、10、15、20、25 个物理步，比较四种输入：自由推演、仅补入真实当前帧、仅补入真实过去两帧、补入完整真实三帧。动作、目标、真实未来和模型均固定。

完整补入时，每次使用预测时刻之前的三张连续真实图像，检验真实输入下的一步预测；不输入待预测的下一帧。部分补入只替换当前调用的对应 latent，其他位置仍取该分支的自回归输出，不追溯修改缓存。**这些对照使用规划时未知的未来观测，部分补入还混合真实与预测轨迹；均只用于诊断，不是可部署策略或新的规划成绩。**

表中末步误差为候选与条件的预测平方误差总量，相对同一检查点自由推演归一化为百分比；100% 表示相同误差。两候选、三种速度在场景内等权，区间按六个场景配对重采样。“正确偏好”只计两候选的预测代价排序，不是重新执行后的成功率。

T1 补入真实三帧后，末步误差降至自由推演的 17.5%，正确排序从 2/18 恢复到 18/18。仅纠正当前帧也达到 17/18，补入过去两帧为 7/18。T0 出现相同方向的现象。所有分支的首步结果相同；差异发生在模型开始接收自身预测之后。这支持**自回归输入误差是本面板中的重要瓶颈**，而不是规划失败只来自宽松目标判定。

| 候选原因 | 本轮能够确认什么 | 仍不能据此确认什么 |
|---|---|---|
| 多步推演不稳定 | 同一模型、同一真实未来，补入真实输入显著降低误差并恢复排序 | 输入分布偏移、数值误差传播和动力学证据更新的贡献不能相加拆分 |
| 三帧历史太短 | 根据已知渲染规则，从三帧图像定位红色智能体并结合动作，无需训练即可区分全部 18 个速度条件；最大速度估计误差 0.1 | 这不证明原生 encoder 已充分提取信息，也不证明更长历史对自由推演无益；结论不外推到 Delay 等任务 |
| 模型容量不足 | 现有容量在真实三帧输入下已能排对两候选，没有“必须扩大模型才能区分”的证据 | 不能排除更大预测器改善自由推演；容量原因需固定表示、数据与曝光量的训练对照 |

当前模型的预测器只有三个已训练的位置 token。预测第 20 个物理步时，窗口已全部由预测帧组成，但条件信息可能隐含保留其中，不能仅据窗口变化判定“忘记了动力学”。直接增加测试历史长度会改变未训练的位置表示，不能作为有效长历史对照。下一项训练研究应先比较相同容量下的单步与自回归多步训练：后者将自身预测作为后续输入，再对照真实续接轨迹计算损失。仅延长目标时域不等于训练自回归稳定性。训练续接必须来自 Training；更大容量和更长训练历史分别作为后续控制变量，不同时改变。

### 5.7 评分有效性验证

**历史对照与完整误差分别检验“历史带来收益”和“预测准确”，但尚未建立九任务统一的物理准确率。** 验证覆盖主表相同的 136 个检查点×任务单元、37,016 个检查点×场景查询，汇总为 86 个组合；模型权重不变，匹配历史的误差与主表复算一致。以下历史对照与物理读出只解释主分，不组成新的总分。

**PushT 存在明确的单帧不可辨识坐标。** 多步候选延续动作后，部分推手位置离开原始 512×512 画布。下表按全部隐藏条件、候选和时刻统计，不删除任何场景。

这项发现限定的是**扩展多步数据上的物理校准**，不能反推原一步数据具有同样比例的问题，也不能解释全部校准误差。主分仍然衡量图像表示中的预测误差；但即使它达到满分，也不能保证离屏物理状态准确。若下一版目标是物理状态预测，应先保证相关后果可观测、校准可识别，再固定评分；不应通过提高模型容量来绕过测量问题。

## 7. 接入与复现

外部模型通过统一的 `LatentWorldModelAdapter` 提供图像编码与条件预测接口。输入只有图像和动作，输出为预测未来的 latent；评分器不要求图像解码器。接口形状、历史对齐和最小适配示例见[Adapter 规范](External_Model_Adapter_Contract.md)。数据加载见[HF 数据集指南](HF_Dataset_Export.md)，内置模型的训练与初始化参数见[训练指南](StableWM_Training.md)。

新多步结果由冻结权重推理和独立评分两步生成。先登记检查点、训练方案与数据身份，评测时选择 `--modes free`；再由全部场景误差生成分数、区间和结果文件：

```bash
python scripts/diagnose_cross_task_decisions.py \
  --models /path/to/models.json --id action_strength/lewm/scratch \
  --panel /path/to/panels/action_strength \
  --output /path/to/results/action_strength/lewm/scratch \

python scripts/multistep_prediction_score.py \
  --models /path/to/models.json --results-root /path/to/results \
  --panels-root /path/to/panels --output /path/to/multistep.json
```

登记字段、数据格式与补充诊断见[数据生成方法](Data_Generation.md#冻结权重评测与误差定位)。新入口目前支持三种内置模型；外部 Adapter 接入完整多步推演时，仍需验证预测反馈与动作对齐。

## 8. 可复现性与结果报告

报告至少注明数据版本与划分、训练数据和比例、初始化、更新模块、训练预算、检查点及评测版本。表格与 CSV 从同一份 JSON 生成，检查点和数据哈希用于追溯来源；九任务结果按 §5.1 汇总全部可比训练重复。当前多步表含 136 个检查点×任务单元，汇总为 86 个模型／训练方案／任务组合；冻结权重与数据身份检查全部通过。缺少同协议检查点的组合保留为空，不补零。

正式成绩的有效性取决于输入合法、数据隔离及评测时权重不变。方法在 Development 上确定后，Test 应报告预先确定的同一任务集合，包含低分结果；Development 能力门是否通过不作为 Test 报告前提。历史 v3 按旧流程产生的结果保持原样，见[参考附录](reference/Benchmark_Result_Provenance.md)。

完整权重、数据包和逐查询输出尚无稳定公共下载，因此公开汇总还不能支持外部完整复现。包格式、数据身份与发布准备见[HF 数据集指南](HF_Dataset_Export.md)和[发布说明](Expanded_Training_Release.md)。

## 9. 适用范围与限制

- **数据范围：** 多步表覆盖九任务主分布的 2,436 个 Development 源场景，Speed 只含未见速度插值。旧表使用原查询动作；两者的动作分布与预测时域不同，不可直接相减，也都不是 Test 成绩。
- **模型范围：** 每项 ICL 任务分别训练；总表的一行不是一个统一九任务模型。不同模型保留各自的架构、目标和优化器，跨模型差异不能唯一归因到架构。
- **测量范围：** 新分数包含共同预测偏差，但仍在各检查点自身表示中归一化。历史对照检验上下文收益，物理读出检验选定坐标，并单独检查其可见性；两者不能消除编码器几何差异及读出器对分布外预测的误差。历史收益为正也不表示完整预测已准确，详见 §4.5、§5.7。
- **决策范围：** 此前独立的决策与观测替换诊断覆盖 134 个场景与 70 个检查点×任务单元，使用固定候选和物理代价；部分目标、候选和时域尚不具备足够的决策区分度。Speed 闭环实验仅覆盖六个场景，其他任务和完整场景集的闭环收益尚未确定。原环境 CEM 仅衡量能力保持。
- **归因范围：** 冻结 Encoder 固定该模块的参数与训练态缓冲区，但未必固定所有可训练的表示变换；扩量可能改变覆盖和优化步数。要分离这些作用，需进一步控制实验。

## 10. 比较与版本管理

新结果应引用明确的数据版本、训练方案和评测划分。相同任务定义与评分协议下可以比较新模型或训练方法；改变查询分布、任务定义或评分规则时，应记录新的 benchmark 版本。冻结 v3 的数值保存在[冻结参考附录](reference/Benchmark_Result_Provenance.md)，不以新实验覆盖历史结果。

## 11. 开放研究问题

**怎样进一步验证跨表示的预测准确性？** 先保证被评分的物理后果能由观测识别，明确离屏状态的处理；再在独立校准与评测数据上检验物理读出，并检查预测是否落在其有效范围内。没有可靠读出时，应保留 native latent 预测分及其解释范围，不能强行给出统一物理排名。历史的充分性也需要独立辨识证据，不能由像素存在差异或某个模型得分高替代。

**怎样减小递推误差？** 已有对照表明，部分任务补入真实历史后误差显著减小。下一步应在这些任务上检验多步训练或信息保持方式，同时区分状态误差修正与动力学证据刷新；真实观测替换本身不能作为可部署的方法。

**已有改善能否泛化到其他分布？** 九任务主分布已覆盖注册 Development 查询。仍需分别扩展速度已见分布与两类外推；之后固定方法，再评测独立 Test。扩展查询时保留同一公式与等权规则，不以成绩选择场景。

**哪些因素限制学习与决策？** 先用现有检查点检查动作覆盖、历史证据与预测误差，再按观察到的瓶颈决定是否调整模型容量、历史长度或训练方式。CEM 用于验证预测改善的应用价值，不能替代预测本身的测量。
