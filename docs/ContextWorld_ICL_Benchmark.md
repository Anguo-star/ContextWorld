# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 评测 latent 世界模型能否从最近几步交互中识别隐藏的环境动力学，并据此
预测下一状态。模型只通过上下文适应：评分过程不更新任何模型参数，也不向模型提供速度、
动作延迟、物体质量、接触属性或空间转移规则等模拟器隐藏变量。

评测直接在参评模型自己的 latent 空间中进行，不要求图像解码器或像素重建。因此，
JEPA、LeWM、PLDM、PreJEPA 以及其他 latent 世界模型可以使用同一套数据与评分协议。

数据如何生成——连续仿真、配对构造、划分隔离以及九项任务的生成入口——见
[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
而不是按环境数量组织；九项任务分别计分，不计算跨任务平均分或统一总分。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不构成分数权重。

## 2. 数据与划分

`ContextWorld-v1` 是统一的数据分发包，包含九项任务的 Training、Development 和 Test 数据、
任务注册表、组件说明及文件完整性清单。该数据包已在本地完成组装，但尚未公布稳定的
公共下载版本。

每项任务使用三种互不重叠的数据划分：

- **Training**：用于训练或适配模型；
- **Development**：用于实现检查、训练配方选择和消融实验；
- **Test**：公开的离线最终报告划分；不参与配方或检查点选择。

选择在 Development 上完成，结论在 Test 上报告。参考方法在读取任何 Test 分数之前
固定检查点步数：Development 只用于选择训练配方，不用于挑选检查点，Public Test 既不
参与配方选择也不参与检查点选择。Development 结果必须明确标注划分，不能作为
Test 成绩报告。公开 Test 提高了可复现性，但由于当前没有托管提交服务，协议依赖作者遵守
“Development-only selection, Test-only final reporting”的信息边界。

Development 的公开抽取由每个组件的 `task_registry.json` 固定，不是统一采样：门通行
规则与动作延迟各 300 个 query，速度按四条 track 的参考速度族抽取，其余六项各 256 对。
原任务 CEM 的“6 × 50”是另一套预算（见 4.3），不要与 Development 的抽样数混用。

| 任务 | Training | Development | Public Test | 主要变化范围 |
|---|---:|---:|---:|---|
| 速度 | 32 档速度 | 每个参考速度 300 个查询 | 每个参考速度 300 个查询 | 训练内插值与范围外速度 |
| 推手移动幅度 | 2,048 对 | 256 对 | 256 对 | 移动幅度 60 / 140 |
| 机械臂质量 | 2,048 对 | 256 对 | 256 对 | 密度 500 / 1500 |
| 动作延迟 | 延迟 0–10 | 300 个查询 × 11 种延迟 | 300 个查询 × 11 种延迟 | 0、1、2、3、4、5–10 六个响应组 |
| 接触摩擦 | 8,192 对 | 256 对 | 256 对 | 摩擦系数 0.05 / 0.80 |
| 运动阻尼 | 8,192 对 | 256 对 | 256 对 | 阻尼 0.2 / 1.0 |
| Cube 夹爪携带规则 | 2,048 对 | 256 对 | 256 对 | 可携带 / 不可携带 |
| 门通行规则 | 96 个门位置 | 16 个 loader-val 门位置、300 个场景 | 42 个未见门位置、300 个场景 | 可通过 / 被阻挡 |
| 传送门出口位置 | 2,048 对 | 256 对 | 256 对 | 靠近边界 / 远离边界的出口 |

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 最近若干帧真实图像；
2. 已经执行的动作序列；
3. 当前图像；
4. 接下来要执行的查询动作；
5. 每种候选隐藏规律对应的模拟器真实未来。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器连续向前执行。`x0` 之后不写入状态、不重建模拟器，也没有仲裁
过程改写中间状态；历史与未来之间没有任何 reset。干净模拟器重放只用于审计，确认不可见
的求解器缓存不改变 `x3`，从不用于生成保存进数据集的画面或目标。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只保留在审计通道，不进入模型输入。

## 4. 评测指标

### 4.1 上下文学习正确率

每个查询产生一个 0/1 结果：模型是否选择了与历史所示隐藏规律一致的真实未来。任务主
分数是查询正确率；部分任务还要求最弱条件、历史使用、历史切换、方向一致性或 bootstrap
置信下界同时达标。

| 任务 | 主分数要求 | 其他必要条件 |
|---|---:|---|
| 速度、门通行规则 | 按预先规定的方向判定 | 每个方向与每个评测种子分别达标 |
| 推手移动幅度、接触摩擦、运动阻尼 | ≥ 95% | 正确历史 ≥ 95%、历史切换 ≥ 95%、最弱条件 ≥ 90% |
| 传送门出口位置 | ≥ 95% | 最弱出口 ≥ 90%，bootstrap 95% 下界 ≥ 90% |
| 动作延迟 | ≥ 75% | 最弱响应组 ≥ 60%，bootstrap 95% 下界 ≥ 70% |
| 机械臂质量、Cube 夹爪携带规则 | ≥ 75% | 正确历史 ≥ 75%、历史切换 ≥ 90%、最弱条件 ≥ 70% |

参考方法通常使用三个独立训练种子。只有三个检查点分别满足该任务的全部条件，方法才
记为 3/3 通过；平均分达到门槛不能替代逐检查点判定。

Development 与 Public Test 共用主指标和门槛内核，使用隔离的数据行。Speed 的主指标是
匹配历史相对其余每一个历史条件的严格胜率；早期 history-utility 数值仅保留为历史诊断。
Development 原始结果不含通过字段；当前版本的独立决策回执按相同阈值核算准入。

### 4.2 评分有效性与防作弊

评测是 decoder-free 的：评分器只调用模型的编码器和 latent 预测器，不调用图像解码器，
真实未来帧已经离线保存，一步预测不需要在线运行模拟器。距离只在同一个检查点自己的
latent 空间内计算，然后转成任务层面的对错。不同模型（以及同一模型的不同检查点）的
原始 latent MSE 没有共同单位，不能直接比较或排名。

正确率之外，评分程序还检查：

- 两种真实未来在该检查点的 latent 中确实可分；
- 改变历史会改变模型预测（历史切换）；
- 预测响应的方向与真实未来一致；
- 最弱隐藏条件和各个方向分别达标；
- 对要求 latent 响应门的组件，预测响应经同一检查点的真实目标响应归一化后达标：
  响应增益 ≥ 0.50，归一化响应误差
  严格小于“完全不使用历史”的基线值 1.00。

归一化响应检查用于排除“模型几乎不使用历史，只因距离的微小差异碰巧选中目标”的假阳性。
它是内部有效性门，不作为公开主分数，也不用于跨模型排名。

### 4.3 原任务规划能力

ICL 正确率回答“模型是否学会隐藏规律”，CEM 回答“模型原有的规划能力是否保持”。两项
结果分别报告，不合成一个分数。

标准 CEM 预算为六个评测种子（42–47），每个种子 50 次规划，共 300 次。评测种子改变
起点、方向和环境结构，不是对同一个查询重复加噪声。部分较早完成的 Reacher 与 Cube
结果使用三个评测种子、每个种子 100 次，总预算同样是 300 次，表中已分别标注。训练后
检查点与其对应的原始检查点在相同查询上比较，并使用任务预先规定的最大允许下降；速度
PLDM 使用配对非劣性判定而不是固定下降额度。

| 参数 | 值 |
|---|---:|
| candidates | 300 |
| iterations | 30 |
| top-k | 30 |
| history | 3 |
| action block | 5 |
| goal offset | 25 |
| episode budget | 50 |

### 4.4 结果比较

同一任务内的模型使用相同查询，可以直接比较正确率。若要声称一个方法优于另一个方法，
应对相同查询进行配对 bootstrap，并报告正确率差的 95% 置信区间。不同任务的分数不求
平均，不用于生成单一排行榜总分。

## 5. 参考结果

ContextWorld 的参考结果分两部分维护：§5.1 是**当前标准参考**——同一训练配方、
同一评测划分、可直接互相比较的结果，是新方法和后续研究应该对齐的起点；§5.2 是
历史参考，来自不同训练方法或协议的结果归档在独立文档，不与当前参考并列。§5.3
说明当前参考的已知边界。ICL 衡量模型能否从短历史中识别当前规律；CEM 检查
规划能力是否保留；两项指标互补，不合成为单一总分。出现在参考结果表或记分板中并不代表
通过该组件的门槛；每行通过与否只看“判定”列。

训练后原任务 CEM**。完整逐训练

**读表前必须明确的四件事：**

1. **ICL 起点与训练后分数均为三训练种子。** 基线侧是只用原环境数据
   训练的检查点（4 环境 × 2 家族 × 3 种子），训练后侧是加入 ContextWorld 组件数据训练的
   检查点（3 模型 × 9 组件 × 3 种子）。两侧的 Development 都读 `ContextWorld-v1`
   （rc1），Public Test 都读 `ContextWorld-v1-full`（rc2）；同一任务、同一划分上的训练前后

   数据身份见本节下方的溯源表。
2. **每项任务的主分数字段不同，不能跨任务比较绝对值。** 速度两侧都是训练

3. **DINO-WM 没有基线 ICL 列。** 其原始检查点的 predictor 需要 `observation`/`proprio`

   DINO-WM 的基线原任务 CEM 完整，与其组件结果同属补充证据；本轮固定其数值与来源，
   不改变原工件的 `official_frozen_matrix: false` 身份。
4. **通过判定见「ICL 门槛结果」列。** 主分数、最弱条件、历史使用、上下文切换、latent

   主分数很高，但 latent 响应增益低于 0.50；推手移动幅度则主分数本身未达 0.95。

**本表默认报告 Public Test；Development 单元逐格标注。** Development 用于配方选择、
实现检查和准入，逐单元数值见[结果复现附录](reference/Benchmark_Result_Provenance.md)。
两个划分共用评分结构与阈值，依靠不同的数据行保持隔离；相同评分合同本身不构成数据泄漏。

数值为百分比，`±` 后为三个训练种子间的样本标准差。训练前是只用原环境数据训练的检查点，
训练后是加入 ContextWorld 组件数据训练的检查点，两者均为三训练种子。随机基线列给出该任务
完全不使用历史时的期望水平，是判断“是否真的学到”的下界参照。带 † 的 CEM 单元是 DINO-WM
的补充证据，已纳入当前研究参考的来源绑定，但未升级为原正式 scoreboard 成绩。

**「ICL 门槛结果」列是本表的结论列，主分数不是。** 主分数只回答“能否选对真实未来”，
不能排除模型靠与历史无关的静态线索取巧，因此每个检查点还要过该组件冻结发布里的全部
反捷径门槛（最弱条件正确率、正确历史使用率、上下文/规律切换率、latent 响应增益、
归一化响应误差，以及具备该项的组件的 paired bootstrap 95% 下界）。本列写“3/3 通过”
只在三个训练种子**全部**过齐全部门槛时成立；否则写“未通过（n/3）”。阈值逐组件不同，
以各自 `configs/benchmark/*_icl_release_v1.yaml` 及追加的
`contextworld_test_gate_completion_v1.yaml` 为准。当前版本的统一决策合取原门槛和追加门槛，
历史字段保留原义，本表不折减阈值。

高主分数被门槛否决的情形是本表要暴露的重点，不是异常：

- **传送门出口位置 / DINO-WM 主分数 99.35% 但 0/3。** 唯一失败项是 latent 响应增益
  0.355 / 0.410 / 0.372，低于 0.50 的下限——预测确实优于“完全不使用历史”的锚点
  （归一化响应误差 0.52–0.57 < 1.00），但响应幅度只有真实响应的约四成，不足以判定
  该能力已经学到。
- **推手移动幅度 / DINO-WM 主分数 93.82% 但 0/3。** 该组件冻结阈值要求主分数 ≥ 0.95，
  三个种子分别为 0.945 / 0.930 / 0.939，是主分数本身未达线，与捷径无关。
- **速度 / LeWM 与 PLDM 主分数 98.19% 与 96.78% 但均为 0/3。** 主分数按已发布口径取
  `unseen_interpolation` 一条 track，而门槛要求四条 track 全部达标；两者在
  `seen_for_multi` 与 `unseen_interpolation` 上六项全过，在两条外推 track 上正确历史

#### 5.1.2 证据等级与已知不对称

- **基线侧与训练后侧现在是同口径三训练种子。** 基线检查点共 24 枚（4 环境 × 2 家族 ×
  3 种子）保存在 `data/world_model/quentinll/lewm-{tworooms,pusht,reacher,cube}/ckpt/`，
  命名为 `{env}_lewm_20260430` / `{env}_lewm_baseline_seed307{3,4}` 与
  `{env}_pldm_baseline` / `{env}_pldm_baseline_seed307{3,4}`，均为 10 epoch、纯原环境
  h5 数据训练（配置中无 `contextworld://` 合成数据 URI）。每枚按其所属环境评测该环境的
  组件，Development 与 Public Test 各 54 个单元。§3 的原始环境 CEM 三种子结果同样来自
  这 24 枚。
- **DINO-WM 没有基线 ICL。** 其原始检查点的 predictor 需要 `observation`/`proprio`
  状态输入，在只给 RGB 与动作的评分接口下记为 `not_compatible`，因此表中基线两列为“—”。
  DINO-WM 的基线原任务 CEM 是完整的三训练种子 × 300 次，可以对照；当前参考固定其
  数值与来源，同时保留其补充证据身份。
- **动作延迟的基线是跨历史长度读数。** 基线检查点是 History=3，该任务要求 History=7，
  基线两列使用 `h3_tail_projection`（只把对齐的最后三帧与最后五个动作块交给模型，不插值
  位置编码、不训练、不改权重）。因此 16.67% → 97.68% 的差值里同时含有“学会延迟规律”与
  “H3→H7 结构变化”两件事，不是严格配对的训练增益。16.67% 是所测检查点的实测零样本
  结果，不能据此推出 H3 架构的理论上限。其余八个组件的任务历史长度都是 3，基线原生匹配。
- **CEM 两列的差不是非劣性判定。** 表中只并列训练前后的成功率，读者自行对读；正式非
  劣性判定与逐组件预注册的允许下降额度见 §4.3 与结果复现附录 §4.2。CEM 均为每枚检查点
  300 次；基线 Reacher 与 Cube 那批使用三个评测种子 × 100 次，其余使用六个评测种子 ×
  50 次，总预算相同但抽样结构不同。
- **本表的总判定逐检查点计算。** 门槛包括最弱条件、历史使用、上下文或规律切换、latent

#### 5.1.4 动作延迟：为什么以六组口径为准

动作延迟有两套评分口径，**随机基线不同，因此数值不可互换**：

| | 二元诊断（自动管线的次要参考值，§6.2.1） | 正式口径（§4.1，Public Test） |
|---|---|---|
| 指标字段 | `delay_0_correct_future_rate` / `delayed_correct_future_rate` | `physical_group_macro_accuracy` |
| 分类方式 | delay=0 vs delay≠0，二元 | 0 / 1 / 2 / 3 / 4 / 5–10 六个物理响应组宏平均 |
| 随机基线 | **50%** | **16.67%** |
| 附加门槛 | 无 | 最弱组 ≥60%、bootstrap 95% 下界 ≥70% |
| 本批数值 | LeWM 99.78%、PLDM 100.00% | LeWM 97.75%、PLDM 100.00% |

**以六组正式口径为准**，理由有三：

1. 二元诊断的随机基线是 50%，一个只会区分“动/不动”的模型即可达到，无法支撑“识别出
   延迟了几步”的结论；六组口径的随机基线 16.67% 与原始基线实测值（16.67%，最弱响应
   组 0%）一致，基线到训练后的链条同口径。
2. 只有六组口径带最弱组与 bootstrap 下界，能挡住把整体高分建立在个别响应组上的假阳性。
3. 历史值 32.43%（LeWM，0/3）与 93.36%（PLDM，3/3）本来就是六组口径的结果，与本批的
   97.75% / 100.00% 同 benchmark id、同 `aggregation`（"equal physical-group mean
   within query, then query mean"）、同冻结资产集，可以直接比较。

LeWM 从 32.43%（历史参考）到 97.75%（本批）的变化**不是口径变更，也不是批次
随机性**：两次的训练身份完全不同——

| | 32.43% 那次 | 97.75% 本批 |
|---|---|---|
| run 标签 | `h7_action_delay_curriculum_v4_lewm_formal_*` | `action_delay_lewm_joint_scratch_v1_*` |
| 权重 | `weights_final_step_1024.pt`（仅 1024 步） | `weights_epoch_10.pt` |
| 训练种子 | 3072 / 4096 / 5120 | 3072 / 3073 / 3074 |
| adapter | `stable_worldmodel_lewm_history7_v1` | 同左（一致） |

评分侧三项一致（同 adapter、同六组聚合、同冻结资产 catalog `5a3fc1a5…`），
差异全部来自训练配方与训练量。PLDM 侧同理（93.36% 那次也是 `curriculum_v4` @1024 步）。
逐枚回执见
`artifacts/evaluation/history7/action_delay_validation_v1/score_receipts/model_results/`。

### 5.3 当前参考的已知边界

- **门通行规则在训练后模型的顶端已无区分度，这是余量限制而不是数据缺陷。** 三个训练后
  模型在 Development 与 **Public Test 两侧**的主分数都落在 99.83–100.00%，基线则是
  50.00%。因此该组件仍能决定性地回答"学到 / 没学到"，但无法在已经学到的候选之间排序。
  **不为此重新合成 Development 数据**：Public Test 已冻结且同样饱和，而 Development 必须
  与 Public Test 结构与难度对等、只在数据行上不重叠；把 Development 造得更难会让它去测
  Public Test 不测的东西，正是本轮消除的"两套口径"。要提高门通行的难度，只能同时改两侧、
  发布新的 Public Test 版本。
  在此之前，门通行的候选排序应读门槛输入而不是主分数——它们仍有区分力：三个满分模型的
  latent 响应增益分别是 LeWM 0.942、PLDM 1.045、DINO-WM 0.758，归一化响应误差
  0.045 / 0.021 / 0.223，即 DINO-WM 的响应幅度只有真实响应的约四分之三，这一点主分数
  看不出来。
- **训练代码在家族内统一；残留的版本差异在评测 checkout 上。** LeWM 与 PLDM 各自
  27 个训练单元共用一份 `stablewm_source` 源码快照，因此家族内跨任务比较不含训练代码
  差异（见 §5.1.2）。各次评测 pin 的 `stablewm_ref` checkout 则有 4 个版本、与组件成块
  对应；评分是 decoder-free 的，但要完全排除这一项，应在同一 checkout 下统一重打分。
- **旧批与本批的落差对应训练配方的四条差异轴，不是未定位的批次漂移。** 旧配方与
  `joint_scratch_v1` 在执行模型上有四处系统性不同（配方、训练量与训练种子的逐行登记
  见历史归档 §1、§2），按对分数差异的解释力排序：
  1. **配对关系是否进入训练目标**：旧的 `*_paired_future_fit/matching/ranking` 与
     `dynamics_response` 配方在损失边界显式使用 `pair_indices`；`native` 不渲染任何配对项，
     采样器也不保对，同一 query 的两条臂在 batch 里相遇纯属偶然。
  2. **初始化**：旧配方全部从上游原环境 checkpoint 微调（部分还冻结 encoder+projector），
     本批 `task_checkpoint_initialization: none`，从零训练。
  3. **预测协议**：旧 H3 族每个 clip 监督 3 个转移（`num_preds=3`），本批 `num_preds=1`
     只监督最后一个转移。
  4. **数据几何**：旧配方是“同 query 两臂相邻”的 4 帧配对 clip（2048/8192 对），本批把
     合成数据摊平成 episode 表、按步长 1 滑窗切稠密 clip 后全局 shuffle。
  这四条同时变化，因此**不能把落差归因于任何单一因素**，更不能归因于随机种子。
- **配对关系一条有同批受控证据，但它不是全部答案。** 在其余条件相同、仅加回配对关系项与
  保对采样器的 `coja_v1` 运行下，接触摩擦的响应增益由 0.0002 回到 0.907、传送门由 0.038
  回到 0.516——这是配对假设的直接因果证据。但两处反例说明它不充分：运动阻尼加回配对后
  增益仍只有 0.044（旧配方还额外依赖孪生组抵消 `x0` 捷径、冻结编码器与排序损失）；而
  PLDM 的旧配方（`mixed_pldm_joint` 等）**从未使用配对损失**却也部分学会，其差异轴是
  “微调初始化 + `num_preds=3` + 全转移监督”。
  *证据状态提示：上述 `coja_v1` 数值来自一条仍在进行中的云侧批量训练（单模型族、单训练
  种子 3072、部分组件未完成），尚未冻结登记，只能作为机制性线索，不能作为方法级结论。*
- **因此不应把本批的随机水平结果当作“该任务不可学”。**
  推手移动幅度 LeWM 由旧批次的 96.61%（Public Test，3/3）变为本批的 50.00%
  （Development），传送门出口位置 LeWM 由 83.92% 变为 50.91%。两者本批的响应增益分别
  为 0.01% 与 3.8%，归一化响应误差贴住“完全不使用历史”的锚点值 1.00；两个独立模型家族
  在同一组组件上同时落到该锚点、又在门通行规则上同时拿到 100%。
  **但这两行的旧批次身份尚未逐条核实**：冻结汇总记录未标注其训练配方与训练种子，
  而已核实的同类行（动作延迟用 `curriculum_v4` @1024 步、种子 3072/4096/5120；
  速度 PLDM 用种子 3072/4096/5120；推手 PLDM 用种子 13313/13314/13315）都不是本批的
  `joint_scratch_v1` / 种子 3072-3074。在这两行的旧批次身份核实之前，
  既不能断言这是“同配方下的塌陷”，也不能据此推断历史条件化通道失效。
- **种子间方差很小，批次间落差不能归因于随机性。** 同一批次内三个训练种子的 ICL 主
  分数样本标准差普遍 ≤2.8pp；而 §5.2 历史参考与本节当前参考之间的落差普遍是
  30–70pp 的量级，量级差远超种子噪声。
- **一个历史结果更强，不代表当前参考的方法已被淘汰。** 例如 Cube LeWM 在 `v4r1`
  协议下曾稳定通过（见 §5.2），当前 `native` 配方未能重现——这本身是当前参考的一项
  限制，而不是 `v4r1` 证据失效。新方法与后续研究请参见第 10 节的比较规则。

### 5.4 外部模型验证状态

LeWM、PLDM 和 DINO-WM（StableWM PreJEPA 实现）是仓库提供的参考集成，不限制其他模型
参与。当前参考覆盖三个模型、九项组件、三个训练种子；已有 Development 和历史 Public Test
结果均在 v3 中保留，当前门槛结论见 §5.1。历史 Test 结果存在不等于满足当前 Development

## 6. 任务说明

每张任务卡使用相同的五部分结构，便于读者横向比较任务目标、数据、指标、参考结果与
结论范围。

### 6.1 即时连续响应

#### 6.1.1 速度

##### 任务目标

模型根据近期移动判断当前速度，并预测同一动作对应的下一状态。

##### 数据构成

Training 覆盖 32 档速度。评测分别包含训练中出现的速度、训练范围内未见速度，以及低于
和高于训练范围的速度；每个参考速度使用六个评测种子 × 50 个查询。

##### 评测方法

主指标是训练范围内未见速度的一步严格正确率：与真实速度一致的历史必须同时优于另外
两档历史。Development 使用同一指标，门槛判定写入独立回执。若要把提升归因于
多速度训练，还需要同训练种子的单速度对照。

##### 基线表现

原始 LeWM 和 PLDM 分别为 59.33% 和 51.44%（单检查点，Public Test）。

当前参考的完整三种子数值与总判定统一见 §5.1。LeWM 与 PLDM 的内插主分数分别为
98.19% 和 96.78%，但四条 track 的全部门槛合取后均为 0/3；这保留了内插能力与外推
能力的区别。本批训练后原任务 CEM 为 LeWM 97.44% ± 0.19pp、PLDM 96.89% ± 0.19pp。

旧批次的对应数值（LeWM 平均 95.26%；PLDM 97.22%/96.44%/96.44%，平均 96.70%，训练
种子 3072/4096/5120）见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)；两批 PLDM 的均值
恰好都是 96.70%，但逐检查点数值与训练种子都不同，不是同一组结果。
旧批次 PLDM 原任务 CEM 平均 94.78%，按配对非劣性判定全部保持；另一个 action-planning
分析平均 69.56%，后者是描述性支撑指标，没有预设性能门槛，也不用于保持判定。

##### 适用范围

结果支持 History=3 下的训练内插值，不代表任意速度外推。PLDM 缺少同训练种子的单速度
对照，因此不能把观察到的变化归因于多速度数据本身。

#### 6.1.2 推手移动幅度

##### 任务目标

模型判断相同二维动作会让 PushT 推手移动较短还是较远。两档参数为 60 和 140。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。配对查询共享当前
状态、画面和动作。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查模型是否使用正确历史、是否随历史切换预测，
以及最弱幅度条件是否达标。通过门槛为每个检查点至少 95%。

##### 基线表现

原始 LeWM 和 PLDM 分别为 49.80% 和 43.55%。当前标准参考（§5.1）下，LeWM 与 PLDM 的
主分数均处于随机水平（LeWM 50.00% ± 0.00pp，PLDM 50.07% ± 0.12pp），正确历史与最弱
幅度条件同样处于随机水平，均 0/3 通过；三个训练种子彼此高度一致（标准差 ≤0.12pp），
说明这不是种子随机性。另一批次的检查点曾通过该任务（见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)），当前标准配方
尚未重现这一结果，见 §5.3。

##### 适用范围

任务验证二值动作响应，不验证连续幅度估计或范围外外推。

#### 6.1.3 机械臂质量

##### 任务目标

模型根据相同力矩下的近期运动判断 Reacher 机械臂较轻还是较重。两档密度为 500 和
1500。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。任务改变主体连杆
和末端球的质量，保持第二连杆不变。

##### 评测方法

主指标是真实下一状态选择正确率，并检查历史切换、最弱质量条件、bootstrap 置信下界和
latent 响应。三个训练种子必须分别达到 75%。

##### 基线表现

原始 LeWM 和 PLDM 分别为 50.00% 和 52.93%。当前标准参考（§5.1）下，LeWM 主分数
85.35% ± 0.51pp，3/3 通过，训练后 CEM 均值 58.55% ± 0.69pp，高于原始基线 55.89%，
保持原 Reacher 规划能力；PLDM 主分数 52.61% ± 2.05pp，接近随机，0/3 通过，训练后
CEM（非正式）均值 44.00% ± 5.36pp，明显低于原始基线 69.67%。三个训练种子彼此接近
（标准差 ≤2.05pp），LeWM/PLDM 的差距不是种子随机性。

##### 适用范围

任务验证两档质量的一步适应，不验证连续质量估计、范围外外推或多步闭环控制。

### 6.2 时间延迟动力学

#### 6.2.1 动作延迟

##### 任务目标

模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

##### 数据构成

延迟范围为 0–10。Training 先覆盖差异明显的 0、4、8，再覆盖完整范围；Public Test 包含
300 个查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

动作延迟有两个不同强度的评测问题，回答的研究问题不同，不能互相替代：

- **完整延迟识别（原定义）**：延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，
  各组在每个查询内等权宏平均。总体正确率须至少 75%，最弱组至少 60%，bootstrap 95%
  下界至少 70%。这是判断“模型能否识别每一种延迟对应的具体物理响应”的标准。
- **二元历史响应诊断**：只判断预测在 delay=0 与 delay≠0（合并为一类）之间是否随历史
  正确切换，不要求区分不同的非零延迟。这是判断“历史是否引起了正确方向的条件差异”
  的更弱标准，主要用于快速诊断。

##### 基线表现

原始 History=3 LeWM 和 PLDM 在末尾三帧投影下均为 16.67%（完整延迟识别口径）。

*完整延迟识别（原定义，§5.1 报告的正式数值）：* 专用评分器
`contextworld.benchmarks.action_delay_icl_cli` 对本批全部 6 枚检查点按正式六组口径
评分（2026-09-07，冻结的 300 查询 Public Test 资产、6 个评测种子 × 50 查询、6 个
物理响应组、`online_environment_calls: 0`）：

| 模型 | 逐种子主分数（六组宏平均） | 均值 | 最弱组 | bootstrap 95% 下界 | 判定 |
|---|---|---:|---|---|---|
| LeWM | 97.23% / 98.31% / 97.71% | 97.75% ± 0.54pp | 95.22%–96.94% | 96.24%–97.52% | 3/3 通过 |
| PLDM | 100.00% / 100.00% / 100.00% | 100.00% ± 0.00pp | 100.00% | 100.00% | 3/3 通过 |

三项门槛（主分数 ≥75%、最弱组 ≥60%、bootstrap 下界 ≥70%）逐检查点全部满足。与另一
批检查点的同口径结果相比（PLDM 93.36% 通过；LeWM 32.43%，最弱组 0%，未通过，见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)），LeWM 从未通过
转为通过。两次比较是同口径的：同一 benchmark id
（`contextworld_tworoom_action_delay_icl_history7_v1`）、同一 `aggregation`（"equal
physical-group mean within query, then query mean"）、同一冻结资产集与同一 adapter 类；
历史回执中记录的 `uses_frozen_public_test: true`、六组逐组准确率（0%/13%/95.33%/84%/
5.67%/0%，宏平均 33.00%）也与其登记数值一致。

*二元历史响应诊断（次要参考）：* 二元口径的 Development 分数为 LeWM
99.78% ± 0.25pp、PLDM 100.00% ± 0.00pp。它只验证“有无延迟”的区分，信息量弱于上表
的完整识别结果，保留在此仅供交叉参照，不作为主分数。

训练后 CEM 略低于原始基线（LeWM 均值 87.33% ± 2.33pp 对比 92.44%；PLDM 均值
90.89% ± 0.19pp 对比 90.56%，基本持平）。

##### 适用范围

正式结果验证 History=7 下六个一步物理响应组（0、1、2、3、4、5–10）分别达标。
一步未来无法区分 5–10，因此不表示精确识别全部 11 档延迟；h2/h3 是辅助诊断，
不属于当前通过条件。也不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。二元诊断数值只说明
“有无延迟”的区分，不能单独支撑延迟识别结论。

### 6.3 接触或附着条件动力学

#### 6.3.1 接触摩擦

##### 任务目标

模型根据推手与物体接触时的响应判断摩擦较小还是较大。两档摩擦系数为 0.05 和 0.80。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对查询的当前
完整物理状态误差不超过 `1e-5`，历史接触结束后至少连续三步无接触，不同划分不共享查询
或生成模板。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱摩擦条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，正式比较使用
Development；已有历史 Public Test 结果保留来源，但排除正式报告。

##### 基线表现

原始 LeWM 和 PLDM 的 Development 起点为 49.61% 和 50.00%。当前标准参考（§5.1）下，
LeWM 与 PLDM 三个检查点主分数均在随机水平（LeWM 均值 50.07% ± 0.12pp，PLDM 均值
50.13% ± 0.30pp），正确历史（50.6%–53.7%）、上下文切换、最弱摩擦条件全部远低于
95%/90% 门槛，0/3 通过；训练后 CEM（非正式）均值 LeWM 76.11% ± 2.01pp、PLDM
66.56% ± 3.27pp，均低于原始基线。LeWM 曾用 `mixed_frozen_image_paired_future_matching_1p00` 配方
（8192 步，单训练种子 13313）达到 96.09%（但正确历史门未过），见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)；当前标准配方
在三个种子上均未提供达到完整门槛的能力证据，落差不是种子随机性（见 §5.3）。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会接触摩擦。

#### 6.3.2 运动阻尼

##### 任务目标

模型根据接触结束后的运动判断物体减速较快还是较慢。两档阻尼为 0.2 和 1.0。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对样本交换起点，
使仅凭起点预测标签的准确率为 50%。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱阻尼条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，正式比较使用
Development；已有历史 Public Test 结果保留来源，但排除正式报告。

##### 基线表现

原始 LeWM 和 PLDM 的 Development 起点为 50.00% 和 50.39%。当前标准参考（§5.1）下，
LeWM 与 PLDM 三个检查点主分数均在随机水平（LeWM 均值 50.07% ± 0.12pp，PLDM 均值
51.89% ± 2.11pp），最弱阻尼条件仅 26.2%–30.5%，远低于 90% 门槛，0/3 通过；训练后
CEM（非正式）均值 LeWM 79.33% ± 4.04pp（接近原始基线 82.22%）、PLDM 61.56% ±
0.96pp（明显低于原始基线 75.67%）。LeWM 曾用 `mixed_frozen_image_paired_future_ranking_twin_1p00` 配方
（8192 步，单训练种子 14321）达到 97.46%（但正确历史只有 52.93%，接近随机），见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)；当前标准配方
在三个种子上均未提供达到完整门槛的能力证据，与接触摩擦同属一类差距。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会运动阻尼。

#### 6.3.3 Cube 夹爪携带规则

##### 任务目标

模型根据夹爪与方块的近期响应判断闭合夹爪能否携带方块，并预测共享查询动作对应的真实
下一状态。

##### 数据构成

Training 包含 2,048 对，Development 和 Public Test 各包含 256 对。四类动作模板在每个划分中严格均衡；源轨迹、动作模板、场景、配对内容和 query 画面互不重叠。

##### 评测方法

每个检查点的真实未来正确率至少为 75%，正确历史至少 75%，上下文切换至少 90%，最弱
规则至少 70%。通过 Development 的模型还需完成 300 次原 Cube CEM，成功数相对原始检查点
最多减少 15 次。外部模型使用独立结果身份，不会覆盖仓库提供的参考结果。

##### 基线表现

原始 LeWM 和 PLDM 均为 50.98%。当前标准参考（§5.1）下，LeWM 与 PLDM 三个检查点
主分数均在随机水平（LeWM 均值 49.93% ± 0.12pp，PLDM 均值 50.00% ± 0.00pp），正确
历史、上下文切换、最弱规则条件全部远低于 75%/90%/70% 门槛，0/3 通过；训练后 CEM
（非正式）均值 LeWM 60.89% ± 0.70pp（低于原始基线 65.44%）、PLDM 57.00% ± 3.18pp
（与原始基线 53.44% 大致持平）。LeWM 曾在专门的 `v4r1` 协议（`docs/protocols/
Cube_Gripper_Carry_History3_v4r1_*`）下稳定通过：三个检查点的 Public Test 主分数分别为
77.73%、79.10% 和 78.52%（3/3 通过），对应的原任务 CEM 成功数为 186、183、185/300，
见 [历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)；当前
标准配方尚未重现这一结果——这是当前配方的一项已知限制，不代表 `v4r1` 证据失效
（见 §5.3）。

##### 适用范围

结果验证二值携带规则的一步 ICL 和原 Cube 规划能力保持，不验证连续夹持强度或多步闭环
适应。公开分发仍须补齐许可证和稳定下载地址。

### 6.4 隐藏结构转移规则

#### 6.4.1 门通行规则

##### 任务目标

模型根据历史中的穿门或碰壁结果判断外观相同的门能否通过。

##### 数据构成

Training 覆盖 96 个门位置，Development 覆盖 16 个门位置，Public Test 使用 42 个训练中
未见的门位置并包含 300 个场景。

##### 评测方法

每个查询保存“可通过”和“被阻挡”两种模拟器真实未来。评分分别检查两个穿门方向、历史
是否改变判断，以及两种未来在 latent 中是否可分；每个评测种子与方向的组合都必须达标，
配对 bootstrap 的 95% 下界必须大于 0。

##### 基线表现

原始 LeWM 和 PLDM 均为 50.00%。当前标准参考（§5.1）下，两个家族 ICL 主分数均为
100.00% ± 0.00pp（3/3 通过），训练后 CEM 均值 LeWM 95.11% ± 3.85pp、PLDM
95.78% ± 1.17pp，均不低于各自原始基线（92.44%、90.56%），保持原 TwoRoom 规划能力。
历史参考批次同样通过 ICL，但训练后 CEM 明显下降、未保持规划能力（见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)）；当前配方的
CEM 结果明显更好。

##### 适用范围

任务验证一步门规则判断，不验证多步闭环穿门规划。

#### 6.4.2 传送门出口位置

##### 任务目标

模型根据历史中的传送结果判断进入同一入口后会从靠近边界还是远离边界的位置出现。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。两种规律在查询前
汇合到相同当前状态，因此当前画面和动作本身不能泄露答案。

##### 评测方法

主指标是真实出口下一状态选择正确率，并检查正确历史、预测切换、最弱出口条件、
bootstrap 置信下界和 latent 响应。三个训练种子必须分别满足完整标准。

##### 基线表现

原始 LeWM 和 PLDM 分别为 50.00% 和 50.20%。当前标准参考（§5.1）下，两个家族仍未满足
完整 ICL 标准（均 0/3）：LeWM 主分数 50.91% ± 0.30pp（接近随机），PLDM 主分数
69.53% ± 2.77pp（仍低于 95% 门槛）。训练后 CEM（非正式）两个家族均保持良好：LeWM
均值 98.66% ± 0.58pp、PLDM 均值 94.44% ± 2.17pp，均高于原始基线（92.44%、90.56%）。
历史参考批次上 LeWM 主分数为 83.92%、PLDM 为 59.31%（见
[历史参考](archive/LeWM_PLDM_Pre_2026-09-03_Reference_Results.md)）；本批 LeWM
明显更接近随机，PLDM 则更接近门槛，方向不一致，属于 §5.3 所述的批次间差异。

##### 适用范围

任务验证二值出口规则的一步适应，不验证连续出口坐标、范围外出口或多步传送规划。

## 7. 接入新的 latent 世界模型

外部模型实现
`contextworld.benchmarks.adapters.LatentWorldModelAdapter` 即可使用统一评分器，不需要为
九项任务分别实现一套接口。Adapter 提供：

- `encode_pixels`：用模型的冻结目标编码器编码真实未来图像；
- `rollout_latents`：根据历史图像、历史动作、当前图像和查询动作预测未来 latent；
- `protocol`：声明历史长度、动作块、动作维度和预测步数；
- `metadata` 与 `frozen_state_hash()`：记录模型身份，并确认评测没有改变模型权重。

评分器只检查历史长度、每个动作块的原始步数、动作维度和预测 horizon。它不限制 latent
维度、网络结构、深度学习框架或训练数据加载方式。

```bash
pip install -e ".[eval]"
export CONTEXTWORLD_BENCHMARK_ROOT=/absolute/path/to/ContextWorld-v1

python -m contextworld.benchmarks.external_model_cli \
  --evaluation-split development \
  --task speed \
  --adapter your_package.module:YourAdapter \
  --checkpoint /path/to/checkpoint \
  --model-name your-model \
  --output /path/to/result.json
```

`CONTEXTWORLD_BENCHMARK_ROOT` 必须是 `ContextWorld-v1` clean export 的绝对路径。
Development 用于方法开发。方法、配方与终点固定后，用 `--evaluation-split test` 运行公开
Test；兼容别名 `public` 等价于 `test`。Test 结果保留冻结任务门，但会明确标为离线最终报告，
不是托管排行榜条目。

完整接口、数组形状和模型加载方式见
[外部模型 Adapter 规范](External_Model_Adapter_Contract.md)。

## 8. 可复现性与结果报告

公开 Training 与 Development 工作流只需要 `ContextWorld-v1`。原始模型训练和 CEM 还需要
相应的原环境数据。

建议每项结果至少报告：

- 模型名称、参数量和检查点标识；
- 训练数据、训练种子和优化预算；
- Adapter 版本与输入协议；
- 评测划分；
- 主分数、附加条件和逐训练种子结果；
- 若模型支持规划，训练前后的原任务 CEM；
- 未运行或不能评分的项目及明确原因。

机器可读的参考结果保存在
`artifacts/evaluation/contextworld_icl_suite_v2_release_addendum_v1/public_scoreboard.json`，
可用 `contextworld-scoreboard --input <public_scoreboard_spec.json>` 从冻结的逐种子记录
重新渲染。训练配方、检查点哈希、逐训练种子结果与逐次评测记录见
[结果复现附录](reference/Benchmark_Result_Provenance.md)。历史实验协议位于
`docs/protocols/`，用于复核结果，不是运行公开数据包的前置要求。

## 9. 适用范围与限制

ContextWorld 的结论仅覆盖本文列出的环境、隐藏规律、历史长度和参数范围。当前结果不能
证明：

- 一个模型能够同时解决全部九项任务；
- 模型能够处理多种隐藏规律同时变化；
- 模型能够外推到任意未见参数；
- 一步预测能力必然转化为所有任务上的闭环规划能力；
- 仓库内参考模型已经代表所有 latent 世界模型架构。

当前 ICL 门槛测量的是固定数据分布内的历史条件响应：目标选择、历史使用、响应方向和
相对幅度。两种预测同时带有共同偏置时，差分响应仍可能通过；因此 ICL 通过不能单独
证明绝对预测误差小，原任务 CEM 也不能代替隐藏规律条件下的闭环规划验证。
门通行历史提供直接的碰撞线索，接近满分支持当前两规则任务，不等于已验证抽象规则迁移。

固定正/负控制用于检验这些门槛能否拒绝无历史、反向历史和微弱响应，并保留正确响应。
它们验证具体辨别机制，不是所有潜在捷径的穷举，也没有给出真实模型总体的假阳性率。

Test 已公开以支持完全离线复现，但仍不应用于模型选择。公开发布还需提供稳定的数据集修订
版本与最终分发元数据；若未来需要抗 Test 过拟合的竞赛，可另设新的私有 challenge split，
不改变本版公开 Test 的角色。

## 10. 后续研究基线与比较规则

本节面向计划在 ContextWorld 上继续研究新方法、或对现有结果做根因分析的读者，说明
应该以什么为起点、如何与当前参考做对比。

**以 §5.1 的冻结快照为当前主参考。** 新方法与根因研究都应从
[`contextworld_joint_scratch_v1_reference_results_freeze_v3.json`](../configs/benchmark/contextworld_joint_scratch_v1_reference_results_freeze_v3.json)
锁定的数据版本、评分协议版本、训练配方版本与检查点/种子清单出发，而不是从 §5.2 的
历史归档出发。历史结果保留、标注方法与训练身份，但不与当前参考混合归因——已有的
历史检查点若训练身份（配方、训练量、训练种子、数据与代码版本）与当前快照一致，
可以直接复用并补齐比较；不一致则仍作为历史证据保留，不强行拼入当前主参考。
（§5.2 归档的十行经逐行核实，**没有任何一行**与当前快照的训练
身份一致。）

**新方法必须使用同配方的 native 结果作为对照，而不是任意历史结果。** 方法效应应
定义为“新方法结果 − 同一快照下 native 结果”，而不是“历史配方下的旧方法结果 −
当前快照的 native 结果”。统一比较要求任务定义、数据边界、预算报告和评测问题一致，
不要求所有模型族使用完全相同的优化器超参数——各模型族的合理原生训练设置应保留并
明确说明。

**根因分析需要同一批检查点与数据的完整证据链。** 从训练输入，到该检查点的表示，到
该训练状态的梯度/更新，到同协议下的 held-out 行为，应尽量在同一个冻结的研究单元内
建立，而不是把旧检查点的中间诊断和新检查点的最终指标拼接作为同一个结论的证据。新的
完整结果应当用于重新选择值得解释的成功和失败单元，而不是为了保留某个历史叙事而固定
哪个任务算“成功”、哪个算“失败”。

**评测问题必须先对齐研究问题，再谈“统一新规则”。** 动作延迟是当前唯一已知存在这类
风险的任务（§6.2.1）：二元历史响应诊断和完整延迟识别是两个不同强度的评测问题，应
明确使用哪一个，而不是默认最新、最高的分数就是最终结论。这个原则同样适用于未来对
评测协议的任何修改——协议可以更新，但更新过程中不能悄悄改变“在测什么能力”。

**不要求在开始新研究前解释清楚所有历史差异。** §5.3 列出的批次间差异（如 4 个
不同的 stable_worldmodel commit、Cube LeWM 在 `v4r1` 下曾经通过而当前配方未能重现）
可以先记为未解释的已知限制。只有当某项历史差异直接关系到新方法的必要性判断，或
提供了一个明显更强的合理基线时，才需要在对应的新方法研究中专门处理。
