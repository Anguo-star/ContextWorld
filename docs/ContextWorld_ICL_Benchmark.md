# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 评测 latent 世界模型能否从最近几步交互中识别隐藏的环境动力学，并据此
预测下一状态。模型只通过上下文适应：评分过程不更新任何模型参数，也不向模型提供速度、
动作延迟、物体质量、接触属性或空间转移规则等模拟器隐藏变量。

评测直接在参评模型自己的 latent 空间中进行，不要求图像解码器或像素重建。因此，
JEPA、LeWM、PLDM、PreJEPA 以及其他 latent 世界模型可以使用同一套数据与评分协议。

数据如何生成——连续仿真、配对构造、划分隔离以及九项任务的生成入口——见
[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
而不是按环境数量组织；九项任务分别计分，不计算跨任务平均分或统一总分。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不构成分数权重。

## 2. 数据与划分

`ContextWorld-v1` 是统一的数据分发包，包含九项任务的 Training、Development 和 Test 数据、
任务注册表、组件说明及文件完整性清单。该数据包已在本地完成组装，但尚未公布稳定的
公共下载版本。

每项任务使用三种互不重叠的数据划分：

- **Training**：用于训练或适配模型；
- **Development**：用于实现检查、训练配方选择和消融实验；
- **Test**：公开的离线最终报告划分；不参与配方或检查点选择。

选择在 Development 上完成，结论在 Test 上报告。参考方法在读取任何 Test 分数之前
固定检查点步数：Development 只用于选择训练配方，不用于挑选检查点，Public Test 既不
参与配方选择也不参与检查点选择。Development 结果必须明确标注划分，不能作为
Test 成绩报告。公开 Test 提高了可复现性，但由于当前没有托管提交服务，协议依赖作者遵守
“Development-only selection, Test-only final reporting”的信息边界。

Development 的公开抽取由每个组件的 `task_registry.json` 固定，不是统一采样：门通行
规则 288 对，动作延迟 300 对，速度 288 个 history-utility case，其余六项各 256 对。
原任务 CEM 的“6 × 50”是另一套预算（见 4.3），不要与 Development 的抽样数混用。

| 任务 | Training | Development | Public Test | 主要变化范围 |
|---|---:|---:|---:|---|
| 速度 | 32 档速度 | 288 个 history-utility case | 每个参考速度 300 个查询 | 训练内插值与范围外速度 |
| 推手移动幅度 | 2,048 对 | 256 对 | 256 对 | 移动幅度 60 / 140 |
| 机械臂质量 | 2,048 对 | 256 对 | 256 对 | 密度 500 / 1500 |
| 动作延迟 | 延迟 0–10 | 300 对 | 300 个查询 × 11 种延迟 | 0、1、2、3、4、5–10 六个响应组 |
| 接触摩擦 | 8,192 对 | 256 对 | 256 对 | 摩擦系数 0.05 / 0.80 |
| 运动阻尼 | 8,192 对 | 256 对 | 256 对 | 阻尼 0.2 / 1.0 |
| Cube 夹爪携带规则 | 2,048 对 | 256 对 | 256 对 | 可携带 / 不可携带 |
| 门通行规则 | 96 个门位置 | 16 个门位置、288 对 | 42 个未见门位置、300 个场景 | 可通过 / 被阻挡 |
| 传送门出口位置 | 2,048 对 | 256 对 | 256 对 | 靠近边界 / 远离边界的出口 |

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 最近若干帧真实图像；
2. 已经执行的动作序列；
3. 当前图像；
4. 接下来要执行的查询动作；
5. 每种候选隐藏规律对应的模拟器真实未来。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器连续向前执行。`x0` 之后不写入状态、不重建模拟器，也没有仲裁
过程改写中间状态；历史与未来之间没有任何 reset。干净模拟器重放只用于审计，确认不可见
的求解器缓存不改变 `x3`，从不用于生成保存进数据集的画面或目标。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只保留在审计通道，不进入模型输入。

## 4. 评测指标

### 4.1 上下文学习正确率

每个查询产生一个 0/1 结果：模型是否选择了与历史所示隐藏规律一致的真实未来。任务主
分数是查询正确率；部分任务还要求最弱条件、历史使用、历史切换、方向一致性或 bootstrap
置信下界同时达标。

| 任务 | 主分数要求 | 其他必要条件 |
|---|---:|---|
| 速度、门通行规则 | 按预先规定的方向判定 | 每个方向与每个评测种子分别达标 |
| 推手移动幅度、接触摩擦、运动阻尼 | ≥ 95% | 正确历史 ≥ 95%、历史切换 ≥ 95%、最弱条件 ≥ 90% |
| 传送门出口位置 | ≥ 95% | 最弱出口 ≥ 90%，bootstrap 95% 下界 ≥ 90% |
| 动作延迟 | ≥ 75% | 最弱响应组 ≥ 60%，bootstrap 95% 下界 ≥ 70% |
| 机械臂质量、Cube 夹爪携带规则 | ≥ 75% | 正确历史 ≥ 75%、历史切换 ≥ 90%、最弱条件 ≥ 70% |

参考方法通常使用三个独立训练种子。只有三个检查点分别满足该任务的全部条件，方法才
记为 3/3 通过；平均分达到门槛不能替代逐检查点判定。

公开 Speed Development 不复用上述匹配指标。它比较完整 H3 历史与 current-frame-only
消融的一步预测误差，报告历史带来的改善（history-utility diagnostic）。这不是匹配反事实
评测，也不产生正式通过判定；速度任务的正式分数来自 Public Test 的严格历史比较。

### 4.2 评分有效性与防作弊

评测是 decoder-free 的：评分器只调用模型的编码器和 latent 预测器，不调用图像解码器，
真实未来帧已经离线保存，一步预测不需要在线运行模拟器。距离只在同一个检查点自己的
latent 空间内计算，然后转成任务层面的对错。不同模型（以及同一模型的不同检查点）的
原始 latent MSE 没有共同单位，不能直接比较或排名。

正确率之外，评分程序还检查：

- 两种真实未来在该检查点的 latent 中确实可分；
- 改变历史会改变模型预测（历史切换）；
- 预测响应的方向与真实未来一致；
- 最弱隐藏条件和各个方向分别达标；
- 对要求 latent 响应门的组件，预测响应经同一检查点的真实目标响应归一化后达标：
  响应增益 ≥ 0.50，归一化响应误差
  严格小于“完全不使用历史”的基线值 1.00。

归一化响应检查用于排除“模型几乎不使用历史，只因距离的微小差异碰巧选中目标”的假阳性。
它是内部有效性门，不作为公开主分数，也不用于跨模型排名。

### 4.3 原任务规划能力

ICL 正确率回答“模型是否学会隐藏规律”，CEM 回答“模型原有的规划能力是否保持”。两项
结果分别报告，不合成一个分数。

标准 CEM 预算为六个评测种子（42–47），每个种子 50 次规划，共 300 次。评测种子改变
起点、方向和环境结构，不是对同一个查询重复加噪声。部分较早完成的 Reacher 与 Cube
结果使用三个评测种子、每个种子 100 次，总预算同样是 300 次，表中已分别标注。训练后
检查点与其对应的原始检查点在相同查询上比较，并使用任务预先规定的最大允许下降；速度
PLDM 使用配对非劣性判定而不是固定下降额度。

| 参数 | 值 |
|---|---:|
| candidates | 300 |
| iterations | 30 |
| top-k | 30 |
| history | 3 |
| action block | 5 |
| goal offset | 25 |
| episode budget | 50 |

### 4.4 结果比较

同一任务内的模型使用相同查询，可以直接比较正确率。若要声称一个方法优于另一个方法，
应对相同查询进行配对 bootstrap，并报告正确率差的 95% 置信区间。不同任务的分数不求
平均，不用于生成单一排行榜总分。

## 6. 任务说明

每张任务卡使用相同的五部分结构，便于读者横向比较任务目标、数据、指标、参考结果与
结论范围。

### 6.1 即时连续响应

#### 6.1.1 速度

##### 任务目标

模型根据近期移动判断当前速度，并预测同一动作对应的下一状态。

##### 数据构成

Training 覆盖 32 档速度。评测分别包含训练中出现的速度、训练范围内未见速度，以及低于
和高于训练范围的速度；每个参考速度使用六个评测种子 × 50 个查询。

##### 评测方法

主指标是训练范围内未见速度的一步严格正确率：与真实速度一致的历史必须同时优于另外
两档历史。公开 Development 是 history-utility 诊断，不产生通过判定。若要把提升归因于
多速度训练，还需要同训练种子的单速度对照。

##### 基线表现

原始 LeWM 和 PLDM 分别为 59.33% 和 51.44%。训练后 LeWM 平均 95.26%；PLDM 三个检查点
为 97.22%、96.44% 和 96.44%，平均 96.70%。两者都通过训练范围内插值，但高、低范围外
结果均未通过。PLDM 原任务 CEM 平均 94.78%，按配对非劣性判定全部保持；另一个
action-planning 分析平均 69.56%，后者是描述性支撑指标，没有预设性能门槛，也不用于
保持判定。

##### 适用范围

结果支持 History=3 下的训练内插值，不代表任意速度外推。PLDM 缺少同训练种子的单速度
对照，因此不能把观察到的变化归因于多速度数据本身。

#### 6.1.2 推手移动幅度

##### 任务目标

模型判断相同二维动作会让 PushT 推手移动较短还是较远。两档参数为 60 和 140。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。配对查询共享当前
状态、画面和动作。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查模型是否使用正确历史、是否随历史切换预测，
以及最弱幅度条件是否达标。通过门槛为每个检查点至少 95%。

##### 基线表现

原始 LeWM 和 PLDM 分别为 49.80% 和 43.55%。训练后 LeWM 平均 96.61%，3/3 通过且保持
原 PushT 规划能力；PLDM 三个检查点为 94.34%、93.95% 和 94.53%，平均 94.27%，均低于
95% 门槛，因此正式流程未授权训练后 CEM。完整对照补跑仍按“全部报告”原则执行了相同
检查点的原任务 CEM，PLDM 平均为 76.22% ± 0.51pp；该补充结果不改变 ICL 未通过的判定。

##### 适用范围

任务验证二值动作响应，不验证连续幅度估计或范围外外推。

#### 6.1.3 机械臂质量

##### 任务目标

模型根据相同力矩下的近期运动判断 Reacher 机械臂较轻还是较重。两档密度为 500 和
1500。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。任务改变主体连杆
和末端球的质量，保持第二连杆不变。

##### 评测方法

主指标是真实下一状态选择正确率，并检查历史切换、最弱质量条件、bootstrap 置信下界和
latent 响应。三个训练种子必须分别达到 75%。

##### 基线表现

原始 LeWM 和 PLDM 分别为 50.00% 和 52.93%。训练后 LeWM 平均 76.11%，3/3 通过并保持
原 Reacher 规划能力；PLDM 平均 63.15%，未通过。完整对照补跑中的 PLDM 原任务 CEM 为
76.33% ± 0.88pp，按该行冻结的同家族非劣性规则未保持；它不改变 ICL 判定。

##### 适用范围

任务验证两档质量的一步适应，不验证连续质量估计、范围外外推或多步闭环控制。

### 6.2 时间延迟动力学

#### 6.2.1 动作延迟

##### 任务目标

模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

##### 数据构成

延迟范围为 0–10。Training 先覆盖差异明显的 0、4、8，再覆盖完整范围；Public Test 包含
300 个查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，各组在每个查询内等权。总体
正确率须至少 75%，最弱组至少 60%，bootstrap 95% 下界至少 70%。

##### 基线表现

原始 History=3 LeWM 和 PLDM 在末尾三帧投影下均为 16.67%。训练后 PLDM 平均 93.36%，
最弱响应组平均 84.83%，bootstrap 下界平均 91.71%，3/3 通过；LeWM 平均 32.43%，最弱
响应组为 0%，同时未通过总体与分组门限。两者的训练后原任务 CEM 均保持。

##### 适用范围

结果验证 History=7 下的一步延迟响应，不验证未见延迟外推、多步自回归或隐藏延迟下的
闭环规划。

### 6.3 接触或附着条件动力学

#### 6.3.1 接触摩擦

##### 任务目标

模型根据推手与物体接触时的响应判断摩擦较小还是较大。两档摩擦系数为 0.05 和 0.80。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对查询的当前
完整物理状态误差不超过 `1e-5`，历史接触结束后至少连续三步无接触，不同划分不共享查询
或生成模板。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱摩擦条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，因此没有读取
Public Test。

##### 基线表现

原始 LeWM 和 PLDM 的 Development 起点为 49.61% 和 50.00%。当前训练后 LeWM 主分数为
96.09%，但正确历史只有 90.23%，未达 95% 的历史使用门；PLDM 为 52.73%，主分数与历史
使用门均未达标。两者均只完成一个训练种子，没有 Public Test 或训练后 CEM 结果。
另有早期 2,048 对配方的三种子 Public Test 与 CEM 对照；它只用于补充模型比较，不能替代
当前 8,192 对配方的结论。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会接触摩擦。

#### 6.3.2 运动阻尼

##### 任务目标

模型根据接触结束后的运动判断物体减速较快还是较慢。两档阻尼为 0.2 和 1.0。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对样本交换起点，
使仅凭起点预测标签的准确率为 50%。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱阻尼条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，因此没有读取
Public Test。

##### 基线表现

原始 LeWM 和 PLDM 的 Development 起点为 50.00% 和 50.39%。当前训练后 LeWM 主分数为
97.46%，但正确历史只有 52.93%，未达 95% 的历史使用门；PLDM 为 51.95%，主分数与历史
使用门均未达标。两者均只完成一个训练种子，没有 Public Test 或训练后 CEM 结果。
另有早期 2,048 对配方的三种子 Public Test 与 CEM 对照；它只用于补充模型比较，不能替代
当前 8,192 对配方的结论。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会运动阻尼。

#### 6.3.3 Cube 夹爪携带规则

##### 任务目标

模型根据夹爪与方块的近期响应判断闭合夹爪能否携带方块，并预测共享查询动作对应的真实
下一状态。

##### 数据构成

Training 包含 2,048 对，Development 和 Public Test 各包含 256 对。四类动作模板在每个划分中严格均衡；源轨迹、动作模板、场景、配对内容和 query 画面互不重叠。

##### 评测方法

每个检查点的真实未来正确率至少为 75%，正确历史至少 75%，上下文切换至少 90%，最弱
规则至少 70%。通过 Development 的模型还需完成 300 次原 Cube CEM，成功数相对原始检查点
最多减少 15 次。外部模型使用独立结果身份，不会覆盖仓库提供的参考结果。

##### 基线表现

原始 LeWM 和 PLDM 均为 50.98%。训练后 LeWM 三个 Public Test 结果为 77.73%、79.10% 和 78.52%，
全部通过；CEM 为 186、183、185/300，相对原始基线 198/300 分别减少 12、15、
13 次，均在允许范围内。PLDM 的 Development 平均值为 50.13%，补充 Public Test 为
50.98% ± 0.20pp，0/3 通过；其补充 CEM 为 55.11% ± 0.77pp，并保持原 Cube 规划能力。

##### 适用范围

结果验证二值携带规则的一步 ICL 和原 Cube 规划能力保持，不验证连续夹持强度或多步闭环
适应。公开分发仍须补齐许可证和稳定下载地址。

### 6.4 隐藏结构转移规则

#### 6.4.1 门通行规则

##### 任务目标

模型根据历史中的穿门或碰壁结果判断外观相同的门能否通过。

##### 数据构成

Training 覆盖 96 个门位置，Development 覆盖 16 个门位置，Public Test 使用 42 个训练中
未见的门位置并包含 300 个场景。

##### 评测方法

每个查询保存“可通过”和“被阻挡”两种模拟器真实未来。评分分别检查两个穿门方向、历史
是否改变判断，以及两种未来在 latent 中是否可分；每个评测种子与方向的组合都必须达标，
配对 bootstrap 的 95% 下界必须大于 0。

##### 基线表现

原始 LeWM 和 PLDM 均为 50.00%。训练后两者分别达到 100.00% 和 99.33%，均通过 ICL；
但训练后 CEM 明显下降，均未保持原 TwoRoom 规划能力。

##### 适用范围

任务验证一步门规则判断，不验证多步闭环穿门规划。

#### 6.4.2 传送门出口位置

##### 任务目标

模型根据历史中的传送结果判断进入同一入口后会从靠近边界还是远离边界的位置出现。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。两种规律在查询前
汇合到相同当前状态，因此当前画面和动作本身不能泄露答案。

##### 评测方法

主指标是真实出口下一状态选择正确率，并检查正确历史、预测切换、最弱出口条件、
bootstrap 置信下界和 latent 响应。三个训练种子必须分别满足完整标准。

##### 基线表现

原始 LeWM 和 PLDM 分别为 50.00% 和 50.20%。训练后 LeWM 平均 83.92%，PLDM 平均
59.31%，均未满足完整 ICL 标准；LeWM 保持原 TwoRoom 规划能力。完整对照补跑中的 PLDM
原任务 CEM 为 95.33% ± 0.67pp，并保持规划能力，但不改变其 ICL 未通过的判定。

##### 适用范围

任务验证二值出口规则的一步适应，不验证连续出口坐标、范围外出口或多步传送规划。

## 7. 接入新的 latent 世界模型

外部模型实现
`contextworld.benchmarks.adapters.LatentWorldModelAdapter` 即可使用统一评分器，不需要为
九项任务分别实现一套接口。Adapter 提供：

- `encode_pixels`：用模型的冻结目标编码器编码真实未来图像；
- `rollout_latents`：根据历史图像、历史动作、当前图像和查询动作预测未来 latent；
- `protocol`：声明历史长度、动作块、动作维度和预测步数；
- `metadata` 与 `frozen_state_hash()`：记录模型身份，并确认评测没有改变模型权重。

评分器只检查历史长度、每个动作块的原始步数、动作维度和预测 horizon。它不限制 latent
维度、网络结构、深度学习框架或训练数据加载方式。

```bash
pip install -e ".[eval]"
export CONTEXTWORLD_BENCHMARK_ROOT=/absolute/path/to/ContextWorld-v1

python -m contextworld.benchmarks.external_model_cli \
  --evaluation-split development \
  --task speed \
  --adapter your_package.module:YourAdapter \
  --checkpoint /path/to/checkpoint \
  --model-name your-model \
  --output /path/to/result.json
```

`CONTEXTWORLD_BENCHMARK_ROOT` 必须是 `ContextWorld-v1` clean export 的绝对路径。
Development 用于方法开发。方法、配方与终点固定后，用 `--evaluation-split test` 运行公开
Test；兼容别名 `public` 等价于 `test`。Test 结果保留冻结任务门，但会明确标为离线最终报告，
不是托管排行榜条目。

完整接口、数组形状和模型加载方式见
[外部模型 Adapter 规范](External_Model_Adapter_Contract.md)。

## 8. 可复现性与结果报告

公开 Training 与 Development 工作流只需要 `ContextWorld-v1`。原始模型训练和 CEM 还需要
相应的原环境数据。

建议每项结果至少报告：

- 模型名称、参数量和检查点标识；
- 训练数据、训练种子和优化预算；
- Adapter 版本与输入协议；
- 评测划分；
- 主分数、附加条件和逐训练种子结果；
- 若模型支持规划，训练前后的原任务 CEM；
- 未运行或不能评分的项目及明确原因。

机器可读的参考结果保存在
`artifacts/evaluation/contextworld_icl_suite_v2_release_addendum_v1/public_scoreboard.json`，
可用 `contextworld-scoreboard --input <public_scoreboard_spec.json>` 从冻结的逐种子记录
重新渲染。训练配方、检查点哈希、逐训练种子结果与逐次评测记录见
[结果复现附录](reference/Benchmark_Result_Provenance.md)。历史实验协议位于
`docs/protocols/`，用于复核结果，不是运行公开数据包的前置要求。

## 9. 适用范围与限制

ContextWorld 的结论仅覆盖本文列出的环境、隐藏规律、历史长度和参数范围。当前结果不能
证明：

- 一个模型能够同时解决全部九项任务；
- 模型能够处理多种隐藏规律同时变化；
- 模型能够外推到任意未见参数；
- 一步预测能力必然转化为所有任务上的闭环规划能力；
- 仓库内参考模型已经代表所有 latent 世界模型架构。

Test 已公开以支持完全离线复现，但仍不应用于模型选择。公开发布还需提供稳定的数据集修订
版本与最终分发元数据；若未来需要抗 Test 过拟合的竞赛，可另设新的私有 challenge split，
不改变本版公开 Test 的角色。
