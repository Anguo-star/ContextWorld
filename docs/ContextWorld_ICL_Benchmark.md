# ContextWorld：Latent 世界模型的上下文学习基准

本文是 ContextWorld 的统一技术报告：任务与数据、评分协议、冻结参考、最新训练方式对比，以及这些结果支持的发现均在此维护。

快速阅读：[任务与数据](#1-benchmark-概览) · [指标解释](#4-评测指标) · [最新九任务总表](#training-comparison) · [主要发现](#56-结果支持的发现与尚未解决的问题) · [复现与报告](#8-可复现性与结果报告)。

ContextWorld 评测 latent 世界模型能否从最近几步交互中识别隐藏的环境动力学，并据此
预测下一状态。模型只通过上下文适应：评分过程不更新任何模型参数，也不向模型提供速度、
动作延迟、物体质量、接触属性或空间转移规则等模拟器隐藏变量。

评测直接在参评模型自己的 latent 空间中进行，不要求图像解码器或像素重建。因此，
JEPA、LeWM、PLDM、PreJEPA 以及其他 latent 世界模型可以使用同一套数据与评分协议。

数据如何生成——连续仿真、配对构造、划分隔离以及九项任务的生成入口——见
[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
而不是按环境数量组织；九项任务分别计分，不计算跨任务平均分或统一总分。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不构成分数权重。

## 2. 数据与划分

冻结 v3 的数据身份分开固定：Training 与 Development 使用 `ContextWorld-v1`，Public Test 使用
`ContextWorld-v1-full`。两者包含九项任务、任务注册表、组件说明及文件完整性清单；当前
数据包已在本地完成组装，但尚未公布稳定的公共下载版本。

HF 发布候选 `ContextWorld-v3-hf` 汇集上述两个来源的对应划分，保留数据字节与任务选择
合同，不替换 v3 的来源身份；目录和加载方式见 [HF 数据集指南](HF_Dataset_Export.md)。

每项任务使用三种互不重叠的数据划分：

- **Training**：用于训练或适配模型；
- **Development**：用于实现检查、训练配方选择和消融实验；
- **Test**：公开的离线最终报告划分；不参与配方或检查点选择。

选择在 Development 上完成，结论在 Test 上报告。参考方法在读取任何 Test 分数之前
固定检查点步数：Development 只用于选择训练配方，不用于挑选检查点，Public Test 既不
参与配方选择也不参与检查点选择。Development 结果必须明确标注划分，不能作为
Test 成绩报告。公开 Test 提高了可复现性，但由于当前没有托管提交服务，协议依赖作者遵守
“Development-only selection, Test-only final reporting”的信息边界。

Development 的公开抽取由每个组件的 `task_registry.json` 固定，不是统一采样：门通行
规则与动作延迟各 300 个 query，速度按四条 track 的参考速度族抽取，其余六项各 256 对。
原任务 CEM 的“6 × 50”是另一套预算（见 4.3），不要与 Development 的抽样数混用。

| 任务 | 冻结 v3 Training | Development | Public Test | 主要变化范围 |
|---|---:|---:|---:|---|
| 速度 | 32 档速度 | 每个参考速度 300 个查询 | 每个参考速度 300 个查询 | 训练内插值与范围外速度 |
| 推手移动幅度 | 2,048 对 | 256 对 | 256 对 | 移动幅度 60 / 140 |
| 机械臂质量 | 2,048 对 | 256 对 | 256 对 | 密度 500 / 1500 |
| 动作延迟 | 延迟 0–10 | 300 个查询 × 11 种延迟 | 300 个查询 × 11 种延迟 | 0、1、2、3、4、5–10 六个响应组 |
| 接触摩擦 | 8,192 对 | 256 对 | 256 对 | 摩擦系数 0.05 / 0.80 |
| 运动阻尼 | 8,192 对 | 256 对 | 256 对 | 阻尼 0.2 / 1.0 |
| Cube 夹爪携带规则 | 2,048 对 | 256 对 | 256 对 | 可携带 / 不可携带 |
| 门通行规则 | 96 个门位置 | 16 个 loader-val 门位置、300 个场景 | 42 个未见门位置、300 个场景 | 可通过 / 被阻挡 |
| 传送门出口位置 | 2,048 对 | 256 对 | 256 对 | 靠近边界 / 远离边界的出口 |

较新的训练方式研究扩展了六项任务的 Training，另外三项沿用原数据；版本、配对数量与独立来源定义统一列在[当前研究结果](#training-comparison)。上表描述冻结 v3，不代表扩量后的训练规模。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 最近若干帧真实图像；
2. 已经执行的动作序列；
3. 当前图像；
4. 接下来要执行的查询动作；
5. 每种候选隐藏规律对应的模拟器真实未来。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器连续向前执行。`x0` 之后不写入状态、不重建模拟器，也没有仲裁
过程改写中间状态；历史与未来之间没有任何 reset。干净模拟器重放只用于审计，确认不可见
的求解器缓存不改变 `x3`，从不用于生成保存进数据集的画面或目标。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只保留在审计通道，不进入模型输入。

## 4. 评测指标

### 4.1 上下文学习正确率

每个查询产生一个 0/1 结果：模型是否选择了与历史所示隐藏规律一致的真实未来。任务主
分数是查询正确率（0–100%）；表中的三个训练种子均值和样本标准差描述分数的
中心与种子间波动。部分任务还要求最弱条件、历史使用、历史切换、方向一致性或 bootstrap
置信下界同时达标。

| 任务 | 主分数要求 | 其他必要条件 |
|---|---:|---|
| 速度、门通行规则 | 按预先规定的方向判定 | 每个方向与每个评测种子分别达标 |
| 推手移动幅度、接触摩擦、运动阻尼 | ≥ 95% | 正确历史 ≥ 95%、历史切换 ≥ 95%、最弱条件 ≥ 90% |
| 传送门出口位置 | ≥ 95% | 最弱出口 ≥ 90%，bootstrap 95% 下界 ≥ 90% |
| 动作延迟 | ≥ 75% | 最弱响应组 ≥ 60%，bootstrap 95% 下界 ≥ 70% |
| 机械臂质量、Cube 夹爪携带规则 | ≥ 75% | 正确历史 ≥ 75%、历史切换 ≥ 90%、最弱条件 ≥ 70% |

参考方法使用三个独立训练种子，以主分数的均值 ± 样本标准差比较表现。达标种子数另记为
0/3、1/3、2/3 或 3/3，表示多少个检查点满足全部预定条件；它不改变任何检查点的分数。
均值描述平均表现，达标种子数描述完整条件下的稳定性，两者回答不同问题。

Development 与 Public Test 共用主指标、门槛阈值和分层结构，使用隔离的数据行。Speed 的
主指标是匹配历史相对其余每一个历史条件的严格胜率。Development 原始结果不含通过字段，
独立决策回执使用与 Test 相同的内核核验；输出格式差异不改变评分标准。

### 4.2 评分有效性与防作弊

评测是 decoder-free 的：评分器只调用模型的编码器和 latent 预测器，不调用图像解码器，
真实未来帧已经离线保存，一步预测不需要在线运行模拟器。距离只在同一个检查点自己的
latent 空间内计算，然后转成任务层面的对错。不同模型（以及同一模型的不同检查点）的
原始 latent MSE 没有共同单位，不能直接比较或排名。

正确率之外，评分程序还检查：

- 两种真实未来在该检查点的 latent 中确实可分；
- 改变历史会改变模型预测（历史切换）；
- 预测响应的方向与真实未来一致；
- 最弱隐藏条件和各个方向分别达标；
- 对要求 latent 响应门的组件，预测响应经同一检查点的真实目标响应归一化后达标：
  响应增益 ≥ 0.50，归一化响应误差
  严格小于“完全不使用历史”的基线值 1.00。

冻结结果还保留以下数值，用于解释主分数变化。这里的“响应”指切换历史后，预测未来之间的
差异；目标响应是对应模拟器真实未来在该模型 latent 空间中的差异。

| 诊断指标 | 如何解读 |
|---|---|
| 方向一致性 `response_alignment` | 越接近 1，预测响应方向越接近真实响应方向 |
| 响应增益 `response_gain` | 理想值为 1；接近 0 表示响应过弱，超过 1 表示沿真实方向响应过强，不是越大越好 |
| 归一化响应误差 `normalized_response_error` | 越小越好，0 表示响应一致；完全不随历史改变预测时为 1 |

当前九项任务、三模型、三个训练种子的冻结报告均保留这些字段；Speed 按四条 track 分别
记录。可以直接展示和分析，无需重新训练或推理。各任务仍按自己的配对条件解释这些指标，
不把它们合成为统一总分或跨模型的绝对预测误差排名。主分数提高只表示对应判别指标提高，
不能自动推出响应幅度、方向或范围外外推能力同时提高。

统一结果表还使用以下字段：

| 字段 | 衡量什么 | 方向 |
|---|---|---|
| 主分 | 各任务定义的未来选择或规律识别正确率；Speed 使用严格历史选择 | 越高越好 |
| 最弱条件 | 在该任务各隐藏条件或响应组中表现最弱的一项 | 越高越好 |
| History | 匹配的历史是否比错误历史产生更准确的目标预测 | 越高越好 |
| Switch | 交换历史后预测选择是否按任务定义发生切换 | 越高越好，但不能单独证明响应正确 |
| Joint | 六个配对任务中，两条件均选对未来、均正确利用历史，且该对 NRE<1 的比例 | 越高越好 |
| CalResp | 条件响应 NRE<1 的样本对比例，即优于零历史响应 | 越高越好；不表示响应幅值已接近理想值 |

Gain、Alignment、NRE 使用上表定义。所有比率以百分数显示；Gain、Alignment、NRE 保留原数值。不同检查点的目标表示不同，归一化指标用于描述各自的相对响应质量，不能当作共同物理单位的绝对误差。当前不把这些互补维度合成总分。

### 4.3 原任务规划能力保持（附加分析）

原任务 CEM 使用 TwoRoom、PushT、Reacher 和 Cube 的原环境任务，衡量引入 ICL 数据后
原有规划能力的变化。它不评测九项隐藏规律条件下的规划能力，不进入 ICL 主分数。
已有成功率及变化统一保存在[附录 §5.3](reference/Benchmark_Result_Provenance.md#original-task-cem-retention)。

标准 CEM 预算为六个评测种子（42–47），每个种子 50 次规划，共 300 次。
这些结果是描述性保持分析，正式非劣性声明须另有预注册协议与配对证据。

### 4.4 结果比较

同一任务内的模型使用相同查询，可以直接比较正确率。若要声称一个方法优于另一个方法，
应对相同查询进行配对 bootstrap，并报告正确率差的 95% 置信区间。不同任务的分数不求
平均，不用于生成单一排行榜总分。

### 5.3 冻结 v3 参考的已知边界

- **门通行规则主分数接近饱和。** 当前模型的 Public Test 主分数为 LeWM 99.83%、PLDM 100.00%、DINO-WM 100.00%；候选之间的细节应读取门槛输入，不能只看主分数。

### 5.5 九任务训练方式比较（Development，2026-09-24）

本节回答三个问题：扩大训练覆盖后哪些能力改善；原环境预训练是否有帮助；第二阶段是否应继续更新视觉表示。九项任务的三个模型均有 ICL 从头训练结果；六个扩量任务另有 LeWM / PLDM 的二阶段联合与冻结 Encoder 对照。

这些实验沿用任务评分协议，使用 Development 进行研究，与 §5.1 的冻结 v3 分开报告。每个配置的实际分数都保留；未报告的训练方式不填零，也不以是否跨过门槛代替能力获得程度。

#### 训练方案

| 表中名称 | 初始化与训练数据 | 第二阶段哪些模块更新 |
|---|---|---|
| 原始模型 | 只用对应原环境数据训练 | 不适用；直接评测原始权重 |
| ICL 从头 | 使用模型家族默认初始化，原环境数据与该任务数据各占 50% | LeWM / PLDM 按原生方案联合训练；DINO-WM 的视觉 Encoder 始终冻结 |
| 二阶段联合 | 完整加载原始模型权重，再用相同的 50/50 混合数据训练；重新建立优化器 | LeWM / PLDM 的 Encoder、预测器及其余原生训练模块联合更新 |
| 二阶段冻结 | 与联合训练使用相同的完整原始初始化和混合数据 | LeWM / PLDM 仅固定 Encoder 参数和训练态缓冲区；projector、预测器、动作编码器等继续更新 |
| 历史转换初始化 | 旧 DINO-WM 原始模型包含额外状态输入，转换视觉与动作相关参数后进行 ICL 训练 | 冻结 DINO Encoder，训练转换后的预测器；单独列为历史参照 |

DINO-WM 的“从头”指预测器从头训练，不是重新训练 DINO 视觉骨干。新的 DINO-WM 原始模型只使用 `pixels` 和 `action`；从它们完整初始化预测器的二阶段结果尚未报告。旧的六个转换初始化结果不能代填这一列。

ICL 训练使用 seed 3072、10 epochs、8 张 GPU、每卡 batch 128、梯度累积 1；原始模型和二阶段初始化来自 seed 3073。每项能力分别训练一个检查点，不是一个模型同时学习九项能力。原始预训练使二阶段方案具有额外总训练预算，因此“二阶段优于从头”本身不能证明初始化是唯一原因。

六任务的 LeWM / PLDM 联合与冻结对照已核对训练数据 manifest、成员列表、混合比例、历史长度、帧间隔和原始初始化权重一致。不同模型保留各自的 Encoder、训练目标和优化器；跨模型差异不能单独归因于某一个架构部件。

### 5.6 结果支持的发现与尚未解决的问题

**训练方式可以决定已有数据是否转化为条件响应。** 固定数据与原始初始化，PLDM Strength 的主分由联合训练的 60.55% 提高至冻结 Encoder 后的 98.05%，Joint 由 17.97% 提高至 94.92%，NRE 由 0.798 降至 0.115。LeWM Friction 由 50.20% 提高至 87.50%；PLDM Portal 由 53.91% 提高至 92.58%。这些结果说明，数据量不足不能单独解释这些失败，原始表示中已有可用于学习相应任务的信息。

**继续调整表示也可能有益，冻结并非统一解法。** PLDM Damping 冻结后的主分从 77.54% 降至 56.05%，Gain 从 0.830 降至 0.135，NRE 从 0.221 升至 0.882；LeWM Mass 也在选择和响应指标上退步。已有证据支持“表示更新方式与模型、任务存在交互”，尚不能证明 JEPA 普遍阻碍 ICL，或某任务在所有训练方案下都必须更新 Encoder。

**选择、响应幅值、泛化和规划需要分别测量。** DINO-WM Cube 从头训练的主分为 61.33%，但 Gain 仅 0.095；LeWM / PLDM Speed 未见插值约 98%，两侧外推约 29–36%。PLDM Strength 冻结后 ICL 大幅改善，原环境 CEM 却由 72.00% 降至 59.33%；PLDM Damping 则出现 ICL 下降、CEM 上升。因此，较高主分不能替代充分校准、外推或规划能力的证据。

**混合训练并非总会损害原环境规划。** PLDM Friction 冻结方案的 CEM 为 79.67%，原始模型参考为 73.00%；PLDM Mass 分别为 89.00% 和 80.00%。这些是描述性对照，不是经过配对显著性检验的普遍改进结论。不同任务的保持与损失应按实际指标分别报告，不能统一解释为合成数据质量差。

ContextWorld 的作用是让上述差异可以被识别和检验：同一当前画面和查询动作下，模型是否利用历史选择正确未来，是否产生足够准确的条件响应，以及这种能力能否泛化。成功任务提供正对照，弱响应或失败任务提供机制研究对象；任务失败不自动证明数据不可学。

具体根因仍待验证。冻结 Encoder 同时改变了表示参数、训练态缓冲区和目标表示随训练变化的过程，当前对照尚未分离各项作用。下一步应围绕已有失败与反例检验表示、优化和历史信息利用，而不是为填满表格重复训练已学会的任务。更大数据或模型是否遵循稳定 scaling 规律，也需要多个规模点和受控训练预算才能判断。

历史 ICL 是否提升隐藏条件下的动作决策仍是独立问题：需要固定候选动作与真实后果，比较正确历史、无历史和错误历史下的动作排序、选择 regret 或闭环成功率。当前原环境 CEM 不提供这项结论。

### 5.7 如何复用本节结果

本文同时报告可复用的测量结果和它们支持的有限结论，不把待验证的解释写成事实。训练种子、初始化、任务数据和评测划分应随分数一起引用；对新方法的比较采用相同训练条件下的 native 对照。当前单训练种子结果用于发现和检验机制，不以门槛是否通过代替连续能力变化，也不宣称已经完成九任务全部训练方式的正式 Test 基线。

数据生成、加载、模型接入与训练命令分别见[数据生成方法](Data_Generation.md)、[HF 数据集指南](HF_Dataset_Export.md)、[Adapter 规范](External_Model_Adapter_Contract.md)和[训练指南](StableWM_Training.md)。这些是操作文档，任务结果和科学解释只在本文维护。扩量数据的 HF 打包准备见[发布说明](Expanded_Training_Release.md)；扩量数据仍处于发布准备阶段，冻结 v3 保留原有评分规则和参考数字。


## 6. 任务说明

每张任务卡说明任务定义及冻结 v3 的参考范围。较新的训练方案分数统一见 §5.5，不在各任务卡重复维护。五部分结构分别介绍任务目标、数据、指标、冻结参考与适用范围。

### 6.1 即时连续响应

#### 6.1.1 速度

##### 任务目标

模型根据近期移动判断当前速度，并预测同一动作对应的下一状态。

##### 数据构成

Training 覆盖 32 档速度。评测分别包含训练中出现的速度、训练范围内未见速度，以及低于
和高于训练范围的速度；每个参考速度使用六个评测种子 × 50 个查询。

##### 评测方法

主指标是训练范围内未见速度的一步严格正确率：与真实速度一致的历史必须同时优于另外
两档历史。Development 使用同一指标，门槛判定写入独立回执。若要把提升归因于
多速度训练，还需要同训练种子的单速度对照。

##### 基线表现

当前 v3 三训练种子结果见 §5.1：LeWM 98.19% ± 0.57pp、PLDM 96.78% ± 2.02pp、DINO-WM 59.41% ± 3.87pp；三者均为 0/3 通过，因为完整门槛还要求四条速度 track。原任务 CEM 保持结果见[附录 §5.3](reference/Benchmark_Result_Provenance.md#original-task-cem-retention)。结果支持 History=3 的训练范围内插值，不支持范围外外推。

##### 适用范围

结果支持 History=3 下的训练内插值，不代表任意速度外推。PLDM 缺少同训练种子的单速度
对照，因此不能把观察到的变化归因于多速度数据本身。

#### 6.1.2 推手移动幅度

##### 任务目标

模型判断相同二维动作会让 PushT 推手移动较短还是较远。两档参数为 60 和 140。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。配对查询共享当前
状态、画面和动作。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查模型是否使用正确历史、是否随历史切换预测，
以及最弱幅度条件是否达标。通过门槛为每个检查点至少 95%。

##### 基线表现

当前 v3 三训练种子结果见 §5.1：LeWM 50.00% ± 0.00pp、PLDM 50.26% ± 0.23pp、DINO-WM 93.82% ± 0.79pp；三者均为 0/3 通过，主分数与完整历史使用门槛均未达标。

##### 适用范围

任务验证二值动作响应，不验证连续幅度估计或范围外外推。

#### 6.1.3 机械臂质量

##### 任务目标

模型根据相同力矩下的近期运动判断 Reacher 机械臂较轻还是较重。两档密度为 500 和
1500。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。任务改变主体连杆
和末端球的质量，保持第二连杆不变。

##### 评测方法

主指标是真实下一状态选择正确率，并检查历史切换、最弱质量条件、bootstrap 置信下界和
latent 响应。三个训练种子必须分别达到 75%。

##### 基线表现

当前 v3 三训练种子结果见 §5.1：LeWM 85.35% ± 1.09pp（3/3 通过）、PLDM 53.06% ± 1.81pp（0/3）、DINO-WM 51.17% ± 0.52pp（0/3）。原任务 CEM 保持分析见[附录 §5.3](reference/Benchmark_Result_Provenance.md#original-task-cem-retention)。

##### 适用范围

任务验证两档质量的一步适应，不验证连续质量估计、范围外外推或多步闭环控制。

### 6.2 时间延迟动力学

#### 6.2.1 动作延迟

##### 任务目标

模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

##### 数据构成

延迟范围为 0–10。Training 先覆盖差异明显的 0、4、8，再覆盖完整范围；Public Test 包含
300 个查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

动作延迟有两个不同强度的评测问题，回答的研究问题不同，不能互相替代：

- **六组物理响应识别（正式指标）**：延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，
  各组在每个查询内等权宏平均。总体正确率须至少 75%，最弱组至少 60%，bootstrap 95%
  下界至少 70%。该指标判断模型是否区分六组一步响应，不区分 5–10 组内的延迟值。
- **二元历史响应诊断**：只判断预测在 delay=0 与 delay≠0（合并为一类）之间是否随历史
  正确切换，不要求区分不同的非零延迟。这是判断“历史是否引起了正确方向的条件差异”
  的更弱标准，主要用于快速诊断。

##### 基线表现

当前 v3 Public Test 三训练种子结果见 §5.1：LeWM 97.68% ± 0.62pp、PLDM 100.00% ± 0.00pp，均 3/3 通过；DINO-WM 16.65% ± 0.03pp，0/3。正式口径是六个物理响应组宏平均；二元历史响应只作辅助诊断。

##### 适用范围

正式结果验证 History=7 下六个一步物理响应组（0、1、2、3、4、5–10）分别达标。
一步未来无法区分 5–10，因此不表示精确识别全部 11 档延迟；h2/h3 是辅助诊断，
不属于当前通过条件。也不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。二元诊断数值只说明
“有无延迟”的区分，不能单独支撑延迟识别结论。

### 6.3 接触或附着条件动力学

#### 6.3.1 接触摩擦

##### 任务目标

模型根据推手与物体接触时的响应判断摩擦较小还是较大。两档摩擦系数为 0.05 和 0.80。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对查询的当前
完整物理状态误差不超过 `1e-5`，历史接触结束后至少连续三步无接触，不同划分不共享查询
或生成模板。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱摩擦条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，正式比较使用
Development；已有历史 Public Test 结果保留来源，但排除正式报告。

##### 基线表现

当前 v3 Development 三训练种子结果见 §5.1：LeWM 50.07% ± 0.11pp、PLDM 50.13% ± 0.30pp、DINO-WM 49.61% ± 0.20pp，均 0/3。该组件当前未通过 Development 准入，因此不把历史 Test 工件当作正式当前结果。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会接触摩擦。

#### 6.3.2 运动阻尼

##### 任务目标

模型根据接触结束后的运动判断物体减速较快还是较慢。两档阻尼为 0.2 和 1.0。

##### 数据构成

Training 包含 8,192 对样本，Development 和 Public Test 各包含 256 对。配对样本交换起点，
使仅凭起点预测标签的准确率为 50%。

##### 评测方法

主指标是真实下一状态选择正确率，同时检查正确历史、预测切换和最弱阻尼条件，四项门限
分别为 95%、95%、95% 和 90%。当前参考方法未满足 Development 的全部条件，正式比较使用
Development；已有历史 Public Test 结果保留来源，但排除正式报告。

##### 基线表现

当前 v3 Development 三训练种子结果见 §5.1：LeWM 50.07% ± 0.11pp、PLDM 51.89% ± 2.11pp、DINO-WM 50.13% ± 0.11pp，均 0/3。该组件当前未通过 Development 准入。

##### 适用范围

数据和评分器可用于评测新模型；现有结果不能说明 LeWM 或 PLDM 已稳定学会运动阻尼。

#### 6.3.3 Cube 夹爪携带规则

##### 任务目标

模型根据夹爪与方块的近期响应判断闭合夹爪能否携带方块，并预测共享查询动作对应的真实
下一状态。

##### 数据构成

Training 包含 2,048 对，Development 和 Public Test 各包含 256 对。四类动作模板在每个划分中严格均衡；源轨迹、动作模板、场景、配对内容和 query 画面互不重叠。

##### 评测方法

每个检查点的真实未来正确率至少为 75%，正确历史至少 75%，上下文切换至少 90%，最弱
规则至少 70%。通过 Development 的模型还需报告原 Cube CEM；CEM 的当前预算与解释规则见
§4.3。外部模型使用独立结果身份，不会覆盖仓库提供的参考结果。

##### 基线表现

当前 v3 三训练种子结果见 §5.1：LeWM 50.00% ± 0.00pp、PLDM 50.00% ± 0.20pp、DINO-WM 50.78% ± 0.20pp，均 0/3。CEM 只作原任务规划能力的描述性补充。

##### 适用范围

结果只支持二值携带规则的一步 ICL 评测，当前 0/3 不支持已学会该规则的结论；CEM 见 §4.3。
不验证连续夹持强度或多步闭环适应。公开分发仍须补齐许可证和稳定下载地址。

### 6.4 隐藏结构转移规则

#### 6.4.1 门通行规则

##### 任务目标

模型根据历史中的穿门或碰壁结果判断外观相同的门能否通过。

##### 数据构成

Training 覆盖 96 个门位置，Development 覆盖 16 个门位置，Public Test 使用 42 个训练中
未见的门位置并包含 300 个场景。

##### 评测方法

每个查询保存“可通过”和“被阻挡”两种模拟器真实未来。评分分别检查两个穿门方向、历史
是否改变判断，以及两种未来在 latent 中是否可分；每个评测种子与方向的组合都必须达标，
配对 bootstrap 的 95% 下界必须大于 0。

##### 基线表现

当前 v3 Public Test 三训练种子结果见 §5.1：LeWM 99.83% ± 0.29pp、PLDM 100.00% ± 0.00pp、DINO-WM 100.00% ± 0.00pp，均 3/3 通过。主分数接近饱和，门槛输入仍用于区分响应质量。

##### 适用范围

任务验证一步门规则判断，不验证多步闭环穿门规划。

#### 6.4.2 传送门出口位置

##### 任务目标

模型根据历史中的传送结果判断进入同一入口后会从靠近边界还是远离边界的位置出现。

##### 数据构成

Training 包含 2,048 对场景，Development 和 Public Test 各包含 256 对。两种规律在查询前
汇合到相同当前状态，因此当前画面和动作本身不能泄露答案。

##### 评测方法

主指标是真实出口下一状态选择正确率，并检查正确历史、预测切换、最弱出口条件、
bootstrap 置信下界和 latent 响应。三个训练种子必须分别满足完整标准。

##### 基线表现

当前 v3 三训练种子结果见 §5.1：LeWM 51.30% ± 0.23pp、PLDM 69.53% ± 1.37pp、DINO-WM 99.35% ± 0.30pp，均 0/3。DINO-WM 的高主分数仍未满足 latent 响应门槛。

##### 适用范围

任务验证二值出口规则的一步适应，不验证连续出口坐标、范围外出口或多步传送规划。

## 7. 接入新的 latent 世界模型

外部模型实现
`contextworld.benchmarks.adapters.LatentWorldModelAdapter` 即可使用统一评分器，不需要为
九项任务分别实现一套接口。Adapter 提供：

- `encode_pixels`：用模型的冻结目标编码器编码真实未来图像；
- `rollout_latents`：根据历史图像、历史动作、当前图像和查询动作预测未来 latent；
- `protocol`：声明历史长度、动作块、动作维度和预测步数；
- `metadata` 与 `frozen_state_hash()`：记录模型身份，并确认评测没有改变模型权重。

评分器只检查历史长度、每个动作块的原始步数、动作维度和预测 horizon。它不限制 latent
维度、网络结构、深度学习框架或训练数据加载方式。

```bash
pip install -e ".[eval]"
export CONTEXTWORLD_BENCHMARK_ROOT=/absolute/path/to/ContextWorld-v1

python -m contextworld.benchmarks.external_model_cli \
  --evaluation-split development \
  --task speed \
  --adapter your_package.module:YourAdapter \
  --checkpoint /path/to/checkpoint \
  --model-name your-model \
  --output /path/to/result.json
```

`CONTEXTWORLD_BENCHMARK_ROOT` 在 Development 运行时必须指向 `ContextWorld-v1` clean export；
方法、配方与终点固定后，Test 运行时切换到 `ContextWorld-v1-full`，再用
`--evaluation-split test` 运行公开 Test；兼容别名 `public` 等价于 `test`。Test 结果保留冻结任务门，但会明确标为离线最终报告，
不是托管排行榜条目。

完整接口、数组形状和模型加载方式见
[外部模型 Adapter 规范](External_Model_Adapter_Contract.md)。

## 9. 适用范围与限制

ContextWorld 的结论仅覆盖本文列出的环境、隐藏规律、历史长度和参数范围。当前结果不能
证明：

- 一个模型能够同时解决全部九项任务；
- 模型能够处理多种隐藏规律同时变化；
- 模型能够外推到任意未见参数；
- 一步预测能力必然转化为所有任务上的闭环规划能力；
- 仓库内参考模型已经代表所有 latent 世界模型架构。

当前 ICL 门槛测量的是固定数据分布内的历史条件响应：目标选择、历史使用、响应方向和
相对幅度。两种预测同时带有共同偏置时，差分响应仍可能通过；因此 ICL 通过不能单独
证明绝对预测误差小，原任务 CEM 也不能代替隐藏规律条件下的闭环规划验证。
隐藏规律下的闭环规划可作为后续独立扩展：固定规划预算，比较正确历史、无历史与错误
历史条件下的成功率；当前版本未包含这项规划评测。
门通行历史提供直接的碰撞线索，接近满分支持当前两规则任务，不等于已验证抽象规则迁移。

固定正/负控制用于检验这些门槛能否拒绝无历史、反向历史和微弱响应，并保留正确响应。
它们验证具体辨别机制，不是所有潜在捷径的穷举，也没有给出真实模型总体的假阳性率。

Test 已公开以支持完全离线复现，但仍不应用于模型选择。公开发布还需提供稳定的数据集修订
版本与最终分发元数据；若未来需要抗 Test 过拟合的竞赛，可另设新的私有 challenge split，
不改变本版公开 Test 的角色。

## 10. 后续研究基线与比较规则

本节面向计划在 ContextWorld 上继续研究新方法、或对现有结果做根因分析的读者，说明
应该以什么为起点、如何与当前参考做对比。

**v3 已于 2026-09-11 正式封板，冻结文件永久不改。**
[最终验收](reference/Baseline_Final_Acceptance_2026-09-10.md)确认其可在既定范围内作为
固定研究基线。后续按以下规则维护：

- 根因分析、新方法与新训练数据实验保存独立结果，引用 v3，保留原始成功和失败结果。
- 修改评测数据、任务定义、评分合同、阈值或关键评分依赖时建立 benchmark 新版本；
  发现的问题独立记录，不回写 v3 数字或重新封存以覆盖原身份。
- 历史 provenance、稳定公共下载和外部独立复现属于发布层工作，不作为继续修改
  baseline 的理由；文档可澄清说明，但不得改变冻结结果或其含义。

**以 §5.1 的冻结快照为当前主参考。** 新方法与根因研究都应从
[`contextworld_joint_scratch_v1_reference_results_freeze_v3.json`](../configs/benchmark/contextworld_joint_scratch_v1_reference_results_freeze_v3.json)
锁定的数据版本、评分协议版本、训练配方版本与检查点/种子清单出发。历史结果保留其
训练身份和协议，不能与当前参考混合归因；身份不一致的结果只作历史证据。

**新方法必须使用同配方的 native 结果作为对照，而不是任意历史结果。** 方法效应应
定义为“新方法结果 − 同一快照下 native 结果”，而不是“历史配方下的旧方法结果 −
当前快照的 native 结果”。统一比较要求任务定义、数据边界、预算报告和评测问题一致，
不要求所有模型族使用完全相同的优化器超参数——各模型族的合理原生训练设置应保留并
明确说明。

**根因分析需要同一批检查点与数据的完整证据链。** 从训练输入，到该检查点的表示，到
该训练状态的梯度/更新，到同协议下的 held-out 行为，应尽量在同一个冻结的研究单元内
建立，而不是把旧检查点的中间诊断和新检查点的最终指标拼接作为同一个结论的证据。新的
完整结果应当用于重新选择值得解释的成功和失败单元，而不是为了保留某个历史叙事而固定
哪个任务算“成功”、哪个算“失败”。

**评测问题必须先对齐研究问题，再谈“统一新规则”。** 动作延迟的二元历史响应诊断和
六组物理响应识别是两个不同强度的评测问题，应明确使用哪一个。未来协议可以更新，但必须
同时说明指标、随机基线、阈值和数据身份的变化。

**不要从不匹配的历史结果推断原因。** 若要解释训练配方、初始化、数据几何或代码版本
的影响，须在同一冻结研究单元中改变一个明确因素，并报告相同的 held-out 任务、预算和
逐种子结果；否则只能将差异记录为相关性或已知限制。
