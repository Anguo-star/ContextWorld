# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 通过控制隐藏动力学和可见历史，衡量世界模型是否学会利用交互经验预测未来。本文介绍任务、数据、评分方法，以及三个模型在不同训练方式下的完整结果和主要发现。

快速阅读：[任务与数据](#1-benchmark-概览) · [指标解释](#4-评测指标) · [主结果表](#training-comparison) · [主要发现](#53-主要发现与解释边界) · [数据扩量](#54-数据规模与能力变化) · [复现与报告](#8-可复现性与结果报告)。

ContextWorld 评测 latent 世界模型能否从最近几步交互中识别隐藏的环境动力学，并据此
预测下一状态。模型只通过上下文适应：评分过程不更新任何模型参数，也不向模型提供速度、
动作延迟、物体质量、接触属性或空间转移规则等模拟器隐藏变量。

评测直接在参评模型自己的 latent 空间中进行，不要求图像解码器或像素重建。因此，
JEPA、LeWM、PLDM、PreJEPA 以及其他 latent 世界模型可以使用同一套数据与评分协议。

数据如何生成——连续仿真、配对构造、划分隔离以及九项任务的生成入口——见
[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
九项任务分别报告 ICL 与原环境 CEM，用于比较模型在具体任务上的能力。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不作为评分汇总单位。

## 2. 数据与划分

数据由物理模拟器生成。每项任务改变一个隐藏动力学因素，保存连续交互轨迹、查询动作及真实未来。Training 用于训练，Development 用于实现检查与方法选择，Test 用于方法固定后的最终报告。表中的训练方式比较统一使用 Development；其分数不作为 Test 成绩报告。

**规模统一以训练配对数表示：2k=2,048，8k=8,192，32k=32,768。** 一对包含两种隐藏条件下的轨迹，不等于两个独立来源 episode。

| 任务 | 实际训练档位 | 如何比较 | Development / Test |
|---|---|---|---|
| 推手移动幅度 | **2k → 8k → 32k** | LeWM 原始权重初始化有三档；三个模型的从头训练对比 2k / 32k | 各 256 对 |
| 接触摩擦 | **8k → 32k** | 增加重置状态与接触几何，起点不是 2k | 各 256 对 |
| 运动阻尼 | **8k → 32k** | 增加初始状态，包含成对镜像样本，起点不是 2k | 各 256 对 |
| 机械臂质量 | **2k → 32k** | 增加初始关节状态与探测动作 | 各 256 对 |
| Cube 夹爪携带 | **2k → 10k 独立来源** | 旧 32k 仍复用 2,048 个来源，属于变体扩增，不计为独立规模档 | 各 256 对 |
| 传送门出口 | **2k → 32k 覆盖扩展** | 同时改变初始距离与动作幅值；旧、新 32k 的区别是覆盖，不是数量 | 各 256 对 |
| 速度 | 没有扩量对照；32 档速度 | 32 档是参数种类，不是 32k 样本 | 每个参考速度 300 个查询 |
| 动作延迟 | 没有扩量对照；延迟 0–10 | 沿用基础版训练载荷 | 各 300 个查询 × 11 种延迟 |
| 门通行规则 | 没有扩量对照；96 个训练门位 | 沿用基础版训练载荷 | 16 / 42 个门位置，各 300 个场景 |

不同任务的独立覆盖单位不同。Strength 的 32k 包新增 30,720 个状态与动作窗口，来自 12,069 个来源 episode；Friction、Damping 各新增 24,576 个初始状态，其中 Damping 包含 12,288 组前向／镜像样本；Mass 新增 30,720 个初始关节状态与探测动作。Cube 的 10k 来自 10,000 个不同来源 episode。这些数量不能统称为“32k 独立 episode”。

这些数据版本只改变 Training；Development 和 Test 沿用各自固定载荷。其余三任务使用基础版训练数据。每条结果的具体数据包版本、manifest 和评测身份记录在[结果 JSON](research/data/icl_training_study_v2.json)。数据生成与划分检查见[数据生成方法](Data_Generation.md)。

公开 Test 采用离线评测，没有托管提交服务。方法、训练预算和检查点选择应在 Development 上完成；读取 Test 后不得再用它调整方法。稳定公共数据下载版本尚未公布，包格式和本地加载方式见[HF 数据集指南](HF_Dataset_Export.md)。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 最近若干帧真实图像；
2. 已经执行的动作序列；
3. 当前图像；
4. 接下来要执行的查询动作；
5. 每种候选隐藏规律对应的模拟器真实未来。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器从 `x0` 连续执行到真实未来，中途不重置或改写状态。独立重放仅用于检查模拟器状态的一致性，不替换保存的数据。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只保留在审计通道，不进入模型输入。

## 4. 评测指标

### 4.1 主分与历史利用

六个二值配对任务的主分是选择正确真实未来的比例，随机基线为 50%。Door 使用同历史下的两种目标选择正确率；Delay 使用六个物理响应组宏平均，随机基线为 16.67%；Speed 要求匹配历史的预测优于每一个竞争历史条件，随机基线为 33.33%。Speed 分别报告已见速度、未见插值、低端外推和高端外推。

主表保留各任务的原始百分数，并将 ICL 与原环境 CEM 分开报告。任务详情保留以下互补维度，不以通过门槛与否替代实际分数：

| 指标 | 含义与解读 |
|---|---|
| 主分↑ | 按对应任务定义，选择正确未来或匹配历史的比例 |
| 响应分↑ | `100 × (1 − NRE)`，100 为完全恢复条件响应，0 与零响应同等误差，负值表示误差更大；单位为分，不是成功率 |
| 最弱条件↑ | 隐藏条件、响应组或参考速度中表现最弱的一项 |
| History↑ | 匹配历史是否比错误历史产生更准确的目标预测 |
| Switch↑ | 历史切换响应的任务特定读数；例如 Strength 检查预测差与真实差的内积是否为正，不能据此认定幅值正确 |
| Joint↑ | 六个配对任务中，两种条件都选对未来、都正确利用历史，且该样本对 NRE<1 的比例；其他三任务不定义此项 |
| Gain≈1 | 预测条件响应在真实条件响应方向上的相对幅值；理想值 1，接近 0 表示响应过弱 |
| Alignment↑ | 预测与真实条件响应的余弦相似度；理想值 1 |
| NRE↓ | 条件响应误差的平方范数除以真实响应的平方范数；理想值 0，完全不随历史变化的预测为 1 |
| 优于零响应↑ | NRE<1 的样本对比例；保留结果字段 `calibrated` / `calibrated_response_success_rate`，不解释为幅值已充分校准 |
| CEM↑ | 对应原环境的规划成功率，独立于 ICL 评分 |

各任务的主分定义和随机参照不同，且每项任务分别训练检查点，因此不合并为跨任务总分。当前严格比较将平局记为失败：例如 Speed 完全不随历史变化时，竞争历史的损失相等，严格胜率为 0；33.33% 是随机选择参照，不能解释为无历史模型的得分。

### 4.2 响应指标与评分有效性

设切换隐藏条件后的真实目标 latent 差为 Δz，匹配历史下的预测差为 Δẑ，则每对样本的 Gain 为 `〈Δẑ, Δz〉 / ‖Δz‖²`，NRE 为 `‖Δẑ − Δz‖² / ‖Δz‖²`，Alignment 为两者的余弦相似度。共享配对实现先累加响应能量，再计算总体 Gain、Alignment 与 NRE，并非直接平均每对的比值；任务分组沿用各自协议。评分同时检查真实未来在模型表示中是否可分。

**连续响应分为 `100 × (1 − NRE)`，不截断负值，也不再次平方 NRE。** 它与 NRE 携带相同信息，用于直观展示改善程度，不是一条独立证据。先按原协议计算每个检查点的 NRE，再跨可比训练重复汇总；响应分的标准差为 NRE 标准差的 100 倍，缺失值保持缺失。任务详情和扩量表使用响应分展示该维度，原始 NRE 保留在 CSV / JSON 中。

例如真实目标为 −1、1，预测为 −ε、ε 时，ε=0.001、0.5、1 都可在严格选择及 NRE<1 的联合判断中成功，但响应分分别只有 0.1999、75、100。这说明正确率与响应幅值应分别阅读。条件差分也会消去两侧共同预测偏差，因此响应分满分仍不能证明绝对未来预测准确。

距离只在同一检查点的 latent 空间中计算。不同检查点的原始 latent MSE 不具有共同单位；归一化响应指标描述各自表示中的相对响应质量，不能当成同一物理单位的绝对预测误差。高主分也不能自动证明正确响应幅值或范围外泛化。

完整能力判定是评分协议的补充，不决定模型是否取得进步，也不将低于阈值的分数置零。各任务的历史阈值统一见[评分与复现附录](reference/Benchmark_Result_Provenance.md)。

### 4.3 原环境规划

CEM 在 TwoRoom、PushT、Reacher 和 Cube 原环境上评测，衡量引入 ICL 训练后的原有规划能力。CEM 预算为六个评测种子（42–47），每个种子 50 次，共 300 次；历史原始模型的预算差异在总表前注明。

原环境 CEM 衡量能力保持，不能替代隐藏规律下的上下文规划收益。这里区分固定候选动作的选择质量与 CEM 闭环控制。

隐藏规律下的动作评价使用相同候选、目标与模拟器真实代价，比较正确历史与控制历史带来的选择差异。Strength 的具体实验与结果见 §5.5。

### 4.4 比较原则

同任务的模型使用相同查询。正式优劣或非劣性声明应使用逐查询配对分析并报告置信区间；描述性分数变化本身不提供显著性结论。训练样本量、独立覆盖、初始化和表示更新方式应分别控制，才能讨论原因。

## 5. 模型与训练方案比较

### 5.1 实验设置

本文比较九项任务、LeWM、PLDM 和 DINO-WM，以及以下训练方案。“原始权重”指仅用对应原环境数据训练得到的完整模型权重。

- **原始模型**：只用对应原环境数据训练，直接评测其权重。
- **ICL 从头**：原环境数据与对应任务的 ICL 数据按 50/50 混合，使用模型家族的默认初始化训练。
- **原始权重初始化**：加载原始权重，在相同混合数据上联合训练 Encoder、预测器及其他原生训练模块。
- **原始权重初始化（冻结 Encoder）**：加载相同原始权重，固定 Encoder 参数和训练态缓冲区，在相同混合数据上训练预测器、projector、动作编码器等其余模块。

两种原始权重初始化方案均重新建立优化器。

DINO-WM 的视觉 Encoder 始终使用冻结的预训练权重；“ICL 从头”与“原始权重初始化”的区别是预测器是否加载原环境训练权重。因此，它的原始权重初始化结果统一列入“原始权重初始化（冻结 Encoder）”。标有 ‡ 的转换初始化来自包含额外状态输入的旧 DINO-WM 原始模型：转换保留视觉和动作相关参数，其结果仅保留在历史附录，不能替代新 `pixels+action` 原始权重的完整初始化。

ICL 训练为 10 epochs、8 张 GPU、每卡 batch 128、梯度累积 1；原始模型评测及原始权重初始化使用对应原环境权重。每项任务分别训练一个检查点，主表的一行是同一模型与训练方案在九项任务上的实验集合，不表示同一权重同时获得九项能力。原始权重初始化包含额外的原环境预训练预算，因此它与从头训练的差异同时涉及初始化和总训练经历。

**重复实验的汇总方式：** 相同任务、数据版本、训练方案和输入协议的全部可用训练重复参与均值；已有三个训练种子的配置使用三者，不选取其中一个。主表显示均值，任务详情显示“均值 ± 样本标准差”及重复数 `n`。仅有一次结果时显示该数值，标准差不写作零。ICL 与 CEM 分别统计有效重复数。具体种子、初始化检查点及逐次结果见结果 JSON。

每个检查点的 CEM 先按评测次数汇总，再跨训练重复等权平均。六个 CEM 评测种子是同一检查点的评测重复，不能当成六次独立训练。不同规模、训练方式和初始化协议始终分别汇总。

LeWM / PLDM 在八项任务上的两种原始权重初始化方案使用相同任务数据、混合比例、历史长度、帧间隔及原始初始化权重。跨模型保留各自骨干、训练目标和优化器；这些结果可以比较能力获得程度，但不能单独分离某个架构部件的贡献。配对数和 epoch 数也不等于独立样本数或各数据成分的曝光量。

### 5.3 主要发现与解释边界

**训练方式影响条件信息能否转化为有效响应。** 在相同扩量数据与原始初始化下，PLDM Strength 的主分由原始权重初始化的 60.55% 提高到冻结 Encoder 后的 98.05%，Joint 由 17.97% 提高到 94.92%，响应分由 20.19 提高到 88.49。LeWM Friction 的主分也由 50.20% 提高到 87.50%。这些变化不能仅由数据量解释，说明原始表示中已有可用于这些任务的信息。

**冻结 Encoder 不是统一解法。** PLDM Damping 冻结后的主分从 77.54% 降至 56.05%，Gain 从 0.830 降至 0.135，响应分从 77.94 降至 11.78。LeWM Mass 的选择和响应指标也退步。表示更新是否有利取决于任务与模型，当前结果不能证明 JEPA 普遍阻碍 ICL。

**初始化的收益也随任务变化。** DINO-WM 完整原始权重初始化使 Speed 的未见插值明显改善，但 Damping 与 Cube 的条件响应仍较弱。该对照同时改变了预测器的初始状态与总训练经历，不能把全部收益归于某一个模块。

**选择正确未来、响应校准、外推和规划是不同能力。** DINO-WM Cube 从头训练的主分为 61.33%，Gain 却只有 0.095；LeWM / PLDM Speed 的插值接近满分，两侧外推仍明显不足。PLDM Strength 冻结后 ICL 提高，原环境 CEM 却由 72.00% 降至 59.33%；PLDM Damping 则出现 ICL 下降而 CEM 上升。因此，单独的高主分不能替代响应质量与规划指标。

ContextWorld 将这些差异转化为可比较的测量：同一当前画面和查询动作下，历史是否改变预测、变化方向和幅值是否正确、能力能否迁移。成功任务提供正对照，弱响应任务提供机制研究对象；某次训练失败不自动证明数据不可学。

根因仍需通过控制实验定位。冻结 Encoder 同时改变表示参数、训练态缓冲区和目标表示随训练变化的过程，现有结果尚未分离这些作用。Strength 的固定候选结果已覆盖多种训练方案并提供局部决策证据（§5.5）；其他任务与闭环控制的收益仍未验证。原环境 CEM 本身不提供隐藏动力学下的上下文收益结论。

### 5.5 条件预测与动作选择

**推手移动幅度（Strength）的候选动作实验。** 每个模型在同一组 256 对 Development 查询上，对 21 个固定候选动作评分。候选沿原查询动作方向取 0–1 的幅度，每个执行 5 个物理步；两种隐藏规律共用低增益条件下原动作的真实未来作为目标。模型使用预测未来与目标的 latent 距离选动作，随后用模拟器真实后果计算代价。

动作遗憾值（regret）等于所选候选的真实代价减去**同一条件、同一候选集**的最低代价，越低越好；单位为综合推手位置、物块位置与角度误差的像素等价距离。正确历史收益为“错误历史 regret − 正确历史 regret”，正值表示正确历史帮助选择了更好的动作。

“真实未来编码”直接编码模拟器给出的候选未来，再按相同 latent 目标距离选动作，绕过模型预测，是诊断参照。它与模型预测的 regret 差距用于判断预测路径带来的损失，不能单独定位某个预测器部件。若强制两种隐藏条件共用一个候选，即使知道真实代价，平均 regret 的下界也为 6.618。

区间为按查询对重采样的 95% bootstrap 区间，反映这些检查点在查询上的不确定性。错误历史来自另一隐藏规律的真实轨迹，查询时的状态与已执行动作匹配；本实验没有无历史控制。删除历史也可能删除速度等普通状态信息，不能把这类控制的全部收益自动归于动力学辨识。

**冻结 Encoder 的收益也出现在真实动作选择上。** LeWM 在相同原始权重初始化下冻结 Encoder 后，动作 regret 从 5.831 降至 4.804，配对下降量为 1.027，95% 区间为 [0.413, 1.675]；PLDM 从 11.838 降至 2.295，下降量为 9.543，[8.657, 10.446]。这支持这些检查点的条件预测改善具有局部决策价值。PLDM 的原环境 CEM 同时从 72.00% 降至 59.33%：隐藏规律下的决策收益和原有规划能力保持，需要分别评价。

这些结果衡量固定方向、短时域的局部决策，不代表完整动作空间或闭环 CEM 的成功率。目标分布和候选族对所有模型固定，但仍限定了结论的适用范围。[机器可读结果与协议](research/data/icl_action_selection_v1.json)提供检查点身份、面板身份和完整统计。

### 6.2 时间延迟动力学

<a id="task-action-delay"></a>

#### 6.2.1 动作延迟

##### 任务目标

模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

##### 数据构成

300 个查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

动作延迟有两个不同强度的评测问题，回答的研究问题不同，不能互相替代：

- **六组物理响应识别（正式指标）**：延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，
  各组在每个查询内等权宏平均，并报告最弱组表现。该指标判断模型是否区分六组一步响应，不区分 5–10 组内的延迟值。
- **二元历史响应诊断**：只判断预测在 delay=0 与 delay≠0（合并为一类）之间是否随历史
  正确切换，不要求区分不同的非零延迟。这是判断“历史是否引起了正确方向的条件差异”
  的更弱标准，主要用于快速诊断。

##### 适用范围

正式结果衡量 History=7 下六个一步物理响应组（0、1、2、3、4、5–10）的识别能力。
一步未来无法区分 5–10，因此不表示精确识别全部 11 档延迟；h2/h3 是辅助诊断，
不计入主分。也不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。二元诊断数值只说明
“有无延迟”的区分，不能单独支撑延迟识别结论。

## 7. 接入与复现

外部模型通过统一的 `LatentWorldModelAdapter` 提供图像编码与条件预测接口。输入只有图像和动作，输出为预测未来的 latent；评分器不要求图像解码器。接口形状、历史对齐和最小适配示例见[Adapter 规范](External_Model_Adapter_Contract.md)。数据加载见[HF 数据集指南](HF_Dataset_Export.md)，内置模型的训练与初始化参数见[训练指南](StableWM_Training.md)。

从可用数据包运行 Development 评测：

```bash
python -m contextworld.benchmarks.external_model_cli \
  --benchmark-root /path/to/ContextWorld-bundle \
  --evaluation-split development \
  --task action_strength \
  --adapter lewm \
  --checkpoint /path/to/weights.pt \
  --model-name my-model \
  --output /path/to/development-result.json
```

新模型沿用相同任务查询和评分方法。报告中注明数据版本与划分、训练数据比例、样本覆盖、初始化权重、更新模块、训练预算、种子、检查点和评测版本。若要声称某因素造成能力变化，应使用只改变该因素的对照；跨模型比较本身不能完成这种归因。

## 8. 可复现性与结果报告

原始结果的检查点与数据哈希用于追溯分数来源。主文档和 CSV 由同一份 JSON 自动生成，避免不同页面维护不同数值。冻结 v3 的数据、评分规则和三种子结果继续保留；新的训练数据与方法使用独立结果记录。

新结果以输入合法、数据隔离和评测时权重不变等协议要求作为有效性条件。模型与训练方案在 Development 上确定后，Test 应报告同一预先确定的任务集合，包括低分结果；Development 能力门是否通过不作为 Test 报告的前提。能力门作为补充描述保留，不能替代连续成绩。参考附录中按旧准入流程产生的 v3 结果保持原样，不与新的报告规则混写。

本表的完整权重和逐查询输出尚无稳定公共下载，当前公开汇总不足以支持外部完整复现。HF 数据集的准备状态及加载约束见[发布说明](Expanded_Training_Release.md)。数据包可获取性与模型能力结果是两个独立问题。

## 9. 适用范围与限制

ContextWorld 的九任务主评测衡量固定权重下的条件预测：模型是否识别历史中的规律，是否产生方向与幅值正确的响应，以及是否泛化到新的场景或参数范围。§5.5 另提供 Strength 固定候选集内的决策证据；这些结果尚不证明长期 rollout、完整动作空间优化或闭环控制能力。

这些结果来自 Development，按相同实验配置汇总全部可用训练重复；各配置的重复数并不相同。分数用于描述能力变化并定位机制问题。响应指标在各检查点自己的 latent 空间中归一化，不是共享物理单位的预测误差。

## 10. 比较与版本管理

新结果应引用明确的数据版本、训练方案和评测划分。相同任务定义与评分协议下可以比较新模型或训练方法；改变查询分布、任务定义或评分规则时，应记录新的 benchmark 版本。冻结 v3 的数值保存在[参考附录](reference/Benchmark_Result_Provenance.md)，不以新实验覆盖历史结果。

## 11. 开放研究问题

**条件预测怎样转化为决策收益？** Strength 的固定候选结果表明，正确历史能够改善部分模型的动作选择；尚不清楚这种收益能否覆盖其他隐藏规律、目标分布与较长规划时域。固定候选评测可以隔离模型对动作后果的评价，闭环评测则进一步考察搜索、历史更新与真实执行。两者需要相同初始条件和计算预算下的历史对照。

**为什么固定表示对不同任务产生相反影响？** §5.6 中，Strength 的联合训练表现出后期泛化退化，Damping 冻结 Encoder 后，即使在训练样本上也响应偏弱。第二阶段表示更新的作用依赖任务。同起点、同数据和同预算的干预，才能进一步区分表示参数、归一化状态与预测目标的作用；当前结果尚不能唯一归因到某个模块或损失。

**数据覆盖与训练方式如何共同决定能力？** 扩量缓解了部分条件下的泛化退化，但未消除模型之间及训练方式之间的差异。建立缩放规律需要分别控制独立场景覆盖、样本重复次数、优化步数与模型规模；当前几档数据结果提供了研究线索，尚不足以确立普适规律。
