# ContextWorld：Latent 世界模型的上下文学习评测

ContextWorld 用于评测 latent 世界模型能否从最近几步交互中识别隐藏的环境规律，并据此预测下一状态。模型在测试时不更新参数，也不能读取模拟器中的速度、门规则、动作延迟或物体质量等隐藏变量。

本项目主要面向 JEPA、LeWM 和 PLDM 等 latent 世界模型。评测不要求图像解码器，也不使用像素重建质量作为分数。协议定义训练、开发和冻结测试划分，并提供评分程序、参考基线和数据完整性审计；测试数据的公共下载和部分参考运行仍受发布门限制。

当前状态：九项任务的源码、配置、评分器和本地审计接口已具备技术运行条件；Public Test
是协议中的冻结测试划分，当前不可公开下载。完整评测只面向已获授权并持有冻结工件的
使用者；Public v1 的许可证、可下载工件和正式发布决定尚未完成。

## 1. 快速开始

以下命令安装软件并检查本地已有工件；它们不会下载 Benchmark 数据或正式 checkpoint。
完整评测需要使用者自备或获授权取得冻结工件，公共下载将在 Public v1 正式发布后另行提供。

读取冻结数据并运行完整审计时安装 eval 依赖：

```bash
pip install -e ".[eval]"

contextworld-benchmark info
contextworld-benchmark results
contextworld-benchmark audit --full
```

若只需要读取 YAML 配置并使用通用 adapter 接口，可安装核心包：`pip install -e .`。
组件级 `load_*_release`、冻结数据读取、重评分和审计需要下述 eval 依赖。

使用仓库内置的 LeWM 或 PLDM adapter 还需要安装 `pip install -e ".[stablewm]"`；该 extra
已经包含 eval 依赖。评测时选择对应任务，并提供模型适配器和检查点。下面以 PushT
推手移动幅度为例：

```bash
contextworld-action-strength eval \
  --adapter lewm \
  --checkpoint /path/to/model.ckpt \
  --model-name my-model \
  --output /path/to/result.json
```

内置 adapter 默认使用该任务 release 中登记的 Stable-WorldModel checkout 和 commit。如果
源码位于其他目录，可用 `--stablewm-repo /path/to/stable-worldmodel` 指定位置；加载时仍会
核对 release 要求的 commit，不能用任意安装版本替代冻结训练配置。

九项任务的命令按能力类型排列如下：

| 能力类型 | 任务 | 命令 |
|---|---|---|
| 即时连续响应 | TwoRoom 速度 | `contextworld-speed` |
| 即时连续响应 | PushT 推手移动幅度 | `contextworld-action-strength` |
| 即时连续响应 | Reacher 机械臂质量 | `contextworld-reacher-arm-mass` |
| 时间延迟动力学 | TwoRoom 动作延迟 | `contextworld-action-delay` |
| 接触或附着条件动力学 | PushT 接触摩擦 | `contextworld-contact-friction` |
| 接触或附着条件动力学 | PushT 运动阻尼 | `contextworld-motion-damping` |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | `contextworld-cube-gripper-carry` |
| 隐藏结构转移规则 | TwoRoom 门通行规则 | `contextworld-door` |
| 隐藏结构转移规则 | TwoRoom 传送门出口位置 | `contextworld-portal-exit` |

每个正式任务命令均提供 `info`、`audit` 和 `eval`；部分任务还提供方法级 `score`、
`train-plan` 或训练脚本的 `--dry-run`：

- `info`：查看数据、评分规则和通过标准；
- `audit --full`：校验数据、代码和结果文件；
- `eval`：评测指定模型；
- `train-plan` 或训练脚本的 `--dry-run`：查看参考训练配方，不启动训练。

## 2. 能力分类与任务地图

ContextWorld 目前在四个环境中评测九种隐藏规律。任务按模型需要从历史中识别的因果变化
组织，而不是按环境数量组织。下面四类只用于说明研究问题和安排阅读顺序，不构成分数
权重、排行榜分组或跨任务总分。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要从历史中判断什么 | 训练后参考方法状态 |
|---|---|---|---:|---|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 | LeWM、PLDM 均在训练范围内通过；原任务 CEM 均保持 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 同一指令让推手移动较短还是较远 | LeWM 通过；PLDM 未通过（0/3） |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 相同力矩下机械臂较轻还是较重 | LeWM 通过，PLDM 未通过 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 | PLDM 通过，LeWM 未通过 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时的摩擦较小还是较大 | LeWM、PLDM 均未通过 Development |

| 隐藏结构转移规则 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 | LeWM、PLDM 通过；规划能力未保持 |

被解读为同一类能力的重复计数。

“训练后参考方法未通过”不表示任务不能执行。九项任务都提供数据、评分接口和审计；该状态
只说明仓库附带的方法尚未满足对应任务的门槛。它也不同于第 5.1 节的原始单-checkpoint
描述性基线。ContactFriction 和 MotionDamping 的模型评分仍停留在 Development，Public
保持未读、未评分；Cube 当前只有训练后 LeWM 的正式 Public reference。

## 3. 评测协议

### 3.1 模型输入与输出

每个样本由历史上下文（History）和待预测状态（Query）组成：

- 历史上下文包含最近的真实画面和已经执行的动作，用于展示隐藏规律造成的物理响应；
- 待预测状态包含当前画面和下一步动作；
- 模型输出执行该动作后的未来 latent。

模型不能读取隐藏规律的名称或数值，也不能在评测过程中更新权重。只有当预测随历史中展示的规律改变，并接近模拟器产生的真实未来，才算正确。

### 3.2 连续的真实轨迹

一步配对任务使用以下因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器连续向前执行。`x1`、`x2` 和 `x3` 不能通过瞬移、手工写入状态或重新创建模拟器得到。

一对样本分别使用两种隐藏规律。两条轨迹在查询时具有相同的当前状态 `x2`、查询动作 `u2` 和可见输入，但产生不同的真实未来 `x3`。模型必须利用历史中的物理响应区分两种规律。

部分任务不要求两条轨迹共享 `x0`。遇到这种情况，数据生成器会交换两种规律的起点，并检查仅凭起点无法预测标签，防止模型利用无关线索。

### 3.3 数据划分

- **训练集（Training）**用于训练模型；
- **开发集（Development）**用于选择训练配方和超参数；
- **冻结测试集（Public Test）**用于报告最终结果。Public Test 是协议名称；当前公共下载和
  部分参考运行授权仍受 [Public v1 发布准备清单](ContextWorld_Public_v1_Release_Readiness.md)
  所列发布门限制。

三个划分的场景、生成模板和查询哈希互不重叠。冻结测试集不应参与模型选择或反复调参。

TwoRoom 任务常用六个数据生成种子，每个种子生成 50 个场景，共 300 个不同的查询。这里的种子用于生成不同的位置、方向和房间结构，不是对同一个查询重复加噪声。

PushT、Reacher 和传送门出口位置任务通常包含 256 对查询。每对查询各有两种隐藏条件，因此每个模型检查点需要完成 512 次条件预测。

## 4. 评分方法

### 4.1 Decoder-free latent 评测

评测直接比较预测 latent 与真实未来的 latent：

```text
历史上下文 + 当前画面 + 动作 ──被测模型──> 预测 latent z_hat
模拟器真实下一帧 ──该模型的冻结目标编码器──> 目标 latent z
```

真实下一帧已保存在测试集中，单步预测评测不需要在线运行模拟器。评分器只调用模型的编码器和 latent 预测器，不调用图像解码器。

不同模型可以使用不同维度和尺度的 latent。距离只在同一个模型检查点的 latent 空间内计算，随后转换成任务正确或错误。不同模型的原始 latent MSE 没有共同单位，不能直接比较。

### 4.2 ICL 正确率

每个测试查询产生一个任务层面的正确或错误判断，所有查询的平均值即为 ICL 正确率：

- 两种隐藏规律的配对任务：预测是否更接近当前规律对应的真实未来；
- 门通行规则：预测是否更接近真实的“通过”或“被阻挡”结果；
- 动作延迟：预测是否属于真实下一步对应的物理响应组；
- 速度：由真实速度生成的历史是否同时优于另外两档速度历史。

本文中的 H1 指一步预测（one-step forecast）；例如速度任务的 H1 指对查询动作后的下一状态作出判断。

同一任务中，不同模型使用完全相同的冻结测试查询，因此正确率可以直接比较。若要声明模型 A 优于模型 B，还需要对相同查询的成对结果进行 bootstrap；只有正确率差的 95% 置信区间下界大于 0，才认为 A 稳定优于 B。

不同任务测量的能力和难度不同。ContextWorld 分别报告每项任务，不计算跨任务平均分或 Suite 总分。

### 4.3 评分有效性

正确率之外，评分程序还会检查：

- 两种真实未来在被测模型的 latent 中能够区分；
- 改变历史上下文会改变模型预测；
- 预测变化的方向与真实未来一致；
- 最弱隐藏条件和不同方向的样本均达到最低要求。

连续配对任务还会使用同一模型检查点的真实目标响应对预测响应进行归一化。该检查可以排除“模型几乎不使用历史，只因距离微小差异碰巧选对目标”的假阳性。归一化响应和原始 latent 误差用于验证分数是否可信，不用于跨模型排名。

### 4.4 多训练种子与规划能力

参考训练方法使用三个独立训练种子。三个模型检查点分别评分，只有三者都达到任务标准，才记为该方法通过。结果中的“3/3”表示三个检查点分别通过，而不是把三个检查点的预测合并后计算一次分数。

对于包含规划的环境，Benchmark 还报告原任务的 CEM 规划保持结果：

- ICL 正确率衡量模型是否根据历史识别了隐藏规律；
- CEM 成功率衡量加入新训练数据后，原有规划能力是否明显退化。

两项结果分别报告，不合成为一个分数。某个方法可能学会隐藏规律，但同时损害原任务规划能力。
表中的“保持”表示结果没有超过该任务预注册的允许下降，不表示成功率完全没有下降。

## 5. 参考结果

参考结果分为三类，回答三个不同问题：原始模型的 ICL 起点、原始环境的规划起点，以及训练
后方法是否稳定学会目标规律。三类证据不能互相补足，也不能合并为总分：

- **原始 ICL 矩阵**：TwoRoom、PushT、Reacher、Cube 各固定一枚 LeWM 和一枚 PLDM，
  共 8 个只用原环境数据训练的检查点。同一检查点可用于该环境的多个能力项，
  但每项仍只是单检查点的描述性结果；
- **原始 CEM 矩阵**：对同一批原始配方按 4 个原始环境各执行规划评测，每个族覆盖
  3 个训练种子（3072/3073/3074）、每个种子 300 次，报告均值 ± 样本标准差。
  这是环境级结果，不按能力项复制计分；
- **训练后参考结果（trained reference）**：按各能力协议训练，正式方法通常使用 3 个独立
  检查点，并要求逐检查点过门。原始矩阵的一项不是训练后方法的一个训练种子，不能据此
  生成“3/3”、正式参考结果、榜单条目或 CEM 结论。

原始 ICL 与原始 CEM 分别预注册、分别冻结，只提供描述性基线，不增加正式榜单条目。
第 2 节是九项任务的读者摘要；5.1 和 5.2 是描述原始模型起点的技术基线，5.3 才汇总
训练后参考运行。5.1 和 5.3 按能力类型排列；5.2 报告环境级 CEM，因此按原始环境排列。

### 5.2 冻结原始环境 CEM 矩阵（4 个环境 / 8 个基线族）

这张表使用与 5.1 同源的原始检查点，但按原始环境评测，而不是按能力项重复评测。
每个族现在报告 3 个独立训练种子（3072/3073/3074）各 300 次规划评测的均值 ± 样本标准差
（ddof=1），共 24 个 cell、7200 次评测。早期的单检查点数值作为历史列保留在
`complete_comparison_v2.json` 的每一行里，便于回溯。

“族”指同一训练配方下的 3 个训练种子；“±”是这 3 个种子之间的样本标准差，衡量配方
对训练种子的敏感度，**不是**同一检查点内部的评测噪声。每个种子的 300 次评测按环境
拆分：TwoRoom 与 PushT 为 6 个 eval seed（42–47）× 50 次，Reacher 与 Cube 为 3 个
eval seed（42–44）× 100 次。CEM 规划参数全环境一致：300 candidates、30 iterations、
topk 30、History=3、action block 5、goal offset 25、budget 50。

这些基线检查点的来源见 5.1：由本仓库在 LeWM 公开数据集上按其基线配方训练 10 epochs，
不做微调、继续训练或按分数挑选检查点。评测前后都会
核对权重的 state-dict SHA-256，确认规划过程没有改动模型（逐 cell 记录见
`family_summary.json` 的 `model_state_audit`）。

### 5.5 结果解释与冻结边界

三层结果分别支持不同结论：原始 ICL 只描述一枚冻结 checkpoint 在各任务上的起点；原始
CEM 只描述同一 checkpoint 在原环境中的规划起点；训练后 reference 才按任务协议和多个
训练种子判断方法是否学会目标规律、是否达到规划保持门。任何一层都不能补成另一层的
缺失结果，也不能跨任务或跨环境求平均。

正式 reference 与外部模型结果使用不同输出身份。外部模型可以运行相同离线评分协议，
但不能改写冻结 reference 或正式 scoreboard。Public Test 只能在模型、适配器、训练预算、
checkpoint 选择和 Development 结论冻结后读取；ContactFriction、MotionDamping 和训练后
Cube PLDM 当前都没有新的 Public 授权。ActionDelay 的原始结果只代表 tail-H3 投影，不是
原生 History=7 baseline；共享 TwoRoom CEM 也不是 History=7 闭环规划结果。

速度 PLDM 的 action-planning CEM 是无性能门的描述性诊断；只有单独的配对 retention CEM
用于判断原 TwoRoom 规划能力是否保持。两类 CEM 不得互相替代。

任务配置、评分代码和结果文件均接受一致性校验；任一文件不一致时，完整性审计不会通过。

## 6. 任务定义

任务按第 2 节的能力类型组织。每张任务卡都按相同的五个问题说明：模型要从历史中识别什么、
数据怎样构成、怎样评分、现有参考方法表现如何，以及结果能说明什么。

### 6.1 即时连续响应

这组任务考察：在其他可见条件相同的情况下，模型能否从最近的运动响应判断连续动力学参数。

#### 6.1.1 速度

##### 任务目标

模型根据最近两次移动，判断相同动作在当前 TwoRoom 环境中会移动多远。

##### 数据构成

参考配方将原 TwoRoom 数据与 32 档合成速度数据各占一半。冻结测试分为训练中见过的速度、训练范围内未见速度、低于训练范围和高于训练范围四组；每个参考速度包含 300 个不同查询。

##### 评测方法

主判定是训练范围内未见速度的一步严格正确率：真实速度生成的历史必须同时优于另外两档速度历史，并在不同参考速度和数据生成种子上保持一致方向。若要把提升归因于多速度训练，三个多速度模型还必须分别优于同种子的单速度对照模型。1、2、3、5 步真实 latent 预测与 50、75、100 步 CEM 仅作多步预测和规划诊断。

##### 基线表现

冻结原始 LeWM 在未见插值速度 H1（一步预测）的严格正确率为 59.33%，训练中见速度为 59.56%；原始 PLDM 为 51.44% 和 53.33%。两者的高、低范围外推均未通过。独立冻结的原始 TwoRoom CEM 族基线为 LeWM 92.44% ± 0.51pp、PLDM 90.56% ± 5.17pp（各 3 个训练种子 × 300 次；早期单检查点值 273/300 与 278/300 见 5.2），是环境级基线。

训练后的三个多速度 LeWM 正确率为 94.89%、95.00% 和 95.89%，平均 95.26%，且均优于同种子的单速度对照模型；其原 TwoRoom CEM 为 289/300、284/300 和 290/300，均保持基础规划能力。低于和高于训练范围的平均正确率为 26.19% 和 25.19%，均未通过。

三个 PLDM 检查点在训练范围内未见速度的一步严格正确率分别为 97.22%、96.44% 和
96.44%（平均 96.70%），均通过 checkpoint 级门槛；已见速度平均为 98.19%。低于和高于
训练范围的平均正确率分别为 26.28% 和 25.39%，均未通过。因此，该结果是冻结 History=3
协议下的行为性参考结果，只支持训练范围内的未见速度插值。

PLDM 的 action-planning CEM 成功率为 70.33%、71.67% 和 66.67%（平均 69.56%）。该运行
用于描述规划表现，没有性能通过门。独立的原任务 TwoRoom 配对 retention CEM 为 94.33%、
94.33% 和 95.67%（平均 94.78%）；三枚检查点均通过成功率非劣、最终距离非劣和可解房间
关系分层不坍塌三项门槛，因此在该冻结协议下判定为保持。由于没有同种子的单速度 PLDM
训练对照，这些观察结果不能归因于多速度训练。

##### 适用范围

LeWM 和 PLDM 的结果支持 History=3 下的训练范围内速度适应和未见速度插值，不代表能够
外推到任意速度；其中只有 LeWM 具备同种子的单速度训练对照，PLDM 不支持训练因素的因果
归因。

#### 6.1.2 推手移动幅度

##### 任务目标

模型根据近期交互判断同一个二维动作会让 PushT 推手移动较短还是较远。两档环境参数为 60 和 140。

##### 数据构成

训练集包含 2,048 对场景，开发集和冻结测试集各包含 256 对。参考配方混合原 PushT 数据与配对移动幅度数据；所有保存状态均来自连续模拟器轨迹。

##### 评测方法

主要指标是模型在两档条件下选择真实下一状态的正确率。评分程序同时验证历史使用、预测切换、最弱条件和 latent 响应。标准 PushT CEM 对每个模型检查点运行 300 次，规划保持标准为至少 210/300。

##### 基线表现

冻结原始 PushT LeWM 和 PLDM 的 ICL 正确率分别为 49.80% 和 43.55%，均未通过；共享的原始 PushT CEM 族基线为 82.22% ± 3.69pp 和 75.67% ± 2.40pp（早期单检查点值 235/300 和 233/300 见 5.2）。加入移动幅度数据后，三个 LeWM 的正确率为 97.07%、96.48% 和 96.29%，平均 96.61%，均通过；其 CEM 为 224、216、232/300，均保持基础规划能力。相同数据上的 PLDM 三枚检查点为 94.34%、93.95% 和 94.53%，平均 94.27%；三者均低于每枚检查点 95% 的门槛，因此正式判定为 0/3 未通过，并按预注册顺序停止在 ICL，不运行训练后 CEM。

##### 适用范围

该结果验证两档推手移动幅度的一步适应，不验证连续幅度估计、范围外外推或其他 PushT 动力学。

#### 6.1.3 机械臂质量

##### 任务目标

模型根据相同力矩下的近期运动，判断 Reacher 机械臂的主体与末端较轻还是较重。两档密度为 500 和 1500；环境改变 `arm` 主体连杆和 `finger` 末端球，`hand` 第二连杆保持原始密度。

##### 数据构成

训练集包含 2,048 对场景，开发集和冻结测试集各包含 256 对。配对查询共享当前画面、完整状态和查询动作，历史与真实下一状态展示两档质量的不同响应。

##### 评测方法

主要指标是模型选择真实下一状态的正确率。评分程序还检查正确历史、预测切换、最弱质量条件、bootstrap 和 latent 响应。三个训练种子必须分别达标。标准 Reacher CEM 相对对应基础模型最多允许减少 15/300 次成功。

##### 基线表现

冻结原始 LeWM 和 PLDM 的 ICL 正确率为 50.00% 和 52.93%，原始 Reacher CEM 族基线为 55.89% ± 1.07pp 和 69.67% ± 20.25pp（早期单检查点值 164/300 和 248/300 见 5.2）。使用质量数据训练后，LeWM 三个正确率为 76.17%、76.56% 和 75.59%，均通过，CEM 为 163、163、160/300，均保持规划能力；PLDM 为 63.48%、62.70% 和 63.28%，均未通过，训练后 CEM 未评测。

注意 Reacher PLDM 基线族的离散度极大（248、240、139/300，±20.25pp）。把训练后 PLDM
与单一的 248/300 相比会显著高估退化幅度；该族的基线区间本身就跨越 46.33%–82.67%。

##### 适用范围

该结果验证两档机械臂质量的一步 ICL，不验证连续质量估计、范围外外推或多步闭环控制。

### 6.2 时间延迟动力学

这组任务考察模型是否能把较长的动作—响应历史与当前的延迟状态对应起来。

#### 6.2.1 动作延迟

##### 任务目标

模型根据较长历史判断动作等待多少步才生效，并预测下一步真实物理响应。延迟范围为 0 至 10 个原始环境步。

##### 数据构成

任务使用 History=7。训练先覆盖差异明显的延迟 0、4、8，再覆盖完整的 0 至 10。冻结测试集包含 300 个不同查询，每个查询保存 11 种延迟的真实轨迹。

##### 评测方法

根据真实下一步结果，将延迟分为 0、1、2、3、4 和 5–10 六个物理响应组。六组在每个查询内等权，再对 300 个查询求平均。通过标准为总体正确率至少 75%、最弱组至少 60%、配对 bootstrap 下界至少 70%，并要求三个训练种子分别满足标准。

##### 基线表现

冻结原始 LeWM/PLDM 均为原生 History=3 checkpoint，因此原始结果只在 H7 评分器中使用对齐的最后三帧和最后五个 action block；两者 physical-group macro 均为 16.67%，最弱组为 0，均未通过。这是 tail-H3 投影的零样本结果，不是原生 History=7 baseline。共享的 History=3 TwoRoom CEM 族基线为 LeWM 92.44% ± 0.51pp、PLDM 90.56% ± 5.17pp，也不构成 History=7 闭环规划结果。

使用动作延迟数据训练后，两阶段 PLDM 的三个正确率为 93.06%、93.22% 和 93.81%，均通过；使用相同数据和训练预算的 LeWM 为 33.00%、32.11% 和 32.17%，均未通过。训练后 LeWM CEM 为 292、292、292/300，PLDM 为 285、292、289/300，均保持原任务规划能力。

##### 适用范围

该结果验证 History=7 下的一步延迟响应，不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。

### 6.3 接触或附着条件动力学

这组任务考察决定性差异只在接触、脱离或夹持条件下出现时，模型能否利用历史而非当前画面作出预测。

#### 6.3.1 接触摩擦

##### 任务目标

模型根据推手与物体接触时的历史响应，判断接触摩擦较小还是较大。两档摩擦系数为 0.05 和 0.80，运动阻尼保持不变。

##### 数据构成

数据集包含 8,192 对训练样本、256 对开发样本和 256 对冻结测试样本。配对查询的当前完整物理状态误差不超过 `1e-5`，三个划分之间没有查询或生成模板重叠。

##### 评测方法

主要指标是模型选择真实下一状态的正确率。开发集还要求正确历史、预测切换和最弱摩擦条件分别达标。当前参考方法未通过开发门，因此不读取 Public Test，也不运行训练后 CEM。

##### 基线表现

冻结原始 PushT LeWM/PLDM 的真实未来正确率为 49.61% 和 50.00%；原始 PushT CEM 为
235/300 和 233/300，是独立的环境级基线。当前 LeWM 与 PLDM 参考配方均未通过
Development 的全部预设检查，因此没有 Public Test 结果，也未进入训练后 CEM。详细诊断
保留在机器可读结果与复现材料中。

##### 适用范围

数据、评分程序和因果审计可用于评测新模型；现有结果不能说明当前 LeWM 或 PLDM 参考配方已稳定学会接触摩擦 ICL。

#### 6.3.2 运动阻尼

##### 任务目标

PushT 是零重力平面。该任务根据接触结束后的运动历史，判断物体减速较快还是较慢。两档阻尼为 0.2 和 1.0，接触摩擦保持不变。

##### 数据构成

数据集包含 8,192 对训练样本、256 对开发样本和 256 对冻结测试样本。配对场景在查询时具有相同的 12 维物理状态、画面和动作；正反样本交换起点，使仅凭起点预测标签的准确率为 50%。全部 17,408 条条件均可由干净模拟器重放。

##### 评测方法

主要指标是模型选择真实下一状态的正确率。开发集还要求正确历史、预测切换和最弱阻尼条件达标。当前参考方法未通过开发门，因此不读取 Public Test，也不运行训练后 CEM。

##### 基线表现

冻结原始 PushT LeWM/PLDM 的真实未来正确率为 50.00% 和 50.39%；原始 PushT CEM 为
235/300 和 233/300，是独立的环境级基线。当前 LeWM 与 PLDM 参考配方均未通过
Development 的全部预设检查，因此没有 Public Test 结果，也未进入训练后 CEM。详细诊断
保留在机器可读结果与复现材料中。

##### 适用范围

任务数据、评分程序和历史可观测性已通过审计；现有结果不能说明当前 LeWM 或 PLDM 参考配方已稳定学会运动阻尼 ICL。

#### 6.3.3 Cube 夹爪携带规则

##### 任务目标

模型根据最近三帧中夹爪与方块的响应，判断当前隐藏规则是夹爪不能携带方块（`cannot_hold`）还是能够携带方块（`can_hold`），并预测共享 query 动作对应的真实下一状态。

##### 数据构成

v4r1 包含 2,048 个 Training 配对、256 个 Development 配对和 256 个 Public Test 配对。四类动作模板在每个划分中严格均衡；三个划分的源轨迹、动作模板、场景、配对内容和 query 画面互不重叠。每对样本共享 query 状态、画面和动作，只改变历史中展示的携带规则。精确扰动约束记录在任务 release 配置中。

##### 评测方法

每个检查点必须同时满足真实未来正确率至少 75%、正确历史至少 75%、上下文切换至少 90% 和最弱规则至少 70%。评分还会排除两种真实未来不可区分、模型没有使用历史或预测变化方向错误等假阳性；方法级要求三个检查点全部通过。通过 Development 的模型族还要在 300 个共享 query 上完成原 Cube CEM 留存，每个候选最多允许比原始基线少 15 次成功。外部模型使用独立结果身份，不得改写正式参考结果。

##### 基线表现

独立 v4r1 描述性基线显示，冻结原始 Cube LeWM 和 PLDM 的真实未来正确率均为 50.98%，原始 Cube CEM 分别为 198/300 和 159/300；这些结果不进入正式 scoreboard。训练后 LeWM 三个 Public 正确率为 77.73%、79.10% 和 78.52%，平均 78.45%，全部通过；CEM 为 186、183、185/300，相对原始 LeWM 分别变化 -12、-15、-13，均通过留存门。PLDM 在 Development 为 50.20%、50.20% 和 50.00%，0/3 未通过，未进入 Public，也未运行训练后 CEM。

##### 适用范围

当前正式结果只验证二值夹爪携带规则的一步 Public ICL 和原 Cube 规划能力保持，不验证连续夹持强度、范围外规则或多步闭环适应。公开分发仍须补齐许可证和稳定下载地址。

### 6.4 隐藏结构转移规则

这组任务不以连续参数大小为线索，而是要求模型从历史中识别离散的空间转移规则。

#### 6.4.1 门通行规则

##### 任务目标

模型根据历史中的穿门或碰壁结果，判断外观相同的门在当前环境中能否通过。

##### 数据构成

训练集覆盖 96 个门位置，开发集覆盖 16 个门位置，冻结测试集使用训练中从未出现的 42 个门位置。冻结测试集包含 300 个不同场景，两个穿门方向各占一半。

##### 评测方法

每个查询保存模拟器真实产生的“可通过”和“被阻挡”下一帧。主要指标是模型选择真实结果的正确率。评分程序还检查两种结果在 latent 中可分、历史确实改变判断，并分别验证两个穿门方向。原 TwoRoom CEM 对每个模型检查点评测 300 个相同查询，允许的最大下降为 15 次成功。

##### 基线表现

冻结原始 LeWM 和 PLDM 的 two-target 正确率均为 50.00%，均未通过；原始 TwoRoom CEM 为 273/300 和 278/300。使用门数据训练后，LeWM 达到 100.00%，PLDM 达到 99.33%，两个方法的三个训练种子均通过 ICL。但 LeWM 的 CEM 为 197、189、187/300，PLDM 为 135、132、146/300，均未达到 258/300 的规划保持标准。

##### 适用范围

该任务验证一步门规则判断，不验证多步闭环穿门规划。当前参考训练方法会显著损害原 TwoRoom 规划能力。

#### 6.4.2 传送门出口位置

##### 任务目标

模型根据历史中的传送结果，判断进入同一个入口后会从靠近边界还是离边界更远的位置出现。

##### 数据构成

训练集包含 2,048 对场景，开发集和冻结测试集各包含 256 对。两种规律各自从真实起点连续向前执行，在查询前汇合到相同当前状态；相同当前画面和动作随后对应两个模拟器真实出口。

##### 评测方法

主要指标是模型选择真实出口下一状态的正确率。评分程序还检查正确历史、预测切换、最弱出口条件、bootstrap 和 latent 响应。三个训练种子需要分别达到标准。原 TwoRoom CEM 最多允许比基础模型减少 15/300 次成功。

##### 基线表现

冻结原始 LeWM/PLDM 的 ICL 正确率为 50.00% 和 50.20%，均未通过；共享的原始 TwoRoom CEM 为 273/300 和 278/300。使用出口位置数据训练后，LeWM 三个正确率为 85.55%、83.20% 和 83.01%，PLDM 为 59.77%、58.59% 和 59.57%，均未通过完整标准。LeWM 的 CEM 为 276、271、266/300，均保持规划能力；训练后 PLDM CEM 未评测。

##### 适用范围

该任务已具备训练和评分条件，但当前参考方法尚未稳定解决。它不验证连续出口坐标、范围外出口或多步传送规划。

## 7. 接入新的 latent 世界模型

### 7.1 通用 adapter 接口

外部模型只需实现一个
`contextworld.benchmarks.adapters.LatentWorldModelAdapter`，不需要为九项任务分别编写
adapter。接口提供：

- `encode_pixels`：使用模型的冻结目标编码器，将真实未来画面编码为目标 latent；
- `rollout_latents`：根据历史上下文、当前画面和查询动作预测未来 latent；
- `protocol`：声明历史长度、动作组织方式和预测步数；
- `metadata` 和 `frozen_state_hash()`：记录模型身份，并确认评测前后权重没有变化。

任务评分器只检查四项输入输出兼容性：历史长度、每个 action block 包含的原始动作步数、
动作维度，以及至少可预测的 future block 数。它不要求模型属于 LeWM 或 PLDM，也不限制
latent 维度、图像解码器、网络结构或深度学习框架。旧的按任务 adapter 类名只为兼容已有
代码保留，不是新的集成要求。

该接口目前是 Python scorer API 的公共边界；九个命令行入口只内置 `lewm` 和 `pldm`。
外部模型应在 Python 中构造 adapter 并调用相应 scorer；当前不提供自定义 adapter 的 CLI
插件加载。

跨模型比较必须使用相同冻结测试集和相同查询 ID 的任务正确率。请勿直接比较不同模型的原始 latent MSE。

### 7.2 安装范围

```bash
# 读取 YAML 配置并使用通用 adapter 接口
pip install -e .

# 冻结数据读取、结果重评分与审计
pip install -e ".[eval]"

# 随仓库提供的 Stable-WorldModel LeWM / PLDM adapter
pip install -e ".[stablewm]"

# 测试与开发工具
pip install -e ".[dev]"
```

这些 extras 只安装 Python 软件依赖，不包含数据或 checkpoint。`.[stablewm]` 提供可安装的
运行时；正式 checkpoint 审计仍需要各任务 release 指定的 Stable-WorldModel 源码 checkout
和 commit，以便按对应训练配置严格加载历史权重。

contextworld-scoreboard \

## 9. 适用范围与已知限制

ContextWorld 的结论仅覆盖本文列出的环境、隐藏规律、历史长度和参数范围。当前任务不用于证明：

- 一个模型能够同时解决全部九项能力；
- 模型能够处理多种隐藏规律同时变化；
- 模型能够外推到任意未见参数；
- 一步预测能力必然转化为所有任务上的闭环规划能力。

冻结测试集用于最终结果报告，不应替代开发集进行调参。当前仓库可完成本地技术审计和导出；公开分发前还需要补充代码与生成数据许可证以及稳定下载地址。
