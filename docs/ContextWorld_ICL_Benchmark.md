# ContextWorld：Latent 世界模型的上下文学习基准

ContextWorld 评测世界模型能否从最近几步真实交互中识别隐藏动力学，并据此预测未来。模型只接收图像与动作，评测时不更新权重；预测和真实未来在参评模型自己的表示（latent）空间中比较，不要求图像解码器。

本文围绕三个问题组织结果：**模型利用历史区分了不同未来吗？恢复了多少条件响应？这些信息帮助它选出更好的动作了吗？** 九任务主评测回答前两个问题；推手移动幅度与速度的候选动作实验，以及速度的小规模闭环实验，检验决策收益。原环境 CEM 另行衡量原有规划能力保持，不代表隐藏动力学下的规划收益。

| 评测 | 回答的问题 | 当前结果范围 |
|---|---|---|
| 九任务 ICL | 历史利用与条件响应学到了多少？ | 各任务的固定 Development 查询；总表与任务子表 |
| 原环境 CEM | 原有规划能力是否保持？ | 四个原环境；与各任务 ICL 在总表中并列 |
| 固定候选动作 | 匹配历史能否帮助选出更好的动作？ | 推手移动幅度与速度；5 个物理步的局部选择 |
| 隐藏速度下的闭环 CEM | 初始历史证据能否改善执行和重规划？ | 6 个场景的初步实验，未覆盖全部 300 个场景 |

CEM（交叉熵方法）在模型预测上搜索动作序列。不同评测的任务、目标和统计单位不同，应在各自固定条件内比较结果。

阅读顺序：[任务与数据](#1-benchmark-概览) → [评分方法](#4-评测指标) → [训练方案](#training-schemes) → [九任务总表](#training-comparison)与[主要发现](#53-主要发现与解释边界)。具体任务的完整指标见 §6；接入与复现见 §7–8。数据合成细节见[数据生成方法](Data_Generation.md)。

## 1. Benchmark 概览

ContextWorld 包含九项任务，覆盖四类需要从历史中推断的动力学变化。任务按能力类型组织，
九项任务分别报告 ICL 与原环境 CEM，用于比较模型在具体任务上的能力。

| 能力类型 | 任务 | 环境 | 历史长度 | 模型需要判断什么 |
|---|---|---|---:|---|
| 即时连续响应 | 速度 | TwoRoom | 3 | 相同动作会移动多远 |
| 即时连续响应 | 推手移动幅度 | PushT | 3 | 相同动作会让推手移动较短还是较远 |
| 即时连续响应 | 机械臂质量 | Reacher | 3 | 质量如何改变机械臂对力矩的响应 |
| 时间延迟动力学 | 动作延迟 | TwoRoom | 7 | 动作等待多少步才生效 |
| 接触或附着条件动力学 | 接触摩擦 | PushT | 3 | 接触时摩擦如何改变运动 |
| 接触或附着条件动力学 | 运动阻尼 | PushT | 3 | 脱离接触后运动衰减得快还是慢 |
| 接触或附着条件动力学 | Cube 夹爪携带规则 | Cube | 3 | 闭合夹爪能否携带方块 |
| 隐藏结构转移 | 门通行规则 | TwoRoom | 3 | 外观相同的门能否通过 |
| 隐藏结构转移 | 传送门出口位置 | TwoRoom | 3 | 进入同一入口后会从哪里离开 |

TwoRoom 承载四项任务，但它们分别考察连续响应、时间延迟和结构转移。环境只是任务的
实现载体，不作为评分汇总单位。

表中历史长度是**包含当前帧的观测帧数**。通常相邻观测间隔 5 个物理步；例如长度 3 表示两个过去观测和一个当前观测，以及它们之间已执行的两个动作块。

## 2. 数据与划分

数据由物理模拟器生成。每项任务改变一个隐藏动力学因素，保存连续交互轨迹、查询动作及真实未来。Training 用于训练，Development 用于实现检查与方法选择，Test 用于方法固定后的最终报告。表中的训练方式比较统一使用 Development；其分数不作为 Test 成绩报告。

**六项二值配对任务以训练配对数表示规模：2k=2,048，8k=8,192，32k=32,768；Cube 的 10k=10,000。** 一对包含两种隐藏条件下的轨迹，不等于两个独立来源 episode。速度、动作延迟和门通行规则另列各自的覆盖单位。

| 任务 | 主结果表使用的 Training | 覆盖单位与含义 | Development / Test |
|---|---|---|---|
| 推手移动幅度 | **32,768 对** | 状态与动作窗口；可从同一来源 episode 取得多个窗口 | 各 256 对 |
| 接触摩擦 | **32,768 对** | 重置状态与接触几何 | 各 256 对 |
| 运动阻尼 | **32,768 对** | 初始状态；包含成对的前向／镜像样本 | 各 256 对 |
| 机械臂质量 | **32,768 对** | 初始关节状态与探测动作 | 各 256 对 |
| Cube 夹爪携带 | **10,000 对** | 来自 10,000 个不同来源 episode | 各 256 对 |
| 传送门出口 | **32,768 对** | 不同初始距离与动作幅值的场景 | 各 256 对 |
| 速度 | 覆盖 **32 档速度** | 档数表示参数种类，不是样本数 | 每个参考速度 300 个查询 |
| 动作延迟 | 覆盖 **延迟 0–10** | 11 种隐藏延迟，一步评分合并为 6 个物理响应组 | 各 300 个查询 × 11 种延迟 |
| 门通行规则 | 覆盖 **96 个门位** | 每个门位包含可通过／被阻挡两种规则 | 16 / 42 个门位置，各 300 个场景 |

配对数、动作窗口数与独立来源 episode 数不能互换。各档规模及覆盖变化集中见 §5.4；速度、延迟和门通行规则没有扩量对照。扩量只改变 Training，Development 和 Test 保持固定。每条结果的数据包版本、manifest 和评测身份记录在[结果 JSON](research/data/icl_training_study_v2.json)；生成与划分检查见[数据生成方法](Data_Generation.md)。

公开 Test 采用离线评测，没有托管提交服务。方法、训练预算和检查点选择应在 Development 上完成；读取 Test 后不得再用它调整方法。稳定公共数据下载版本尚未公布，包格式和本地加载方式见[HF 数据集指南](HF_Dataset_Export.md)。

## 3. 评测协议

### 3.1 模型输入与输出

一个评测样本包含：

1. 连续真实历史图像，包括最后的当前图像；
2. 历史图像之间已经执行的动作序列；
3. 接下来要执行的查询动作；
4. 每种候选隐藏规律对应的模拟器真实未来，仅供评分。

模型只能接收图像和动作。评分器不会提供隐藏参数、模拟器状态、奖励、价值函数或任务
标签。模型输出未来 latent；真实未来图像使用同一模型的冻结目标编码器编码，因此不同
模型不需要共享 latent 维度或数值尺度。

```text
历史图像 + 历史动作 + 当前图像 + 查询动作
                         │
                         ▼
                 参评模型预测未来 latent

每个候选真实未来图像 ──参评模型的冻结目标编码器──> 目标 latent
```

预测 latent 与各候选目标 latent 的距离用于判断模型选择了哪个真实未来。

评测只通过上下文适应，不更新模型权重：评分器在推理前后记录模型的 `frozen_state_hash()`
或 state-dict SHA-256，一旦发生变化即判定该次评测无效。

### 3.2 连续的真实轨迹

一步配对任务使用同一条因果链：

```text
x0 --u0--> x1 --u1--> x2（当前状态）--u2--> x3（真实下一状态）
```

每条轨迹都由同一个模拟器从 `x0` 连续执行到真实未来，中途不重置或改写状态。独立重放仅用于检查模拟器状态的一致性，不替换保存的数据。

### 3.3 配对构造与起点交换

一对样本分别使用两种隐藏规律。两者在查询时刻共享当前状态 `x2`、当前画面和查询动作
`u2`，只有历史中展示的物理响应不同，因此真实未来 `x3` 不同。配对约束以实测上限固定，
例如 PushT 接触摩擦要求配对的完整物理状态差异不超过 `1e-5`（实测最大 3.7e-6），并要求
两个真实未来在像素上可区分（运动阻尼要求真实未来的物块位置差不小于 2 px）。

部分任务不要求两条轨迹共享 `x0`。这类任务交换两种规律的起点，并检查起点本身不泄露
答案：`x0` 的图像哈希多重集在两种规律下相同，仅凭起点判定隐藏模式的准确率为 50%。

### 3.4 划分隔离与防泄漏

Training、Development 和 Public Test 的场景、生成模板和 query 哈希互不重叠，实测重叠
计数为 0。除隔离检查外，生成阶段还固定了以下防泄漏门限：仅凭 `x0` 的静态判别准确率
上限 50%，由 Training 训练、在公开划分上测试的 `x0` 几何分类器准确率上限 55%，历史必须
产生可测的物理响应（最小历史响应差以像素等价量给出）。

模型可见字段只有 `pixels` 和 `action`。隐藏参数、模拟器完整状态、配对标识和目录索引
只用于数据校验与评分，不进入模型输入。

## 4. 评测指标

### 4.1 主分与历史利用

六个二值配对任务的主分是选择正确真实未来的比例，随机选择参照为 50%。Door 使用同历史下的两种目标选择正确率；Delay 使用六个物理响应组宏平均，随机参照为 16.67%。Speed 要求匹配历史的预测优于该组每一个竞争历史条件：已见速度、未见插值各含三档速度，随机参照为 33.33%；低端、高端外推各含四档，为 25%。四种速度分布分别报告。

主表保留各任务的原始百分数，并将 ICL 与原环境 CEM 分开报告。任务详情保留以下互补维度，不以通过门槛与否替代实际分数：

| 指标 | 含义与解读 |
|---|---|
| 主分↑ | 按对应任务定义，选择正确未来或匹配历史的比例 |
| 响应分↑ | `100 × (1 − NRE)`，100 为完全恢复条件响应，0 与零响应同等误差，负值表示误差更大；单位为分，不是成功率 |
| 最弱条件↑ | 隐藏条件、响应组或参考速度中表现最弱的一项 |
| History↑ | 匹配历史是否比错误历史产生更准确的目标预测 |
| Switch↑ | 历史切换响应的任务特定读数；例如 Strength 检查预测差与真实差的内积是否为正，不能据此认定幅值正确 |
| Joint↑ | 六个配对任务中，两种条件都选对未来、都正确利用历史，且该样本对 NRE<1 的比例；其他三任务不定义此项 |
| Gain≈1 | 预测条件响应在真实条件响应方向上的相对幅值；理想值 1，接近 0 表示响应过弱 |
| Alignment↑ | 预测与真实条件响应的余弦相似度；理想值 1 |
| NRE↓ | 条件响应误差的平方范数除以真实响应的平方范数；理想值 0，完全不随历史变化的预测为 1 |
| 优于零响应↑ | NRE<1 的样本对比例，不解释为幅值已充分校准 |
| CEM↑ | 对应原环境的规划成功率，独立于 ICL 评分 |

各任务的主分定义和随机参照不同，且每项任务分别训练检查点，因此不合并为跨任务总分。严格比较将平局记为失败：例如 Speed 完全不随历史变化时，竞争历史的损失相等，严格胜率为 0；随机选择参照不能解释为无历史模型的得分。

### 4.2 响应指标与评分有效性

设切换隐藏条件后的真实目标 latent 差为 Δz，匹配历史下的预测差为 Δẑ，则每对样本的 Gain 为 `〈Δẑ, Δz〉 / ‖Δz‖²`，NRE 为 `‖Δẑ − Δz‖² / ‖Δz‖²`，Alignment 为两者的余弦相似度。共享配对实现先累加响应能量，再计算总体 Gain、Alignment 与 NRE，并非直接平均每对的比值；任务分组沿用各自协议。评分同时检查真实未来在模型表示中是否可分。

**连续响应分为 `100 × (1 − NRE)`，不截断负值，也不再次平方 NRE。** 它与 NRE 携带相同信息，用于直观展示改善程度，不是一条独立证据。先按原协议计算每个检查点的 NRE，再跨可比训练重复汇总；响应分的标准差为 NRE 标准差的 100 倍，缺失值保持缺失。任务详情和扩量表使用响应分展示该维度，原始 NRE 保留在 CSV / JSON 中。

例如真实目标为 −1、1，预测为 −ε、ε 时，ε=0.001、0.5、1 都可在严格选择及 NRE<1 的联合判断中成功，但响应分分别只有 0.1999、75、100。这说明正确率与响应幅值应分别阅读。条件差分也会消去两侧共同预测偏差，因此响应分满分仍不能证明绝对未来预测准确。

距离只在同一检查点的 latent 空间中计算。不同检查点的原始 latent MSE 不具有共同单位；归一化响应指标描述各自表示中的相对响应质量，不能当成同一物理单位的绝对预测误差。高主分也不能自动证明正确响应幅值或范围外泛化。

完整能力判定是评分协议的补充，不决定模型是否取得进步，也不将低于阈值的分数置零。各任务的历史阈值统一见[评分与复现附录](reference/Benchmark_Result_Provenance.md)。

### 4.3 原环境规划

CEM 在 TwoRoom、PushT、Reacher 和 Cube 原环境上评测，衡量引入 ICL 训练后的原有规划能力。CEM 预算为六个评测种子（42–47），每个种子 50 次，共 300 次；历史原始模型的预算差异在总表前注明。

原环境 CEM 衡量能力保持，不能替代隐藏规律下的上下文规划收益。这里区分固定候选动作的选择质量与 CEM 闭环控制。

隐藏规律下的动作评价使用相同候选、目标与模拟器真实代价，比较正确历史与控制历史带来的选择差异。推手移动幅度与速度的具体实验和结果见 §5.5。

### 4.4 比较原则

同任务的模型使用相同查询。正式优劣或非劣性声明应使用逐查询配对分析并报告置信区间；描述性分数变化本身不提供显著性结论。训练样本量、独立覆盖、初始化和表示更新方式应分别控制，才能讨论原因。

## 5. 模型与训练方案比较

### 5.1 训练方案与实验设置

<a id="training-schemes"></a>

结果表统一使用 **T0–T3** 四个训练方案代号。先区分两类数据：**原环境数据**是默认环境中的交互轨迹；**ICL 数据**是 ContextWorld 按任务合成、包含隐藏动力学变化的 Training 轨迹。它们都用于预测训练；ICL 评测时不更新参数。

| 代号 | 训练方案 | 初始化 | 训练数据与采样比例 | 训练轮数 | 更新哪些模块 |
|---|---|---|---|---|---|
| **T0** | 仅原环境数据训练 | 模型默认初始化 | 原环境 100% | 10 epochs | 各模型原生可训练模块 |
| **T1** | 直接混合数据训练 | 模型默认初始化，不加载 T0 权重 | 原环境 50% + 对应任务 ICL 50% | 10 epochs | 各模型原生可训练模块 |
| **T2** | 原环境预训练后，混合数据联合训练 | 加载对应环境的完整 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | Encoder、预测器及其余原生可训练模块 |
| **T3** | 原环境预训练后，冻结 Encoder 混合训练 | 加载与 T2 相同的 T0 权重 | 第二阶段：原环境 50% + 对应任务 ICL 50% | T0 的 10 epochs + 混合训练 10 epochs | 固定 Encoder 参数与训练态缓冲区；训练预测器、projector、动作编码器等其余模块 |

下载结果的 `regime` 字段中，`original`、`scratch`、`joint`、`frozen` 分别对应 T0、T1、T2、T3。

T2 / T3 加载模型权重后重新建立优化器，不接续 T0 的优化器状态。T0 按原环境训练一份模型；T1–T3 分别针对每项任务训练。因此，结果表的一行汇集同一模型家族与方案的九项实验，不表示同一份权重同时获得九项能力。

**模型与优化配置。**

| 模型 | T0 / T1 的默认初始化 | 原生可训练模块 | 优化器 | 学习率 | Weight decay |
|---|---|---|---|---:|---:|
| LeWM | Encoder 与预测器随机初始化 | Encoder、预测器及其余原生训练模块 | AdamW | 5×10⁻⁵ | 0.001 |
| PLDM | Encoder 与预测器随机初始化 | Encoder、预测器及其余原生训练模块 | AdamW | 5×10⁻⁵ | 0.001 |
| DINO-WM | 加载预训练 DINOv2-small Encoder 并冻结，预测器随机初始化 | 预测器、动作编码器等；Encoder 始终固定 | AdamW | 5×10⁻⁴ | 0 |

DINO-WM 的 T1 也使用预训练视觉 Encoder，不能解释为整个模型都从随机权重开始。它的 T3 加载在原环境训练过的预测器等模块，视觉 Encoder 仍保持冻结；本报告没有更新其 Encoder 的 T2 方案。历史上转换额外状态输入得到的初始化另列于附录，不作为 T3。

本报告的对比配方各阶段使用 **8 张 GPU、每卡 batch size 128、梯度累积 1（全局 batch size 1024）**。输入为图像与动作；通常使用 3 帧历史、帧间隔 5、预测下一帧，动作延迟的 ICL 训练使用 7 帧历史。训练目标沿用各模型的原生目标，未添加 COJA 辅助损失。T3 改变 Encoder 的更新方式，其余原生损失保留。入口与参数映射见[训练配置](../configs/training/stablewm_family_profiles_v1.yaml)及[模型训练指南](StableWM_Training.md)。

ICL 成分只读取对应任务数据包的 **Training** 划分，不使用 Development / Test 训练。主表的任务数据版本与样本规模见 §2，较小规模在 §5.4 单列；同一任务的 T1、T2、T3 使用相同版本。每条结果的数据身份与初始化权重身份见[结果 JSON](research/data/icl_training_study_v2.json)。

**50/50 指训练轨迹窗口的采样比例，不是来源 episode 数或数据文件大小各占一半。** 默认混合数据集按两个成分的可用窗口数构建 epoch：设其长度分别为 N原、NICL，则名义 epoch 长度为 `2 × max(N原, NICL)`，在划分与分批前的 epoch 排程中，两成分窗口数相等；较小成分会重复采样。因此，加入 ICL 不会简单地把原环境曝光减半，扩量也可能增加每轮更新次数。实际训练还受训练/验证划分、分布式采样与末尾不完整 batch 的处理影响；具体实现见[混合数据加载器](../contextworld/training/stablewm_bundle.py)。

**比较预算时需区分轮数与曝光量。** T2 / T3 比 T1 多出原环境预训练经历；各数据版本的 epoch 长度也可能不同。相同的 10 epochs 不能直接视为相同计算量、相同独立样本数或相同数据曝光次数。

**重复实验的汇总方式：** 相同任务、数据版本、训练方案和输入协议的全部可用训练重复参与均值；已有三个训练种子的配置使用三者，不选取其中一个。主表显示均值，任务详情显示“均值 ± 样本标准差”及重复数 `n`。仅有一次结果时显示该数值，标准差不写作零。ICL 与 CEM 分别统计有效重复数。具体种子、初始化检查点及逐次结果见结果 JSON。

每个检查点的 CEM 先按评测次数汇总，再跨训练重复等权平均。六个 CEM 评测种子是同一检查点的评测重复，不能当成六次独立训练。不同规模、训练方式和初始化协议始终分别汇总。

LeWM / PLDM 在八项任务上的 T2 / T3 使用相同任务数据、混合比例、历史长度、帧间隔及原始初始化权重。跨模型保留各自骨干、训练目标和优化器；这些结果可以比较能力获得程度，但不能单独分离某个架构部件的贡献。

### 5.3 主要发现与解释边界

**同一数据的学习效果取决于模型与训练方式。** PLDM 在推手移动幅度上，T2→T3 的主分从 60.55% 升至 98.05%，响应分从 20.19 升至 88.49；LeWM 在接触摩擦上的主分从 50.20% 升至 87.50%。数据和初始化相同，冻结 Encoder 后仍能改善，说明这些差异不能仅归于数据量不足。

**冻结 Encoder 的作用依赖任务。** PLDM 在运动阻尼上出现相反变化：T2→T3 的主分从 77.54% 降至 56.05%，响应分从 77.94 降至 11.78。LeWM 在机械臂质量上也有退步。§5.6 的训练过程对照进一步区分了后期泛化退化与训练样本上就响应偏弱的情形；这些观察尚不能唯一归因到某个模块或损失。

**部分预测改善已具有动作选择价值，但与原能力保持不同。** 推手移动幅度的固定候选实验中，LeWM 的 T2 / T3、PLDM 的 T3、DINO-WM 的 T1 优于对应 T0；LeWM 的速度插值也有明确收益（§5.5）。与此同时，PLDM 的 T2→T3 原环境 CEM 从 72.00% 降至 59.33%。隐藏规律下选动作更好，与默认环境中规划能力保持，需要分别评价。

### 5.5 条件预测与动作选择

这里检验：**正确历史能否帮助模型选出真实后果更好的动作？** 固定候选实验先隔离模型的动作评价能力，闭环实验再引入搜索、执行与反馈。两者均使用 Development 场景和真实历史，按模拟器后果评价，不按模型分数筛选场景。

**固定候选实验的共同指标。** 三列均使用各任务自己的真实代价单位，不跨任务直接比较。

- **动作 regret**：正确历史下所选动作相对候选集内最优动作多出的真实代价；越低越好。这里的最优仅限于给定候选集。
- **正确历史收益**：同一检查点的“错误历史 regret − 正确历史 regret”。错误历史来自同一场景的其他规律，当前状态与已执行动作匹配；正值表示匹配历史帮助选动作。
- **真实未来编码 regret**：直接编码模拟器真实未来，再用同一 latent 目标距离选动作。它绕过预测，用于检查目标距离本身是否支持良好的候选选择。

**比较与统计。** 本节比较具体检查点，不是总表中跨训练重复的均值；LeWM / PLDM 的 Strength T0 就是 T2 / T3 加载的初始化权重。95% 区间按场景 bootstrap，同一场景的不同规律一起重采样。T0 与训练后模型的比较衡量训练收益；同一模型的正确／错误历史比较衡量历史收益。两者使用不同对照，不能作为可相加或相减的因果分解。

#### 速度：插值与外推的动作选择

本实验检验速度预测的改善是否带来动作选择收益。分别使用已见速度、未见插值、低端外推和高端外推的全部 Development 场景，每类 300 个。场景与真实历史沿用速度任务；每个场景的不同速度共享当前状态、目标和候选集。

**实验设置。** 31 个候选将原查询的 5 步动作整体乘以 0–1.5 的幅度系数，步长 0.05；目标为该类最慢速度执行原查询动作后的终点。真实代价为最终位置到目标的欧氏距离，单位为像素。候选与目标规则在模型推理前固定，全部场景参与评测。所有场景均存在速度相关的最优候选，不能始终选择同一动作就达到各条件的最优代价。

#### 速度：初始历史与闭环规划

这项实验检验初始速度证据在执行和重规划中是否仍有价值。比较 LeWM 的同一组 T0、T1 检查点，使用未见插值速度 3.4、4.8、6.9 和 6 个固定场景，共 108 次闭环试验。每个场景、真实速度与模型均使用一次正确初始历史和两种错误初始历史。

**比较范围。** 表内各方案使用相同的新场景，只比较模型与初始历史的差异。它采用隐藏速度和远距离目标；九任务总表中的 CEM 使用原环境，两表的绝对成功率不表示同一测试上的升降。完整闭环数据有 300 个场景，本实验按每个评测种子取索引 0 的固定规则选取 6 个，不按模型分数筛选。

**设置与对照。** 不同速度共享起点和远距离目标。CEM 沿用原预算：300 个候选、30 轮搜索、30 个精英，规划 25 步、执行 25 步后重规划，总预算 50 步，成功半径 16 px。正确与错误历史只在首次规划时不同；之后均使用实际执行形成的新历史。因此，本实验衡量初始证据的影响，不代表持续提供错误历史的效果。

### 6.2 时间延迟动力学

<a id="task-action-delay"></a>

#### 6.2.1 动作延迟

**任务目标。** 模型使用七帧历史判断动作等待多少步才生效，并预测下一步真实物理响应。

**数据构成。** 延迟范围为 0–10。Training 覆盖完整范围；Public Test 包含
300 个查询，每个查询保存 11 种延迟的真实轨迹。

**评测方法。** 动作延迟有两个不同强度的评测问题，回答的研究问题不同，不能互相替代：

- **六组物理响应识别（正式指标）**：延迟按真实下一步响应分为 0、1、2、3、4 和 5–10 六组，
  各组在每个查询内等权宏平均，并报告最弱组表现。该指标判断模型是否区分六组一步响应，不区分 5–10 组内的延迟值。
- **二元历史响应诊断**：只判断预测在 delay=0 与 delay≠0（合并为一类）之间是否随历史
  正确切换，不要求区分不同的非零延迟。这是判断“历史是否引起了正确方向的条件差异”
  的更弱标准，主要用于快速诊断。

**适用范围。** 正式结果衡量 History=7 下六个一步物理响应组（0、1、2、3、4、5–10）的识别能力。
一步未来无法区分 5–10，因此不表示精确识别全部 11 档延迟；两步、三步未来（h2/h3）是辅助诊断，
不计入主分。也不验证未见延迟外推、多步自回归或隐藏延迟下的闭环规划。二元诊断数值只说明
“有无延迟”的区分，不能单独支撑延迟识别结论。

## 7. 接入与复现

外部模型通过统一的 `LatentWorldModelAdapter` 提供图像编码与条件预测接口。输入只有图像和动作，输出为预测未来的 latent；评分器不要求图像解码器。接口形状、历史对齐和最小适配示例见[Adapter 规范](External_Model_Adapter_Contract.md)。数据加载见[HF 数据集指南](HF_Dataset_Export.md)，内置模型的训练与初始化参数见[训练指南](StableWM_Training.md)。

从可用数据包运行 Development 评测：

```bash
python -m contextworld.benchmarks.external_model_cli \
  --benchmark-root /path/to/ContextWorld-bundle \
  --evaluation-split development \
  --task action_strength \
  --adapter lewm \
  --checkpoint /path/to/weights.pt \
  --model-name my-model \
  --output /path/to/development-result.json
```

新模型沿用相同任务查询和评分方法，结果报告要求见 §8。

## 8. 可复现性与结果报告

报告至少注明数据版本与划分、训练数据和比例、初始化、更新模块、训练预算、检查点及评测版本。表格与 CSV 从同一份 JSON 生成，检查点和数据哈希用于追溯来源；九任务结果按 §5.1 汇总全部可比训练重复。

正式成绩的有效性取决于输入合法、数据隔离及评测时权重不变。方法在 Development 上确定后，Test 应报告预先确定的同一任务集合，包含低分结果；Development 能力门是否通过不作为 Test 报告前提。历史 v3 按旧流程产生的结果保持原样，见[参考附录](reference/Benchmark_Result_Provenance.md)。

完整权重、数据包和逐查询输出尚无稳定公共下载，因此公开汇总还不能支持外部完整复现。包格式、数据身份与发布准备见[HF 数据集指南](HF_Dataset_Export.md)和[发布说明](Expanded_Training_Release.md)。

## 9. 适用范围与限制

- **数据范围：** 训练方案对比均为 Development 结果，用于描述能力与选择方法，不是最终 Test 成绩。
- **模型范围：** 每项 ICL 任务分别训练；总表的一行不是一个统一九任务模型。不同模型保留各自的架构、目标和优化器，跨模型差异不能唯一归因到架构。
- **测量范围：** latent 响应指标在各模型自己的表示空间中归一化，不等于共享物理单位的误差；条件差分也无法反映两侧共同预测偏差。
- **决策范围：** 推手移动幅度与速度的固定候选实验提供局部证据；速度闭环实验只覆盖六个场景。其他任务、范围外动力学和完整场景集上的闭环收益尚未确定。原环境 CEM 仅衡量能力保持。
- **归因范围：** 冻结 Encoder 同时固定了表示参数、训练态缓冲区及目标表示；扩量可能改变覆盖和优化步数。要分离这些作用，需进一步控制实验。

## 10. 比较与版本管理

新结果应引用明确的数据版本、训练方案和评测划分。相同任务定义与评分协议下可以比较新模型或训练方法；改变查询分布、任务定义或评分规则时，应记录新的 benchmark 版本。冻结 v3 的数值保存在[冻结参考附录](reference/Benchmark_Result_Provenance.md)，不以新实验覆盖历史结果。

## 11. 开放研究问题

**条件预测何时改善决策？** 推手移动幅度与速度展示了训练收益和匹配历史收益的区别；需要在完整场景集与更多隐藏规律上检验其闭环效果，以及反馈会保留还是消除初始证据的影响。

**表示更新为何对不同任务产生相反影响？** 推手移动幅度与运动阻尼提供了对照：前者在冻结 Encoder 后改善，后者可能需要表示继续调整。后续干预应区分表示变化、预测器学习与训练目标的作用。

**数据覆盖与训练方式如何共同决定能力？** 分别控制独立场景覆盖、重复曝光、优化步数与模型规模，才能判断观察到的扩量收益是否形成可复现的缩放规律。
