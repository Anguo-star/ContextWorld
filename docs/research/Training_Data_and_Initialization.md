# 数据覆盖与初始化如何影响世界模型的上下文学习

本研究比较 LeWM、PLDM 和 DINO-WM 在六项隐藏动力学任务上的学习表现。我们扩大训练数据覆盖，并比较默认初始化与原环境预训练权重初始化，考察：更多数据是否足以获得上下文学习能力，以及不同模型是否遇到相同困难。

**结果表明，数据覆盖、模型和训练起点共同影响能力获得。** DINO-WM 在接触摩擦任务上明显优于另两种模型；PLDM 在运动阻尼任务上更强。增加数据并不是所有任务的统一解法，预训练初始化也并非始终有益。

这是基于 **Development 划分、每个配置一个训练种子** 的研究结果，不替代 [ContextWorld 冻结 v3 基线](../ContextWorld_ICL_Benchmark.md#51-当前标准参考v3--dino-wm-原环境-icl-补充)，不构成新的正式排行榜或缩放定律。

## 阅读结果前需要知道什么

- **ICL 正确率**：给定历史、当前图像和动作，模型是否更接近该历史对应的真实未来。评测时不更新模型参数。本报告六项任务均为两条件配对，随机正确率为50%；“最弱条件正确率”取两个条件各自正确率中的较低值。
- **响应幅值与误差**：检查交换历史后，预测是否发生足够大且方向正确的变化。高正确率不保证变化幅值正确。
- **原环境 CEM（Cross-Entropy Method，交叉熵规划方法）**：使用模型进行原任务闭环规划的成功率，用于观察基本规划能力是否保持。它不直接测量模型能否利用隐藏动力学条件改善规划。
- **默认初始化（scratch）**：不加载原环境任务检查点，保留模型家族自身的默认初始化。DINO-WM 仍使用其预训练视觉骨干，因此不意味着所有参数随机初始化。
- **预训练初始化（warmstart）**：LeWM 和 PLDM 加载原环境模型权重，再用混合数据训练；优化器重新建立。
- **DINO-WM 转换初始化**：原环境检查点含额外状态输入，本实验迁移视觉与动作对应的参数子空间，移除状态输入通道。该操作不保持原预测器的数值等价性，不能与完整权重 warmstart 视为同一种干预。

## 实验设置

每个任务分别训练一个模型。训练数据由原环境数据与对应任务合成数据各占50%组成，使用模型自身训练目标，不添加额外的条件响应辅助损失。三种模型保留各自的骨干、目标函数和优化器，因此家族差异不能单独归因于架构。实现分别对应Stable-WorldModel的[LeWM](https://github.com/Anguo-star/stable-worldmodel/blob/ag/dev/scripts/train/lewm.py)、[PLDM](https://github.com/Anguo-star/stable-worldmodel/blob/ag/dev/scripts/train/pldm.py)和[PreJEPA / DINO-WM](https://github.com/Anguo-star/stable-worldmodel/blob/ag/dev/scripts/train/prejepa.py)训练入口。

| 设置 | 本研究使用的值 |
|---|---|
| 训练种子 | 3072，每个配置一次训练 |
| 原环境初始化权重的训练种子 | 3073 |
| 训练预算 | 10 epochs，8张GPU，每卡batch 128，梯度累积1 |
| ICL评测 | 完整Development划分，每任务256对样本 |
| 原环境CEM | 评测种子42–47，每次50回合，共300次；可能抽到重复查询 |
| 检查点 | 固定使用epoch 10，不按Development分数挑选轮次 |

六个任务均有三模型、两种初始化结果，共36个配置。固定训练轮次不意味着预训练初始化与默认初始化具有相同总计算量：前者额外使用了原环境预训练。当前混合数据加载器的每轮长度由较大的原环境样本集合主导；扩大较小的合成集合主要降低单个合成样本被重复使用的频率，并非简单增加优化步数。

## 结果支持哪些结论

### 同一任务对不同模型提出不同困难

接触摩擦上，DINO-WM两种初始化的ICL正确率均超过81%，而LeWM和PLDM约为50%。运动阻尼上，PLDM预训练初始化达到77.54%，响应增益约0.83；另两家表现较弱。两项都属于PushT环境，却呈现不同的模型优势。这比“某模型整体更强”更具体，也不支持“任务数据对所有模型都不可学”的解释。

### 较小训练集与本轮结果存在模型相关差异

已有DINO-WM较小训练集记录中，Friction、Mass、Cube的Development正确率分别为49.61%、50.59%、50.20%；本轮默认初始化分别达到81.84%、80.47%、61.33%。这些历史记录同为训练seed3072、epoch10的默认初始化检查点，使用256对Development样本；来源身份也列入结果JSON。它们仍是训练配置比较，未完整控制历史训练软件和数据身份，不能仅凭两点建立缩放定律或唯一归因于样本数量。

Portal的正确率原本已很高；本轮DINO-WM默认初始化的响应增益约0.83，历史记录约为0.35。两者在各自评测中与理想增益1的距离不同，但本轮未完整验证历史评分实现一致性，因此保留为响应校准线索，不作严格配对的因果结论。只看正确率会忽略这类差异。

### 预训练初始化不是必要条件，也不是普遍改进

LeWM在Strength上从默认初始化的50.78%提高至90.82%。但DINO-WM默认初始化已达到96.09%，转换初始化只提高到97.46%。PLDM在Portal上则由73.63%降至53.91%。因此不能将某个模型上的初始化收益推广到所有模型或任务。

### Cube只出现部分能力，不能标为完整成功

DINO-WM的Cube正确率达到61.33%和63.87%，但响应增益仅约0.095和0.114；最弱条件正确率分别约50.39%和53.91%。结果说明有部分条件信息进入预测，仍不足以支持充分、稳定的条件响应。

### 原环境规划与条件能力可以分离

PLDM在Portal上预训练初始化后的CEM更高，ICL却更低。Mass也提示保持能力的问题：PLDM预训练初始化的CEM为58.67%，低于原权重历史参考80%。后者尚未建立严格相同查询的配对比较，但不能因ICL较高而忽略它。

目前没有证据证明这36个配置的ICL提升都转化成隐藏条件下的闭环规划收益。原环境CEM和条件动作决策需要分别报告。

## 下一步可检验的问题

优先比较Friction和Damping：分别有较强模型和较弱模型，且原环境相同。使用已有检查点比较正确历史与交换历史下的候选动作排序和真实动作后果，再比较训练样本与Development的响应。

- 训练样本响应充分而Development不足，优先检验覆盖与泛化。
- 两者都不足，需要进一步区分表示、历史信息利用和训练目标的作用。
- 有方向正确的预测变化但幅值不足，需要检验响应校准。

这些是待验证的解释，不是已定位的根因。现阶段没有必要把所有任务继续统一扩量，或直接开展大规模模型缩放实验。

## 可复现性与报告边界

[结果JSON](data/icl_training_study_v1.json)提供36个配置的任务、数据清单哈希、检查点哈希、初始化身份、主要指标及六个CEM种子结果。它是已有实验的结果汇总，不替代原始逐查询输出。

本研究的扩量数据包、完整检查点和逐查询原始输出尚未提供稳定公共下载。因此当前可以检查表格生成和数值汇总，不能声称外部读者已能完整重现实验。默认初始化与原权重初始化的总训练预算不同；DINO-WM还包含明确的参数转换。只有一个训练种子，六个CEM评测种子不能替代多训练种子验证。

冻结v3的训练数据身份、任务定义、评分门槛与参考分数均保持不变。任何进一步方法选择使用Development；正式Test报告应另行固定实验配置后进行。

下一版数据的范围、HF数据卡和发布前检查见[发布准备](../Expanded_Training_Release.md)。当前准备不包含HF上传。
