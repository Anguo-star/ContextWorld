# TwoRoom History-3 隐藏通行规则：可行性协议与结果

**版本**：v1

**日期**：2026-07-23

**状态**：固定碰撞器上的可行性 smoke 已通过；端到端 pilot 待执行，正式训练未放行

## 结论先行

本阶段证明了一件事：

> TwoRoom 可以构造“当前画面和待执行动作完全相同，但只有历史交互能说明门是否可通行”
> 的 History-3 任务。

32 个配对模板全部通过检查。对于每个模板：

- “可以通过”和“不能通过”使用完全相同的历史动作；
- 第二张历史画面会显示不同的交互结果，智能体位置相差 **8.5 px**；
- 两条历史随后通过相同动作回到完全相同的当前状态和画面；
- 从这个相同起点执行相同动作，两种规则的真实未来相差 **25 px**；
- 只看动作猜规则的最好准确率为 **50%**，等于随机猜测。

这说明任务在当前固定的碰撞器上可测，而且当前画面和动作没有泄露规则。可行性
loader 已验证只输出 `pixels` 和 `action`，但正式 Stable-WorldModel 训练与评测入口
尚未接通。这里没有运行任何模型，因此还不能说 LeWM 已经学会这种 ICL。

## 1. 为什么这是门规则 ICL 的前置任务

之前的可见门位置实验中，门的位置直接显示在当前画面里。模型即使完全不利用历史，
也可以根据画面选择动作，因此那个实验测的是可见几何泛化。

本实验改为一扇外观始终相同的门，并为它设置两种隐藏规则：

| 隐藏规则 | 画面 | 物理效果 |
|---|---|---|
| 可以通过 | 显示正常门洞 | 智能体可以穿过墙 |
| 不能通过 | 显示相同门洞 | 门洞在碰撞计算中视为实墙 |

隐藏规则不会改变相同状态下的任何像素，也不出现在模型输入中。规则在同一段历史和
后续预测期间保持不变。模型未来若想判断这扇门能不能通过，只能利用历史中“相同动作
究竟穿过去了，还是被墙挡住了”这一结果。

一组配对样本的结构如下：

```text
相同历史第 1 帧
        │ 相同探测动作
        ▼
不同历史第 2 帧：可以通过时进入门洞，不能通过时停在墙边
        │ 相同恢复动作
        ▼
完全相同的历史第 3 帧，也就是当前 query
        │ 相同待预测动作
        ▼
不同的真实未来：穿过墙，或继续停在墙边
```

因此，需要保持相同的是当前 query 和所有动作；历史第二帧则必须不同，因为它正是
模型用来识别规则的证据。

## 2. History-3 动作怎样构造

History-3 由三张连续画面和中间两段动作组成。每段动作包含 5 个原始环境步，
`agent.speed` 固定为 5。初始位置紧邻门或墙，第一步非零动作就会产生“通过或被挡住”
的规则证据。历史内部没有重置、瞬移或画面拼接。

### 2.1 左向右

```text
探测动作：
[(+1, 0), (+1, 0), (0, 0), (0, 0), (0, 0)]

当前 query 后的待预测动作：
[(+1, 0)] × 5
```

### 2.2 右向左

```text
探测动作：
[(-1, 0), (-1, 0), (0, 0), (0, 0), (0, 0)]

当前 query 后的待预测动作：
[(-1, 0)] × 5
```

### 2.3 恢复到相同 query

门位置 49 和 89 使用：

```text
[(0, +1), (0, -1), (0, 0), (0, 0), (0, 0)]
```

门位置 129 和 169 使用：

```text
[(0, -1), (0, +1), (0, 0), (0, 0), (0, 0)]
```

恢复动作先把智能体短暂移出门洞范围，使两种规则都被同一侧墙边界约束，再回到原来的
纵向位置。这样既保留了第二帧中的规则证据，又让第三帧在两种规则下逐像素一致。

这里必须说明一个限制：恢复到相同 query 依赖当前 TwoRoom 碰撞器的投影。可通行轨迹
离开门洞时，即使该步横向动作是 0，碰撞器也会把横坐标从 108.0 推回 99.5，单步横向
修正为 8.5 px。这是连续 `env.step()` 的确定性结果，不是手工瞬移；但它不是自然的
自由运动。当前结果因此只按“固定碰撞器上的 History-3 可行性 smoke”报告，尚未批准
直接用于正式训练。

以门位置 49、左向右、偏移 14 px 为例：

| 时刻 | 可以通过 | 不能通过 |
|---|---:|---:|
| 探测后的第二帧 | `[108.0, 63.0]` | `[99.5, 63.0]` |
| 恢复后的相同 query | `[99.5, 63.0]` | `[99.5, 63.0]` |
| query 动作后的真实未来 | `[124.5, 63.0]` | `[99.5, 63.0]` |

## 3. Smoke 数据覆盖

本轮只构造用于证明任务可行的小规模数据，不把它当作正式训练集或 Eval：

```text
4 个门位置 × 2 个方向 × 4 个门内偏移 = 32 个配对模板
32 个模板 × 2 种隐藏规则 = 64 条环境 rollout
```

| 维度 | 实际覆盖 |
|---|---|
| 门位置 | 49、89、129、169；每个位置 8 对 |
| 方向 | 左向右、右向左；每个方向 16 对 |
| 门内偏移 | 11、12、13、14 px |
| 配对模板 | 32 |
| 规则 rollout | 64 |
| 不同 query 画面 | 32/32 |

每个模板中的两种规则共享环境种子、初始状态、目标、可见环境参数和全部动作。唯一允许
不同的是评测器保存、但模型不可见的 `passage.open`。

本 smoke 把目标统一固定为 `[190, 190]`，用途只是验证两种规则下目标完全相同。它与
右向左动作的方向不一致，因此这批样本不能直接用于 CEM 或目标导向规划；正式规划
catalog 必须重新生成方向一致的目标。

## 4. 预先规定的检查与实际结果

### 4.1 每个模板必须通过的物理检查

| 检查 | 预先规定的标准 | 实际结果 |
|---|---:|---:|
| 初始 observation、状态和像素 | 两种规则完全相同 | 32/32 对通过 |
| 历史动作 | 逐位相同 | 32/32 对通过 |
| 历史第二帧 | 像素不同，状态差至少 5 px | 全部相差 8.5 px |
| 历史第三帧 | 必须是真实连续转移后的 query | 32/32 对通过 |
| query 状态 | 完全相同 | 32/32 对通过 |
| query 像素 | 逐位相同 | 32/32 对通过 |
| query 动作 | 逐位相同 | 32/32 对通过 |
| 目标状态和目标画面 | 完全相同 | 32/32 对通过 |
| 真实未来 | 像素不同，状态差至少 20 px | 全部相差 25 px |
| 通行物理结果 | 可通行必须跨墙；不可通行不得跨墙 | 32/32 对通过 |
| 隐藏规则读回 | 与声明规则一致 | 32/32 对通过 |
| 相同模板重新运行 | 所有保存数组完全一致 | 32/32 对通过 |
| NPZ 重新加载 | 字段、形状、类型和数组内容完全一致 | 32/32 对通过 |
| 逻辑产物路径 | 必须解析回实际文件并匹配哈希 | 32/32 对通过 |
| 失败模板数 | 必须为 0 | 0 |

这里的“逐位相同”表示数组的数据类型、形状和每一个数值都相同，不是视觉上近似。

### 4.2 整体平衡和泄露检查

| 检查 | 实际结果 |
|---|---|

## 5. 现在能得出什么结论

本轮已经证明：

- 隐藏通行规则不会从当前 query 画面、状态或动作中泄露；
- 两段连续历史能够提供清楚、可重复的规则证据；
- 两种历史可以在不重置环境的情况下回到同一个 query；
- 相同 query 和动作确实对应两种明显不同的真实未来；
- 该构造足以进入数据管线与真实模型输入的端到端 pilot。

本轮尚未证明：

- 原始 LeWM 能识别隐藏通行规则；
- 使用双规则数据训练的 LeWM 会利用 History-3；
- 历史能够改善下一帧 latent 预测、动作选择或 CEM 成功率；
- 能力可以推广到训练未见的门位置或新的隐藏规则。
- 当前依赖碰撞投影的恢复动作适合直接进入正式训练。

因此，本文件的准确结论是“隐藏通行规则任务物理可测”，不是“门规则 ICL 已经生效”。

## 6. 下一阶段的正式门槛

下一阶段不能直接开始大规模训练。必须先完成一条小规模端到端 pilot：

1. 让新环境经过 ContextWorld `World` 采集到 Lance；
2. 从 Lance 重新加载隐藏规则、状态、画面和动作；
3. 恢复 `passage.open` 后逐原始步重放，确认物理结果与原轨迹一致；
4. 通过正式 Stable-WorldModel adapter 实测最终输入张量只包含像素和动作；
5. 审查 8.5 px 碰撞投影：若接受，应把能力明确限定为当前碰撞器；若不接受，应改用
   更长 History 构造更自然的恢复轨迹。

pilot 全部通过后，才冻结等数据量的单规则训练控制组和双规则训练组，并使用三个配对
训练种子。原始 LeWM 只用于检查原有能力是否保留，不能替代配对训练控制组。

正式 Validation 使用完整的 `2×3` 历史—未来矩阵。前两列是主要配对比较；第三列由
从不接触门、但仍连续回到同一 query 的动作生成，用来检查没有规则证据时的模型先验：

| 真实未来规则 | 可以通过的历史 | 不能通过的历史 | 没有探门的历史 |
|---|---|---|---|
| 可以通过 | 与未来规则相同 | 与未来规则不同 | 不提供规则证据 |
| 不能通过 | 与未来规则不同 | 与未来规则相同 | 不提供规则证据 |

每个矩阵单元、每个模型都必须独立使用：

```text
50 个不同 query × 6 个评测随机种子 = 300 条
```

不能把 300 条样本分给六个单元。六个单元必须共享配对的 query 和待预测动作，真实
未来画面在模型评分前离线生成并冻结。“没有探门的历史”也必须由真实连续轨迹生成，
不能复制或拼接画面。

模型 ICL 的最小正式判定是：

1. 对“可以通过”的真实未来，可以通过的历史同时优于不能通过和没有探门的历史；
2. 对“不能通过”的真实未来，不能通过的历史同时优于可以通过和没有探门的历史；
3. 两个方向都在 6/6 评测种子和 3/3 双规则训练种子上成立，不能只看平均值；
4. 双规则训练相对单规则控制的提升在 3/3 配对训练种子上方向一致；
5. 新模型同时通过原始 TwoRoom 能力保持检查。

相同候选动作评测可以作为第二层证据，CEM 实际规划可以作为第三层效用结果，但它们
都不能替代真实下一帧预测这一主要证据。Validation 通过前，正式 Test 必须继续封存。
