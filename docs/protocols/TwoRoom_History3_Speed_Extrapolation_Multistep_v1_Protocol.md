# TwoRoom History-3 速度范围外与多步预测执行协议

**协议版本**：v1  
**冻结日期**：2026-07-21  
**冻结状态**：数据生成和模型评分前预注册，尚未执行  
**配置文件**：`configs/benchmark/tworoom_speed_multistep_extrap_v5.yaml`

本协议扩展已经完成的 History-3 速度 Benchmark，但不改写原 v2 协议和 v4 一步
结果。它只回答两个尚未回答的问题：

1. 模型能否根据历史处理低于或高于多速度训练范围的新速度；
2. 上下文带来的一步预测优势，在完全自回归预测 2、3、5 个 action block 时还能
   保持多久。

当前结论仍统一写入
[TwoRoom 速度上下文学习 Benchmark 报告](../TwoRoom_Speed_Benchmark_Report.md)。

## 1. 不改变的实验基础

模型仍只接收像素和动作，不接收 `agent.speed`、二维位置或真实未来。History-3
由两段历史转移和一张当前 query 图像组成：

```text
历史帧 x0 --动作 u0--> 历史帧 x1 --动作 u1--> query 帧 x2
query 帧 x2 --动作 u2/u3/u4/u5/u6--> 五个待预测未来帧
```

每个 action block 包含 5 个原始环境步。实验改变的是环境的 `agent.speed`，不是
frameskip。模型评分期间不更新权重，也不调用环境。

比较以下 7 个固定最终 checkpoint：

| 训练数据配方 | 数量 | 作用 |
|---|---:|---|
| 只用原始速度 5 数据 | 1 | 公共参考 |
| 原始数据 + 速度 5 合成数据 | 3 | 单速训练控制 |
| 原始数据 + 32 个速度的合成数据 | 3 | 多速度训练目标 |

单速与多速度模型按训练种子 `3072/4096/5120` 成对比较。训练步骤、架构、原始与
合成抽样比例以及 normalizer 沿用 v2 协议。

## 2. 四条评测轨道

多速度合成训练的速度范围是 `[2.6, 7.9]`。本协议分别保留训练内控制、区间内
插值和两端范围外测试：

| 轨道 | 参考未来与历史速度 | 用途 |
|---|---|---|
| 训练见过速度 | 3.1 / 5.1 / 7.0 | 与已完成结果对照 |
| 范围内未见速度 | 3.4 / 4.8 / 6.9 | 区间内插值控制 |
| 低端范围外速度 | 1.75 / 1.95 / 2.15 / 2.35 | 低于训练范围的外推 |
| 高端范围外速度 | 8.25 / 8.75 / 9.50 / 10.25 | 高于训练范围的外推 |

低端和高端速度不与原始训练、多速度合成训练、训练期监控、planner calibration、
已有 Validation 或封存 Test 重合。评分前由脚本按 `1e-6` 容差自动审计。

四条轨道不能合成一个总分，低端和高端范围外也必须分别判断。训练范围内表现不能
代替范围外表现。

## 3. 冻结数据怎样构造

### 3.1 Query 数量

每条轨道共用同一组 300 个静态 query geometry：

```text
6 个起点—目标距离 × 每档 50 个 geometry = 300
```

每个参考速度将 300 个 query 固定划成六个互不重复的评测种子分区：

```text
每个参考速度、每个历史条件：50 query × 6 seeds = 300
```

这 300 个样本不会在多个速度或历史条件之间平摊。同一个静态 query 在所有参考
速度、历史速度和轨道中严格配对。

### 3.2 历史转移

每个历史速度都从相同状态出发，先沿安全方向移动一个 block，再执行完全相反的
动作返回 query 状态。因此：

- 中间帧显示该历史速度造成的位移；
- 第三个输入帧对所有历史速度完全相同；
- 模型若要区分速度，只能利用前两段动作—画面转移，不能从 query 单帧读取速度。

构建时要求每个历史轨迹无碰撞、无边界截断、无提前终止，并检查自由运动公式的
最大残差不超过 `1e-3 px`。

### 3.3 未来动作和真实目标

每个 query 固定使用五个有界动作块。300 个 geometry 在三种安全动作族之间等量
分配，避免结论依赖单一方向：

- 先横向的轴向回路；
- 先纵向的轴向回路；
- 含对角动作的有界回路。

同一 query 的未来动作对所有参考速度和历史条件完全相同。环境按每个参考速度真实
执行五个 action block，并在评分前保存和哈希第 1/2/3/5 个 block 后的真实帧。
所有未来轨迹同样要求无碰撞、无截断和无终止。

## 4. 完全自回归的多步评分

模型输入 3 张真实历史/query 帧以及 7 个 action token：前两个是历史动作，后五个
是未来动作。模型只在输入端看到 `x0/x1/x2`；未来 `x3…x7` 全部由模型自己的预测
递推，不使用真实中间帧 teacher forcing。

对每个 checkpoint，真实未来帧使用该 checkpoint 自己的冻结 encoder 编码。第
`h` 个 horizon 的 loss 为：

```text
L_h(v_history → v_reference)
= MSE(自回归预测 latent_h,
      encoder(按 v_reference 真实执行到第 h 个 block 的冻结帧))
```

评分脚本还会分别只输入 1、2、3 个未来动作，核对其预测前缀与完整五步 rollout
完全一致；最大差异必须不超过 `1e-6`。这项检查用于排除未来动作反向影响较早预测。

本协议不计算 latent 反推速度、像素坐标或位置误差，也不运行 CEM。它测的是给定
相同动作时，模型预测的未来画面 latent 是否更接近真实未来。

## 5. 指标与汇总

每个参考速度和 horizon 分别计算：

```text
同速历史 loss = L_h(v_reference → v_reference)

同速历史优势
= 其他历史的平均 loss − 同速历史 loss

相对 loss 降低
= 同速历史优势 / 其他历史的平均 loss
```

“同速”只表示历史和参考未来由同一稳定速度生成，不表示历史本身有对错。只有在
历史与 query 属于同一、短期速度不变环境的任务假设下，同速历史才是准确性参照。

汇总规则固定为：

- 先在每个参考速度内求 condition loss 的均值，再算比值；
- 一条轨道内的各参考速度等权；
- 不平均四条轨道；
- 不平均 1/2/3/5-step horizon；
- 不直接跨 checkpoint 比较原始 latent MSE 尺度；
- 10,000 次静态 query cluster bootstrap 区间只作不确定性描述，不新增 p-value 门。

每个 checkpoint 的样本数为：

| 轨道 | 速度×历史矩阵 | 条件轨迹 |
|---|---:|---:|
| 训练见过速度 | 3×3 | 2,700 |
| 范围内未见速度 | 3×3 | 2,700 |
| 低端范围外速度 | 4×4 | 4,800 |
| 高端范围外速度 | 4×4 | 4,800 |
| 合计 | — | 15,000 |

四个 horizon 对应每个 checkpoint 60,000 条 loss，7 个 checkpoint 合计 105,000
条条件轨迹和 420,000 条 horizon loss。

## 6. 预注册判断门

每条轨道、每个 horizon 独立通过，必须同时满足：

1. 三个多速度 checkpoint 在该轨道的每个参考速度上，同速历史优势都为正；
2. 上述每个参考速度的六个评测种子分区方向都为正；
3. 按训练种子成对比较，多速度模型的相对 loss 降低均高于单速模型，三个训练种子
   方向全部为正。

“同速历史分别低于每一种其他历史”作为更严格的诊断表报告，但不是正式门；正式门
使用其余历史的平均 loss，与既有 v4 判定保持一致。

多步能力按从 horizon 1 开始连续通过的最远步数报告。例如 `1/2` 通过、`3` 未通过、
`5` 又通过时，正式最长连续 horizon 仍是 2。后续失败不会抹去更早 horizon 的结果。

范围外结论分三级：

- 只有低端通过：只支持低端范围外；
- 只有高端通过：只支持高端范围外；
- 两端一步都通过：才支持双向一步范围外泛化。
