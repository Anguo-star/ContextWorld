# ContextWorld 世界模型上下文学习评测设计规范

**版本**：v8.0
**日期**：2026-07-21
**文档性质**：通用设计规范

## 1. 评测目标

ContextWorld 评估世界模型能否在不更新权重的情况下，从近期交互中识别当前环境
的规则，并立即把该规则用于未来预测和规划。速度、摩擦和动作响应延迟等动力学
通常不能从一张静态图像直接看出；门位置和障碍布局通常可以直接看见。两类因素
必须分开报告。

一个完整 Benchmark 需要依次回答：

1. 上下文是否真的包含隐藏规则的信息；
2. 模型是否会随上下文改变预测；
3. 改变后的预测是否更接近当前环境的真实未来；
4. 预测变化是否改善固定候选动作的选择；
5. 在冻结规划资源后，闭环任务是否完成、用了多少真实步和计算量；
6. 该效应能否归因于目标训练变量，并且不损伤原有能力。

最终成功率很重要，但它同时受模型、规划器、任务距离、成功半径和资源上限影响。
因此 ContextWorld 不把多个指标混成一个难以解释的总分，也不允许只凭单个
Eval score 宣布 ICL 生效。

## 2. 能力声明与术语

### 2.1 Query 规则与历史规则

对隐藏因子记：

```text
z_query：评测器固定、决定 query 后续转移的隐藏规则
z_history：生成历史动作—观测转移的隐藏规则
```

Query 可以只有一帧，因而不能直接显示速度等动力学状态。此时上下文是模型识别
规则的唯一证据。只有任务明确假设“历史和 query 属于同一稳定环境阶段”时，
`z_history = z_query` 才表示与查询环境使用同一设定。

对有大小顺序的因子，统一使用：

| 名称 | 定义 |
|---|---|
| 低值历史 | `z_history < z_query` |
| 同设定历史 | `z_history = z_query` |
| 高值历史 | `z_history > z_query` |

三种历史都应是合法、可回放的数据，名称只描述历史规则与 query 规则的相对
关系。如果任务不包含历史与 query 共用规则的假设，就只能比较不同历史造成的
响应，不能把其中一种视为标准答案。

### 2.2 证据顺序

| 等级 | 要回答的问题 | 最低证据 |
|---|---|---|
| 数据有效 | 数据和上下文是否可信 | replay、readback、哈希、泄漏审计 |
| 上下文响应 | 模型是否读取隐藏因子 | 固定 query/action 后，预测随历史有稳定方向变化 |
| 预测校准 | 响应是否符合真实动力学 | 同设定历史的下一状态和多步误差更低 |
| 决策校准 | 模型是否会选更合适的动作 | 固定候选下，被选动作与真实最优动作的代价差更低 |
| 闭环效用 | 在冻结资源下是否更有用 | 成功曲线、连续轨迹、到达时间和计算量 |
| 训练归因 | 效应是否来自目标训练变量 | 匹配控制、多个训练种子、基础能力保持 |
| 泛化 | 是否能处理训练未见规则 | 因子值插值或外推与留出 geometry |

前一项通过不自动推出后一项。例如，预测位移随历史变快只能证明存在上下文响应；
若变化幅度偏小、偏大或有系统偏差，就不能声称已经完成物理校准。

### 2.3 一个因素能否称为 ICL

每个新因素开始训练前，先冻结并运行 query-only 基线：模型只看当前 query，不看
历史。按可观测性把因素分成三类：

| 类型 | 当前 query 能否识别 | Benchmark 中的角色 |
|---|---|---|
| 隐藏动力学 | 不能，需要动作—画面转移 | ICL 正式主任务 |
| 可见几何 | 能，例如全局图像中的门位置 | 可见条件泛化或 ICL 负对照 |
| 隐藏×可见组合 | 一部分需要历史，一部分当前可见 | 因素解耦与训练未见组合泛化 |

如果 query-only 已经足够解决任务，增加历史后的提升不能直接归因为“从上下文识别
了该因素”。这类任务仍可用于检验视觉泛化和组合能力，但结论名称必须与隐藏动力学
ICL 分开。

## 3. 数据对象与可追溯性

### 3.1 核心对象

| 对象 | 定义 |
|---|---|
| BaseTask | 状态、动作、终止规则、可变因子和合法干预 |
| Scenario | 固定 geometry、起点、目标、因子和采集种子 |
| EpisodeInstance | 一次完整轨迹及状态、动作、像素和终止信息 |
| ContextQueryBundle | 同一 query 配套的一组历史条件 |
| CandidateBank | 对同一 query 冻结的候选动作序列 |
| PlannerProtocol | 模型视野、搜索参数、执行预算和成功规则 |
| CollectionProfile | 采集策略、分层、episode 预算和有效曝光量 |

同一 geometry 只改变隐藏因子时，不能误计为多个独立 geometry。

### 3.2 正式产物必须保存

- 配置、代码、模型和模拟器版本；
- 数据、catalog、checkpoint、normalizer 和候选 bank 哈希；
- scenario、episode、query、evaluation 和 split 标识；
- 隐藏因子真实值、模拟器 readback 和训练支持关系；
- 训练、采集、评测和 planner 随机种子；
- 上下文像素、状态和稠密动作 payload 哈希；
- 原始结果、审计报告、统一汇总和运行日志。

## 4. Split 与泄漏控制

### 4.1 隔离维度

| 隔离层级 | 要求 |
|---|---|
| Clip | Query clip 不在训练数据中 |
| Episode | 同一完整轨迹不跨训练和评测 |
| Scenario | 关键 reset-goal geometry 不跨关键 split |
| 组合 | 测试组合外推时，因子组合类别也 heldout |

报告必须写清满足哪一层，不能用 clip-heldout 代替 episode-heldout 或
scenario-heldout。

Geometry 是否见过和因子值是否见过是两个独立维度：

| 轨道 | 因子值 | 可声明能力 |
|---|---|---|
| 见过规则 | Train 中出现 | 根据历史选择并调用已学规则 |
| 区间内新规则 | Train 中未出现但位于训练范围内 | 插值 |
| 范围外新规则 | 超出训练范围 | 外推压力测试 |

Train、训练监控、Calibration、Validation 和 Test 的因子集合必须分别保存，并
做数值交集审计。见过规则、插值和外推不得合并成一个分数。

对有大小顺序的因子，低端和高端范围外也必须分开报告。只有两端都通过同一套冻结
门时，才能声明双向外推；某个端点或轨道平均为正不能代替逐参考值通过。

### 4.2 Split 角色

| Split | 用途 | 是否可根据结果调整 |
|---|---|---|
| Train | 模型拟合和 normalizer | 可以 |
| Calibration | 选难度带、验证正对照、冻结 planner | 可以，但不训练主模型 |
| Validation | 比较方法和检验预注册机制 | 只能在重新冻结后提出新假设 |
| Test | 一次性最终报告 | 不可以 |

Test catalog 在模型、规划器、指标和阈值冻结前不得评分。

### 4.3 测试时上下文边界

上下文不得包含 query 的未来帧、隐藏因子标签、任务结果或超出协议的额外历史。
同一配对组必须保持 query、goal、context actions、输入长度、候选 bank 和规划
随机计划一致。

模型必须记录时间 attention 形式。Causal 模型要用未来 token 扰动检查确认较早
输出不受未来 observation/action 影响；full temporal attention 模型必须单列。
图像内部的 ViT 空间 attention 与模型帧之间的时间因果性是两件事。

## 5. 数据构建与计数

### 5.1 数据正确性

训练和评测数据至少检查：

- 状态、动作和因子范围；
- 模拟器因子 readback；
- 逐步回放及像素、状态、目标、终止状态一致性；
- split 泄漏、重复 episode 和重复 geometry；
- 上下文动作—位移是否足以恢复目标因子；
- 静态 query 是否只在被允许的字段上变化。

关键检查失败时，结果不能标为正式通过。

### 5.2 样本量

默认确认规模为：

```text
每个 Eval × 每个 query/condition 单元 × 50 次 × 6 个评测种子
= 每个单元 300 次
```

两个 Eval 必须各自执行 300 次，不能把多个任务均分到一次 300 次中。模型、
配置或任务数量增加时，样本量按单元线性增加。

“300 次”必须结合评分是否含随机性解释：

- 确定性的离线预测指标必须使用 300 个不同 query，六个种子各 50 个且互不重复；
- CEM 等随机算法可以在同一 query 上运行多个独立搜索种子，但统计时仍要按 query
  聚类，不能把随机重复当成新的场景。

确定性任务中的“不同 query”不能只靠不同字符串 ID 判断。至少要同时审计独立
geometry/reset、query 像素内容哈希和完整 payload 引用；若目标不渲染，同一画面
下不同 goal 可能仍是完全相同的模型输入。内容重复项不能作为独立样本估计方差。

多个执行预算也不能分摊 300 次：

- 如果 planner 看不到总预算，短预算轨迹又是长预算轨迹的严格前缀，可以运行
  300 条最大预算轨迹，再从同一批轨迹读取各截止点；
- 如果 planner 会根据剩余预算改变动作，每个预算点都要独立执行 300 次；
- 两种方法都必须保持 query、condition 和随机计划的配对关系。

## 6. 指标与计算方式

### 6.1 上下文可辨识性

先用真实状态和动作验证隐藏因子能从上下文恢复。对物理速度，可在无碰撞动作块
中检查：

```text
Δx_block ≈ speed × Σ(raw actions in block)
```

报告恢复 MAE、最大误差、无信息动作块数量和碰撞残差。若 oracle 都无法辨识，
不能把模型无响应归因于没有 ICL。

### 6.2 下一状态预测

直接预测指标使用离线冻结的一步转移。每条 Eval 样本必须在评分前保存：

- query 图像；
- 随后执行的完整 action block；
- 真实执行该 action 后的下一帧。

如果模型输出 latent，评分时用当前 checkpoint 的冻结 encoder 编码真实下一帧，
再计算预测 latent 与真实下一帧 latent 的 MSE。正式评分不在线运行环境，也不把
latent 反推成速度、像素位置或其他物理量。

同一个目标下一帧至少比较同设定历史和其他设定历史：

```text
匹配 loss = MSE(同设定历史下的预测 latent, 真实下一帧 latent)

匹配优势
= 其他设定历史的平均 loss − 匹配 loss

相对 loss 降低
= 匹配优势 / 其他设定历史的平均 loss
```

只报匹配 loss 不能隔离上下文作用。不同 checkpoint 的 encoder 空间和原始 MSE
尺度也可能不同，因此跨模型应比较归一化后的相对 loss 降低、成对训练种子效应和
方向一致性，不直接比较原始 MSE。

需要多步预测时，必须在评分前离线生成、冻结并哈希每个 horizon 的真实目标帧，
再发布新的协议版本；不能在正式评分期间临时调用模拟器补目标。

多步真实未来评分还必须满足：

- 只向模型输入协议允许的真实历史/query 帧；未来帧全部自回归，不使用 teacher
  forcing；
- 每个 horizon 分别计算和汇总，不跨 horizon 平均成一个分数；
- 只输入较短未来动作时，共同预测前缀必须与完整 rollout 一致；
- 能力按从 h1 开始连续通过的最远 horizon 声明，后续某步重新为正不能跨过前面的
  失败；
- 多个 horizon 可以复用同一批 300 条冻结轨迹，但每个 horizon 仍须包含全部 300
  个不同 query。

多步动作轨迹本身也属于结论边界。安全回路可以检验多次自回归后能否回到正确状态，
但不能自动证明持续远离起点的开放轨迹同样准确。报告必须写明动作族、净位移结构、
碰撞筛选和最远实测 horizon。

### 6.3 固定候选动作

对同一 query 生成一组冻结候选动作，三种历史使用完全相同的 candidate bank。
模型只负责产生代价和排序；候选的真实结果由 `z_query` 下的模拟器计算。

至少报告：

- 代价与真实末端距离的 rank 相关；
- top-k 和 argmin 变化；
- 被选候选的真实成功率和最终距离；
- 被选候选与真实最优候选的末端代价差。

固定候选隔离了模型代价，不包含 CEM 采样分布和滚动重规划。固定候选没有改善、
而自由 CEM 有差异时，不能把闭环差异全部归于预测正确性。

### 6.4 闭环规划

闭环结果至少包含：

| 类别 | 指标 |
|---|---|
| 截止结果 | 每个执行预算的成功数和成功率 |
| 连续轨迹 | final/best distance、normalized progress、distance AUC |
| 执行效率 | 配对 steps-to-success、path length、progress/path length |
| 计算效率 | CEM solve 次数、候选评估量、rollout blocks、GPU 时间 |

成功条件必须区分：

- ever success：轨迹是否曾进入成功半径；
- terminal success：固定 horizon 末端是否仍在半径内；
- deadline success：是否在执行预算耗尽前完成；
- steps-to-success：首次进入成功半径的真实步数。

不同条件的成功集合不同时，只比较各自成功样本的平均步数会产生选择偏差。应优先
报告共同成功 query 上的配对到达时间，并同时给出新增成功任务数量。

### 6.5 原能力保持

新训练至少在原始 heldout、与基线同分布的合成 Eval 和 1/2/3/5-step rollout
error 上与原始模型比较。能力保持使用预先冻结的非劣效界限，不能因为新能力较强
就忽略原能力退化。

## 7. 规划资源与因果边界

### 7.1 必须冻结的资源

| 资源 | 例子 |
|---|---|
| 时间聚合接口 | frameskip、action block |
| 模型视野 | rollout horizon × action block |
| 搜索预算 | candidates、iterations、top-k、采样方差 |
| 真实执行预算 | 最大环境步数和允许的重规划次数 |
| 代价与成功定义 | terminal cost、成功半径、是否立即终止 |

最终分数只能写成“该 PlannerProtocol 下的表现”，不能写成模型无条件能力。

### 7.2 速度等时间尺度因子

物理速度会改变单位动作位移和预计到达时间，因此要分开：

```text
B_exec：真实环境最多执行多少原始步
H_model：每次规划时预测多少模型步
H_model_raw = H_model × action_block
```

增加 `B_exec` 只允许执行和重规划更多次，不会自动扩大单次规划视野。速度轨道
至少需要紧、标准、宽松三个执行预算，并在固定执行预算下检查模型视野。候选数和
迭代数是另一组搜索资源，不得与模型视野同时改变后再做单因素归因。

如果条件差异随 `B_exec` 增加而消失，真实截止有贡献；如果只随 `H_model` 增加
而消失，内部可达性是主要原因；若两者都不消失，再检查搜索预算、代价函数、
滚动重规划和模型误差。

物理速度和 frameskip/action block 不是同一变量。单因子速度实验必须固定
action block，保存块内全部有序动作，并把结论限定为“固定时间聚合下的物理速度
ICL”。改变 frameskip、动作重复次数或观测频率需要独立训练和独立协议。

### 7.3 其他因子是否需要预算阶梯

| 因子类型 | 示例 | 资源设计 |
|---|---|---|
| 时间尺度或动力学 | 速度、摩擦、质量、动作延迟 | 完整执行预算和视野阶梯 |
| 时间聚合 | frameskip、action repeat、观测频率 | 独立接口控制和完整预算阶梯 |
| 路径与拓扑 | 门位置、障碍、通道开闭 | 至少紧/宽预算敏感性检查 |
| 语义或观测映射 | 颜色规则、目标语义 | 通常一个冻结主预算即可 |
| 随机性与噪声 | 观测噪声、随机转移 | 优先检查不确定性和搜索预算 |

门位置等变量不一定像速度一样改变单位动作位移，但可能改变路径长度，所以仍应在
Calibration 上排除预算地板和天花板。

## 8. 训练归因

只比较原始模型与目标模型可以说明两者不同，不能证明差异来自目标因子支持。
正式训练归因至少需要：

| 模型 | 作用 |
|---|---|
| 原始数据模型 | 原始能力基线 |
| 原始 + 单一因子合成混训模型 | 控制额外数据、训练步数和合成流程 |
| 原始 + 多样因子合成混训模型 | 检验因子多样性训练 |

需要匹配模型结构、初始化方案、optimizer、训练步数、有效 batch、原始/合成抽样
比例、总曝光量、normalizer、geometry、采集策略和 checkpoint 选择。单一因子与
多样因子混训模型之间应只改变被研究的因子支持，并使用多个成对训练种子。不同
原始 clip 数可以是速度导致 episode 提前终止的自然结果，但正式抽样次数必须相等
并明确审计。

合成单训模型可以回答“合成数据能否重建基础能力”，但不是多速度训练归因的必要
组成部分；它应作为数据质量对照单列。

## 9. 统计与预注册

同一 query 的不同历史条件应共享 geometry、goal、动作探针、candidate bank 和
随机计划。主要统计单位是独立 geometry 或预先定义的 geometry×probe cluster，
不能把同一 query 的重复规划当成新的独立场景。

至少报告：

- 配对效应量和 bootstrap 区间；
- 成功率的 A-only/B-only/both/neither；
- 六个评测种子的逐种子方向；
- 多个训练种子的最高层复现；
- 若结论依赖 p-value，报告预注册的配对检验；
- 若同时存在多个 p-value 主检验，报告预注册的多重比较校正方法。

评分前必须冻结主假设、模型、checkpoint、normalizer、catalog、样本量、planner
资源、指标、聚合、阈值、统计方法和停止规则。查看 Validation 后新增的分析只能
标为探索性，不能倒写成预注册结论。

若完整性检查在任何模型分数产生前拦截了 catalog，可以修复重复样本、损坏文件或
错误哈希，记录原因并重新冻结；不得借机根据模型表现调整速度、阈值或判断门。已经
看到模型分数后的协议变化必须发布新版本，并清楚区分探索与确认。

## 10. 标准报告与正式 Test

正式报告按以下顺序组织：

1. 一句话结论及允许/不允许的能力声明；
2. 数据、模型和速度/因子支持审计；
3. 上下文响应和单步/多步真实未来校准；
4. 固定候选动作结果；
5. 闭环预算曲线、连续轨迹和计算量；
6. 原能力保持与成对训练种子归因；
7. 失败单元、限制和下一步；
8. 完整复现入口。

不得用实验流水账代替当前结论，也不得把多个预算、多个任务或不同含义的指标简单
平均成一个 “ICL score”。

进入正式 Test 前必须满足：

- 数据全量回放和关键 split 泄漏审计通过；
- 上下文可辨识性与精确动力学正对照通过；
- Validation 中存在非地板、非天花板信号；
- planner 资源敏感性已经摸清并冻结；
- 原能力满足保持标准；
- 模型不按最好训练种子选择；
- 模型、planner、指标、阈值和 Test catalog 全部冻结。
