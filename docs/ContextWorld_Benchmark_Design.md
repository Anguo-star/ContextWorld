# ContextWorld Benchmark 设计指南

**更新日期**：2026-07-21
**用途**：指导 ContextWorld 中新的上下文学习能力如何构造、评测和公开报告

## 1. Benchmark 要回答什么

ContextWorld 关注世界模型能否在不更新参数的情况下，从近期交互中识别当前环境的
规则，并立即把它用于未来预测和规划。

一个完整实验应依次回答：

1. 历史里是否真的包含目标规则的信息；
2. 模型的预测是否会随历史改变；
3. 改变后的预测是否更接近当前环境的真实未来；
4. 更准确的预测是否改善动作选择；
5. 在固定规划资源下，闭环任务能否完成；
6. 提升是否来自目标训练变量，并且没有损伤基础能力；
7. 能力对训练未见值、未见组合和范围外值能保持到哪里。

最终成功率很重要，但不能单独回答这些问题。它同时受世界模型、规划器、任务
距离、成功半径、搜索资源和执行步数影响。ContextWorld 因此采用分层指标，不把
所有结果压成一个难以解释的总分。

## 2. 先判断目标因素是否真的需要历史

不同环境变化需要不同的实验名称和证据。

| 因素类型 | 当前 query 能否直接看出 | 例子 | 合适的任务名称 |
|---|---|---|---|
| 隐藏动力学 | 不能 | 速度、摩擦、动作增益、响应延迟 | 上下文学习主任务 |
| 可见几何 | 通常能 | 门位置、障碍布局 | 视觉条件泛化 |
| 隐藏×可见组合 | 只能看见一部分 | 速度×门位置 | 因素解耦与组合泛化 |

每个新因素训练前都应先跑 query-only 基线。如果只看当前图像已经足以识别因素，
增加历史后的提升不能直接解释为“模型从历史学会了规则”。这不是说任务没有价值，
而是应该把它报告为视觉泛化或组合能力。

对于隐藏因素，评测器固定 query 后续实际使用的规则。历史可以使用较低、相同或
较高的规则值。文档统一称为“较低历史、同设定历史、较高历史”，不使用“正确历史、
错误历史”或“反事实历史”。只有任务明确假设历史与 query 属于同一稳定环境时，
同设定历史才是预测准确性的标准参照。

## 3. 最小而完整的实验结构

### 3.1 训练对照

至少需要三类模型：

| 模型 | 训练数据 | 回答的问题 |
|---|---|---|
| 原始数据模型 | 原始数据 | 原模型本来有多少上下文响应 |
| 单值控制模型 | 原始数据 + 只含一个因素值的合成数据 | 提升是否只是额外数据或训练流程造成 |
| 多值目标模型 | 原始数据 + 多个因素值的合成数据 | 因素多样性是否带来目标能力 |

单值和多值模型应保持场景、样本量、采集策略、结构、优化器、训练步数和 checkpoint
选择规则一致，只改变目标因素是否有变化。至少使用三个配对训练种子，避免把单个
checkpoint 的偶然结果当作训练结论。

如果目标方法不用原始数据，还应增加 synthetic-only 模型，并单独验证基础能力是否
能够重建。

### 3.2 Eval 轨道

有顺序的连续因素至少分开报告：

| 轨道 | 因素值与训练集关系 | 能支持什么结论 |
|---|---|---|
| 训练已见 | 训练中精确出现 | 调用学过的规则 |
| 范围内未见 | 未精确出现，但位于训练最小值和最大值之间 | 插值 |
| 低端范围外 | 低于训练最小值 | 向低端外推 |
| 高端范围外 | 高于训练最大值 | 向高端外推 |

见过、插值和外推不能合并为一个平均分。只有低端和高端都逐参考值通过相同的冻结
判断门，才能声明双向范围外外推。

Geometry 是否见过与因素值是否见过是两个独立维度。实验必须明确做到 clip、
episode、scenario 或组合中的哪一级隔离，不能用较弱的隔离名称代替较强隔离。

### 3.3 每个单元 300 个样本

默认确认规模是：

```text
每个模型 × 每条 Eval × 每个参考值 × 每个历史条件
× 50 个 query × 6 个评测种子 = 每个单元 300 次
```

多个任务不能平分这 300 次。确定性离线评分要使用 300 个不同 query；六个种子的
query 集合也应互不重叠。CEM 可以在相同 query 上运行不同搜索种子，但统计时必须
按 query 聚类，不能把搜索重复当成新的场景。

“不同 query”不能只看字符串 ID。至少检查起点或 geometry、输入图像内容哈希、
动作和目标 payload。若目标不渲染，同一画面配不同 goal 仍可能是完全相同的模型
输入。

## 4. 数据必须先于模型结果通过审计

正式数据至少保存并检查：

- 因素设定值与模拟器实际 readback；
- 状态、动作、图像、目标、终止信息和逐步回放一致性；
- 训练、Validation、Test 的 episode、scenario 和因素值交集；
- query 图像与完整 payload 的唯一性；
- 历史动作是否真的让目标隐藏因素可辨识；
- 碰撞、边界截断和提前终止是否破坏真实未来；
- 配置、代码、数据、checkpoint、normalizer 和候选动作库哈希；
- 采集、训练、评测和规划随机种子。

对速度这类动力学，可先用真实状态和动作验证：

```text
位移 ≈ agent.speed × 原始动作之和
```

如果 oracle 都不能从历史恢复因素，模型没有响应不能被归因于“没有上下文学习”。
关键审计失败时，模型分数只能用于调试，不能进入正式结论。

## 5. 指标体系

### 5.1 第一层：真实未来预测

这是隐藏动力学学习的主证据。数据生成阶段先保存 query 后的动作序列和真实未来
帧；评分阶段只运行模型，不再在线调用环境。

模型从真实历史开始连续自回归：

```text
预测 latent_1 -> 预测 latent_2 -> ... -> 预测 latent_h
```

中间步骤不能用真实帧替换。第 h 步目标是当前 checkpoint 的冻结 encoder 对真实
未来帧的编码：

```text
L_h = MSE(预测 latent_h, encoder(真实未来帧_h))
```

不同 checkpoint 的 encoder 空间可能不同，所以原始 MSE 只用于同一 checkpoint
内部的配对比较。公开报告应优先给出以下尺度：

| 指标 | 计算方式 | 解释 |
|---|---|---|
| loss 比值 | 同设定历史 loss ÷ 其他历史平均 loss | 越低越好，1 表示没有平均优势 |
| query 胜率 | 同设定 loss 小于其他历史平均 loss 的 query 比例 | 说明效果覆盖多少独立 query |
| 严格胜率 | 同设定 loss 小于每一种其他历史 loss 的 query 比例 | 检查优势是否同时胜过所有条件 |

“相对 loss 降低 = 1 − loss 比值”可以保留用于冻结的旧判定门，但不应称为准确率。
也不建议从 latent 反推出像素位置或数值速度：decoder 和位置提取误差会混入指标。
直接与同一 encoder 编码的真实未来比较，证据更少依赖额外假设。

多步结果必须逐 horizon 报告。若动作轨迹包含回路，还要说明哪些 horizon 的真实
状态重复；这种测试可以证明连续自回归的误差传播，但不能冒充任意开放轨迹。

### 5.2 第二层：固定候选动作选择

对每个 query 冻结完全相同的候选动作序列，让不同历史条件和模型从同一个动作库
选择。使用真实环境评估候选动作后，报告：

- 被选动作与真实最优动作的终点差距；
- regret 或动作排序相关性；
- 逐 query 胜率及置信区间。

这一层把“预测更准”连接到“动作排序更好”，同时避免 CEM 每次随机搜索不同动作
造成的混淆。

### 5.3 第三层：闭环规划

闭环报告至少包括：

- 成功率；
- 最终目标距离；
- 首次到达目标所用真实环境步；
- 失败类型；
- 模型调用数、候选数和实际执行动作数。

对于速度，必须设置多个执行步数预算，例如 50/75/100 步。较快的速度假设可能在
有限预算内更容易覆盖目标，即使它并不符合 query 的真实速度。预算曲线能展示这种
现象，但不能代替真实未来预测误差。

规划资源也应至少做单变量阶梯：

| 参数 | 作用 |
|---|---|
| rollout horizon | 模型规划时向前看多远 |
| candidates | 每轮搜索多少条动作序列 |
| iterations | 候选分布优化多少轮 |

每次只改变一个参数。若提升 horizon 后历史条件差距缩小，问题更可能来自视野不足；
若增加 candidates 或 iterations 后缩小，更可能来自搜索不充分；若都不改变，则应
进一步检查模型预测与代价函数。

并非所有因素都需要速度式的执行预算阶梯。门位置等可见几何通常只需固定预算的
预测、动作选择和规划评测；只有因素会直接改变单位动作覆盖距离或可达步数时，预算
阶梯才是必要主项。

### 5.4 第四层：能力保持

新能力通过后，还必须回到原始任务检查：

- episode-heldout 原始 Eval；
- 与原任务规则匹配的合成 Eval；
- 既有困难集；
- 若使用 synthetic-only，增加原始能力重建对照。

报告每个训练种子是否通过，不用多个数据集的均分掩盖某一项明显退化。

## 6. 正式判断与统计

一个推荐的预测校准门是：

1. 每个目标模型训练种子，在每个参考值上的同设定历史平均优势为正；
2. 每个参考值的六个评测种子方向一致；
3. 目标模型相对成对单值控制模型，在每个训练种子上提升为正；
4. 同时报告 query 胜率和严格胜率，避免均值由少量样本支配。

多步能力按从 h1 开始连续通过的最远 horizon 报告。某一步未通过后，即使更远一步
偶然为正，也不能填补中间断点。

统计单位应是独立 query 或独立 scenario，不是轨迹中的每一帧。建议使用配对
bootstrap 或按 query 聚类的置信区间。训练种子只有三个时，方向一致性比不稳定的
渐近显著性检验更容易解释，但仍应公开三个种子的原始结果。

Test 必须在模型、数据、指标、判定门和规划配置冻结后一次性运行。Validation 可用
于形成新假设，但新假设必须重新登记，不能改写成事先计划。

## 7. 结果应该怎样公开

每个能力类别的公开报告应按固定顺序写：

1. 一页内给出问题、训练配方、关键数字和一句话结论；
2. 解释模型输入以及因素为什么需要历史；
3. 列出训练对照、Eval 轨道和每格样本量；
4. 先报告真实未来预测，再报告动作选择和闭环规划；
5. 单列训练归因、能力保持和失败边界；
6. 最后给出下一阶段与复现入口。

不要把时间顺序的实验追加记录当成最终报告，也不要让代号代替名称。表头应直接写
“原始数据模型”“多速度合成混训模型”等可读名称；内部 ID 只放在复现协议或机器
结果中。

以下说法应避免：

- 把相对 loss 降低写成“预测准确率”；
- 把较快历史的更高 CEM 成功率直接写成“速度预测更准”；
- 把区间内未见值写成范围外外推；
- 把可从 query 直接看见的因素不加验证地称为 ICL；
- 把多个 Eval 或多个条件均分到一次 300 样本中；
- 用跨 checkpoint 的原始 latent MSE 给模型排名。

## 8. ContextWorld 的推荐能力路线

1. 先完成一种隐藏动力学的训练对照、插值、外推、多步预测和规划资源评测；
2. 用 query-only 基线加入一种可见几何，确认它是视觉泛化还是确实需要历史；
3. 测试隐藏动力学与可见几何的训练未见组合；
4. 加入第二种隐藏动力学，例如动作增益或响应延迟；
5. 最后统一比较更长 History 对不同因素和组合的作用。

这一路线先把每一种证据的含义固定下来，再增加任务复杂度。当前 TwoRoom 速度实例
及其数据见 [History-3 速度学习报告](TwoRoom_Speed_Benchmark_Report.md)，冻结配置与
复现命令见 [协议索引](protocols/README.md)。
