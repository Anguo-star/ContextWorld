# TwoRoom 门能力 Benchmark 设计

**更新日期**：2026-07-22

**当前状态**：第 1 阶段设计已预注册，新的训练数据、模型和正式 Eval 尚未生成或执行

**机器配置**：`configs/benchmark/tworoom_door_visual_generalization_v1.yaml`

## 1. 结论先说清楚

TwoRoom 当前的门位置会直接画在模型看到的图像里。模型不需要从历史动作和状态变化
中猜门在哪里，只看当前 query 画面就能看到开口。因此，下一阶段不能直接写成“门
位置 ICL”。

门部分按以下顺序推进：

1. **可见门位置泛化**：确认模型能否看懂训练未见的门位置，并据此预测穿门、撞墙和
   跨房间规划；
2. **隐藏通道规则 ICL**：改造环境，使当前画面无法判断哪条通道能通过，必须根据
   History-3 中的交互结果判断；
3. **速度 ICL 与可见门位置的组合**：前两项分别成立后，再测试隐藏速度和可见几何
   同时变化时的组合能力。

这个顺序对应“先验证视觉基础，再验证真正的门相关 ICL，最后做组合”。如果直接做
组合实验，失败时无法判断模型究竟没看懂门、没学会隐藏规则，还是不会组合两者。

## 2. 当前已有基础与缺口

已有 `tworoom_door_pixel_v1` 数据完成了 12,624 帧的逐行回放，状态误差和编码后像素
误差均为 0；像素 oracle 也证明门位置变化会确定地改变当前画面。它可以继续用于
环境、渲染和数据管线校核。

它还不能直接用于正式训练归因：

- 训练部分只有 128 个 episode，正式训练会大量重复同一批 clip；
- 没有一份数据量、reset、轨迹采集方式完全匹配，但门始终固定在 49 的控制数据；
- 早期 Eval 以场景 rollout 为主，没有冻结“每个门位置、每个任务、每个条件均
  50×6”的真实未来 latent 评分单元；
- 早期配置中的“换成另一门位置历史”会制造可见几何突变，不再用于正式实验。

因此，旧数据保留为物理基础，不作为第 1 阶段正式训练集或正式结论来源。

## 3. 第 1 阶段：可见门位置泛化

### 3.1 要回答的问题

第 1 阶段只回答四个问题：

1. 多门位置训练是否让模型更准确地预测训练未见门位置下的真实未来；
2. 这种提升是否来自门位置多样性，而不是仅仅增加了合成数据和训练步数；
3. 更准确的预测是否改善固定候选动作的排序；
4. 在固定 CEM 配置下，模型是否更容易完成跨房间任务，同时保留原始能力。

它不回答“模型是否从历史推断门位置”。门在当前画面中可见，无论 History-3 是否
有帮助，这一阶段都只报告为可见几何泛化。

### 3.2 训练对照

正式比较使用下列三类模型。公开表格使用完整中文名称，不用字母代号代替含义。

| 模型 | 训练数据 | 用途 |
|---|---|---|
| 原始数据模型 | 只用原始 TwoRoom 数据 | 描述原模型面对新门位置时的基础能力 |
| 固定门位置合成混训模型 | 原始数据 50% + 门位置始终为 49 的合成数据 50% | 排除额外数据量和训练流程的影响 |
| 多门位置合成混训模型 | 原始数据 50% + 16 个门位置的合成数据 50% | 检验门位置多样性是否带来泛化能力 |

训练归因的主比较是“固定门位置合成混训模型”与“多门位置合成混训模型”。两者均
从头训练，并使用三个配对训练种子：3072、4096、5120。原始数据模型是描述性参考，
不代替匹配控制组。

两种混训模型统一使用：

- History-3 LeWM，action block 为 5；
- 每个逻辑 epoch 2,629,632 个样本，共 5 个逻辑 epoch；
- 有效 global batch 为 1,024，共 12,840 次 optimizer step；
- 只用原始训练 split 计算 normalizer；
- 不早停，固定选择最后一步 checkpoint；
- 原始数据和合成数据各获得 6,574,080 次训练抽样。

### 3.3 新训练数据

需要重新生成两份严格匹配的数据：

| 数据 | 门位置 | Train | Validation |
|---|---|---:|---:|
| 固定门位置控制数据 | 始终为 49 | 512 场景 × 32 episode | 96 场景 × 16 episode |
| 多门位置目标数据 | 49 至 169，共 16 个位置 | 512 场景 × 32 episode | 96 场景 × 16 episode |

多门位置训练值为：

```text
49, 57, 65, 73, 81, 89, 97, 105,
113, 121, 129, 137, 145, 153, 161, 169
```

两份数据使用完全相同的场景数量、episode 数量、reset 与 goal seed 组、专家策略
seed 组、采集策略、episode 上限、图像编码和数据校核。唯一有意改变的是门位置是否
变化。多门位置数据按门位置均衡分配场景；固定门数据为每个场景使用独立 seed，
不能复制少量轨迹来凑样本数。

表中的 Validation 只供训练过程监控，使用与各自 Train 相同的门位置集合和独立
scenario seed；它不包含下面正式 Eval 的留出门位置。模型不早停，Validation 也不
参与 checkpoint 选择。

正式训练前，每份数据至少要有 600,000 个不同的训练 clip，按冻结训练预算计算的
平均重复抽样不能超过 11 次。这个门槛沿用已经跑通的 Speed Benchmark 数据质量
标准。

### 3.4 Eval 门位置划分

Eval 的门位置和训练关系必须分开报告：

| Eval 轨道 | 门位置 | 用途 |
|---|---|---|
| Validation：训练已见 | 49、89、129、169 | 检查是否能调用训练中见过的几何 |
| Validation：范围内未见 | 53、85、117、149 | 形成和验证方法，不接触 Test |
| Test：范围内未见 | 61、77、93、109、125、141、157、165 | 正式检验插值 |
| Test：低端范围外 | 24、32、40 | 检验低端外推 |
| Test：高端范围外 | 180、190、199 | 检验高端外推 |

表中的“已见/未见”均相对于多门位置目标模型的训练值。固定门位置控制模型除 49 外
没有见过其他门位置，这正是它作为数据量匹配控制组的作用。

Validation 和 Test 使用独立的 reset、goal、动作和 catalog seed。Test 在数据、模型、
指标、阈值和 CEM 配置全部冻结后只运行一次。

### 3.5 每个 Eval 到底有多少样本

离线预测包含两个互不合并的任务：

- **穿过开口**：query 动作会从开口通过墙体；
- **接触墙面**：query 动作会撞到开口外的墙面并受到碰撞约束。

每个门位置、每个任务都使用 6 个 Eval seed；每个 seed 有 50 个不同 query，共 300
个 query。不能让“穿门”和“撞墙”平分这 300 条。

同一批 300 个 query 分别在两种模型输入下完整评分：

| 输入 | 内容 | 作用 |
|---|---|---|
| 只给当前画面 | 当前 query 帧和待执行动作 | 检查模型能否直接利用可见门位置；属于诊断项 |
| 正常连续三帧 | 同一 episode 中前两次转移加当前 query | 对应 LeWM 的正常 History-3 输入；属于正式主项 |

这两种输入共享 query，便于配对比较，但每种输入都会完整运行 300 条，不会拆分样本。
正常连续三帧中的门位置始终不变，不构造“前面是另一扇门、到 query 突然换门”的
不自然历史。

只给当前画面会把训练时的三帧输入缩短为一帧，因此它同时包含输入长度变化，不能
单独作为能力硬门槛。正式结论以正常连续三帧为主；单帧结果如果也改善，可以进一步
说明模型直接利用了当前画面的门几何。如果单帧没有改善，只能报告单帧输入限制，
不能反过来宣称正常三帧中的提升来自“历史推断门位置”。

Validation 每个 checkpoint 共评分：

```text
8 个门位置 × 2 个预测任务 × 2 种输入 × 300 = 9,600 条序列
9,600 条序列 × 4 个 horizon = 38,400 个 loss
```

封存 Test 每个 checkpoint 共评分 16,800 条序列，产生 67,200 个逐 horizon loss。
六个 Eval seed 的 query 集合互不重叠；不同模型和输入条件复用相同 query、动作和
随机数，保持配对。

### 3.6 数据生成后必须通过的校核

任何模型开始训练前，数据必须同时通过：

- 环境实际读回的门位置和速度等于配置值，速度始终为 5；
- 保存状态、动作、目标、终止信息和重新执行结果逐项一致；
- 使用相同 PNG 编码后，重新渲染帧逐字节一致；
- Train、Validation、Test 的 scenario、episode 和留出门位置无交集；
- 六个 Eval seed 之间没有重复 query 图像或重复完整 payload；
- 像素 oracle 能从当前帧确定开口位置；
- 穿门动作确实通过，撞墙动作确实被墙阻挡；
- 每条预测 query 的真实未来不是静止画面的重复；
- 跨房间规划 query 能被真实环境 scripted oracle 在 100 步内完成；
- 配置、代码、catalog、payload 和数据树均保存哈希。

任一关键项失败时，只能修数据并重新冻结，不能先训练再解释。

## 4. 评价指标与计算逻辑

### 4.1 第一层：真实未来 latent 误差

这是第 1 阶段的主证据。生成 Eval 数据时预先保存 query 后的动作和真实未来帧；
评分时不再调用环境。模型从 query 开始连续自回归，评测第 1、2、3、5 个 action
block：

```text
L_h = MSE(模型预测的 latent_h,
          当前 checkpoint 的冻结 encoder(真实未来帧_h))
```

中间步骤不喂真实帧，不使用 teacher forcing，也不从 latent 反推出门位置或像素
坐标。

不同 checkpoint 的 encoder 空间并不完全相同，原始 latent MSE 只在同一 checkpoint
内部解释。跨模型比较使用“相对静止预测的误差倍数”：

```text
误差倍数_h = 模型预测 MSE_h
             ÷ MSE(encoder(query 帧), encoder(真实未来帧_h))
```

误差倍数 1 表示和“未来画面保持不变”一样；小于 1 表示模型比静止预测更好。它不是
准确率，也不转换成容易误解的百分数。catalog 生成阶段如果发现真实未来几乎不变、
导致分母失去意义，就丢弃候选并重新采样；正式 catalog 冻结后每格仍须完整保留
300 个 query，不能在看到模型结果后删样本。

同时报告：

- 每个门位置和 horizon 的真实未来 latent MSE；
- 相对静止预测的误差倍数；
- 多门位置模型逐 query 优于配对固定门模型的比例；
- 只给当前画面与正常连续三帧的同 checkpoint 配对差异。

### 4.2 第二层：固定候选动作排序

每个 query 预先冻结同一组 300 条候选动作序列。所有模型看到完全相同的候选库，
再用真实环境算出每条候选的真实结果，报告：

- 模型所选候选与真实最优候选的终点距离差；
- 模型预测代价与真实终点距离的 Spearman 排序相关；
- 所选候选是否成功穿过门。

这一层回答“更准确的预测有没有改变动作排序”，不混入 CEM 随机搜索差异。

### 4.3 第三层：固定 CEM 闭环规划

闭环任务统一为跨房间导航。每个门位置仍是独立的 50×6 Eval，不把多个门位置均分
300 次。query 分布同时包含左右两个方向和不同绕行距离，但这些只作为同一跨房间
任务的预先冻结分层，不单独宣称结论。

为避免门在上方或下方时顺带改变任务距离，起点和目标相对当前门中心平移。左右方向
各占一半，起点与目标相对门中心使用 0、20、40 像素三个垂直偏移，并统一朝房间内部
取偏移方向。相同的相对几何模板平移到每个门位置，使各门位置具有相同的路线长度
分布。方向和偏移只用于保证覆盖，不从每格 300 条中再拆出小样本结论。

固定配置为：

| 项目 | 数值 |
|---|---:|
| 执行预算 | 100 个真实环境步 |
| rollout horizon | 10 个 action block |
| receding horizon | 5 个 action block |
| CEM candidates | 300 |
| CEM iterations | 30 |
| top-k | 30 |

报告成功率、最终目标距离、首次成功步数和穿门率。门位置不改变单位动作位移，因此
第 1 阶段不设置速度式 50/75/100 预算阶梯。CEM 结果是规划效用证据，不能代替真实
未来预测误差。

### 4.4 第四层：原始能力保持

多门位置模型还要运行原始 episode-heldout Eval，每个模型、每条 Eval 均为 50×6。
沿用现有非劣门槛：成功率最多下降 5 个百分点，最终距离最多增加 5 像素，并检查
是否有某个原本可解的距离层整体崩溃。

## 5. 第 1 阶段怎样形成结论

只有同时满足以下条件，才写“多门位置训练带来了可见门位置泛化”：

1. 在训练已见和 Validation 范围内未见门位置上，多门位置模型的 h1 误差倍数均低于
   配对固定门模型；
2. 三个配对训练种子都成立，并且每个门位置的六个 Eval seed 分区方向一致；
3. 穿门与撞墙两个任务都成立；
4. 正常连续三帧主项成立；只给当前画面的结果同时完整报告，但不作为硬门槛。

多步结果从 h1 开始报告连续通过的最远 horizon。低端和高端范围外 Test 分开判断；
只有两端每个门位置都通过，才声明双向外推。

固定候选和 CEM 分别形成“动作排序改善”和“闭环规划改善”的附加结论。如果预测
通过但规划不通过，结论应写成“视觉预测泛化成立，尚未转化为当前规划配置下的成功
率提升”，不能抹掉预测结果，也不能把两层混写。

无论结果如何，第 1 阶段都不使用“门位置 ICL”这一结论。

## 6. 第 2 阶段：真正的门相关 ICL

当前单门环境不适合直接做正向 ICL。第 2 阶段将增加一个专用隐藏通道环境：画面中
同时显示上下两个外观相同的通道，但物理上只有一个可以通过。当前 query、起点、
目标和动作在两种规则下保持相同，仅凭 query 无法知道哪条通道有效。

History-3 的前两次交互用于探测一条通道：通过或碰撞的结果揭示当前规则。正式生成
前必须先通过三个 oracle：

1. 两种隐藏规则的 query 像素、状态、目标和动作完全相同；
2. 只看 query 时规则不可辨识，使用两次历史交互时可以唯一判断；
3. History-3 的 support-query 排布在训练和 Eval 中完全一致，不把未经训练的轨迹
   拼接方式当成模型能力。

训练仍使用固定单规则控制与多规则目标两个匹配配方、三个配对种子。Eval 比较无
历史、与 query 同一门规则的历史、另一门规则的历史。只有同一规则历史在真实未来
latent、固定候选和规划上稳定占优，才能声明“门相关 ICL”。

这一步需要新的环境实现和辨识性 pilot，不能复用当前 `door.position` 数据冒充。

## 7. 第 3 阶段：速度 ICL × 可见门位置组合

第 3 阶段测试已建立的速度 ICL 能否在门位置变化时保持，并泛化到训练未见的
“速度 × 门位置”组合。query 直接提供门位置，History-3 只负责提供速度相关的动作
与状态变化；同一段自然历史中不能突然更换门位置。

正式训练至少包含：

- 单速度、多门位置控制；
- 多速度、多门位置目标；
- 每个速度值和门位置值都在训练出现，但指定参数对只在 Eval 出现；
- 三个配对训练种子和匹配的数据量、训练预算。

每个速度 × 门位置 × 历史速度条件仍独立运行 50×6。真实未来 latent 是主指标，
固定候选和 CEM 分开报告。因为任务仍包含速度，闭环部分继续保留 50/75/100 步预算
阶梯。

早期 `tworoom_speed_door_composition_v1` 的 5×5 网格可用于组合 split 和物理管线
pilot，但规模不足以直接支撑正式训练结论。

## 8. 下一步具体执行顺序

第 1 阶段按下列顺序执行，不能跳过数据校核直接训练：

1. 实现固定门位置和多门位置两份 v2 合成配置，并增加门位置均衡、独立 seed 和训练
   clip 重用率检查；
2. 先做 compile-only 和少量场景 pilot，核对 reset、专家轨迹、PNG 编码、Lance
   loader 与 exact replay；
3. 生成两份完整训练/Validation 数据，完成全量回放、split、唯一性、覆盖率和数据树
   哈希校核；
4. 生成 Validation 的穿门、撞墙、固定候选和跨房间 CEM catalog；每格冻结 50×6，
   运行 scripted oracle 后封存 payload；
5. 对两个训练配方先跑 data preflight 和真实 LeWM GPU smoke；
6. 使用 8 张 GPU 同时运行两个 4-GPU 训练任务，按三个种子分三轮完成六个模型；
7. 先批量计算真实未来 latent；确认评分链路和数据完整后，无论模型差异方向如何，
   都继续运行已冻结的固定候选与 CEM，避免根据主结果选择是否评测；
8. 运行原始能力保持，汇总三个训练种子与六个 Eval seed 的逐门位置结果；
9. 冻结代码、配置、阈值和 checkpoint 后，一次性打开 Test；
10. 将最终数字写入独立结果报告，并把本设计文档的状态从“尚未执行”更新为对应
    阶段结论。
