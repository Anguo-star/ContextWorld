# ContextWorld 公开评分与展示建议

这是公开报告设计建议，尚未替代 v3 的冻结指标、结果或准入规则。建议采用“每任务判别分数为主、
连续响应误差并列、种子与条件明细补充”的展示方式。3/3 保留为内部完整能力条件的达标计数，
不作为排行榜成绩，也不将未达标的有效预测归零。

## 可参考的已有工作

| 工作 | 原始评分方式 | 对 ContextWorld 的启示与边界 |
|---|---|---|
| [Physion++](https://dingmyu.github.io/physion_v2/) | 观察运动以推断质量、摩擦等隐藏属性，再预测物体是否接触；报告任务准确率 | 与我们的研究问题最接近。物理预测可以有逐案例正确率；其接触预测 readout 不能直接替代我们的 latent 预测接口 |
| [Physion](https://physion-benchmark.github.io/) | 用物体接触预测读出物理理解，比较模型和人的准确率 | 判别任务是衡量物理预测的一种可解释读出，不等于完整动力学误差 |
| [Meta-World](https://metaworld.farama.org/evaluation/evaluation/) | 汇总任务、目标位置与 episode 的成功率；meta-RL 报告适应后的表现 | 训练种子是重复实验，案例/episode 才是得分样本；其交互和梯度适应条件不同于我们的冻结权重 ICL |
| [PDEBench](https://papers.nips.cc/paper/2022/file/0a9747136d411fb83f0cf81820d44afb-Paper-Datasets_and_Benchmarks.pdf) | RMSE、归一化 RMSE及边界、守恒、频率等误差 | 连续物理响应需看误差，而不能仅看分类是否正确；它比较共同物理状态，我们使用模型各自的 latent 空间，不能直接照搬跨模型误差排名 |
| [RLiable](https://github.com/google-research/rliable) | 分层 bootstrap 区间、分数分布、IQM 等统计报告方法 | 参考其不确定性报告原则；它是统计方法，不是新的物理能力指标，也不能让三个训练种子变成充分的重复性证据 |

## 与已有工作的重叠及公开价值

Physion++ 是直接相关工作，不能只作为评分格式参考。其论文 §3.1 已设计预测阶段起点画面
相同、隐藏属性不同而结局不同的配对视频；§4.1 比较保留/移除属性推断历史，并训练逻辑回归
readout 预测接触事件。因此，“从历史推断隐藏属性”“配对控制画面”“用历史消融判断是否利用
属性”都不能宣称为 ContextWorld 独有。部分 Physion++ 场景在遮挡后重新布置物体，以考察属性
推断的使用；这与我们连续短轨迹的设计不同，但不是其协议有缺陷。
来源：[Physion++ 原论文](https://arxiv.org/pdf/2306.15668)。

更早的 [CoPhy](https://projet.liris.cnrs.fr/cophy/) 已从视觉经历推断隐藏物理因素，并预测干预后
的反事实轨迹；“因果/反事实物理评测”也不是新的问题定义。Meta-World 的重点是适应后的控制
成功率，PDEBench 的重点是物理状态预测误差；两者可供我们借鉴报告方式，但不与当前固定权重、
带动作的 latent 预测接口完全相同。

ContextWorld 值得验证的增量是一个更窄的组合：面向带动作输入的 latent 世界模型，在固定
权重、不额外拟合任务分类 readout 的条件下，比较相同查询对应的历史条件预测，并展示差分
响应方向与幅度。无解码器接口、归一化误差和增加任务数量本身，都不足以证明研究新颖性；
当前九项任务的接口统一和数值冻结首先提供的是可复用的工程与诊断价值。

建议保留内部固定基准，并可按“latent 世界模型 ICL 诊断工具集”公开。若目标是独立 benchmark
论文，还需证明现有评测不能方便回答、而本工具能可靠回答的具体问题。最低成本的证据应先用
同一检查点和同一批查询比较准确率与响应指标，选出可复现的不同结论，再针对最近相关协议做
一个小规模对应实验。当前内部高准确率/弱响应例子只说明多指标有用，不能证明 Physion++ 会
误判同一模型。若无法建立这种增量，宜作为已有基准的扩展或评测工具发布，不再为独立新基准
的定位扩充数据、模型或门槛。本次相关工作核对也不是对全部文献的新颖性证明。

## 样本、分数和重复实验

我们的九项任务是九类能力；每类包含数百个受控预测试验。每个试验提供历史、当前画面、
查询动作和模拟器真实未来。预测是否选择正确未来可以计分，不要求样本必须是文字题目。
三个训练种子是在同一套试验上重复评测三个检查点，不是“三道题”。

公开得分保持现有任务指标：先计算逐案例结果，再按冻结合同中的条件/响应组权重汇总；
最后对训练种子等权求均值，同时报告样本标准差与逐种子值。动作延迟按六个响应组宏平均，
Speed 按参考速度及 track 汇总，不能为了统一外观而改为所有记录直接混合平均。

高分表示当前判别任务完成得好；它不自动表示响应幅度准确、所有条件均可靠或能够闭环规划。
例如同样没有跨过某个门槛，60% 与 90% 的结果仍须保留差异。3/3 只表达三个已观察检查点均
满足全部阈值，不能解释为任务准确率 100%，也不能保证下一次训练一定满足条件。

## 建议的公开表格

主表按论文常见形式排列：每行是模型架构与训练数据配方，各能力项作为列。当前数据可展示
三架构 × 两种数据配置的六行矩阵；ICL 与原任务 CEM 分两张表，保持相同的行序和任务列序。
每个数值显示三个训练种子的均值 ± 样本标准差。ICL 配比组按组件独立训练，不得将横向一行
解释为一个检查点同时具备全部能力；原环境数据组与 ICL 配比组都是训练后的检查点。

连续响应误差可另生成相同布局的诊断矩阵，方向一致性、响应增益、最弱条件及达标种子数放入
明细。主表中的 CEM 表示对应检查点在原环境上的规划表现，不与 ICL 合成总分。协议有效性
单独标注：有限但表现差的有效结果仍保留分数，协议无效或指标无定义的结果标为无效/不可评分
并解释原因，不能静默删除不利样本后继续排名。

Speed 将 seen、unseen interpolation、extrapolation low、extrapolation high 分开显示；
现有主分数明确标为内插指标。不得把内插高分写成任意速度外推能力，也不应让外推失败掩盖内插分数。

## 连续响应误差的含义

沿用当前评分器的定义：

\[
E=\frac{\sum_i\|\Delta\hat z_i-\Delta z_i\|^2}
        {\sum_i\|\Delta z_i\|^2}.
\]

其中，差分比较同一查询在不同历史下的预测响应与真实目标响应。0 表示差分响应完全一致，
1 是预测完全不随历史变化的参照。该汇总按目标响应能量加权，不是每对归一化误差的等权平均；
新展示直接读取现有字段，不能更换聚合公式。方向一致性理想值为 1；响应增益理想值也为 1，
后者不是越大越好。实现见 [paired_latent_response.py](../../contextworld/benchmarks/paired_latent_response.py)。

该误差对统一缩放有归一化作用，但各模型的表示几何仍不同。它适合解释响应方向和幅度，
不等于统一物理坐标中的绝对误差，也不能单独替代跨模型主分数。两种预测共有的偏置会在差分中
抵消，因此低差分误差不证明绝对未来预测或规划都准确。不要临时将准确率与误差相乘，或将
误差变换后与其他任务混成一个未经验证的总分。

## 统计与公开范围

现有三个训练种子的均值、样本 SD 与逐种子值可以直接展示；SD 不能改名为 95% 置信区间。
若新增比较区间，应保留训练种子、场景/配对及共享查询的关联结构，比较方法时按共同查询配对，
不能把同一场景的多个历史条件、不同 horizon 或不同训练种子的输出都当作独立新样本。
只有三个训练种子时，对训练重复性的推断仍有限；区间的估计对象和重采样单位必须公开。

当前参考是七项 Test 与两项 Development，不计算混合划分总分。九任务公开排行榜必须固定
任务覆盖和 Test 报告资格，不能按某个模型做得好的任务动态选择平均范围。

“性能达标”与“允许公开有效 Test 得分”是否脱钩，属于公开报告协议的正式决策。建议未来公开
版本仅以协议合规性决定是否有效计分，以性能条件支持额外能力声明；这项建议不追认目前被排除
的历史 Test 结果。若采纳，应单独版本化发布报告规则，保留 v3 内部固定参考及其原有资格说明。

## 落地范围

本次核查确认现有冻结报告已保存九任务、三模型、三训练种子的响应增益、方向一致性和归一化
误差；Speed 按四条 track 保留。展示这些已有数值不需要重新训练或推理。后续必要工作是增加
从冻结工件生成的响应诊断表、明确公开列名和协议有效性状态；新的置信区间需单独计算并说明
统计方法。更换主指标、权重、阈值或 Test 资格须发布新协议，不能随展示调整覆盖当前基准。
