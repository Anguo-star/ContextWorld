# Baseline 测量有效性校核（2026-09-10）

> 本文是修复前的 v2 校核记录。后续修复与当前验收状态见
> [最终验收记录](Baseline_Final_Acceptance_2026-09-10.md)。

**结论：当前数据和指标能测出限定任务内的历史条件响应，但 v2 尚不能验收为后续研究的最终地基。**
上一轮完成的是结果归档和工程补齐；本轮发现判定逻辑和关键依赖绑定仍有缺口。
现有分数没有因此整体失效，也没有证据要求重新训练全部 baseline。

审查对象为 `contextworld_joint_scratch_v1_reference_results_freeze_v2`；三个独立 Luna / max
线程负责速度/延迟、六项配对任务和门任务，主进程复现实例并审查结论。
本轮只读已有数据、进行小型 CPU 控制实验；没有修改冻结数据、原始分数或门槛。
机器可读证据见 [baseline_validity_review_2026-09-10.json](baseline_validity_review_2026-09-10.json)。

## 已获得的有效性证据

1. **六项配对数据可以排除当前帧捷径。** 独立线程实际解码 Development/Test Lance 的
   query 与 x0 RGB：每任务每 split 有 256 个 query，各对应两种隐藏条件；query-only
   Bayes 准确率均为 0.5，Dev/Test query 和 x0 哈希交集均为零。六项 reader 同时强制
   配对 query RGB/动作相同、历史不同、真实未来不同。
   对应实现包括 `reacher_arm_mass_icl_data.py:320`、`contact_friction_icl_data.py:335`、
   `motion_damping_icl_data.py:255`、`cube_grasp_rule_icl_data.py:470` 等。
2. **均分相同不是本次发现的数据泄漏。** 机械臂质量 LeWM 两划分均为 85.3515625%，
   但逐种子分数分别为 Dev 84.7656/85.7422/85.5469%、Test 85.1563/86.5234/84.3750%；
   传送门 PLDM 同样是不同逐种子结果恰好具有相同总正确数。像素交集检查也支持数据独立。
3. **反捷径门槛并非只看主分数。** 使用实际 Reacher metric/gate 的 32 对 CPU 控制实验：
   无历史响应被判 50%、gain=0、error=1，拒绝；反向响应拒绝；正确响应通过；
   只有真实响应 1% 的预测虽有 100% 目标选择率，仍因 gain=0.01 被拒绝。
4. **当前门任务通过实例未受已发现遗漏项影响。** 核对两划分共 30 个单元，当前各 9 个
   通过实例的最小 seed-direction 历史收益分别为 Dev 0.434566、Test 0.445831，均为正。

Action Strength 两划分的 256 个 pair_id 重名，但实际 query 像素不重叠，ID 不提供给模型；
这是标识需要加 split 命名空间的问题，不是本次证实的模型输入泄漏。

## 最终验收前的硬缺口

### 1. 门任务的统一判定并未完整重算原合同

`reference_decision.py:582` 的 Development 路径只逐 seed-direction 检查目标正确率，漏掉
原始 Test 合同要求的逐 cell matching-history advantage > 0（原判据见
`hidden_passage_validation.py:2245`）。在真实通过结果的内存副本里，将一个 cell 的
`paired_advantage.same_vs_other_rule_history` 改为 -10，统一判定仍返回通过。

`reference_decision.py:494` 的 Test 路径还直接相信 `summary.decision.checks/passed`。
把两种规则的主正确率和 history win rate 都改成 0、保留旧标志，仍返回通过。
这是错误或陈旧结果信封可绕过完整重判的证据，**不是现有原始结果被篡改的证据**。

最小修复：Dev/Test 共用一份从数值证据重算的 Door 原门槛，明确必需规则和全部 cell，
覆盖正历史收益、准确率、bootstrap 与 separation；旧 passed/checks 只用于一致性核验。
添加上述负例，再重判已有结果。现有输入齐全，这部分不需要重新推理模型。

### 2. 冻结尚未覆盖全部关键评分依赖与 Test 数据成员

共享 `paired_latent_response.py` 实际定义 gain、error 和 separation，但 v2 完全没有这个
源码路径的绑定。`causal_data_contract.py` 也未被列入；冻结工具目前是手工列举入口文件
（`freeze_current_reference_baseline.py:1204`）。因此，入口源码没变不能保证被调用的评分
公式没有变。这里应补齐关键依赖，不能把“入口已 pin”当作整个评测标准已固定。

六项配对 Test 的 freeze `data_identity` 还普遍是外层 bundle manifest、空 members/selection；
原始结果另有 release/data 身份，但当前验证器未像 Development 一样明确核对实际 validation
table 的成员绑定。实际数据校核结果良好，仍需补齐这条可验证来源链。

最小修复：绑定共同响应内核及实际数据读取合同，记录 Test 所用表/选择与 manifest 的关系，
加入关键依赖改变时必须拒绝的回归。保留 v2 归档，以新版本记录修正后的最终参考。

## 最终分数能够支持的能力结论

| 任务 | 当前结果的合理结论 |
|---|---|
| 门通行 | 三模型均通过当前两规则、配对 query 的历史条件响应检查；Test 均值约 99.83–100% |
| 动作延迟 | LeWM 97.68%、PLDM 100% 支持 h1 六个物理响应组的能力；DINO-WM 约 16.65%，未通过 |
| 机械臂质量 | LeWM 85.35% 且全部门槛通过，支持当前质量对照任务内的条件响应 |
| 速度 | LeWM/PLDM 内插分数 98.19%/96.78%，有明确内插能力；因外推失败而总门槛未过，不能解释为完全没学到速度 |
| 传送门 | DINO-WM 99.35%，但 gain 约 0.355–0.410，未达到完整响应标准；有区分能力，不是完全无能力 |
| 推手幅度 | DINO-WM 93.82%，低于主阈值 95%；未满足验收线不等于毫无学习 |
| 摩擦、阻尼、Cube 携带 | 当前参考未提供达到门槛的能力证据；负结果应保留，不能据此断言任务本身不可学习 |

这些是“固定数据分布内，模型能否利用历史作出正确方向和足够幅度的条件响应”的结论。
还须固定以下解释边界，避免后续研究因措辞变化而改变基准：

- **动作延迟 h1 无法区分 5–10。** 这些延迟在一步未来中物理上不可区分，因此合为一组是
  正确的；h2/h3 虽已产出，却不是正式通过条件。当前通过不能改称“精确识别全部 11 个延迟”。
- **ICL 响应通过不等于绝对预测或规划可靠。** CPU 实例中，给两种预测加上巨大且与目标
  差异正交的共同偏置，绝对 MSE=10000，差分响应门槛仍通过。这是相对响应设计的边界；
  绝对预测、长时 rollout 和 CEM 必须分别报告。
- **门任务有容易读取的历史证据。** 已检查的 300 个 Test payload 中，blocked 中间历史帧
  与 query 相同、passable 不同，可用简单帧比较识别规则。这是合法的碰撞历史信号，不能
  单凭这一现象认定作弊；但饱和高分不能证明更广泛的抽象规则或复杂布局迁移。
- **不能把整体缩小 latent 当成已证实的 collapse 漏洞。** 一个线程构造了间距很小但可
  精确预测的 latent 正例。归一化指标本来就应对可逆缩放不敏感，因此它不能证明信息丢失
  或错误通过；跨模型追加绝对 latent-MSE 下限反而会破坏该性质。是否存在实际数值不稳定
  需要另外证据，本轮不把它列为阻塞项。
- **门任务 Dev 多出的 no-attempt 统计不是新增最终门槛。** reader 仍用旧 strict 配置生成
  六个 bootstrap 统计，但统一判定取 Test release 要求的四项。不能仅凭多两个诊断字段
  断言当前最终 gate 多了一套标准；真正漏掉的是上述逐 cell 历史收益条件。

阈值由相邻任务沿用的来源已有记录，但不等于已经估计本任务的灵敏度与假阳性率。
后续应把固定正/负控制作为验收依据，不以观察新方法分数后再调阈值的方式补救。

## 验收状态

当前可保留 v2 作为已有测量的归档，**暂不把工程封板等同于最终研究基准验收**。
优先完成上述两项修复及能力声明边界，然后重判/重建身份记录并锁定最终版本。
本次证据不支持重训全部模型或重跑全部 GPU 评测；先使用已有原始结果完成可验证的修复。
